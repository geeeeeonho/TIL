# Cypher 기초 문법 정리

> Neo4j의 기본 Cypher 문법을 **작성 형태 중심**으로 정리.  
> 전체 흐름은 `CREATE → MATCH / RETURN → SET / REMOVE → DELETE` 순서로 보면 됨.

## 1. 노드·관계 패턴과 데이터 생성

Cypher는 그래프 구조를 그대로 그리는 형태로 작성함.

```text
(노드)-[관계]->(노드)
```

- 노드: `(...)`
- 관계: `-[...]->`
- 변수: 쿼리 안에서 해당 노드·관계를 가리키는 이름
- 레이블: 노드의 종류
- 속성: `{키: 값}` 형태의 데이터

### 노드 생성

```cypher
CREATE (:Employee {name: '한소희', role: '백엔드'})
```

기본 구조:

```text
CREATE (변수:레이블 {속성: 값})
```

변수까지 붙이면 생성한 노드를 같은 문장에서 다시 참조할 수 있음.

```cypher
CREATE (p:Project {name: '알림봇', status: '진행'})
RETURN p.name AS name, p.status AS status
```

결과:

```python
[{'name': '알림봇', 'status': '진행'}]
```

`CREATE`만 사용하면 데이터는 만들어지지만 반환값은 없음.

```cypher
CREATE (:Employee {name: '한소희'})
```

```python
[]
```

### 속성 자료형

속성은 작성 형태에 따라 자료형이 결정됨.

| 종류 | Cypher 표기 |
|---|---|
| 문자열 | `'한소희'` |
| 정수 | `5` |
| 실수 | `4.5` |
| 불리언 | `true`, `false` |
| 리스트 | `['문서', '검색']` |
| 날짜 | `date('2024-05-01')` |

예:

```cypher
CREATE (p:Project {
    name: '사내위키',
    budget: 3000,
    rating: 4.5,
    active: true,
    tags: ['문서', '검색'],
    started: date('2024-05-01')
})
```

숫자와 문자열은 구분해야 함.

```text
years: 5      // 정수
years: '5'    // 문자열
```

날짜도 문자열과 다름.

```text
date('2024-05-01')    // 날짜
'2024-05-01'          // 문자열
```

날짜형이면 날짜의 일부를 꺼내거나 기간 계산 가능.

```cypher
RETURN p.started.year AS year,
       p.started.month AS month,
       duration.between(p.started, date()).months AS months
```

### 여러 레이블

한 노드가 여러 레이블을 가질 수 있음.

```cypher
CREATE (:Employee:Mentor {name: '류지호'})
```

조회할 때도 동일.

```cypher
MATCH (x:Employee:Mentor)
RETURN x.name AS name
```

`Employee:Mentor`는 **Employee이면서 Mentor**라는 뜻.  
레이블을 나란히 적으면 OR가 아니라 AND로 동작함.

### 관계 생성

관계 기본 형태:

```text
(a)-[:관계종류]->(b)
```

예:

```cypher
(e)-[:WORKS_IN]->(t)
```

이미 존재하는 두 노드를 연결하려면 먼저 `MATCH`로 각각 찾은 뒤 관계를 생성함.

```cypher
MATCH (e:Employee {name: '한소희'}),
      (t:Team {name: '개발팀'})
CREATE (e)-[:WORKS_IN]->(t)
```

즉 다음 패턴을 자주 사용함.

```text
MATCH (a), (b)
CREATE (a)-[:관계]->(b)
```

관계에도 속성을 저장할 수 있음.

```cypher
MATCH (e:Employee {name: '한소희'}),
      (p:Project {name: '앱개편'})
CREATE (e)-[r:ASSIGNED_TO {
    since: 2024,
    hours: 20
}]->(p)
RETURN r.since AS since, r.hours AS hours
```

관계 속성을 읽으려면 관계에도 변수를 붙임.

```text
-[r:ASSIGNED_TO]->
```

```cypher
MATCH (e:Employee)-[r:ASSIGNED_TO]->(p:Project)
RETURN p.name AS project,
       r.since AS since,
       r.hours AS hours
```

노드가 아니라 **그 연결 자체에 해당하는 값**은 관계 속성으로 둠.

```text
Employee -[ASSIGNED_TO {since, hours}]-> Project
```

### 노드와 관계를 한 번에 생성

양쪽 노드가 모두 새 데이터라면 한 패턴으로 생성 가능.

```cypher
CREATE
(e:Employee {name: '문가영', role: '기획'})
-[:WORKS_IN]->
(t:Team {name: '기획팀'})
```

관계 속성도 함께 작성 가능.

```cypher
CREATE
(s:Student {name: '하지원', major: '음악', grade: 1})
-[r:BELONGS_TO {joined: 2026}]->
(c:Club {name: '노래동아리'})
RETURN s.name AS name,
       c.name AS club,
       r.joined AS joined
```

단, `CREATE`는 적힌 패턴을 새로 생성함.  
한쪽 노드가 이미 있다면 같은 이름의 노드가 중복 생성될 수 있으므로 기존 노드는 `MATCH`로 찾은 뒤 연결함.

## 2. MATCH와 RETURN으로 조회

조회 기본 구조:

```text
MATCH 패턴
RETURN 반환값
```

### 노드 조회

레이블에 해당하는 모든 노드 조회:

```cypher
MATCH (e:Employee)
RETURN e.name AS name
```

속성까지 지정하면 해당 값과 일치하는 노드만 찾음.

```cypher
MATCH (e:Employee {name: '한소희'})
RETURN e.name AS name, e.role AS role
```

관계 패턴 자체를 조건으로 사용할 수도 있음.

```cypher
MATCH (e:Employee)-[:WORKS_IN]->(:Team {name: '개발팀'})
RETURN e.name AS name
```

여기서 변수 없는 노드:

```text
(:Team {name: '개발팀'})
```

은 패턴을 찾는 조건으로만 사용됨.

### RETURN과 별칭

여러 값을 반환할 때 쉼표로 연결.

```cypher
RETURN e.name AS name,
       e.role AS role
```

`run_cypher()`에서는 결과가 `dict`의 리스트로 반환되며, `AS` 별칭이 dict의 키가 됨.

```python
rows = run_cypher("""
MATCH (e:Employee)
RETURN e.name AS name, e.role AS role
""")

print(rows[0]['name'])
print(rows[0]['role'])
```

노드 전체를 반환할 수도 있음.

```cypher
MATCH (e:Employee {name: '한소희'})
RETURN e
```

결과 형태:

```python
[
    {
        'e': {
            'name': '한소희',
            'role': '백엔드'
        }
    }
]
```

따라서 속성 접근:

```python
rows[0]['e']['name']
```

필요한 속성이 정해져 있다면 다음처럼 골라 받는 형태가 단순함.

```cypher
RETURN e.name AS name
```

```python
rows[0]['name']
```

### 긴 쿼리 작성

파이썬에서는 삼중따옴표로 Cypher를 여러 줄 작성 가능.

```python
rows = run_cypher("""
// 개발팀 직원 조회
MATCH (e:Employee)-[:WORKS_IN]->(:Team {name: '개발팀'})
RETURN e.name AS name, e.role AS role
""")
```

Cypher 내부 주석은 `//` 사용.

```cypher
// Cypher 주석
MATCH (e:Employee)
RETURN e
```

## 3. SET과 REMOVE로 수정

수정은 먼저 `MATCH`로 대상을 찾고, 해당 변수에 `SET` 또는 `REMOVE`를 적용함.

### SET

기본 형태:

```cypher
MATCH (e:Employee {name: '김서준'})
SET e.years = 6
```

기존 속성이 있으면 덮어쓰고, 없으면 새 속성이 만들어짐.

```cypher
MATCH (e:Employee {name: '김서준'})
SET e.phone = '010-1234-5678'
RETURN e.phone AS phone
```

여러 속성은 쉼표로 한 번에 수정.

```cypher
MATCH (e:Employee {name: '김서준'})
SET e.role = '백엔드 리드',
    e.level = '시니어'
RETURN e.role AS role, e.level AS level
```

관계 속성도 같은 방식.

```cypher
MATCH (:Employee {name: '김서준'})
      -[r:ASSIGNED_TO]->
      (:Project {name: '결제시스템'})
SET r.hours = 30
RETURN r.hours AS hours
```

레이블을 추가할 때도 `SET` 사용.

```cypher
MATCH (e:Employee {name: '김서준'})
SET e:Manager
```

구분:

```text
SET e.phone = '...'    // 속성
SET e:Manager          // 레이블
```

### REMOVE

속성 제거:

```cypher
MATCH (e:Employee {name: '김서준'})
REMOVE e.phone
```

레이블 제거:

```cypher
MATCH (e:Employee {name: '김서준'})
REMOVE e:Manager
```

구분:

```text
REMOVE e.phone      // 점(.) → 속성
REMOVE e:Manager    // 콜론(:) → 레이블
```

속성을 제거한 뒤 조회하면 `run_cypher()` 결과에서는 `None`으로 확인됨.

```cypher
MATCH (e:Employee {name: '김서준'})
RETURN e.phone AS phone
```

```python
[{'phone': None}]
```

`REMOVE`는 노드 자체를 삭제하지 않음.  
속성이나 레이블만 제거함.

## 4. DELETE와 DETACH DELETE

삭제도 먼저 `MATCH`로 대상을 지정함.

### 노드 삭제

관계가 붙어 있지 않은 노드:

```cypher
MATCH (p:Project {name: '알림봇'})
DELETE p
```

`DELETE` 뒤에 적은 변수가 실제 삭제 대상임.

### 관계만 삭제

관계에 변수를 붙여 삭제.

```cypher
MATCH (:Employee {name: '한소희'})
      -[r:ASSIGNED_TO]->
      ()
DELETE r
```

여기서:

```text
()
```

은 특정 레이블이나 속성을 지정하지 않은 노드 패턴.

`DELETE r`이므로 관계만 없어지고 양쪽 노드는 남음.

### 관계가 붙은 노드 삭제

관계가 연결된 노드는 일반 `DELETE`로 바로 삭제할 수 없음.

```cypher
MATCH (e:Employee {name: '문가영'})
DETACH DELETE e
```

`DETACH DELETE`는 해당 노드에 붙어 있는 관계를 먼저 제거하고 노드까지 삭제함.

차이:

```text
DELETE r
→ 관계만 삭제

DELETE n
→ 관계가 없는 노드 삭제

DETACH DELETE n
→ 연결된 관계 + 노드 삭제
```

전체 그래프를 지우는 형태도 같은 문법의 확장임.

```cypher
MATCH (n)
DETACH DELETE n
```

조건이 없으므로 모든 노드가 `MATCH`되고 전부 삭제됨.

## 핵심 문법 압축

| 목적 | 기본 문법 |
|---|---|
| 노드 생성 | `CREATE (:Label {key: value})` |
| 생성 후 바로 반환 | `CREATE (n:Label {...}) RETURN n.key AS key` |
| 여러 레이블 | `(n:Label1:Label2)` |
| 관계 표현 | `(a)-[:REL]->(b)` |
| 관계 속성 | `(a)-[r:REL {key: value}]->(b)` |
| 노드 조회 | `MATCH (n:Label) RETURN n` |
| 속성 조건 조회 | `MATCH (n:Label {key: value})` |
| 속성 반환 | `RETURN n.key AS alias` |
| 관계 속성 반환 | `RETURN r.key AS alias` |
| 속성 수정·추가 | `SET n.key = value` |
| 여러 속성 수정 | `SET n.a = 1, n.b = 2` |
| 레이블 추가 | `SET n:Label` |
| 속성 제거 | `REMOVE n.key` |
| 레이블 제거 | `REMOVE n:Label` |
| 노드 삭제 | `DELETE n` |
| 관계 삭제 | `DELETE r` |
| 관계 포함 노드 삭제 | `DETACH DELETE n` |

### 작성 흐름

```text
생성
CREATE (n:Label {property: value})

        ↓

조회
MATCH (n:Label {property: value})
RETURN n.property AS alias

        ↓

수정
MATCH (...)
SET ...
REMOVE ...

        ↓

삭제
MATCH (...)
DELETE ...
DETACH DELETE ...
```

### 가장 중요한 구분

```text
()                  = 노드
-[...]->             = 관계
:Label               = 레이블
{key: value}         = 속성
n.property           = 노드 속성 접근
r.property           = 관계 속성 접근
AS alias             = 반환값 이름 지정
```

```text
SET      = 값 또는 레이블을 붙이거나 수정
REMOVE   = 속성 또는 레이블만 제거
DELETE   = 노드·관계 자체 제거
```

> `SET`, `REMOVE`, `DELETE`의 적용 범위는 앞의 `MATCH`가 결정함.  
> 수정·삭제 전 같은 `MATCH`를 `RETURN`으로 먼저 실행해 대상을 확인하는 형태가 안전함.

## 원본 실습에서 주의할 부분

노트북은 셀을 여러 번 실행한 흔적 때문에 일부 예제에서 같은 노드·관계가 중복되어 출력됨. 이는 Cypher 문법 자체의 결과라기보다 `CREATE` 셀의 반복 실행 영향임.

또한 새 학생·동아리 생성 예제의 반환 별칭에 다음 오타가 있음.

```cypher
c.name AS clud
```

학습용 문법에서는 다음처럼 정리.

```cypher
c.name AS club
```
