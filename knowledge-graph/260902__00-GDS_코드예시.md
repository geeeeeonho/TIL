# GDS 투영 · 차수 · 중심성 실전 코드

## 준비. 적재된 데이터 확인

분석에 사용할 노드와 관계가 정상적으로 적재되었는지 확인한다.

```python
# 사용할 노드 종류 확인
counts = run_cypher("""
MATCH (n)
WHERE n:PharmacologicClass OR n:Compound
RETURN labels(n)[0] AS label, count(*) AS cnt
ORDER BY cnt DESC
""")

for row in counts:
    print(f"  {row['label']:20} {row['cnt']:>6,}")


# 사용할 관계 종류 확인
rel_counts = run_cypher("""
MATCH ()-[r]->()
WHERE type(r) IN ['INCLUDES', 'RESEMBLES_CC']
RETURN type(r) AS rel_type, count(*) AS cnt
ORDER BY cnt DESC
""")

for row in rel_counts:
    print(f"  {row['rel_type']:20} {row['cnt']:>6,}")


# 특정 약효분류에 포함된 약 예시 확인
sample = run_cypher("""
MATCH (p:PharmacologicClass {name: 'Thiazides'})-[:INCLUDES]->(c:Compound)
RETURN c.name AS drug
ORDER BY drug
""")

print("Thiazides 에 속한 약:", [row["drug"] for row in sample])
```

**결과**

```text
Compound              1,531
PharmacologicClass      345
RESEMBLES_CC          6,486
INCLUDES              1,029

Thiazides 에 속한 약:
['Bendroflumethiazide', 'Chlorothiazide', 'Hydrochlorothiazide',
 'Hydroflumethiazide', 'Methyclothiazide', 'Polythiazide']
```

# 1. 그래프 투영

## 1-1. 분석용 그래프 투영 만들기

Neo4j에 저장된 데이터를 GDS가 분석할 수 있도록 메모리 그래프로 투영한다.

`INCLUDES`, `RESEMBLES_CC` 관계를 모두 **무방향(`UNDIRECTED`)** 으로 사용한다.

```python
rows1_1 = run_cypher("""
CALL gds.graph.project(
    'classGraph',

    // 투영할 노드 레이블
    ['PharmacologicClass', 'Compound'],

    // 두 관계를 무방향으로 투영
    {
        INCLUDES: {
            orientation: 'UNDIRECTED'
        },
        RESEMBLES_CC: {
            orientation: 'UNDIRECTED'
        }
    }
)

YIELD nodeCount
RETURN nodeCount
""")

n_nodes = rows1_1[0]['nodeCount']
print(n_nodes)
```

**결과**

```text
1876
```

---

## 1-2. 노드 레이블이 부족한 경우

`INCLUDES` 관계는 `PharmacologicClass → Compound`를 연결한다.

따라서 `PharmacologicClass`만 투영하면 관계의 반대편인 `Compound`가 없기 때문에 `INCLUDES` 관계도 투영되지 않는다.

```python
rows1_2 = run_cypher("""
CALL gds.graph.project(
    'onlyClassGraph',

    // PharmacologicClass만 투영
    ['PharmacologicClass'],

    // INCLUDES 관계 투영 시도
    ['INCLUDES']
)

YIELD relationshipCount
RETURN relationshipCount
""")

only_rels = rows1_2[0]['relationshipCount']
print(only_rels)
```

**결과**

```text
0
```

> 관계를 투영하려면 해당 관계의 양쪽 노드가 모두 투영 대상에 포함되어야 한다.

## 2-2. 무방향 투영 검산

무방향 투영은 하나의 원본 관계를 양쪽 방향으로 사용할 수 있도록 저장한다.

따라서 GDS 내부 관계 수는 원본 관계 수의 **2배**가 된다.

```python
# 1. 원본 Neo4j 관계 수
raw_rows = run_cypher("""
MATCH ()-[r]->()
WHERE type(r) IN ['INCLUDES', 'RESEMBLES_CC']
RETURN count(r) AS relationshipCount
""")

raw_rels = raw_rows[0]['relationshipCount']


# 2. classGraph의 투영 관계 수
proj_rows = run_cypher("""
CALL gds.graph.list('classGraph')

YIELD relationshipCount
RETURN relationshipCount
""")

proj_rels = proj_rows[0]['relationshipCount']


# 3. 원본 관계 수의 2배인지 확인
is_undirected = proj_rels == raw_rels * 2

print('Neo4j 원본 관계 수:', raw_rels)
print('투영된 그래프의 관계 수:', proj_rels)
print(is_undirected)
```

**결과**

```text
Neo4j 원본 관계 수: 7515
투영된 그래프의 관계 수: 15030
True
```

# 3. 중심성과 실행 모드

## 3-1. PageRank 1위 찾기

PageRank는 단순히 연결 수만 보는 것이 아니라 **중요한 노드와 얼마나 연결되어 있는지**까지 반영한다.

```python
rows3_1 = run_cypher("""
CALL gds.pageRank.stream('classGraph')

YIELD nodeId, score

// GDS 내부 nodeId → 실제 Neo4j 노드
RETURN gds.util.asNode(nodeId).name AS name

ORDER BY score DESC
LIMIT 1
""")

top_node = rows3_1[0]['name']
print('PageRank 1위 노드:', top_node)
```

**결과**

```text
PageRank 1위 노드: Eltrombopag
```

---

## 3-2. Degree와 PageRank 비교

Degree는 **직접 연결된 관계 수**만 계산한다.

따라서 Degree 1위와 PageRank 1위는 서로 다를 수 있다.

```python
rows3_2 = run_cypher("""
CALL gds.degree.stream('classGraph')

YIELD nodeId, score

RETURN gds.util.asNode(nodeId).name AS name

ORDER BY score DESC
LIMIT 1
""")

deg_top = rows3_2[0]['name']

# Degree 1위와 PageRank 1위 비교
tops_differ = deg_top != top_node

print('차수(Degree) 1위 노드:', deg_top)
print('PageRank 1위와 다른가:', tops_differ)
```

**결과**

```text
차수(Degree) 1위 노드: Diphenhydramine
PageRank 1위와 다른가: True
```

## 3-3. 방향을 유지해 외차수 · 내차수 비교

이번에는 관계 방향을 유지한 별도의 투영을 만든다.

`INCLUDES` 관계만 선택해 다음을 각각 계산한다.

- 외차수: 나가는 `INCLUDES` 관계 수
- 내차수: 들어오는 `INCLUDES` 관계 수

### 방향 그래프 생성

```python
rows3_3_proj = run_cypher("""
CALL gds.graph.project(
    'classDirected',

    ['PharmacologicClass', 'Compound'],

    // orientation을 지정하지 않으면 원본 방향 유지
    ['INCLUDES', 'RESEMBLES_CC']
)

YIELD graphName, nodeCount, relationshipCount
RETURN graphName, nodeCount, relationshipCount
""")

print(rows3_3_proj)
```

**결과**

```text
[{
    'graphName': 'classDirected',
    'nodeCount': 1876,
    'relationshipCount': 7515
}]
```

### 외차수 1위

```python
out_rows = run_cypher("""
CALL gds.degree.stream(
    'classDirected',
    {
        // INCLUDES 관계만 사용
        relationshipTypes: ['INCLUDES']
    }
)

YIELD nodeId, score

RETURN gds.util.asNode(nodeId).name AS name, score

ORDER BY score DESC, name ASC
LIMIT 1
""")

out_top = out_rows[0]['name']
print('외차수 1위:', out_top)
```

**결과**

```text
외차수 1위: Corticosteroid Hormone Receptor Agonists
```

### 내차수 1위

관계를 뒤집어서 계산하면 들어오는 관계 수를 셀 수 있다.

```python
in_rows = run_cypher("""
CALL gds.degree.stream(
    'classDirected',
    {
        relationshipTypes: ['INCLUDES'],

        // 원본 방향을 반대로 계산
        orientation: 'REVERSE'
    }
)

YIELD nodeId, score

RETURN gds.util.asNode(nodeId).name AS name, score

ORDER BY score DESC, name ASC
LIMIT 1
""")

in_top = in_rows[0]['name']
print('내차수 1위:', in_top)
```

**결과**

```text
내차수 1위: Eltrombopag
```

## 3-4. 분석 결과 저장하기

GDS 알고리즘 결과는 실행 모드에 따라 저장 위치가 달라진다.

- `write` : 원본 Neo4j DB에 속성으로 저장
- `mutate` : GDS 메모리 그래프 안에만 저장
- `stream` : 결과만 반환하고 저장하지 않음

### write

PageRank 결과를 원본 노드의 `class_rank` 속성으로 저장한다.

```python
write_rows = run_cypher("""
CALL gds.pageRank.write(
    'classGraph',
    {
        writeProperty: 'class_rank'
    }
)

YIELD nodePropertiesWritten
RETURN nodePropertiesWritten
""")

n_written = write_rows[0]['nodePropertiesWritten']
print('원본 DB에 저장된 노드 수:', n_written)
```

**결과**

```text
원본 DB에 저장된 노드 수: 1876
```

### mutate

같은 결과를 `classGraph` 투영 내부의 `pr_mutated` 속성으로만 저장한다.

```python
mutate_rows = run_cypher("""
CALL gds.pageRank.mutate(
    'classGraph',
    {
        mutateProperty: 'pr_mutated'
    }
)

YIELD nodePropertiesWritten
RETURN nodePropertiesWritten
""")

n_mutated = mutate_rows[0]['nodePropertiesWritten']
print('투영에 저장된 노드 수:', n_mutated)
```

**결과**

```text
투영에 저장된 노드 수: 1876
```

### 원본 DB 확인

`mutate`로 만든 `pr_mutated` 속성이 원본 Neo4j DB에는 저장되지 않았는지 확인한다.

```python
db_rows = run_cypher("""
MATCH (n)

WHERE 'pr_mutated' IN keys(n)

RETURN count(n) AS count
""")

n_in_db = db_rows[0]['count']
print('원본 DB의 pr_mutated 노드 수:', n_in_db)
```

**결과**

```text
원본 DB의 pr_mutated 노드 수: 0
```

## 3-5. write로 저장한 속성 조회

`write`로 저장한 `class_rank`는 원본 Neo4j 속성이므로 이후에는 GDS 알고리즘을 다시 실행하지 않고 일반 Cypher로 조회할 수 있다.

```python
rows3_5 = run_cypher("""
MATCH (c:PharmacologicClass)

WHERE c.class_rank IS NOT NULL

RETURN c.name AS name, c.class_rank AS score

ORDER BY score DESC
LIMIT 1
""")

saved_top = rows3_5[0]['name']
print(saved_top)
```

**결과**

```text
Alkylating Activity
```

# 4. 개인화 PageRank와 투영 정리

## 4-1. 개인화 PageRank

일반 PageRank가 그래프 전체의 중요도를 계산한다면, 개인화 PageRank는 **특정 노드를 출발점으로 중요도를 다시 계산**한다.

즉 특정 약효분류와 가까우면서 중요한 노드를 찾는 방식으로 사용할 수 있다.

```python
ppr_query = """
// 기준이 될 약효분류 노드
MATCH (c:PharmacologicClass)
WHERE c.name = $name

// PageRank 출발 노드는 리스트 형태로 전달
WITH collect(c) AS sources

CALL gds.pageRank.stream(
    'classGraph',
    {
        sourceNodes: sources
    }
)

YIELD nodeId, score

RETURN gds.util.asNode(nodeId).name AS name

ORDER BY score DESC
LIMIT 3
"""

ppr_rows = run_cypher(
    ppr_query,
    name='Vitamin K Inhibitors'
)

ppr_top3 = [row['name'] for row in ppr_rows]
print(ppr_top3)
```

**결과**

```text
['Vitamin K Inhibitors', 'Phenprocoumon', 'Warfarin']
```

## 4-2. 사용이 끝난 투영 삭제

GDS 투영은 메모리를 사용하므로 분석이 끝나면 삭제한다.

전체 투영을 한꺼번에 삭제하기보다 **그래프 이름을 지정해 필요한 투영만 삭제**하는 것이 안전하다.

`classGraph`는 남기고 다음 두 그래프만 삭제한다.

- `onlyClassGraph`
- `classDirected`

```python
# onlyClassGraph 삭제
drop_only = run_cypher("""
CALL gds.graph.drop('onlyClassGraph')

YIELD graphName
RETURN graphName
""")

print('삭제:', drop_only[0]['graphName'])


# classDirected 삭제
drop_directed = run_cypher("""
CALL gds.graph.drop('classDirected')

YIELD graphName
RETURN graphName
""")

print('삭제:', drop_directed[0]['graphName'])


# 남아 있는 투영 확인
remain_rows = run_cypher("""
CALL gds.graph.list()

YIELD graphName
RETURN graphName
""")

remain = [row['graphName'] for row in remain_rows]
print('남은 투영:', remain)
```

**결과**

```text
삭제: onlyClassGraph
삭제: classDirected
남은 투영: ['classGraph']
```

# 핵심 정리

| 작업 | 사용 기능 | 핵심 |
|---|---|---|
| 분석 그래프 생성 | `gds.graph.project()` | Neo4j 데이터를 GDS 메모리로 투영 |
| 투영 목록 확인 | `gds.graph.list()` | 현재 메모리에 존재하는 그래프 확인 |
| 연결 수 계산 | `gds.degree.stream()` | 직접 연결된 관계 수 계산 |
| 전체 중요도 계산 | `gds.pageRank.stream()` | 연결된 노드의 중요도까지 반영 |
| 특정 노드 기준 분석 | `sourceNodes` | 개인화 PageRank |
| 원본 DB 저장 | `write` | Neo4j 노드 속성으로 저장 |
| 투영 내부 저장 | `mutate` | 메모리 그래프에만 저장 |
| 결과만 사용 | `stream` | 저장 없이 결과 반환 |
| 투영 삭제 | `gds.graph.drop()` | 사용이 끝난 메모리 그래프 제거 |
