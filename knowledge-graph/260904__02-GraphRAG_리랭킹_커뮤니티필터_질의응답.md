# GraphRAG 검색 최적화와 질의응답 핵심 정리

> 핵심 흐름  
> **문서 검색 → 그래프 점수로 리랭킹 → 커뮤니티로 범위 필터 → 근거 구성 → LLM 답변 → 인용 검증**

지난 단계에서 문서를 임베딩하고 `MENTIONS` 관계로 지식그래프의 개체와 연결했다면, 이번 단계는 그 연결을 **검색 품질과 답변 근거에 실제로 사용하는 과정**이다.

---

## 1. GraphRAG 검색 구조

GraphRAG 검색은 크게 두 부분으로 나뉜다.

| 구분 | 역할 |
|---|---|
| 기본 GraphRAG | 질문으로 문서를 찾고, 문서가 가리키는 그래프 개체를 함께 근거로 사용 |
| 검색 최적화 | 그래프 구조를 이용해 후보의 **순위를 바꾸거나**, 검색 **범위를 줄임** |

```text
질문
 ↓
벡터 검색
 ↓
후보 문서
 ├─ PageRank → 리랭킹
 └─ Leiden → 커뮤니티 필터
 ↓
논문 + 연결된 개체
 ↓
LLM 답변
 ↓
인용 검증
```

## 2. `VectorRetriever`로 의미 검색 묶기

직접 구현하면 `질문 임베딩 → 벡터 검색 → 결과 정리`를 매번 연결해야 한다.

`VectorRetriever`는 이 과정을 하나의 검색기(retriever)로 묶는다.

```python
from neo4j_graphrag.retrievers import VectorRetriever

retriever = VectorRetriever(
    driver,
    'doc_vec',
    embedder=query_embedder,
    return_properties=['pmcid', 'title']
)

question = '어떤 유전자가 약물 대사에 관여하나요?'

result = retriever.search(
    query_text=question,
    top_k=3
)
```

### 결과

```text
RetrieverResult · 항목 3 개
```

검색 결과는 `RetrieverResult.items` 안에 들어간다.

```python
print(result.items[0])
```

### 결과

```text
content="{'pmcid': 'PMC13494111', 'title': '...'}"
metadata={
    'score': 0.7306,
    'nodeLabels': ['Document'],
    'id': '...'
}
```

기본 `content`는 딕셔너리처럼 보여도 실제로는 문자열이다.

```python
print(type(result.items[0].content).__name__)
```

### 결과

```text
str
```

### 결과 형식 지정

`result_formatter`를 사용하면 원하는 구조로 결과를 만들 수 있다.

```python
from neo4j_graphrag.types import RetrieverResultItem

def to_item(record):
    paper = record['node']

    return RetrieverResultItem(
        content=paper['text'][:120],
        metadata={
            'pmcid': paper['pmcid'],
            'title': paper['title'],
            'score': record['score']
        }
    )

retriever = VectorRetriever(
    driver,
    'doc_vec',
    embedder=query_embedder,
    result_formatter=to_item
)
```

### 핵심

```text
VectorRetriever
= 질문 임베딩 + 벡터 검색 + 결과 포맷팅
```

`return_properties`는 **노드 자체 속성**만 가져온다.  
`(Document)-[:MENTIONS]->(Entity)`처럼 관계를 따라가야 얻는 정보는 별도 Cypher가 필요하다.

## 3. 직접 `SEARCH` 쿼리로 검색하기

리랭킹에서는 유사도와 그래프 점수를 한 행에서 함께 사용하므로 직접 Cypher로 검색하면 편하다.

```python
def search_docs(question, top_k=5):
    return run_cypher(
        '''
        MATCH (n:Document)

        SEARCH n IN (
            VECTOR INDEX doc_vec
            FOR $q
            LIMIT $k
        )
        SCORE AS score

        RETURN
            n.pmcid AS pmcid,
            n.title AS title,
            score,
            n.graph_score AS graph_score

        ORDER BY score DESC
        ''',
        q=embed_query(question),
        k=top_k
    )
```

검색기와 직접 작성한 `SEARCH` 쿼리는 같은 벡터 인덱스를 사용하므로 같은 검색 결과를 낸다.

```text
검색기       : PMC13494111 → PMC13432136 → PMC13368705
직접 SEARCH : PMC13494111 → PMC13432136 → PMC13368705
```

## 4. 벡터 검색과 전문 검색

벡터 검색은 **의미가 가까운 문서**, 전문 검색은 **특정 문자열이 들어간 문서**를 찾는다.

```python
symbol = 'CYP2C19'

by_vector = [
    hit['pmcid']
    for hit in search_docs(symbol, top_k=5)
]

by_term = [
    row['pmcid']
    for row in run_cypher(
        '''
        CALL db.index.fulltext.queryNodes(
            'doc_ft',
            $t
        )
        YIELD node, score

        RETURN node.pmcid AS pmcid
        ORDER BY score DESC
        ''',
        t=symbol
    )
]
```

```text

PMC13432136
PMC13461525

PMC13368705

키워드 검색:
PMC13478934
PMC13461525
```


# 6. 개체 PageRank를 문서 점수로 변환

문서가 언급하는 개체의 PageRank 평균을 `graph_score`로 저장한다.

```python
run_cypher(
    '''
    MATCH (d:Document)-[:MENTIONS]->(e)

    WHERE e.pagerank IS NOT NULL

    WITH
        d,
        avg(e.pagerank) AS mean

    SET d.graph_score = mean
    '''
)
```

투영에 포함된 개체를 하나도 언급하지 않은 문서는 바닥값을 준다.

```python
run_cypher(
    '''
    MATCH (d:Document)

    WHERE d.graph_score IS NULL

    SET d.graph_score = 0.15
    '''
)
```

### 결과

```text
개체에서 점수를 받은 논문: 58편 / 전체 69편
```

나머지 11편은 현재 투영의 약물·질병·약효분류 개체를 언급하지 않은 문서다.

### 평균을 사용하는 이유

```text
max(PageRank)
→ 중심성이 높은 개체 하나의 영향이 너무 큼

avg(PageRank)
→ 문서가 다루는 개체들의 전반적인 중심성 반영
```

단, 현재 투영에 없는 유전자·증상은 `pagerank`가 없으므로 평균 계산에서 빠진다.

# 7. 검색 점수와 그래프 점수 정규화

두 점수의 범위가 다르다.

```text
검색 유사도 : 약 0.70 ~ 0.73
그래프 점수 : 약 0.15 ~ 8
```

그대로 더하면 그래프 점수가 순위를 지배할 수 있다.

후보 안에서 각각 0~1로 Min-Max 정규화한다.

```python
def minmax(values):
    low = min(values)
    high = max(values)

    return [
        0.5 if high == low
        else (v - low) / (high - low)

        for v in values
    ]
```

### 결과 예시

```text
유사도
[0.703, 0.706, 0.708, 0.731]
→ [0.00, 0.11, 0.18, 1.00]

그래프
[0.80, 0.95, 1.11, 1.31]
→ [0.00, 0.29, 0.61, 1.00]
```

모든 값이 같으면 나눗셈이 불가능하므로 `0.5`를 사용한다.

# 8. 두 점수를 섞어 리랭킹

```text
최종 점수
= (1 - w) × 검색 점수
+ w × 그래프 점수
```

```python
def rerank(hits, weight):
    sim = minmax([
        hit['score']
        for hit in hits
    ])

    graph = minmax([
        hit['graph_score']
        for hit in hits
    ])

    fused = [
        (1 - weight) * s + weight * g
        for s, g in zip(sim, graph)
    ]

    ranked = sorted(
        zip(hits, fused),
        key=lambda pair: -pair[1]
    )

    return [
        hit['pmcid']
        for hit, _ in ranked
    ]
```

### `weight` 의미

```text
w = 0
→ 검색 유사도만 사용

w = 1
→ 그래프 점수만 사용

0 < w < 1
→ 두 점수 혼합
```

### 실제 순위 변화

기본 검색:

```text
PMC13494111  유사도 0.731  그래프 0.95
PMC13432136  유사도 0.708  그래프 1.11
PMC13368705  유사도 0.706  그래프 0.99
PMC13494176  유사도 0.704  그래프 0.80
PMC13464512  유사도 0.703  그래프 1.31
```

```text
의미 검색만:
PMC13494111
PMC13432136
PMC13368705
PMC13494176
PMC13464512

w = 0.3:
PMC13494111
PMC13432136
PMC13464512
PMC13368705
PMC13494176

w = 0.7:
PMC13464512
PMC13494111
PMC13432136
PMC13368705
PMC13494176
```

그래프 비중이 커지면서 기존 5위 문서가 1위까지 올라간다.

### 주의

그래프 중심성이 높다고 현재 질문에도 반드시 더 적합한 것은 아니다.

```text
그래프 가중치가 너무 작음
→ 기존 벡터 검색과 거의 같음

그래프 가중치가 너무 큼
→ 질문보다 중심성이 높은 문서가 과도하게 올라올 수 있음
```

따라서 `weight`는 평가 질문을 두고 직접 조정해야 한다.

# 9. Leiden 커뮤니티로 검색 범위 제한

리랭킹은 **후보 순서를 바꾸지만 후보 자체는 제거하지 않는다.**

특정 약물이나 주제의 주변 그래프만 검색하고 싶다면 커뮤니티를 필터로 사용할 수 있다.

```python
summary = run_cypher(
    '''
    CALL gds.leiden.write(
        'drugGraph',
        {
            writeProperty: 'community',
            randomSeed: 42,
            concurrency: 1
        }
    )

    YIELD
        communityCount,
        modularity

    RETURN
        communityCount,
        round(modularity, 3) AS modularity
    '''
)[0]
```

### 결과

```text
커뮤니티 수 : 173
모듈러리티 : 0.784
```

크기 분포:

```text
혼자인 커뮤니티 : 104
2개 이상         : 69
10개 이상        : 23
가장 큰 커뮤니티 : 194개 노드
```

따라서 단순히 `173개`라는 숫자보다 **실제로 여러 노드가 모인 커뮤니티가 몇 개인지**를 같이 봐야 한다.

# 11. 커뮤니티를 검색 필터로 사용

벡터 검색으로 넓게 후보를 받고, 그중 특정 커뮤니티 개체를 언급한 문서만 남긴다.

```python
def search_in_community(
    question,
    community,
    pool=20
):
    rows = run_cypher(
        '''
        MATCH (n:Document)

        SEARCH n IN (
            VECTOR INDEX doc_vec
            FOR $q
            LIMIT $k
        )
        SCORE AS score

        MATCH (n)-[:MENTIONS]->(e)

        WHERE e.community = $c

        RETURN DISTINCT
            n.pmcid AS pmcid,
            score

        ORDER BY score DESC
        ''',
        q=embed_query(question),
        k=pool,
        c=community
    )

    return [
        row['pmcid']
        for row in rows
    ]
```

### 결과 예시

```text
좁히기 전 상위 5편:
PMC13494111
PMC13432136
PMC13368705
PMC13494176
PMC13464512

커뮤니티 필터 후:
PMC13494111
PMC13432136
PMC13368705
PMC13468388
PMC13473732
PMC13461525
PMC13478934
```

상위 20편 중 7편이 남았다.

### 리랭킹과 필터 차이

| 방식 | 역할 |
|---|---|
| 리랭킹 | 후보를 유지하고 **순서를 변경** |
| 커뮤니티 필터 | 조건 밖 후보를 제거해 **범위를 제한** |

```text
리랭킹
A B C D E
↓
C A B E D

커뮤니티 필터
A B C D E
↓
A C E
```

필터는 관련 문서까지 함께 제거할 수 있으므로 질문 목적에 따라 사용한다.

# 12. GraphRAG용 근거 만들기

검색 문서의 본문뿐 아니라 `MENTIONS`로 연결된 개체도 함께 근거로 가져온다.

```python
def build_context(pmcids):
    rows = run_cypher(
        '''
        MATCH (d:Document)
        WHERE d.pmcid IN $ids

        OPTIONAL MATCH
            (d)-[:MENTIONS]->(e)

        WITH d, e
        ORDER BY e.name

        RETURN
            d.pmcid AS pmcid,
            d.title AS title,
            d.text AS text,
            collect(DISTINCT e.name)[..8] AS entities
        ''',
        ids=pmcids
    )

    by_id = {
        row['pmcid']: row
        for row in rows
    }

    parts = []

    for pmcid in pmcids:
        row = by_id[pmcid]

        parts.append(
            f"[{row['pmcid']}] {row['title']}\n"
            f"본문: {row['text']}\n"
            f"언급 개체: {', '.join(row['entities'])}"
        )

    return '\n\n'.join(parts)
```

근거 구조:

```text
[PMC ID] 논문 제목
본문: ...

언급 개체:
Drug A, Gene B, Disease C ...
```

즉 문서 내용에 **그래프에서 연결된 개체 정보**를 함께 붙여 모델에 전달한다.

### 순서를 고정하는 이유

```text
1. collect 전에 개체 이름 정렬
2. 문서를 검색 순서대로 다시 이어 붙임
```

같은 질문인데 근거 순서가 매번 바뀌면 프롬프트가 달라져 답 비교가 어려워진다.

# 13. 근거를 사용해 답 생성

프롬프트에는 최소한 다음 규칙을 둔다.

```text
1. 제공된 논문 근거 안에서만 답할 것
2. 각 답에 근거 논문의 PMC ID를 표시할 것
```

```python
from langchain_core.output_parsers import StrOutputParser

qa_prompt = ChatPromptTemplate.from_messages([

        'system',

        '발췌에 없는 내용은 지어내지 않는다.'

    (

        '다음 논문 발췌를 근거로 질문에 '
```

# 14. 일반 RAG와 GraphRAG 비교

질문:

```text
약물 대사 유전자 검사를 처방 전에 하면 무엇이 달라지나요?
```

벡터 검색만 사용한 근거:

```text
PMC13494111
PMC13368705
PMC13432136
```

그래프 점수까지 반영:

```python
qa_docs = rerank(
    search_docs(
        qa_question,
        top_k=5
    ),
    0.3
)[:3]
```

### 근거 변화

```text
벡터 검색만:
PMC13494111
PMC13368705
PMC13432136

리랭킹 후:
PMC13494111
PMC13368705
PMC13464512
```

```text
일반 RAG
→ 의미적으로 가까운 문서 선택

GraphRAG
→ 의미 검색 결과를 그래프 구조로 다시 평가
→ 최종 근거가 바뀔 수 있음
→ 답변도 바뀔 수 있음
```

여기서 GraphRAG의 핵심은 **검색이 문서에서 끝나지 않고 그래프까지 이어진다는 점**이다.

# 15. 답변의 인용 검증

LLM이 표시한 PMC ID가 실제로 근거로 넘긴 문서인지 확인한다.

```python
import re

cited = set(
    re.findall(
        r'PMC\d+',
        answer
    )
)

print(
    '답이 인용한 논문:',
    sorted(cited)
)

print(
    '근거로 넘긴 논문:',
    sorted(qa_docs)
)

print(
    '근거 밖 인용:',
    sorted(
        cited - set(qa_docs)
    )
)
```

### 결과

```text
답이 인용한 논문:
['PMC13368705']

근거로 넘긴 논문:
['PMC13368705', 'PMC13464512', 'PMC13494111']

근거 밖 인용:
[]
```

```text
outside = []
→ 인용 출처 검사 통과
```

근거에 없는 PMC ID가 나오면 해당 답을 그대로 사용하지 않는다.

# 16. 인용이 맞아도 내용까지 참인 것은 아님

인용 검사는 **출처 번호가 실제 근거 안에 있는지**만 확인한다.

문장의 의미가 논문의 실제 주장보다 강해졌는지는 별도로 봐야 한다.

| 근거 | 의미 | 답변 표현 |
|---|---|---|
| 논문 발췌 | 해당 연구가 관찰·보고한 내용 | `논문은 ...라고 보고했다` |
| 지식그래프 관계 | 기존 문헌에서 구조화된 관계 | `문헌에는 ...로 정리돼 있다` |
| 근거에 없는 내용 | 모델이 추가한 내용 | 사용하지 않음 |

예:

```text
논문:
"...에 기여할 수 있다"

답변:
"...에 기여한다"
```

인용 번호가 정확해도 이런 **주장의 강도 변화**는 단순 ID 검사로 잡을 수 없다.

```text
       ↓
```

# 핵심 구분

| 구분 | 기능 |
|---|---|
| 벡터 검색 | 의미가 비슷한 문서 검색 |
| 전문 검색 | 정확한 단어·기호 검색 |
| PageRank | 개체의 중요도 계산 |
| 리랭킹 | 후보 순서 변경 |
| Leiden | 구조적으로 가까운 개체 묶기 |
| 커뮤니티 필터 | 검색 후보 범위 제한 |
| `MENTIONS` | 문서와 그래프 개체 연결 |
| `build_context` | 본문 + 연결 개체를 근거로 구성 |
| 인용 검증 | LLM이 실제 제공 근거만 인용했는지 확인 |

---

# 핵심 문법

| 목적 | 문법 |
|---|---|
| 검색기 구성 | `VectorRetriever(...)` |
| 검색 실행 | `.search(query_text=..., top_k=...)` |
| 결과 형식 변경 | `result_formatter` |
| 벡터 검색 | `SEARCH n IN (VECTOR INDEX ...)` |
| 전문 검색 | `db.index.fulltext.queryNodes()` |
| GDS 투영 | `gds.graph.project()` |
| PageRank 저장 | `gds.pageRank.write()` |
| 문서 그래프 점수 | `avg(e.pagerank)` |
| 점수 정규화 | Min-Max |
| 리랭킹 | `(1-w)*similarity + w*graph_score` |
| 커뮤니티 탐지 | `gds.leiden.write()` |
| 커뮤니티 필터 | `WHERE e.community = $c` |
| 그래프 근거 연결 | `(Document)-[:MENTIONS]->(Entity)` |
| 인용 추출 | `re.findall(r'PMC\d+', answer)` |

---

# 최종 핵심

```text
MENTIONS
→ 문서와 지식그래프를 연결하는 다리

PageRank
→ 중요한 개체를 이용해 문서 순위를 다시 조정

Leiden
→ 같은 구조적 묶음으로 검색 범위를 제한

build_context
→ 문서 본문 + 연결 개체를 LLM 근거로 구성

인용 검증
→ LLM이 실제 제공한 근거만 사용했는지 확인
```

GraphRAG의 핵심은 단순히 그래프를 저장하는 것이 아니다.

> **문서 검색 결과를 그래프 구조로 다시 판단하고, 그 구조 정보를 실제 답변 근거에 포함시키는 것**이 핵심이다.
