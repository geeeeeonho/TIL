# Neo4j 집계 · 데이터 가공 · 속성 활용

## 0. 실습 데이터 구조

음식 배달 데이터를 다음 그래프 구조로 사용한다.

```text
Restaurant {category}
    -[:SERVES]->
Menu {price}
    <-[:ORDERED {qty, price}]-
Customer
```

- `Restaurant`: 식당
- `Menu`: 메뉴
- `Customer`: 고객
- `SERVES`: 식당이 판매하는 메뉴
- `ORDERED`: 고객의 주문
  - `qty`: 주문 수량
  - `price`: 해당 주문의 결제 금액

### 데이터 적재

```python
# [제공 코드] 음식 배달 시드 적재

menus = [
    ["비빔밥", 9000, "한마당", "한식"],
    ["불고기", 12000, "한마당", "한식"],
    ["연어초밥", 15000, "초밥왕", "일식"],
    ["우동", 8000, "초밥왕", "일식"],
    ["까르보나라", 13000, "파스타팩토리", "양식"],
    ["마르게리타", 14000, "파스타팩토리", "양식"],
    ["알리오올리오", 11000, "파스타팩토리", "양식"],
]

customers = ["강민", "서연", "준호", "예린"]

orders = [
    ["강민", "비빔밥", 2, 18000],
    ["강민", "연어초밥", 1, 15000],

    ["서연", "연어초밥", 2, 30000],
    ["서연", "까르보나라", 1, 13000],

    ["준호", "비빔밥", 1, 9000],
    ["준호", "불고기", 2, 24000],
    ["준호", "연어초밥", 1, 15000],

    ["예린", "마르게리타", 2, 28000],
    ["예린", "우동", 1, 8000],
    ["예린", "까르보나라", 1, 13000],
]

for name, price, restaurant, category in menus:
    run_cypher(
        "MERGE (rt:Restaurant {name: $restaurant}) "
        "SET rt.category = $category "
        "MERGE (m:Menu {name: $name}) "
        "SET m.price = $price "
        "MERGE (rt)-[:SERVES]->(m)",
        restaurant=restaurant,
        category=category,
        name=name,
        price=price
    )

for name in customers:
    run_cypher(
        "MERGE (:Customer {name: $name})",
        name=name
    )

for customer, menu, qty, price in orders:
    run_cypher(
        "MATCH (c:Customer {name: $customer}), "
        "(m:Menu {name: $menu}) "
        "MERGE (c)-[x:ORDERED]->(m) "
        "SET x.qty = $qty, x.price = $price",
        customer=customer,
        menu=menu,
        qty=qty,
        price=price
    )

print(
    "적재 완료: 메뉴:",
    run_cypher("MATCH (m:Menu) RETURN count(m) AS n")[0]["n"],
    "· 주문:",
    run_cypher("MATCH ()-[x:ORDERED]->() RETURN count(x) AS n")[0]["n"]
)
```

# 1. 기본 집계 함수

Neo4j에서도 SQL과 비슷하게 집계 함수를 사용할 수 있다.

| 함수 | 기능 |
|---|---|
| `count()` | 개수 |
| `sum()` | 합계 |
| `avg()` | 평균 |
| `max()` | 최댓값 |
| `min()` | 최솟값 |
| `percentileCont()` | 백분위수·중앙값 |
| `collect()` | 여러 값을 리스트로 묶기 |

## 메뉴 수 세기 — `count()`

```python
rows = run_cypher("""
MATCH (m:Menu)
RETURN count(m) AS 메뉴수
""")

print(rows)
```

### 결과

```text
[{'메뉴수': 7}]
```

`count(m)`은 매칭된 `Menu` 노드의 개수를 계산한다.

---

## 식당별 메뉴 수 — 그룹 집계

`RETURN`에 **일반 값과 집계 함수가 함께 존재하면 일반 값이 그룹 기준**이 된다.

```python
rows = run_cypher("""
MATCH (rt:Restaurant)-[:SERVES]->(m:Menu)

RETURN
    rt.name AS 식당,
    count(m) AS 메뉴수

ORDER BY 메뉴수 DESC, 식당 ASC
""")

display(rows)
```

### 결과

```text
[
    {'식당': '파스타팩토리', '메뉴수': 3},
    {'식당': '초밥왕', '메뉴수': 2},
    {'식당': '한마당', '메뉴수': 2}
]
```

핵심 구조:

```cypher
RETURN 그룹기준, 집계함수(...)
```

즉,

```cypher
RETURN rt.name, count(m)
```

은 내부적으로 `rt.name`별로 묶은 뒤 각 그룹의 `m` 개수를 계산한다.

---

## 메뉴별 총 주문 수량 — `sum()`

```python
rows = run_cypher("""
MATCH (:Customer)-[x:ORDERED]->(m:Menu)

RETURN
    m.name AS 메뉴,
    sum(x.qty) AS 총수량

ORDER BY 총수량 DESC, 메뉴 ASC
""")

display(rows)
```

### 결과

```text
[
    {'메뉴': '연어초밥', '총수량': 4},
    {'메뉴': '비빔밥', '총수량': 3},
    {'메뉴': '까르보나라', '총수량': 2},
    {'메뉴': '마르게리타', '총수량': 2},
    {'메뉴': '불고기', '총수량': 2},
    {'메뉴': '우동', '총수량': 1}
]
```

여기서 세는 것은 **주문 건수**가 아니라 `ORDERED.qty`의 합계다.

예:

```text
연어초밥
강민 1개 + 서연 2개 + 준호 1개
→ 총수량 4
```

또한 `MATCH`를 주문 관계에서 시작했으므로 주문이 한 번도 없는 `알리오올리오`는 결과에서 제외된다.

## 고객별 평균 결제금액 — `avg()`

```python
rows = run_cypher("""
MATCH (c:Customer)-[x:ORDERED]->(:Menu)

RETURN
    c.name AS 고객,
    avg(x.price) AS 평균결제

ORDER BY 고객 ASC
""")

display(rows)
```

### 결과

```text
[
    {'고객': '강민', '평균결제': 16500.0},
    {'고객': '서연', '평균결제': 21500.0},
    {'고객': '예린', '평균결제': 16333.333333333332},
    {'고객': '준호', '평균결제': 16000.0}
]
```

`x.price`는 메뉴 단가가 아니라 **각 `ORDERED` 관계에 저장된 주문 결제금액**이다.

따라서 강민은:

```text
비빔밥 주문 18,000원
연어초밥 주문 15,000원

(18000 + 15000) / 2
→ 16,500원
```

## 평균 · 중앙값 · 최고가 함께 계산

여러 집계 함수를 한 번에 사용할 수도 있다.

```python
rows = run_cypher("""
MATCH (m:Menu)

RETURN
    round(avg(m.price), 2) AS 평균가격,
    percentileCont(m.price, 0.5) AS 중앙값,
    max(m.price) AS 최고가
""")

display(rows)
```

### 결과

```text
[
    {
        '평균가격': 11714.29,
        '중앙값': 12000,
        '최고가': 15000
    }
]
```

- `avg()` : 전체 값의 평균
- `percentileCont(..., 0.5)` : 50% 지점 → 중앙값
- `max()` : 가장 큰 값
- `round(..., 2)` : 소수점 둘째 자리까지 반올림

# 2. 값을 리스트로 묶고 다시 펼치기

## `collect()` — 여러 값을 리스트로 묶기

파스타팩토리의 메뉴 이름을 하나의 리스트로 모은다.

```python
rows = run_cypher("""
MATCH (rt:Restaurant)-[:SERVES]->(m:Menu)
WHERE rt.name = '파스타팩토리'

RETURN collect(m.name) AS 메뉴목록
""")

display(rows)
```

### 결과

```text
[
    {
        '메뉴목록': [
            '까르보나라',
            '마르게리타',
            '알리오올리오'
        ]
    }
]
```

`collect()`는 여러 행의 값을 하나의 리스트로 합친다.

```text
까르보나라
마르게리타
알리오올리오

        ↓ collect()

['까르보나라', '마르게리타', '알리오올리오']
```

> `collect()` 자체는 리스트의 순서를 보장하는 기능이 아니다.  
> 순서가 중요하면 `ORDER BY`를 함께 사용해 정렬 기준을 명확히 두는 것이 좋다.

---

## `collect()` + `UNWIND`

`collect()`로 리스트를 만든 뒤 `UNWIND`로 다시 한 행씩 펼칠 수 있다.

```python
rows = run_cypher("""
MATCH (rt:Restaurant)-[:SERVES]->(m:Menu)

// 식당별 메뉴를 리스트로 묶어서 다음 단계로 전달
WITH
    rt.name AS 식당,
    collect(m.name) AS 메뉴목록

// 리스트의 원소를 다시 개별 행으로 분리
UNWIND 메뉴목록 AS 메뉴

RETURN 식당, 메뉴
ORDER BY 식당 ASC, 메뉴 ASC
""")

display(rows)
```

### 결과

```text
[
    {'식당': '초밥왕', '메뉴': '연어초밥'},
    {'식당': '초밥왕', '메뉴': '우동'},
    {'식당': '파스타팩토리', '메뉴': '까르보나라'},
    {'식당': '파스타팩토리', '메뉴': '마르게리타'},
    {'식당': '파스타팩토리', '메뉴': '알리오올리오'},
    {'식당': '한마당', '메뉴': '불고기'},
    {'식당': '한마당', '메뉴': '비빔밥'}
]
```

흐름:

```text
여러 행
  ↓
collect()
  ↓
리스트
  ↓
UNWIND
  ↓
여러 행
```

`UNWIND`는 리스트를 이후 쿼리에서 다시 개별 데이터처럼 처리해야 할 때 사용한다.

# 3. `WITH`로 중간 집계 결과 사용하기

## 주문이 2건 이상인 메뉴

먼저 메뉴별 주문 건수를 계산한 뒤 그 결과에 다시 조건을 적용한다.

```python
rows = run_cypher("""
MATCH (:Customer)-[x:ORDERED]->(m:Menu)

// 1. 메뉴별 주문 건수 계산
WITH
    m,
    count(x) AS 주문건수

// 2. 계산 결과에 조건 적용
WHERE 주문건수 >= 2

RETURN
    m.name AS 메뉴,
    주문건수

ORDER BY 주문건수 DESC, 메뉴 ASC
""")

display(rows)
```

### 결과

```text
[
    {'메뉴': '연어초밥', '주문건수': 3},
    {'메뉴': '까르보나라', '주문건수': 2},
    {'메뉴': '비빔밥', '주문건수': 2}
]
```

### `WITH`의 역할

`WITH`는 현재까지 계산한 결과를 **다음 쿼리 단계로 전달**한다.

```text
MATCH
  ↓
WITH에서 메뉴별 count()
  ↓
WHERE로 집계 결과 필터링
  ↓
RETURN
```

따라서 집계된 결과를 다시 조건으로 사용해야 할 때 자주 사용한다.

> 이 예제는 `COUNT { ... }` 서브쿼리를 사용하는 것이 아니라  
> 일반 집계 함수인 `count(x)`를 사용하는 구조다.

# 4. 계산한 값을 노드 속성으로 저장하기

집계 결과를 조회만 하지 않고 `SET`을 이용해 노드 속성으로 저장할 수도 있다.

## 메뉴별 총 주문 수량 저장

```python
# 1. 메뉴별 총 주문 수량 계산 후 Menu 노드에 저장

run_cypher("""
MATCH (:Customer)-[x:ORDERED]->(m:Menu)

WITH
    m,
    sum(x.qty) AS 총수량

SET m.total_ordered = 총수량
""")
```

현재 그래프의 기존 속성:

```text
Menu
├─ name
└─ price
```

실행 후:

```text
Menu
├─ name
├─ price
└─ total_ordered
```

단, 현재 `MATCH`에서는 주문 관계가 있는 메뉴만 잡히므로 **주문이 없는 메뉴에는 `total_ordered` 속성이 만들어지지 않는다.**

### 저장된 값 조회

```python
rows = run_cypher("""
MATCH (m:Menu)

WHERE m.total_ordered IS NOT NULL

RETURN
    m.name AS 메뉴,
    m.total_ordered AS 총수량

ORDER BY 총수량 DESC, 메뉴 ASC
""")

display(rows)
```

### 결과

```text
[
    {'메뉴': '연어초밥', '총수량': 4},
    {'메뉴': '비빔밥', '총수량': 3},
    {'메뉴': '까르보나라', '총수량': 2},
    {'메뉴': '마르게리타', '총수량': 2},
    {'메뉴': '불고기', '총수량': 2},
    {'메뉴': '우동', '총수량': 1}
]
```

`알리오올리오`는 주문 기록이 없기 때문에 `total_ordered` 속성 자체가 없다.

# 5. `CASE`로 값 분류하기

`CASE`는 Python의 `if / elif / else`와 비슷하게 조건에 따라 다른 값을 만들 때 사용한다.

## 식당 카테고리를 새로운 구분값으로 변환

```python
rows = run_cypher("""
MATCH (rt:Restaurant)-[:SERVES]->(m:Menu)

RETURN
    CASE rt.category
        WHEN '한식' THEN '국내식'
        WHEN '일식' THEN '아시아식'
        WHEN '양식' THEN '서양식'
        ELSE '기타'
    END AS 구분,

    count(m) AS 메뉴수

ORDER BY 구분 ASC
""")

display(rows)
```

### 결과

```text
[
    {'구분': '국내식', '메뉴수': 2},
    {'구분': '서양식', '메뉴수': 3},
    {'구분': '아시아식', '메뉴수': 2}
]
```

구조:

```cypher
CASE 값
    WHEN 비교값1 THEN 결과1
    WHEN 비교값2 THEN 결과2
    ELSE 기본값
END
```

현재 예제는 `rt.category` 값이 특정 문자열과 같은지 비교하는 **단순 CASE**다.

# 6. 인덱스 생성

## `Customer.name` 인덱스 생성

인덱스는 특정 **레이블 + 속성**을 기준으로 노드를 더 빠르게 찾을 수 있도록 만드는 조회용 구조다.

여기서는:

```text
Customer 레이블
    ↓
name 속성
    ↓
인덱스 생성
```

### 생성

```python
run_cypher("""
CREATE INDEX customer_name_idx IF NOT EXISTS
FOR (c:Customer)
ON (c.name)
""")
```

### 생성 완료 대기

```python
run_cypher("""
CALL db.awaitIndexes()
""")
```

### 인덱스 확인

```python
rows = run_cypher("""
SHOW INDEXES
YIELD name, type

WHERE type <> 'LOOKUP'

RETURN name
ORDER BY name
""")

display(rows)
```

### 결과

```text
[
    {'name': 'customer_name_idx'}
]
```

이후 다음과 같이 `Customer.name`을 이용해 검색할 때 인덱스를 활용할 수 있다.

```cypher
MATCH (c:Customer {name: '강민'})
RETURN c
```

> 인덱스는 데이터를 잘라서 저장하는 기능이 아니라,  
> 특정 레이블의 특정 속성을 빠르게 조회하기 위한 **검색 보조 구조**다.

# 7. 집계 대상에 따른 결과 차이

집계에서는 **어떤 데이터를 MATCH했는지**에 따라 분모가 달라질 수 있다.

## 주문이 있는 메뉴만 집계 — strict

```python
strict = run_cypher("""
MATCH (:Customer)-[x:ORDERED]->(m:Menu)

WITH
    m,
    sum(x.qty) AS 총수량

RETURN
    count(m) AS 메뉴수,
    round(avg(총수량), 2) AS 평균수량,
    sum(총수량) AS 합계
""")[0]

print("strict:", strict)
```

### 결과

```text
strict: {
    '메뉴수': 6,
    '평균수량': 2.33,
    '합계': 14
}
```

`MATCH`가 `ORDERED` 관계에서 시작하므로 주문 기록이 없는 `알리오올리오`는 처음부터 제외된다.

```text
총 주문수량 14
÷
주문이 존재하는 메뉴 6개

= 약 2.33
```

---

## 주문이 없는 메뉴도 포함 — loose

전체 `Menu`를 먼저 가져온 뒤 주문 관계만 `OPTIONAL MATCH`한다.

```python
loose = run_cypher("""
MATCH (m:Menu)

OPTIONAL MATCH (:Customer)-[x:ORDERED]->(m)

WITH
    m,
    sum(x.qty) AS 총수량

RETURN
    count(m) AS 메뉴수,
    round(avg(총수량), 2) AS 평균수량,
    sum(총수량) AS 합계
""")[0]

print("loose:", loose)
```

### 결과

```text
loose: {
    '메뉴수': 7,
    '평균수량': 2.0,
    '합계': 14
}
```

이번에는 전체 메뉴 7개가 기준이다.

```text
총 주문수량 14
÷
전체 메뉴 7개

= 2.0
```

### 핵심

```text
MATCH
→ 관계가 없는 데이터는 제외될 수 있음

OPTIONAL MATCH
→ 관계가 없어도 앞에서 MATCH한 데이터는 유지
```

따라서 평균·비율 같은 집계에서는 **분모에 무엇이 포함되어야 하는지 먼저 결정하는 것이 중요**하다.

# 8. 값이 없을 때 기본값 사용 — `coalesce()`

`coalesce()`는 전달된 값 중 처음으로 `null`이 아닌 값을 반환한다.

```cypher
coalesce(값, 기본값)
```

예:

```cypher
coalesce(m.total_ordered, 0)
```

- `total_ordered` 존재 → 해당 값 사용
- `total_ordered` 없음 → `0` 사용

## 저장된 `total_ordered` 속성을 이용하는 경우

앞에서 `SET m.total_ordered = 총수량`을 실행했다면 다음처럼 사용할 수 있다.

```python
rows = run_cypher("""
MATCH (m:Menu)

RETURN
    m.name AS 메뉴,
    coalesce(m.total_ordered, 0) AS 총수량

ORDER BY 총수량 DESC, 메뉴 ASC
""")

display(rows)
```

정상적으로 앞의 `SET`이 실행된 상태라면:

### 결과

```text
[
    {'메뉴': '연어초밥', '총수량': 4},
    {'메뉴': '비빔밥', '총수량': 3},
    {'메뉴': '까르보나라', '총수량': 2},
    {'메뉴': '마르게리타', '총수량': 2},
    {'메뉴': '불고기', '총수량': 2},
    {'메뉴': '우동', '총수량': 1},
    {'메뉴': '알리오올리오', '총수량': 0}
]
```

### 원본에서 모든 값이 `0`이 나온 이유

원본 실행 결과에서는 다음 경고가 발생했다.

```text
property key does not exist.
The property `total_ordered` does not exist
```

그리고 모든 메뉴가 `0`으로 출력됐다.

이는 `coalesce()` 문제라기보다 **현재 실행 중인 DB에 `total_ordered` 속성이 존재하지 않았기 때문**이다.

즉:

```text
m.total_ordered
→ 모든 메뉴에서 null

coalesce(null, 0)
→ 모두 0
```

DB를 다시 만들었거나 앞의 `SET` 코드를 실행하지 않은 상태에서 발생할 수 있다.

## 저장된 속성에 의존하지 않고 계산하기

단순히 현재 주문 데이터를 기준으로 총수량을 구하려는 목적이라면 속성을 미리 저장할 필요 없이 `OPTIONAL MATCH`로 직접 계산하는 방식이 더 안전하다.

```python
rows = run_cypher("""
MATCH (m:Menu)

OPTIONAL MATCH (:Customer)-[x:ORDERED]->(m)

RETURN
    m.name AS 메뉴,
    coalesce(sum(x.qty), 0) AS 총수량

ORDER BY 총수량 DESC, 메뉴 ASC
""")

display(rows)
```

### 결과

```text
[
    {'메뉴': '연어초밥', '총수량': 4},
    {'메뉴': '비빔밥', '총수량': 3},
    {'메뉴': '까르보나라', '총수량': 2},
    {'메뉴': '마르게리타', '총수량': 2},
    {'메뉴': '불고기', '총수량': 2},
    {'메뉴': '우동', '총수량': 1},
    {'메뉴': '알리오올리오', '총수량': 0}
]
```

흐름:

```text
전체 Menu 조회
        ↓
OPTIONAL MATCH로 주문 검색
        ↓
메뉴별 qty 합계
        ↓
주문이 없으면 0
```

# 핵심 정리

| 목적 | Cypher |
|---|---|
| 개수 | `count()` |
| 합계 | `sum()` |
| 평균 | `avg()` |
| 최고·최저 | `max()`, `min()` |
| 중앙값 | `percentileCont(x, 0.5)` |
| 그룹별 집계 | `RETURN 그룹값, 집계함수()` |
| 중간 계산 전달 | `WITH` |
| 여러 값을 리스트화 | `collect()` |
| 리스트를 행으로 펼치기 | `UNWIND` |
| 조건에 따라 값 변환 | `CASE` |
| 속성 추가·갱신 | `SET` |
| 관계 없는 데이터 유지 | `OPTIONAL MATCH` |
| `null` 기본값 처리 | `coalesce()` |
| 특정 속성 조회 최적화 | `CREATE INDEX` |

전체 흐름에서 특히 중요한 것은 다음 세 가지다.

```text
1. 집계 함수 + 일반 값
   → 일반 값을 기준으로 그룹화

2. WITH
   → 앞 단계의 집계 결과를 다음 단계에서 사용

3. MATCH와 OPTIONAL MATCH의 차이
   → 집계 대상과 평균의 분모 자체가 달라질 수 있음
```
