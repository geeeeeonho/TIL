# 기존 그래프 준비와 새 관계 추출

## 핵심 개념

**증분 적재(Incremental Loading)**  
기존 그래프를 유지한 채 새 개체·관계만 추가하는 방식.

이번 교안에서는 **기존 관계는 Neo4j에 유지하고, 새 종류의 관계만 원문에서 추출·검사한 뒤 JSON으로 보관**한다.  
실제 Neo4j 적재와 기존 표준 ID 연결은 다음 단계에서 진행한다.

```text
기존 그래프 준비
→ 새 관계만 스키마로 지정
→ LLM 관계 추출
→ 스키마·근거 검사
→ JSON 저장
→ 다음 단계에서 기존 ID와 연결 후 Neo4j 적재
```

---

## 1. 기존 그래프 준비

기존에 검토된 개체와 관계를 Neo4j에 먼저 적재한다.

| 자료 | 기존 관계 | 새로 추출할 관계 |
|---|---|---|
| 영화 | `Person - ACTED_IN -> Movie` | `Movie - HAS_GENRE -> Genre` |
| 의료 | `Compound - TREATS/PALLIATES -> Disease` | `Compound - PALLIATES_CS -> Symptom` |

실습에서는 재현을 위해 대상 노드와 관계를 초기화한 뒤 검토 완료본을 다시 적재한다.  
이 초기화는 **실습용 준비 과정**이며, 실제 증분 적재에서는 기존 데이터를 삭제하지 않는다.

---

## 2. 새 관계만 추출

### 추출 스키마 제한

이번 호출에서 필요한 관계만 `schema`에 넣는다.

예: 의료 관계

```python
paper_schema = {
    "node_types": paper_node_types,
    "relationship_types": paper_relationship_types,
    "patterns": [
        ("Compound", "PALLIATES_CS", "Symptom")
    ],
    "additional_node_types": False,
    "additional_relationship_types": False,
    "additional_patterns": False,
}
```

핵심은 다음과 같다.

- 기존 DB 관계를 추출 스키마에 다시 넣을 필요 없음
- `patterns`로 허용 관계와 방향 제한
- 스키마 변경은 **추출 범위만 제한**
- 기존 Neo4j 관계를 삭제하거나 변경하지 않음

---

## 3. 추출과 DB 적재 분리

새 결과를 바로 Neo4j에 저장하면 기존 개체와 중복될 수 있다.  
따라서 `Neo4jWriter` 대신 `MemoryWriter`를 사용해 그래프를 메모리로 반환한다.

```python
class MemoryWriter(KGWriter):
    async def run(
        self,
        graph: Neo4jGraph,
        lexical_graph_config: LexicalGraphConfig = LexicalGraphConfig(),
    ) -> KGWriterModel:

        graph = Neo4jGraph.model_validate(graph)

        return KGWriterModel(
            status="SUCCESS",
            metadata={
                "graph": graph.model_dump(mode="json")
            },
        )
```

빌더에서는 다음 설정이 핵심이다.

```python
pipeline = SimpleKGPipeline(
    llm=llm,
    driver=driver,
    embedder=embedder,
    schema=deepcopy(schema),
    text_splitter=splitter,
    from_file=False,
    kg_writer=MemoryWriter(),
    perform_entity_resolution=False,
    prompt_template=prompt_template,
    on_error="RAISE",
)
```

### 중요한 설정

- `kg_writer=MemoryWriter()`  
  → DB에 바로 저장하지 않고 결과 반환
- `perform_entity_resolution=False`  
  → 기존 DB 개체와의 통합을 아직 수행하지 않음
- `GraphPruning`  
  → 스키마 밖의 관계 제거
- `kg_writer=None`  
  → 저장 생략이 아니라 **기본 Writer 사용**

## 4. 원문에서 관계 추출

문서를 `run_async()`에 전달한다.

```python
result = await pipeline.run_async(
    text=document["text"],
    file_path=document.get("url") or document["doc_id"],
    document_metadata={
        "source_doc_id": document["doc_id"]
    },
)

graph = result.result["writer"]["metadata"]["graph"]
```

반환 그래프에는 다음 정보가 포함된다.

```text
Document
Chunk
Entity
Relationship
Chunk embedding
출처 연결 관계
```

관계의 양 끝은 이름이 아니라 **빌더 내부 노드 ID**로 연결된다.

따라서 검사 전에 ID를 이용해 노드를 찾아 다음 형태로 변환한다.

```python
{
    "subject": ...,
    "subject_type": ...,
    "relation": ...,
    "object": ...,
    "object_type": ...,
    "evidence": ...,
    "source_doc_id": ...,
}
```

이 ID는 **Neo4j의 기존 표준 ID가 아님**.  
기존 개체 ID 연결은 다음 적재 단계에서 수행한다.

## 5. 새 관계 검사

검사는 크게 두 단계다.

### 스키마 검사

관계와 양 끝 타입이 허용된 패턴과 같은지 확인한다.

```python
expected = signatures.get(row["relation"])
actual = [
    row["subject_type"],
    row["object_type"],
]

schema_ok = expected == actual
```

### 근거 검사

`evidence`가 비어 있지 않고 실제 원문에 그대로 존재하는지 확인한다.

```python
evidence = row["evidence"]
source_text = docs[row["source_doc_id"]]["text"]

evidence_ok = (
    bool(evidence.strip())
    and evidence in source_text
)
```

두 검사를 모두 통과한 관계만 `validated`에 넣는다.

```text
스키마 통과 + 근거 일치
        ↓
    validated

하나라도 실패
        ↓
     rejected
     + reason
```

### 평가 지표

```text
스키마 준수율
= 스키마 통과 관계 수 / 전체 새 관계 수

근거 원문 일치율
= 원문과 일치한 evidence 수 / 전체 새 관계 수
```

단, **근거가 원문에 존재한다는 것만으로 관계 의미까지 정확하다는 뜻은 아니다.**  
관계와 근거를 함께 확인해야 한다.

## 6. 실습 결과

### 영화

```text
The Devil's Advocate
→ HAS_GENRE
→ supernatural horror
```

근거:

```text
a 1997 American supernatural horror film
```

결과:

```text
새 관계: 1
스키마 준수율: 1 / 1 = 100%
근거 일치율: 1 / 1 = 100%
```

### 의료

원문에서 `gabapentin`, `pregabalin`과 다음 증상 사이의 관계를 추출했다.

```text
perioperative pain
chemotherapy-induced neuropathic symptoms
nocturnal discomfort
```

두 약물 × 세 증상으로 총 6개 관계가 생성된다.

```text
새 관계: 6
스키마 준수율: 6 / 6 = 100%
근거 일치율: 6 / 6 = 100%
```

`sleep`, `anxiety`는 원문에서 **secondary benefits**로 표현되므로 직접 사용 대상인 `PALLIATES_CS` 관계에서는 제외한다.

## 7. 결과 파일 저장

검사한 관계와 빌더 결과 전체를 JSON으로 저장한다.

```python
packet = {
    "mode": "append_new_relations",
    "stage": "새 관계 적재 전",
    "schema_version": schema_version,
    "schema": schema,
    "signatures": signatures,
    "documents": docs,
    "rows": batch,
    "validated": validated,
    "rejected": rejected,
    "builder_runs": extraction_runs,
    "baseline_file": "...",
}
```

### 주요 필드

| 필드 | 내용 |
|---|---|
| `rows` | 추출된 새 관계 전체 |
| `validated` | 검사 통과 관계 |
| `rejected` | 검사 실패 관계 + 사유 |
| `builder_runs` | Document, Chunk, Entity, 관계, 임베딩, 출처 연결 |
| `schema` | 실제 추출에 사용한 스키마 |
| `signatures` | 관계별 허용 주어·목적어 타입 |
| `baseline_file` | 기존 그래프 기준 파일 |

최종 상태는 다음과 같다.

```text
Neo4j
└─ 기존 개체 + 기존 관계 유지

JSON packet
└─ 새 관계
   + 검사 결과
   + 문서/청크
   + 임베딩
   + 출처 연결
   + 추출 설정
```

다음 단계에서 `validated` 관계만 기존 표준 ID에 연결해 Neo4j에 추가한다.

---

## 전체 흐름 요약

```text
1. 기존 그래프 적재
   ↓
2. 이번에 필요한 새 관계만 schema 지정
   ↓
3. MemoryWriter로 DB 저장 차단
   ↓
4. SimpleKGPipeline 실행
   ↓
5. 관계를 검사 가능한 triple 형태로 변환
   ↓
6. 스키마 검사
   ↓
7. evidence 원문 일치 검사
   ↓
8. validated / rejected 분리
   ↓
9. JSON packet 저장
   ↓
10. 다음 단계에서 기존 ID 연결 + Neo4j 증분 적재
```

## 기억할 핵심

- **DB에 존재하는 관계와 이번 추출 스키마는 별개**
- 새 관계만 추출하려면 `patterns`에 새 관계만 지정
- 바로 DB에 저장하지 않고 `MemoryWriter`로 먼저 검사
- 빌더 내부 노드 ID와 기존 Neo4j 표준 ID는 다름
- `GraphPruning`은 스키마 밖 결과를 제거하지만 의미적 정확성까지 보장하지 않음
- 적재 전 `schema + evidence`를 검사
- 검증된 관계만 다음 단계에서 기존 개체와 연결해 추가
