# 이름 정규화와 동일 개체 판별 - 코드·결과 정리

> 추출 트리플의 출처를 보존하면서 이름을 정리하고, 동일 개체 후보를 좁힌 뒤 표준 ID로 연결하는 흐름.

## 전체 흐름

```text
트리플 확인
  -> 출처(provenance) 보존
  -> 주어/목적어를 출현(mention)으로 분리
  -> 근거 문장 확인
  -> 비교용 이름 정규화
  -> 타입으로 명백한 오답 제거
  -> 대표 표기로 반복 비교 축소
  -> 문자열 유사도로 후보 검색
  -> 원문 문맥으로 같음/다름/보류 판정
  -> 동일 개체 그룹 생성
  -> 표준 ID 부여
  -> JSONL 저장
```

**핵심:** 문자열 유사도는 동일 개체를 확정하는 기준이 아니라 **검토 후보를 찾는 기준**이다.

# 3. 원래 이름과 비교용 이름 분리

원본 `name`은 그대로 보존하고, 비교에 사용할 `comparison_name`만 따로 만든다.

현재 정규화는 **앞뒤 공백만 제거**한다.

### 코드

```python
normalization_inputs = [
    " kdeplot ",
    "FacetGrid",
    " sns.kdeplot ",
    " 파이썬 입문(개정판) ",
    "  파이썬  입문  ",
    "   ",
]


def normalize(name):
    return name.strip()


normalization_results = []
for name in normalization_inputs:
    normalization_results.append(normalize(name))

prepared_mentions = []
for mention in mentions:
    prepared = mention.copy()
    prepared["comparison_name"] = normalize(mention["name"])
    prepared_mentions.append(prepared)

print("정규화 결과:", normalization_results)
print("prepared_mentions 행 수:", len(prepared_mentions))
pprint(prepared_mentions[0])
```

### 결과

```text
정규화 결과: ['kdeplot', 'FacetGrid', 'sns.kdeplot', '파이썬 입문(개정판)', '파이썬  입문', '']
prepared_mentions 행 수: 16

 'triple_id': 't01',
```

# 4. 같은 이름이라도 타입이 다르면 제외

이름이 같아도 개체 타입이 다르면 명백한 오답 후보로 볼 수 있다.

### 코드

```python
from itertools import combinations


def pair_key(a, b):
    return tuple(sorted([a, b]))


same_name_pairs = set()
compatible_pairs = set()

for left, right in combinations(prepared_mentions, 2):
    if left["comparison_name"] == right["comparison_name"]:
        pair = pair_key(left["mention_id"], right["mention_id"])
        same_name_pairs.add(pair)

        # 이름뿐 아니라 타입까지 같을 때만 유지
        if left["entity_type"] == right["entity_type"]:
            compatible_pairs.add(pair)

excluded_pairs = same_name_pairs - compatible_pairs

mention_by_id = {
    mention["mention_id"]: mention
    for mention in prepared_mentions
}

for left_id, right_id in sorted(excluded_pairs):
    left = mention_by_id[left_id]
    right = mention_by_id[right_id]
    print(
        left["name"], left["entity_type"],
        "<->",
        right["name"], right["entity_type"],
    )

print("같은 이름 쌍:", len(same_name_pairs))
print("타입까지 같은 쌍:", len(compatible_pairs))
print("타입이 달라 제외:", len(excluded_pairs))
```

### 결과

```text
rugplot ApiElement <-> rugplot Document
rugplot ApiElement <-> rugplot Document
rugplot ApiElement <-> rugplot Document
같은 이름 쌍: 16
타입까지 같은 쌍: 13
타입이 달라 제외: 3
```

```text
이름 동일 + 타입 동일 -> 비교 후보 유지
이름 동일 + 타입 다름 -> 후보 제외
```

# 6. 문자열 유사도로 검토 후보 찾기

완전히 같은 이름뿐 아니라 **비슷한 이름**도 검토 대상으로 올린다.

> 원문 설명의 "후보에서 제외하기"는 반대 의미라 수정함. 유사도 기준을 통과하면 **검토 후보로 추가**한다.

### 코드

```python
from difflib import SequenceMatcher
from itertools import combinations


similarity_probe_pairs = [
    ("displot", "histplot"),
    ("kdeplot", "displot"),
    ("violinplot", "countplot"),
    ("regplot", "lmplot"),
    ("boxplot", "heatmap"),
]

representative_list = list(representatives.values())
name_candidates = []

for left, right in combinations(representative_list, 2):
    # 타입이 다르면 비교하지 않음
    if left["entity_type"] != right["entity_type"]:
        continue

    similarity = SequenceMatcher(
        None,
        left["comparison_name"],
        right["comparison_name"],
    ).ratio()

    if similarity >= 0.65:
        name_candidates.append({
            "left_id": left["mention_id"],
            "right_id": right["mention_id"],
            "similarity": similarity,
        })


# 유사도 기준 자체를 확인할 별도 입력
probe_candidates = []

for left_name, right_name in similarity_probe_pairs:
    similarity = SequenceMatcher(
        None,
        left_name,
        right_name,
    ).ratio()

    if similarity >= 0.65:
        probe_candidates.append((left_name, right_name))


print("이름 유사도 후보:")
for row in name_candidates:
    print(row)

print("\n검사 입력 통과 후보:")
print(probe_candidates)
```

### 결과

```text
이름 유사도 후보:
{'left_id': 't01:object', 'right_id': 't08:object', 'similarity': 0.7777777777777778}
{'left_id': 't02:object', 'right_id': 't07:object', 'similarity': 0.7777777777777778}
{'left_id': 't06:object', 'right_id': 't07:object', 'similarity': 0.6666666666666666}
{'left_id': 't06:object', 'right_id': 't08:object', 'similarity': 0.6666666666666666}
{'left_id': 't07:object', 'right_id': 't08:object', 'similarity': 0.7272727272727273}

검사 입력 통과 후보:
[('displot', 'histplot'), ('kdeplot', 'displot')]
```

문자열이 비슷하다는 이유만으로 같은 개체라고 볼 수 없다.

```text
문자열 유사도 -> 후보 검색
원문 문맥     -> 실제 동일 개체 판정
```

# 7. 원문 문맥으로 동일 개체 판정

후보의 이름, 타입, 출처 문서, 근거 문장을 확인하고 다음 중 하나로 판정한다.

| 판정 | 의미 |
|---|---|
| `같음` | 같은 실제 개체로 확정 |
| `다름` | 서로 다른 개체 |
| `보류` | 근거 부족. 자동 통합하지 않음 |

원문에는 `pair_decisions`를 만드는 코드가 빠져 있어, 이후 결과에 나타난 **같음 판정**을 실행 가능한 형태로 보완한다.

# 8. 같음 판정을 동일 개체 그룹으로 묶기

`A-B`, `B-C`가 모두 같다면 `A-B-C` 하나의 그룹으로 묶어야 한다.

원문에서 사용된 `group_pairs()` 정의가 빠져 있어, 같은 동작을 하는 함수로 보완한다.

## 8-1. 그룹화 함수

### 코드

```python
def group_pairs(all_ids, same_pairs):
    # Union-Find 초기화
    parent = {item: item for item in all_ids}

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        root_a = find(a)
        root_b = find(b)
        if root_a != root_b:
            parent[root_b] = root_a

    for left_id, right_id in same_pairs:
        union(left_id, right_id)

    groups = {}
    for item in all_ids:
        root = find(item)
        groups.setdefault(root, []).append(item)

    # 실행할 때마다 같은 순서가 나오도록 정렬
    return sorted(sorted(group) for group in groups.values())
```

# 9. 그룹별 표준 ID 부여

동일 개체 그룹마다 `standard_id` 하나를 부여한다.

```text
여러 mention_id
      -> 동일 개체 그룹
      -> standard_id 1개
```

원문에서 `assign_group_ids()` 정의가 빠져 있어 실행 가능한 형태로 보완한다.

## 9-1. 표준 ID 연결 함수

### 코드

```python
def assign_group_ids(mentions, groups):
    mention_to_standard = {}

    for group in groups:
        # 그룹의 첫 ID를 기준으로 재현 가능한 표준 ID 생성
        standard_id = "entity:" + group[0]

        for mention_id in group:
            mention_to_standard[mention_id] = standard_id

    links = []

    for mention in mentions:
        row = mention.copy()
        standard_id = mention_to_standard.get(mention["mention_id"])

        row["standard_id"] = standard_id
        row["status"] = "linked" if standard_id else "review"
        links.append(row)

    return links
```

# 11. GDS 후보 검색에서 유사도 의미 구분

GDS에서 후보를 찾을 때는 **무엇이 비슷한지를 구분**해야 한다.

| 방식 | 비교 대상 | 의미 |
|---|---|---|
| KNN | 임베딩 벡터 | 의미/표현 벡터가 비슷한가 |
| Node Similarity | 이웃 집합 | 연결된 이웃이 비슷한가 |

원문의 코드는 두 개념 중 **이웃 집합의 Jaccard 유사도**를 확인하는 예시다.

원문에서 `neighbor_examples`가 정의 없이 사용되어 검사 입력을 보완한다.

### 코드

```python
neighbor_examples = {
    "partial": (
        {"doc1", "doc2"},
        {"doc2", "doc3"},
    ),
    "disjoint": (
        {"doc1"},
        {"doc2"},
    ),
    "identical": (
        {"doc1", "doc2"},
        {"doc1", "doc2"},
    ),
    "empty": (
        set(),
        set(),
    ),
}


def neighbor_jaccard(left_docs, right_docs):
    intersection = left_docs & right_docs
    union = left_docs | right_docs

    if len(union) == 0:
        return 0.0

    return len(intersection) / len(union)


neighbor_scores = {}

for name, pair in neighbor_examples.items():
    left_docs, right_docs = pair
    neighbor_scores[name] = neighbor_jaccard(left_docs, right_docs)

print(neighbor_scores)
```

### 결과

```text
{'partial': 0.3333333333333333,
 'disjoint': 0.0,
 'identical': 1.0,
 'empty': 0.0}
```

Jaccard 유사도:

```text
교집합 크기 / 합집합 크기
```

```text
이웃 완전 동일 -> 1.0
일부 겹침     -> 0 ~ 1 사이
겹침 없음     -> 0.0
```

**주의:** KNN 점수와 Node Similarity 점수는 의미가 다르므로 같은 기준으로 해석하면 안 된다.

# 최종 정리

```text
1. 트리플과 원문을 불러옴
2. provenance로 출처를 보존
3. 주어/목적어를 mention 단위로 분리
4. evidence가 실제 원문에 있는지 확인
5. 원래 name은 보존하고 comparison_name만 정규화
6. 이름이 같아도 타입이 다르면 후보에서 제외
7. 같은 타입+이름의 반복은 대표 하나로 비교량 축소
8. 문자열 유사도로 비슷한 이름을 검토 후보로 검색
9. 원문 문맥으로 같음/다름/보류 판정
10. 같음 판정을 동일 개체 그룹으로 연결
11. 그룹별 standard_id 부여
12. 연결 결과를 JSONL로 저장
```

## 핵심 구분

```text
normalize
= 비교하기 쉽게 이름 표기만 정리

candidate search
= 같은 개체일 가능성이 있는 대상을 좁힘

entity resolution
= 원문과 타입을 확인해 실제 동일 개체인지 판정

standard_id
= 동일 개체로 확정된 여러 출현을 하나의 ID로 연결
```
