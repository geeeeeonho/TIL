# GraphRAG 준비: 문서 임베딩 · 검색 · 그래프 연결 핵심

> 기존 지식그래프에 논문을 `Document` 노드로 올리고, 임베딩 검색과 전문 검색을 만든 뒤 `MENTIONS` 관계로 그래프에 연결하는 흐름.

## 전체 흐름

```text
질문
 ├─ 임베딩 → 벡터 인덱스 → 의미가 가까운 Document
 └─ 키워드 → 전문 인덱스 → 글자가 포함된 Document
                              ↓
                        MENTIONS
                              ↓
                    Compound / Gene / ...
                              ↓
                     기존 그래프 관계 탐색
```

핵심은 **문서 검색에서 끝나지 않고, 검색된 문서에서 지식그래프로 넘어가는 것**.


한 논문의 구조.

```python

```

논문은 `:Document` 노드로 저장하고 기존 그래프 개체와 `MENTIONS`로 연결.

```text

(Document)-[:MENTIONS]->(Gene)

...
```

## 2. 문서를 임베딩해 노드에 저장

### 핵심 개념

- 임베딩 모델: `text-embedding-3-large`
- 실습 차원: **768차원**
- 벡터 길이: 1로 정규화
- 가까움: 코사인 기반
- 한국어 질문과 영어 문서를 같은 공간에서 비교 가능

같은 의미의 문장은 벡터가 상대적으로 가깝게 나온다.

```text
같은 이야기 코사인 유사도 : 0.519
다른 이야기 코사인 유사도 : -0.032
```

> 768은 모델 기본 차원이 아니라 `dimensions=768`로 줄여 받은 값. 저장 벡터와 벡터 인덱스의 차원은 반드시 같아야 함.

### Document 노드 적재

```python
run_cypher(
    'CREATE INDEX document_pmcid IF NOT EXISTS '
    'FOR (n:Document) ON (n.pmcid)'
)

run_cypher(
    'UNWIND $rows AS row CREATE (n:Document) SET n += row',
    rows=papers
)
```

`UNWIND`로 리스트를 행 단위로 풀어 한 번에 적재.

`SET n += row`는 기존 속성을 유지하면서 딕셔너리의 키·값을 추가하거나 덮어씀.

### 임베딩 생성 및 저장

제목과 본문을 함께 임베딩.

```python
vectors = embed_texts([
    paper['title'] + ' ' + paper['text']
    for paper in papers
])

run_cypher('''
UNWIND $rows AS row
MATCH (n:Document {pmcid: row.pmcid})
CALL db.create.setNodeVectorProperty(n, 'emb', row.vec)
''', rows=[
    {'pmcid': paper['pmcid'], 'vec': vector}
    for paper, vector in zip(papers, vectors)
])
```

**결과**

```text
임베딩이 붙은 논문: 69
```

`db.create.setNodeVectorProperty`를 이용해 벡터 속성으로 저장.

> 무엇을 임베딩하는지도 검색 결과에 영향을 줌. `제목+본문`과 `제목만`을 각각 임베딩하면 같은 질문에서도 상위 결과가 달라짐.

## 3. 벡터 인덱스와 의미 검색

### 벡터 인덱스 생성

```python
run_cypher('''
CREATE VECTOR INDEX doc_vec IF NOT EXISTS
FOR (n:Document) ON n.emb
OPTIONS {indexConfig: {
    `vector.dimensions`: 768,
    `vector.similarity_function`: 'cosine'
}}
''')

run_cypher('CALL db.awaitIndexes()')
```

핵심 설정.

| 설정 | 의미 |
|---|---|
| `vector.dimensions: 768` | 저장한 임베딩 차원과 일치 |
| `vector.similarity_function: 'cosine'` | 코사인 기반 가까움 계산 |
| `db.awaitIndexes()` | 인덱스가 준비될 때까지 대기 |

Neo4j 벡터 인덱스는 HNSW 기반의 **근사 최근접 이웃 검색**을 사용.

즉, 전수 비교보다 빠르지만 데이터가 커지면 진짜 상위 k개와 완전히 같지 않을 수도 있음.

### 인덱스 없이 전수 비교

```python
q_vec = embed_query('어떤 유전자가 약물 대사에 관여하나요?')

BRUTE = '''
MATCH (n:Document)
RETURN n.pmcid AS pmcid,
       round(vector.similarity.cosine(n.emb, $q), 3) AS score
ORDER BY score DESC
LIMIT 3
'''

run_cypher(BRUTE, q=q_vec)
```

**결과**

```text
PMC13494111  0.731
PMC13432136  0.708
PMC13368705  0.706
```

모든 `Document`의 벡터를 직접 비교하므로 문서 수가 늘수록 비용도 증가.

### 벡터 인덱스로 검색

```python
SEARCH = '''
MATCH (n:Document)
  SEARCH n IN (
      VECTOR INDEX doc_vec
      FOR $q
      LIMIT 3
  ) SCORE AS score
RETURN n.pmcid AS pmcid,
       n.title AS title,
       round(score, 3) AS score
ORDER BY score DESC
'''

hits = run_cypher(SEARCH, q=q_vec)
```

**결과**

```text
PMC13494111 | 0.731
PMC13432136 | 0.708
PMC13368705 | 0.706
```

실습 데이터에서는 전수 비교와 같은 순서가 나옴.

```text
전수 비교 26.9 ms → 벡터 인덱스 18.1 ms
```

69편이라 차이는 작음. 문서가 많아질수록 인덱스의 의미가 커짐.

### `SEARCH` 핵심 문법

```cypher
MATCH (n:Document)
SEARCH n IN (
    VECTOR INDEX 인덱스이름
    FOR 질문벡터
    LIMIT 개수
) SCORE AS score
RETURN n, score
```

- `LIMIT`: 받을 상위 문서 수(top-k)
- `SCORE AS score`: 검색 점수 저장
- 벡터 인덱스 검색은 `SEARCH` 사용
- `vector.similarity.cosine()`은 인덱스를 사용하지 않는 직접 비교

## 4. 벡터 검색의 필터 위치

`SEARCH` 뒤에 `WHERE`를 붙이면 **먼저 top-k를 뽑은 뒤 필터링**.

```cypher
MATCH (n:Document)
SEARCH n IN (VECTOR INDEX doc_vec FOR $q LIMIT 5) SCORE AS score
WHERE n.title CONTAINS 'Pharmacogenomic'
RETURN n.pmcid
```

**결과**

```text
LIMIT 5로 받은 뒤 조건 통과 : 2편
실제 조건에 맞는 전체 문서 : 3편
```

즉, 뒤에서 걸러져도 부족한 수를 다시 채워주지 않음.

### 사후 필터

```text
벡터 검색 → top-k 추출 → WHERE 필터
```

조건이 자유롭지만 원하는 문서가 top-k 밖에 있으면 놓칠 수 있음.

### 사전 필터

필터에 사용할 속성을 인덱스 생성 시 함께 등록.

```python
run_cypher('''
CREATE VECTOR INDEX doc_vec_year IF NOT EXISTS
FOR (n:Document) ON n.emb
WITH [n.year]
OPTIONS {indexConfig: {
    `vector.dimensions`: 768,
    `vector.similarity_function`: 'cosine'
}}
''')
```

검색 조건을 `SEARCH` 안에 넣음.

```cypher
MATCH (n:Document)
SEARCH n IN (
    VECTOR INDEX doc_vec_year
    FOR $q
    WHERE n.year = '2025'
    LIMIT 3
) SCORE AS score
RETURN n.pmcid
```

**결과**

```text
사후 필터 : 0편
사전 필터 : 1편 ['PMC13478934']
```

사전 필터는 **조건에 맞는 문서끼리 먼저 후보를 만들고 그 안에서 가까운 문서를 찾음**.

## 5. 전문 인덱스와 키워드 검색

의미가 아니라 **실제 글자**를 기준으로 찾아야 할 때 사용.

적합한 대상.

- 유전자 기호
- 약 이름
- 코드·식별자
- 문서에 특정 단어가 실제로 존재하는지 확인

### 전문 인덱스 생성

```python
run_cypher('''
CREATE FULLTEXT INDEX doc_ft IF NOT EXISTS
FOR (n:Document) ON EACH [n.title, n.text]
''')

run_cypher('CALL db.awaitIndexes()')
```

### 전문 검색

```python
term_hits = run_cypher('''
CALL db.index.fulltext.queryNodes('doc_ft', $term)
YIELD node, score
RETURN node.pmcid AS pmcid, score
ORDER BY score DESC
''', term='CYP2C19')
```

**결과**

```text
CYP2C19가 포함된 논문: 5편
```

```text
PMC13478934
PMC13461525
PMC13432136
PMC13368705
PMC13494692
```

### Lucene 검색 문법

```text
CYP2C19 AND warfarin  → 둘 다 포함
CYP2C19 OR warfarin   → 하나 이상 포함
title:CYP2C19         → 제목만 검색
```

실행 결과.

```text
CYP2C19 AND warfarin → 1편
CYP2C19 OR warfarin  → 7편
title:CYP2C19        → 2편
```

## 6. 의미 검색과 전문 검색 비교

| 구분 | 의미 검색 | 전문 검색 |
|---|---|---|
| 기준 | 문장의 뜻 | 실제 글자 |
| 인덱스 | Vector | Full-text |
| 질문 표현이 달라도 | 찾을 수 있음 | 해당 글자가 없으면 못 찾음 |
| 다른 언어 | 임베딩 공간이 지원하면 가능 | 글자가 다르면 불가능 |
| 정확한 기호·코드 | 놓치거나 다른 문서가 섞일 수 있음 | 적합 |
| 대표 호출 | `SEARCH ... VECTOR INDEX` | `db.index.fulltext.queryNodes()` |

예시.

```text
'CYP2C19' 전문 검색 : 실제 기호가 들어간 논문 5편
'CYP2C19' 벡터 검색 : 상위 5편 중 실제 기호 포함은 4편
```

한국어 `유전자`를 영어 문서에 전문 검색하면 0건이지만, 한국어 질문을 임베딩한 의미 검색은 관련 영어 논문을 찾음.

따라서 둘은 대체 관계가 아니라 **용도가 다른 검색 방식**.

### 하이픈이 있는 기호 주의

전문 인덱스의 analyzer는 문장부호를 기준으로 단어를 나눌 수 있음.

`HLA-B`는 `hla`, `b`로 분리되어 검색될 수 있음.

```text
원문에 HLA-B가 실제로 있는 논문 : 3편
HLA-B 그대로 검색              : 18편
"HLA-B"로 검색                 : 3편
HLA-A 그대로 검색              : 69편
```

정확한 기호에 하이픈·점·슬래시 등이 있으면 **따옴표로 묶어 구문 질의**하는 습관이 안전함.

## 7. 문서와 지식그래프 연결: `MENTIONS`

검색된 논문에서 그래프로 넘어가려면 논문이 언급한 개체와 기존 노드를 연결해야 함.

```text
Document
   ↓ MENTIONS
Compound
   ↓ BINDS
Gene
```

### 이름이 아니라 `id`로 연결

이름만으로 연결하면 같은 이름을 가진 서로 다른 종류의 노드를 잘못 합칠 수 있음.

예시.

```text
obesity      → Disease / Symptom
progesterone → Compound / PharmacologicClass
```

따라서 사전에서 이름을 그래프의 고유 `id`로 변환한 뒤 연결.

사전 구조.

| 항목 | 역할 |
|---|---|
| `entries` | 일반 이름·동의어 → `id`, `label`, 표준 이름 |
| `genes` | 대소문자를 유지한 유전자 기호 → `id` |
| `ambiguous` | 여러 노드로 해석되는 이름. 연결하지 않음 |
| `brand_stopwords` | 일반 영어 단어와 겹치는 상품명 예외 |

예시.

```text
aspirin  → Compound::DB00945
CYP2C19  → Gene::1557
```

### 개체 추출

```python
found = find_entities(
    paper['title'] + ' ' + paper['text'],
    NAME2ID
)
```

첫 논문 결과.

```text
찾은 개체: 20개

Gene      CYP2C19     Gene::1557
Gene      NUDT15      Gene::55270
Gene      CYP3A5      Gene::1577
Gene      ABCG2       Gene::9429
Gene      UGT1A1      Gene::54658
Compound  Omeprazole  Compound::DB00338
```

## 8. `MENTIONS` 관계 생성

논문별 추출 개체를 레이블별로 모은 뒤 기존 그래프 노드의 `id`와 연결.

```python
links = {}

for paper in papers:
    entities = find_entities(
        paper['title'] + ' ' + paper['text'],
        NAME2ID
    )

    for entity_id, (label, canonical) in entities.items():
        links.setdefault(label, []).append({
            'pmcid': paper['pmcid'],
            'id': entity_id
        })

for label, rows in links.items():
    run_cypher(f'''
    UNWIND $rows AS row
    MATCH (d:Document {{pmcid: row.pmcid}}),
          (e:{label} {{id: row.id}})
    MERGE (d)-[:MENTIONS]->(e)
    ''', rows=rows)
```

`MERGE`를 사용하므로 같은 문서-개체 쌍을 여러 번 처리해도 관계를 중복 생성하지 않음.

### 결과

```text
MENTIONS 전체: 588건

Gene                  318
Compound              214
Symptom                27
Disease                21
PharmacologicClass      8
```

```text
개체가 하나도 연결되지 않은 논문: 0편
한 논문이 언급한 개체 수: 최소 1 / 최대 23
```

69편 모두 검색 결과에서 그래프로 넘어갈 연결을 가짐.

## 9. 검색 결과에서 그래프 확장

벡터 검색 1위 논문에서 언급한 약물을 찾고, 기존 그래프의 `BINDS` 관계를 따라 유전자까지 확장.

```python
run_cypher('''
MATCH (d:Document {pmcid:$pmcid})-[:MENTIONS]->(c:Compound)
MATCH (c)-[:BINDS]->(g:Gene)
WITH c.name AS drug, g.name AS gene
ORDER BY drug, gene
RETURN drug, collect(gene)[..4] AS genes
ORDER BY drug
LIMIT 5
''', pmcid=hits[0]['pmcid'])
```

**결과 예시**

```text
Abacavir      BINDS ['ADH6', 'ADK', 'UGT1A1']
Azithromycin  BINDS ['ABCB1', 'CYP1A2', 'CYP2A6', 'CYP3A4']
Dapsone       BINDS ['CYP2C18', 'CYP2C19', 'CYP2C8', 'CYP2C9']
Efavirenz     BINDS ['CYP1A2', 'CYP2B6', 'CYP2C19', 'CYP2C9']
Erythromycin  BINDS ['ABCB1', 'ABCC1', 'CYP1A2', 'CYP2B6']
```

핵심 구조.

```text
질문
→ 관련 논문 검색
→ 논문이 언급한 약물
→ 기존 그래프의 BINDS 관계
→ 관련 유전자
```

논문 자체에 직접 적히지 않은 사실도 **기존 그래프의 관계를 통해 확장**할 수 있음.

반대로 특정 개체에서 관련 논문을 찾을 수도 있음.

```cypher
MATCH (d:Document)-[:MENTIONS]->(g:Gene {name:$gene})
RETURN d.pmcid AS pmcid, d.title AS title
ORDER BY d.pmcid
```

예: `CYP3A4`를 언급한 논문 검색.

## 10. 이름 기반 연결의 한계

현재 `find_entities`는 사전에 있는 표현을 글자 기준으로 찾는 단순 방식.

주요 한계.

- 여러 단어로 된 이름을 놓칠 수 있음
- 사전에 없는 최신 이름을 못 찾음
- 돌려 말한 표현을 못 찾음
- 같은 글자가 다른 의미로 쓰인 경우 오탐 가능
- 상품명·동의어는 사전 품질에 의존

따라서 현재 방식은 **문서-그래프 연결 원리를 확인하기 위한 1차 연결 방식**.

## 핵심 문법 압축

| 목적 | 문법 | 핵심 |
|---|---|---|
| 문서 일괄 적재 | `UNWIND $rows AS row` | 파이썬 리스트를 행으로 펼침 |
| 속성 추가 | `SET n += row` | 기존 속성을 유지하며 추가·갱신 |
| 벡터 저장 | `db.create.setNodeVectorProperty` | 임베딩을 노드 벡터 속성으로 저장 |
| 벡터 인덱스 | `CREATE VECTOR INDEX` | 차원과 유사도 함수 지정 |
| 의미 검색 | `SEARCH n IN (VECTOR INDEX ...)` | 임베딩 의미 기준 top-k 검색 |
| 직접 유사도 | `vector.similarity.cosine()` | 인덱스 없이 전수 비교 |
| 전문 인덱스 | `CREATE FULLTEXT INDEX` | 텍스트를 단어 단위로 색인 |
| 전문 검색 | `db.index.fulltext.queryNodes()` | 실제 키워드 포함 문서 검색 |
| 문서-개체 연결 | `MERGE (d)-[:MENTIONS]->(e)` | 검색 결과를 지식그래프와 연결 |
| 그래프 확장 | `(d)-[:MENTIONS]->(c)-[:BINDS]->(g)` | 문서에서 기존 그래프 사실까지 탐색 |

---

## 최종 정리

```text
1. 기존 지식그래프 준비
2. 논문을 Document 노드로 적재
3. 문서를 미리 임베딩해 emb 속성에 저장
4. Vector Index 생성
5. 질문을 임베딩해 의미 검색
6. 정확한 키워드는 Full-text Index로 검색
7. 문서의 개체명을 id로 변환
8. Document -[:MENTIONS]-> Entity 연결
9. 검색된 문서에서 기존 그래프 관계를 따라 확장
```

### 한 줄 핵심

> **GraphRAG의 핵심은 벡터 검색 자체가 아니라, 검색된 문서를 `MENTIONS` 같은 관계로 기존 지식그래프에 연결해 문서 밖의 구조화된 사실까지 탐색하는 것.**
