# Neo4j JSON 적재 및 관계 활용 실전 코드

> 이전 **CSV 실전 코드**에서 이미 다룬 기본 노드 적재, 파라미터 조회, 재적재에 의한 멱등성, 배치 트랜잭션, `SurveyDay` 기본 생성 과정은 제외함.  
> 여기서는 **JSON의 중첩 구조를 그래프로 옮기는 방법과 관계 속성 활용**을 중심으로 정리함.

---

## 1. JSON 데이터 구조 확인

JSON 한 행에는 역 정보와 함께 `요일별` 배열이 들어 있음.

```python
{
    '연번': 1,
    '역명': '신도림',
    '요일별': [
        {'요일': '평일', '인원': 269275},
        {'요일': '토요일', '인원': 229757},
        {'요일': '일요일', '인원': 165107}
    ]
}
```

그래프로 옮기면 다음 구조가 자연스러움.

```text
(Station)-[:TRANSFERS {count}]->(DayType)
```

- `Station`: 역
- `DayType`: 평일 / 토요일 / 일요일
- `TRANSFERS.count`: 해당 역·요일의 환승인원

JSON 배열의 각 원소를 별도 관계로 펼치는 것이 핵심.

---

## 2. JSON 중첩 배열을 펼쳐 노드와 관계 적재

`apoc.load.json()`으로 JSON을 읽고, `UNWIND`로 `요일별` 배열을 한 행씩 펼침.

```python
load_transfer_q = """
// JSON 객체를 한 건씩 value로 읽기
CALL apoc.load.json('file:///seoul_metro_transfer.json')
YIELD value

// 역 노드 생성 또는 찾기
MERGE (s:Station {name: value['역명']})
SET s.seq = value['연번']

// value['요일별'] 배열을 원소 단위로 펼치기
UNWIND value['요일별'] AS day

// 요일 노드 생성 또는 찾기
MERGE (d:DayType {name: day['요일']})

// 역 -> 요일 관계 생성 또는 찾기
MERGE (s)-[r:TRANSFERS]->(d)

// 환승인원은 관계의 속성으로 저장
SET r.count = day['인원']
"""

run_cypher(load_transfer_q)

# 생성된 요일 노드 수 확인
rows = run_cypher("""
MATCH (d:DayType)
RETURN count(d) AS n
""")
n_daytype = rows[0]['n']

# 생성된 환승 관계 수 확인
rows = run_cypher("""
MATCH ()-[r:TRANSFERS]->()
RETURN count(r) AS n
""")
n_transfers = rows[0]['n']

print(n_daytype)
print(n_transfers)
```

**결과**

```text
3
219
```

### 핵심

```text
JSON 배열
  ↓ UNWIND
배열 원소별 행
  ↓
DayType 노드 + TRANSFERS 관계
```

73개 역마다 요일이 3개이므로 관계는 총 `73 × 3 = 219`개가 생성됨.

## 3. 관계 속성으로 집계하기

환승인원은 `Station`이나 `DayType` 노드가 아니라 `TRANSFERS` 관계의 `count`에 저장되어 있음.

```text
(Station)-[r:TRANSFERS {count}]->(DayType)
                   ↓
                r.count
                   ↓
             요일별 sum()
```

```python
# 요일별 총 환승인원을 구하는 쿼리
by_day_query = """
// TRANSFERS 관계를 r로 잡기
MATCH (s:Station)-[r:TRANSFERS]->(d:DayType)

// 같은 DayType별로 관계 속성 count를 합산
RETURN d.name AS 요일,
       sum(r.count) AS 합계

// 총 환승인원이 큰 순서
ORDER BY 합계 DESC
"""

rows = run_cypher(by_day_query)

# [{요일, 합계}, ...] -> {요일: 합계}
by_day = {}
for row in rows:
    by_day[row['요일']] = row['합계']

print(by_day)
```

**결과**

```text
{'평일': 4814846, '토요일': 3861432, '일요일': 2801457}
```

### 핵심

값이 **관계 속성**에 있으면 집계할 때도 관계를 변수로 잡아야 함.

```cypher
MATCH ()-[r:TRANSFERS]->()
RETURN sum(r.count)
```

즉,

```text
노드 속성 집계 -> s.weekday
관계 속성 집계 -> r.count
```

## 4. `MATCH`의 조용한 실패 확인

Cypher의 `MATCH`가 아무 노드도 찾지 못하면 오류가 발생하는 것이 아니라 **다음 절로 전달할 행이 0개가 됨**.

따라서 뒤에 있는 `MERGE`, `SET`도 실행되지 않을 수 있음.

```python
ghost_q = """
CALL apoc.load.json('file:///seoul_metro_transfer.json')
YIELD value

UNWIND value['요일별'] AS day

// 실제 데이터에는 Metro 레이블이 없다고 가정
MATCH (s:Metro {name: value['역명']})

// MATCH 결과가 0행이면 아래 절도 실행되지 않음
MERGE (d:DayType {name: day['요일']})
MERGE (s)-[r:WRONG_TRANSFERS]->(d)
SET r.count = day['인원']

RETURN count(r) AS created
"""

n_ghost = run_cypher(ghost_q)[0]['created']
print('생성된 관계 수:', n_ghost)
```

**결과**

```text
생성된 관계 수: 0
```

### 핵심

```text
MATCH 성공
-> 행이 다음 절로 전달됨
-> MERGE / SET 실행

MATCH 실패
-> 전달되는 행 0개
-> 이후 절도 0번 실행
-> 반드시 오류가 발생하는 것은 아님
```

따라서 적재 쿼리가 오류 없이 끝났더라도 **생성 개수나 조회 결과를 반드시 확인하는 습관**이 필요함.

## 5. 여러 관계 속성을 이용해 파생값 계산

한 역에서 평일과 토요일 `TRANSFERS` 관계를 각각 잡으면 두 관계의 속성을 함께 계산할 수 있음.

여기서는 다음 값을 구함.

```text
토요일 환승인원 / 평일 환승인원
```

```python
ratio_q = """
MATCH (s:Station)

// 해당 역의 평일 관계
MATCH (s)-[weekday:TRANSFERS]->(:DayType {name: '평일'})

// 해당 역의 토요일 관계
MATCH (s)-[sat:TRANSFERS]->(:DayType {name: '토요일'})

// 두 관계 속성으로 비율 계산
SET s.sat_ratio = round(
    toFloat(sat.count) / weekday.count,
    3
)
"""

run_cypher(ratio_q)

# sat_ratio가 저장된 역 개수 확인
rows = run_cypher("""
MATCH (s:Station)
WHERE s.sat_ratio IS NOT NULL
RETURN count(s) AS n
""")
n_ratio = rows[0]['n']

# 비율이 가장 높은 역 조회
rows = run_cypher("""
MATCH (s:Station)
WHERE s.sat_ratio IS NOT NULL
RETURN s.name AS name,
       s.sat_ratio AS ratio
ORDER BY ratio DESC
LIMIT 1
""")

top_ratio = rows[0]['name']

print('sat_ratio가 저장된 역 개수:', n_ratio)
print('sat_ratio가 가장 높은 역:', top_ratio)
```

**결과**

```text
sat_ratio가 저장된 역 개수: 73
sat_ratio가 가장 높은 역: 청량리
```

### 핵심

같은 노드에서 서로 다른 관계를 별도 변수로 잡을 수 있음.

```cypher
MATCH (s)-[weekday:TRANSFERS]->(:DayType {name: '평일'})
MATCH (s)-[sat:TRANSFERS]->(:DayType {name: '토요일'})
```

이후

```cypher
weekday.count
sat.count
```

처럼 각 관계의 속성을 독립적으로 사용 가능.

## 6. 공유 날짜 노드로 같은 날 조사된 역 찾기

CSV 실전 코드에서 만든 다음 구조를 그대로 활용한다고 가정함.

```text
(Station)-[:SURVEYED_ON]->(SurveyDay)
```

같은 `SurveyDay`를 가리키는 두 역은 같은 날 조사된 역으로 볼 수 있음.

```python
pairs_node_q = """
// 두 Station이 같은 SurveyDay를 공유하는 경우 찾기
MATCH (a:Station)-[:SURVEYED_ON]->(d:SurveyDay)<-[:SURVEYED_ON]-(b:Station)

// (A, B)와 (B, A)를 중복 계산하지 않음
WHERE a.name < b.name

RETURN count(*) AS n
"""

rows = run_cypher(pairs_node_q)
n_pairs_node = rows[0]['n']

print('같은 날 조사된 역 쌍:', n_pairs_node)
```

**결과**

```text
같은 날 조사된 역 쌍: 2628
```

73개 역이 모두 같은 날짜 노드를 공유하므로 가능한 역 쌍의 수는 다음과 같음.

```text
73C2 = 2628
```

### 공유 노드를 이용한 관계 표현

```text
Station A ─┐
           ├─> SurveyDay
Station B ─┘
```

속성값을 직접 비교하지 않고 **같은 노드를 공유하는지**로 동일한 날짜를 표현할 수 있음.

## 7. 날짜 노드를 연도 계층으로 확장하기

기존 `SurveyDay`의 날짜에서 연도를 꺼내 `SurveyYear` 노드를 생성함.

```text
SurveyYear
    |
 HAS_DAY
    v
SurveyDay
    ^
SURVEYED_ON
    |
 Station
```

```python
# SurveyDay의 날짜를 이용해 SurveyYear 생성
run_cypher("""
MATCH (d:SurveyDay)

// date 자료형에서 연도 추출
MERGE (y:SurveyYear {year: d.date.year})

// 연도 -> 날짜 관계 생성
MERGE (y)-[:HAS_DAY]->(d)
""")

# 연도별 조사된 Station 수 조회
by_year = run_cypher("""
MATCH (y:SurveyYear)-[:HAS_DAY]->(d:SurveyDay)
      <-[:SURVEYED_ON]-(s:Station)

RETURN y.year AS year,
       count(DISTINCT s) AS n

ORDER BY year ASC
""")

print('연도별 조사 역 수:', by_year)
```

**결과**

```text
연도별 조사 역 수: [{'year': 2025, 'n': 73}]
```

### 핵심

하나의 날짜 속성을 단순 값으로만 두지 않고 노드로 분리하면 계층을 추가할 수 있음.

```text
SurveyYear -> SurveyDay <- Station
```

이후 데이터가 여러 날짜·여러 연도로 늘어나면 연도별 집계나 날짜별 탐색을 그래프 경로로 처리 가능.

# 최종 그래프 구조

```text
                           (DayType {name})
                              ^
                              |
                    TRANSFERS {count}
                              |
                              |
(Station {name, seq, sat_ratio})
                              |
                              | SURVEYED_ON
                              v
                    (SurveyDay {date})
                              ^
                              |
                           HAS_DAY
                              |
                    (SurveyYear {year})
```

# 전체 흐름 요약

```text
JSON 읽기
  ↓
apoc.load.json()
  ↓
중첩 배열 펼치기
  ↓
UNWIND
  ↓
Station -[TRANSFERS {count}]-> DayType
  ↓
관계 속성 집계 / 계산
  ↓
공유 SurveyDay를 이용한 연결 탐색
  ↓
SurveyYear -> SurveyDay 계층으로 확장
```

### 이번 코드의 핵심 구문

| 구문 | 역할 |
|---|---|
| `apoc.load.json()` | JSON 파일 읽기 |
| `UNWIND` | JSON 배열을 행 단위로 펼치기 |
| `MERGE (s)-[r:TRANSFERS]->(d)` | 관계 생성 또는 재사용 |
| `SET r.count = ...` | 관계에 속성 저장 |
| `sum(r.count)` | 관계 속성 집계 |
| `MATCH` 결과 0행 | 이후 절도 실행되지 않는 조용한 실패 가능 |
| `weekday.count`, `sat.count` | 여러 관계 속성을 따로 사용 |
| 공유 `SurveyDay` | 같은 날짜를 그래프 연결로 표현 |
| `d.date.year` | Neo4j 날짜 자료형에서 연도 추출 |
