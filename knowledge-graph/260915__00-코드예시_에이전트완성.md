# 검색 도구 통합 Agent와 근거 추적

> Graph 검색과 Vector 검색을 각각 확인한 뒤, 하나의 Agent에 연결하고 최종 답변의 인용 근거까지 추적하는 흐름.
>
> 핵심 흐름: **도구 직접 호출 → Agent 통합 → 도구 선택 확인 → 인용 ID 검증 → 원문/관계 근거 추적**

---

## 1. 두 검색 도구를 직접 호출해보기

### 1-1. 관계 검색 도구 직접 호출

`search_graph`는 LLM이 아니라 **Cypher를 검사하고 Neo4j 조회 결과를 반환하는 Tool**이다.

```text
graph_tool.invoke(...)
        ↓
{"cypher": graph_cypher}
        ↓
search_graph(cypher=graph_cypher)
        ↓
read_query(cypher)
        ↓
Neo4j 조회
        ↓
{"cypher": "...", "rows": [...]}
```

#### 코드

```python
# 1. 제공된 search_graph 도구 자체를 graph_tool에 담기
graph_tool = search_graph

# 모델이 도구를 선택할 때 참고하는 이름과 설명 확인
print("도구 이름:", graph_tool.name)
print("도구 설명:", graph_tool.description)

# 2. 아락실과립이 어떤 증상을 TREATS로 가리키는지 조회
graph_cypher = """
// Drug의 정식 이름 또는 aliases에서 "아락실과립" 검색
MATCH (d:Drug)-[r:TREATS]->(s:Symptom)
WHERE (d.name = "아락실과립" OR "아락실과립" IN d.aliases)
  AND r.dataset = "drugs"
RETURN
  s.name AS answer_value,
  [r.claim_id] AS evidence_ids,
  [r.evidence] AS evidence_texts,
  [r.source_doc_id] AS source_doc_ids,
  [r.source_kind] AS source_kinds,
  [type(r)] AS relation_types
ORDER BY answer_value ASC, evidence_ids ASC
LIMIT 50
"""

# 3. Tool 직접 호출
graph_output = graph_tool.invoke({
    "cypher": graph_cypher
})

# 4. 실제 실행 Cypher와 조회 결과 확인
print("\n실행 Cypher:")
print(graph_output["cypher"])

print("\n조회 결과:")
print(graph_output["rows"])
```

#### 결과


### 정리

- `search_graph`의 입력은 **Cypher**.

- 이름 표기가 애매하면 바로 Cypher를 작성하기보다 `select_names`로 먼저 확인하는 편이 안전함.

### 1-2. 원문 검색 도구 호출 및 반환 구조 비교

`search_documents`는 그래프 관계가 아니라 **원문 청크와 출처를 검색하는 Vector Search Tool**이다.

같은 근거 검색이라도 반환 형태가 다름.

```text
Graph Search                       Vector Search
search_graph                       search_documents
     │                                    │
     ├─ rows                              └─ chunks
     │                                        │
     └─ evidence_ids = claim_id              └─ chunk_id
```

> 원문의 `chunks_is` 표기는 오타. 정확한 키는 **`chunk_id`**.

#### 코드

```python
# 제공된 원문 검색 도구
vector_tool = search_documents

# 검색할 질문
patch_question = "귀 뒤에 붙이는 멀미약은 어떻게 사용하나요?"

# 원문 벡터 검색 Tool 직접 호출
vector_output = vector_tool.invoke({
    "dataset": "drugs",
    "query": patch_question
})

# 검색된 청크 확인
for chunk in vector_output["chunks"]:
    print("chunk_id:", chunk["chunk_id"])
    print("source_doc_id:", chunk["source_doc_id"])
    print("text:", chunk["text"])
    print()

# 두 Tool의 최상위 반환 키 비교
output_keys = {
    "search_graph": sorted(graph_output),
    "search_documents": sorted(vector_output)
}

print(output_keys)
```

### 정리

| 구분 | `search_graph` | `search_documents` |
|---|---|---|
| 검색 대상 | 그래프 관계 | 원문 청크 |
| 입력 | Cypher | 자연어 query |
| 주요 반환값 | `rows` | `chunks` |
| 근거 ID | `claim_id` | `chunk_id` |
| 적합한 질문 | 관계·구조가 명확한 질문 | 사용법·주의사항 등 원문 확인 질문 |

벡터 검색은 질문과 가까운 청크를 후보로 가져오는 과정임. **검색 점수가 높다는 이유만으로 정답이라고 확정할 수는 없음.** 최종 답변은 실제 청크 내용을 읽고 판단해야 함.

## 2. 두 검색 도구를 한 Agent로 연결

### 2-1. 스키마와 검색 Tool로 Agent 제작

Agent에 세 가지 Tool을 연결함.

```text
사용자 질문
   ↓
LLM Agent
   ├─ select_names      : 이름 후보 확인
   ├─ search_graph      : Graph 관계 검색
   └─ search_documents  : 원문 Vector 검색
   ↓
GroundedAnswer
```

#### 코드

```python
# drugs 데이터셋 전용 시스템 메시지 생성
system_preview = agent_template.format_messages(
    domain="drugs",
    schema=read_schema("drugs"),
    cypher_rules=cypher_rules
)[0]

print("=== 시스템 프롬프트 확인 ===")
print(system_preview.content)

# 세 Tool을 사용하는 Agent 생성
drugs_agent = create_agent(
    model=llm,
    tools=[
        select_names,
        search_graph,
        search_documents
    ],
    system_prompt=system_preview,
    response_format=ProviderStrategy(
        GroundedAnswer,
        strict=True
    )
)

# 생성 상태 확인
print("\n=== 시스템 메시지 타입 ===")
print(type(system_preview))

print("\n=== 연결한 도구 ===")
for tool in [select_names, search_graph, search_documents]:
    print(tool.name)

print("\n=== Agent 생성 확인 ===")
print(type(drugs_agent))
```

#### 결과

```text

drugs 자료를 검색해 한국어로 답하세요.
```

### 정리

`select_names`는 별도의 검색 방식이라기보다 **Graph 검색 전에 엔티티 이름을 확인하는 보조 Tool**에 가까움.

따라서 전체 구조는 다음처럼 보는 편이 명확함.

```text
                 ┌─ 이름 확인: select_names
사용자 질문 → Agent ┤
                 ├─ 관계 검색: search_graph
                 └─ 원문 검색: search_documents
```

### 2-2. 질문 종류에 따라 선택된 Tool 확인

```python

    return [
        call["name"]
        for call in response.get("tool_calls", [])

text_response = ask(

# 3. 실제 사용 Tool 확인
```

### 2-3. 검색 결과와 최종 인용 ID 검증

최종 답변의 `evidence_ids`가 실제 검색 결과에서 나온 ID인지 검사함.

```text
Graph 검색 rows
   └─ evidence_ids(claim_id)

Vector 검색 chunks
   └─ chunk_id

          ↓ 합치기
       known_ids
          ↓ 비교
response["evidence_ids"]
          ↓
검색 결과에 없던 ID만 추출
```

#### 코드

```python
def find_unknown_citations(response):
    # 실제 검색 결과에서 확인된 근거 ID
    known_ids = set()

    # Graph 검색 근거
    for row in response.get("rows", []):
        for evidence_id in row.get("evidence_ids", []):
            known_ids.add(evidence_id)

    # Vector 검색 근거
    for chunk in response.get("chunks", []):
        known_ids.add(chunk["chunk_id"])

    # 최종 답변이 인용했지만 검색 결과에는 없던 ID
    # list로 검사하므로 최종 답변의 순서와 중복은 유지됨
    unknown_ids = []

    for evidence_id in response.get("evidence_ids", []):
        if evidence_id not in known_ids:
            unknown_ids.append(evidence_id)

    return unknown_ids


# Graph + 원문 검색이 모두 필요한 혼합 질문
mixed_question = (
    "구역을 효능으로 쓰는 약은 그래프에서 조회하고, "
    "키미테패취를 만진 뒤 해야 할 일은 원문에서 찾아 주세요."
)

mixed_response = ask(
    drugs_agent,
    mixed_question
)

show_response(mixed_response)

# 최종 인용 중 검색 결과에 없던 ID 확인
mixed_unknown_ids = find_unknown_citations(mixed_response)

print("\n알 수 없는 인용 ID:")
print(mixed_unknown_ids)
```

## 3. 답변이 인용한 원문과 관계 되짚기

### 3-1. 원문 답변이 인용한 청크 추적

최종 답변이 인용한 `chunk_id`가 이번 검색 결과에 실제로 존재하고, 해당 청크 텍스트가 원본 문서 안에도 존재하는지 확인함.

```text
response["evidence_ids"]
        ↓
인용 chunk_id 하나씩 확인
        ↓
response["chunks"]에서 같은 ID 검색
        ↓
source_doc_id 확인
        ↓
documents[source_doc_id]["text"]에서
chunk["text"] 포함 여부 확인
```

#### 코드

원본 코드의 `documents[source_doc_id]` 직접 접근은 문서 ID가 없을 경우 `KeyError`가 날 수 있어 안전하게 보완함.

```python
def trace_chunk_citations(response, documents):
    traces = []

    # 검색된 청크를 chunk_id 기준으로 색인
    chunk_map = {
        chunk["chunk_id"]: chunk
        for chunk in response.get("chunks", [])
    }

    # 최종 답변의 인용 순서와 중복을 그대로 유지
    for citation_id in response.get("evidence_ids", []):
        chunk = chunk_map.get(citation_id)

        # 이번 검색 결과에 없는 ID
        if chunk is None:
            traces.append({
                "chunk_id": citation_id,
                "source_doc_id": None,
                "in_source": False
            })
            continue

        source_doc_id = chunk["source_doc_id"]
        source_doc = documents.get(source_doc_id)

        # 원본 문서가 실제로 존재하고,
        # chunk text가 문서 text에 그대로 포함되는지 확인
        in_source = (
            source_doc is not None
            and chunk["text"] in source_doc.get("text", "")
        )

        traces.append({
            "chunk_id": citation_id,
            "source_doc_id": source_doc_id,
            "in_source": in_source
        })

    return traces


# 2-2의 원문 검색 응답에 적용
chunk_citations = trace_chunk_citations(
    text_response,
    drugs["documents"]
)

for citation in chunk_citations:
    print(citation)
```

#### 결과


### 해석

`in_source=True`는 해당 청크 문자열이 원본 문서의 `text`에 **그대로 포함되어 있음**을 뜻함.

주의할 점:

- 이는 문자열 포함 검사임.
- 공백·개행·정규화 방식이 달라지면 같은 내용이어도 `False`가 나올 수 있음.
- 의미적 동일성을 판단하는 검사가 아님.

### 3-2. 답변이 인용한 관계를 원문 근거와 그래프로 추적

최종 답변의 `evidence_ids` 중 실제 `claim_id`인 항목만 골라 관계 타입, 원문 근거, 출처 문서를 확인함.

```text
mixed_response["evidence_ids"]
        ↓
drugs["relations"]의 claim_id와 비교
        ↓
관계 ID만 추출
        ↓
relation / evidence / source_doc_id 확인
        ↓
인용된 관계만 시각화
```

#### 코드

```python
def trace_relation_citations(response, relations):
    # claim_id → relation 빠른 조회용 색인
    relation_map = {
        relation["claim_id"]: relation
        for relation in relations
    }

    citations = {}

    # 최종 답변에서 실제 관계 claim_id만 추출
    for evidence_id in response.get("evidence_ids", []):
        relation = relation_map.get(evidence_id)

        if relation is not None:
            citations[evidence_id] = {
                "relation": relation["relation"],
                "evidence": relation["evidence"],
                "source_doc_id": relation["source_doc_id"]
            }

    return citations


mixed_relation_citations = trace_relation_citations(
    mixed_response,
    drugs["relations"]
)

# 관계 근거 확인
for claim_id in sorted(mixed_relation_citations):
    citation = mixed_relation_citations[claim_id]

    print("관계 ID:", claim_id)
    print("관계 타입:", citation["relation"])
    print("출처 문서:", citation["source_doc_id"])
    print("원문 근거:", citation["evidence"])
    print()

# 실제 인용된 관계만 그래프로 시각화
mixed_figure = draw_evidence(
    drugs,
    set(mixed_relation_citations.keys())
)
```

# 전체 흐름 정리

```text
[1] Tool 단독 확인

search_graph
Cypher → Neo4j → rows → claim_id

search_documents
자연어 query → Vector Search → chunks → chunk_id


[2] 하나의 Agent에 연결

                    ┌─ select_names
사용자 질문 → Agent ├─ search_graph
                    └─ search_documents
                          ↓
                    GroundedAnswer


[3] 최종 답변 검증

response["evidence_ids"]
        │
        ├─ claim_id → Graph 관계 근거 추적
        │
        └─ chunk_id → 원문 청크 추적


[4] 확인 범위

인용 ID가 검색 결과에 있는가?
        ↓
근거가 실제 원문/관계 데이터에 연결되는가?
        ↓
최종 답변을 근거까지 되짚을 수 있는가?
```

## 핵심 구분

| 항목 | 역할 |
|---|---|
| `select_names` | DB에 등록된 이름·타입 확인 |
| `search_graph` | 구조화된 관계를 Cypher로 조회 |
| `search_documents` | 원문 청크를 Vector Search로 검색 |
| `claim_id` | Graph 관계 근거 ID |
| `chunk_id` | 원문 청크 근거 ID |
| `find_unknown_citations()` | 최종 인용이 실제 검색 결과에서 나온 ID인지 확인 |
| `trace_chunk_citations()` | 인용 청크가 원문 문서에 존재하는지 추적 |
| `trace_relation_citations()` | 인용 관계의 타입·원문 근거·출처 추적 |

핵심은 **Agent가 답을 만드는 것에서 끝내지 않고, 답변에 사용한 근거를 다시 Graph와 원문까지 추적 가능하게 만드는 것**임.
