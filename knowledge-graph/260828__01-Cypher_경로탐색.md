# Cypher 경로 탐색 문법 정리

> 경로 탐색에서 실제로 반복해서 쓰는 **Cypher 문법 중심**으로 정리.  
> 흐름은 **가변 길이 경로 → 최단 경로 → 경로 값 추출 → 정렬·조건 처리** 순서로 보면 됨.

---

## 1. 가변 길이 경로: 관계를 여러 칸 따라가기

기본 관계는 한 칸만 이동한다.

```cypher
(a)-[:NEXT_TO]-(b)
```

여러 칸을 따라가려면 관계 뒤에 `*최소..최대`를 붙인다.

```cypher
(a)-[:NEXT_TO*1..3]-(b)
```

```text
*1..3
→ NEXT_TO 관계를 최소 1번, 최대 3번 따라감
→ 1~3-hop 범위의 노드를 찾음
```

### 길이 표기

| 문법 | 의미 |
|---|---|
| `*1..1` | 정확히 1칸 |
| `*2..2` | 정확히 2칸 |
| `*1..3` | 1~3칸 |
| `*..2` | 1~2칸 |
| `*1..` | 1칸 이상 |
| `*` | `*1..`과 같은 형태 |
| `*0..2` | 0~2칸, 출발 노드 자신 포함 |

예:

```cypher
MATCH (a:Station {name:'남부터미널'})
      -[:NEXT_TO*1..2]-
      (b:Station)
RETURN DISTINCT b.name AS 역
ORDER BY 역
```

`*0..2`처럼 최소 길이를 `0`으로 두면 관계를 한 번도 타지 않는 경우도 허용하므로 **출발 노드 자신도 결과에 포함**된다.

```cypher
MATCH (a:Account {name:'A-1001'})
      -[:TRANSFER*0..2]->
      (b:Account)
RETURN DISTINCT b.name AS 계좌
ORDER BY 계좌
```

### 방향 유무

관계의 방향이 의미를 가지는지에 따라 화살표를 유지할지 결정한다.

```cypher
# 방향을 무시
(a)-[:NEXT_TO*1..3]-(b)

# 방향을 유지
(a)-[:TRANSFER*1..3]->(b)
```

전철의 인접 관계처럼 양쪽 이동이 가능한 경우에는 방향 없이 조회할 수 있다.

송금처럼 흐름의 방향이 중요한 관계에서는 화살표를 유지해야 한다.

```text
A -[:TRANSFER]-> B
→ A가 B에게 송금

A -[:TRANSFER]- B
→ 둘 사이에 송금 관계가 있다는 것만 확인
```

### `DISTINCT`: 같은 도착 노드 중복 제거

가변 길이 경로에서는 **같은 노드에 도달하는 경로가 여러 개일 수 있다.**

```text
남부터미널 → 교대 → 강남
남부터미널 → 양재 → 강남
```

이 경우 `강남`이 경로마다 한 번씩 반환될 수 있다.

노드 이름만 한 번씩 받고 싶다면:

```cypher
RETURN DISTINCT b.name AS 역
```

```text
DISTINCT 없음
→ 경로마다 결과 생성

DISTINCT 사용
→ 같은 반환값을 하나로 합침
```

### 가변 길이 사용 시 주의

상한을 크게 열수록 가능한 경로 수가 급격히 늘어날 수 있다.

```cypher
-[:NEXT_TO*1..12]-
```

특히 경로 자체나 `length(p)` 같은 경로 값을 함께 반환하면 가능한 경로를 많이 만들어야 할 수 있다.

따라서 일반적으로:

```text
도달 가능한 노드 탐색
→ 필요한 범위까지만 *1..N 사용

목적지까지 실제 경로 탐색
→ shortestPath 사용
```

## 2. 최단 경로: `shortestPath`와 `allShortestPaths`

목적지까지 **가장 적은 관계 수로 이동하는 경로**를 찾을 때 `shortestPath()`를 사용한다.

```cypher
MATCH p = shortestPath(
    (a:Station {name:'서울역'})
    -[:NEXT_TO*]-
    (b:Station {name:'경복궁'})
)
RETURN p
```

핵심 구조:

```text
MATCH p = shortestPath( (출발)-[:관계*]-(도착) )
      │
      └ 찾은 경로 전체를 p에 저장
```

`*`에 상한을 두지 않는 이유는 목적지까지 몇 칸인지 미리 모르기 때문이다.

### `shortestPath`

```cypher
MATCH p = shortestPath(
    (a)-[:NEXT_TO*]-(b)
)
```

가장 짧은 경로가 여러 개여도 **한 경로만 반환**한다.

### `allShortestPaths`

동일한 최소 길이의 경로를 모두 확인하려면:

```cypher
MATCH p = allShortestPaths(
    (a)-[:NEXT_TO*]-(b)
)
RETURN p
```

차이:

| 함수 | 반환 |
|---|---|
| `shortestPath()` | 최단 경로 중 한 갈래 |
| `allShortestPaths()` | 같은 최소 길이의 경로 전부 |

예:

```cypher
MATCH p = allShortestPaths(
    (a:Station {name:'광화문'})
    -[:NEXT_TO*]-
    (b:Station {name:'서울역'})
)
RETURN [n IN nodes(p) | n.name] AS 경로,
       length(p) AS 정거장수
```

같은 정거장 수의 경로가 여러 개라면 여러 행이 반환된다.

### `shortestPath`가 최소화하는 값

`shortestPath()`가 기준으로 삼는 것은 **관계의 개수**, 즉 hop 수다.

```text
4-hop 경로
→ 관계 4개

5-hop 경로
→ 관계 5개

shortestPath
→ 4-hop 선택
```

관계의 `km`, `amount` 같은 속성값의 합을 최소화하는 함수는 아니다.

따라서:

```text
최소 정거장 수
→ shortestPath

최소 거리 합계
→ 별도의 가중치 기반 알고리즘 필요
```

## 3. 경로에서 값 꺼내기

`MATCH p = ...`로 경로를 변수 `p`에 저장하면 다음 세 함수로 내부 값을 꺼낼 수 있다.

| 함수 | 반환 | 의미 |
|---|---|---|
| `length(p)` | 정수 | 경로의 관계 개수 |
| `nodes(p)` | 노드 목록 | 지나간 노드 |
| `relationships(p)` | 관계 목록 | 지나간 관계 |

예:

```cypher
MATCH p = shortestPath(
    (a:Station {name:'서울역'})
    -[:NEXT_TO*]-
    (b:Station {name:'이태원'})
)
RETURN length(p) AS 정거장수,
       nodes(p) AS 노드목록,
       relationships(p) AS 관계목록
```

경로가 다음과 같다면:

```text
서울역 → 숙대입구 → 삼각지 → 녹사평 → 이태원
```

```text
nodes(p) 개수          = 5
length(p)              = 4
relationships(p) 개수 = 4
```

즉:

```text
length(p) = 노드 수 - 1
```

### 리스트 표현식: 목록에서 속성만 추출

`nodes(p)`는 노드 자체를 반환하므로 이름만 필요하면 리스트 표현식을 사용한다.

```cypher
[n IN nodes(p) | n.name]
```

기본 문법:

```text
[변수 IN 목록 | 반환할 표현식]
```

파이썬과 비교하면:

```python
[n.name for n in nodes]
```

```cypher
[n IN nodes(p) | n.name]
```

관계 속성도 같은 방식으로 추출한다.

```cypher
[r IN relationships(p) | r.line]
```

```cypher
[r IN relationships(p) | r.amount]
```

실전 형태:

```cypher
MATCH p = shortestPath(
    (a:Station {name:'서울역'})
    -[:NEXT_TO*]-
    (b:Station {name:'이태원'})
)
RETURN length(p) AS 정거장수,
       [n IN nodes(p) | n.name] AS 지나는역,
       [r IN relationships(p) | r.line] AS 구간노선
```

결과 예:

```text
정거장수 : 4
지나는역 : ['서울역', '숙대입구', '삼각지', '녹사평', '이태원']
구간노선 : ['4호선', '4호선', '6호선', '6호선']
```

### 리스트를 만들면서 조건 걸기

세로선 `|` 앞에 `WHERE`를 넣으면 조건에 맞는 원소만 남긴다.

```cypher
[r IN relationships(p)
 WHERE r.line = '6호선'
 | r.line]
```

```text
목록을 순회
→ WHERE 조건 검사
→ 통과한 원소만 | 뒤의 값을 추출
```

노드에도 동일하게 사용한다.

```cypher
[n IN nodes(p)
 WHERE '6호선' IN n.lines
 | n.name]
```

### 한 원소에서 여러 값 꺼내기

리스트로 묶기:

```cypher
[r IN relationships(p) | [r.line, r.km]]
```

결과 형태:

```text
[
  ['4호선', 0.83],
  ['4호선', 1.19],
  ...
]
```

맵 형태로 묶기:

```cypher
[r IN relationships(p) |
    {노선: r.line, 거리: r.km}
]
```

결과 형태:

```text
[
  {노선: '4호선', 거리: 0.83},
  {노선: '4호선', 거리: 1.19}
]
```

여러 속성을 함께 반환할 때는 이름이 붙는 맵 형태가 읽기 쉽다.

## 4. 경로 정렬과 경로 전체 조건

### `ORDER BY length(p)`

경로 길이를 정렬 기준으로 사용할 수 있다.

```cypher
MATCH p = shortestPath(
    (a:Station {name:'서울역'})
    -[:NEXT_TO*]-
    (b:Station)
)
WHERE b.name <> '서울역'
RETURN b.name AS 역,
       length(p) AS 정거장수
ORDER BY 정거장수 DESC, 역
LIMIT 13
```

```text
DESC
→ 먼 순서

ASC 또는 생략
→ 가까운 순서
```

보조 정렬키를 함께 두면 같은 거리의 결과 순서도 고정하기 쉽다.

```cypher
ORDER BY 정거장수 DESC, 역
```

### 도착 노드를 지정하지 않으면

```cypher
MATCH p = shortestPath(
    (a:Station {name:'서울역'})
    -[:NEXT_TO*]-
    (b:Station)
)
```

`b`의 이름을 특정하지 않았으므로 서울역에서 **도달 가능한 각 Station까지의 최단 경로**를 찾는 형태가 된다.

도달할 수 없는 노드는:

```text
거리 = null
```

로 나오는 것이 아니라 **해당 행 자체가 생성되지 않는다.**

### 경로의 모든 관계 검사: `all`, `any`, `none`

`relationships(p)`처럼 목록으로 얻은 관계 전체에 조건을 검사할 수 있다.

| 함수 | 의미 |
|---|---|
| `all(...)` | 모든 원소가 조건 만족 |
| `any(...)` | 하나라도 조건 만족 |
| `none(...)` | 하나도 조건을 만족하지 않음 |

기본 문법:

```cypher
all(r IN relationships(p) WHERE 조건)
any(r IN relationships(p) WHERE 조건)
none(r IN relationships(p) WHERE 조건)
```

예:

```cypher
RETURN all(
    r IN relationships(p)
    WHERE r.line = '4호선'
) AS 전부4호선
```

```cypher
RETURN any(
    r IN relationships(p)
    WHERE r.line = '6호선'
) AS 육호선포함
```

```cypher
RETURN none(
    r IN relationships(p)
    WHERE r.line = '1호선'
) AS 일호선안탐
```

`RETURN`에 사용하면 `True / False` 값을 확인하고, `WHERE`에 사용하면 조건을 만족하는 경로만 남긴다.

```cypher
MATCH p =
    (a:Station {name:'서울역'})
    -[:NEXT_TO*1..4]-
    (b:Station)
WHERE all(
    r IN relationships(p)
    WHERE r.line = '4호선'
)
RETURN DISTINCT b.name AS 역
ORDER BY 역
```

의미:

```text
서울역에서 1~4칸 범위의 경로 중
모든 구간이 4호선인 경로만 남김
```

송금 관계에도 같은 문법을 그대로 사용할 수 있다.

```cypher
MATCH p =
    (a:Account {name:'A-1001'})
    -[:TRANSFER*1..5]->
    (b:Account)
WHERE all(
    r IN relationships(p)
    WHERE r.amount >= 4000000
)
RETURN DISTINCT b.name AS 계좌
ORDER BY 계좌
```

```text
전 구간의 송금액이 4,000,000 이상인 경로만 선택
```

### `length(p)`를 `WHERE`에 바로 사용할 때 주의

노트북의 실습 기준에서는 다음처럼 `shortestPath()`와 같은 단계에서 경로 길이 조건을 넣는 방식에 주의해야 한다.

```cypher
MATCH p = shortestPath(
    (a)-[:NEXT_TO*]-(b)
)
WHERE length(p) >= 4
```

단순히:

```text
최단 경로를 먼저 구함
→ 길이가 4 이상인지 나중에 검사
```

하는 형태로 생각하면 안 된다.

이미 구한 최단 경로 결과를 다시 필터링하려는 목적이라면 이후 학습하는 `WITH`로 중간 결과를 넘긴 뒤 조건을 거는 형태를 사용한다.

## 핵심 문법 압축

| 목적 | 문법 |
|---|---|
| 1~3-hop 탐색 | `-[:R*1..3]-` |
| 정확히 2-hop | `-[:R*2..2]-` |
| 자기 자신 포함 0~2-hop | `-[:R*0..2]-` |
| 방향 유지 | `-[:R*1..3]->` |
| 중복 제거 | `RETURN DISTINCT ...` |
| 경로 변수 저장 | `MATCH p = (...)` |
| 최단 경로 한 갈래 | `shortestPath(...)` |
| 최단 경로 전부 | `allShortestPaths(...)` |
| 이동 횟수 | `length(p)` |
| 노드 목록 | `nodes(p)` |
| 관계 목록 | `relationships(p)` |
| 노드 속성 목록 | `[n IN nodes(p) \| n.name]` |
| 관계 속성 목록 | `[r IN relationships(p) \| r.line]` |
| 조건부 리스트 추출 | `[r IN 목록 WHERE 조건 \| 표현식]` |
| 모든 관계 검사 | `all(r IN 목록 WHERE 조건)` |
| 하나라도 검사 | `any(r IN 목록 WHERE 조건)` |
| 하나도 없는지 검사 | `none(r IN 목록 WHERE 조건)` |
| 경로 길이 정렬 | `ORDER BY length(p)` |
| 결과 일부만 반환 | `LIMIT N` |

### 작성 흐름

```text
1. 탐색 범위 결정
   -[:R*1..3]-
          ↓
2. 목적지가 정해진 최단 경로라면
   shortestPath(...)
          ↓
3. 경로를 p에 저장
   MATCH p = ...
          ↓
4. 필요한 값 추출
   length(p)
   nodes(p)
   relationships(p)
          ↓
5. 속성만 필요하면 리스트 표현식
   [n IN nodes(p) | n.name]
          ↓
6. 필요하면 정렬·조건
   ORDER BY
   all / any / none
   DISTINCT / LIMIT
```

## 참고: 공식 문서에서 볼 수 있는 새 표기

노트북에서는 기존 학습 흐름과 맞추기 위해 `*`와 `shortestPath()` 표기를 사용한다.

공식 문서에서는 GQL 표준에 맞춘 다음 형태도 볼 수 있다.

| 현재 정리에서 사용 | 새 표기 예 |
|---|---|
| `-[:NEXT_TO*1..3]-` | `-[:NEXT_TO]-{1,3}` |
| `shortestPath(...)` | `SHORTEST 1 (...)` |
| `allShortestPaths(...)` | `ALL SHORTEST (...)` |

현재 학습에서는 기존 표기를 기준으로 익히고, 공식 문서에서 다른 표기가 나올 수 있다는 정도만 구분하면 된다.
