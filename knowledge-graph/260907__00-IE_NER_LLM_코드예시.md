# IE 실전 코드 - NER 개체 추출 · 검증 · LLM 구조화 출력

문서의 코드와 결과 흐름을 유지하면서, 중복 설명을 줄이고 실행 흐름이 보이도록 정리한 내용.

## 전체 흐름

`원문/추출 결과 준비 → Span·BIO 이해 → NER 모델 출력 확인 → 개체 스키마 정의 → 추출 결과 검증 → 중복 제거·집계 → LLM 구조화 출력`

> **보완 메모**
> - Span의 `end`는 마지막 글자의 위치가 아니라 **슬라이싱에서 제외되는 끝 위치**임.
> - BIO 예시는 원리를 보기 위한 단순 구현임. 실제 NER 모델의 토크나이저와는 처리 방식이 다를 수 있음.
> - 실제 정제 파이프라인에서는 보통 **유형 검증 → 원문 존재 검증 → 중복 제거 → 집계** 순으로 처리하는 편이 자연스러움.

# 1. 구간과 BIO 태깅

NER에서 개체를 표현하는 기본 방식인 **문자 위치(Span)**와 **토큰 단위 BIO 태그**를 직접 만들어 봄.

## 1-1. 개체의 구간(Span) 만들기

개체의 이름·유형과 함께 원문에서의 시작/끝 위치를 `dict` 형태로 저장함.

```python
# 개체가 포함된 원문
sentence = (
    'ATP is then metabolized into adenine and ultimately converted into '
    'uric acid, which elevates serum uric acid levels and increases the risk of gout.'
)

# 미리 지정된 개체 이름과 유형
labeled = [
    ('adenine', 'Compound'),
    ('uric acid', 'Compound'),
    ('gout', 'Disease')
]

# 개체의 위치 정보를 담을 리스트
spans = []

# 개체 이름과 유형을 하나씩 확인
for name, entity_type in labeled:
    # 원문에서 개체가 시작하는 위치 찾기
    start = sentence.find(name)

    # 시작 위치 + 문자열 길이 = 끝 위치
    # Python 슬라이싱에서 end 위치 자체는 포함되지 않음
    end = start + len(name)

    # 개체 정보와 위치 저장
    span = {
        'name': name,
        'type': entity_type,
        'start': start,
        'end': end
    }

    spans.append(span)

    # 저장된 정보 확인
    print(span)

    # 해당 위치가 실제 원문과 일치하는지 확인
    print(sentence[start:end])
```

### 결과

```text
{'name': 'adenine', 'type': 'Compound', 'start': 29, 'end': 36}
adenine
{'name': 'uric acid', 'type': 'Compound', 'start': 67, 'end': 76}
uric acid
{'name': 'gout', 'type': 'Disease', 'start': 142, 'end': 146}
gout
```

> **보완**: `str.find()`가 대상을 찾지 못하면 `-1`을 반환함. 실제 파이프라인에서는 `start != -1`인지 검사한 뒤 Span을 만드는 편이 안전함.

## 1-2. BIO 태깅으로 표현하기

NER 학습에서는 각 토큰에 개체 여부를 나타내는 BIO 태그를 붙일 수 있음.

- `B-유형`: 개체가 시작되는 토큰
- `I-유형`: 같은 개체가 이어지는 토큰
- `O`: 개체가 아닌 토큰

```python
# 개체가 포함된 원문
sentence = (
    'ATP is then metabolized into adenine and ultimately converted into '
    'uric acid, which elevates serum uric acid levels and increases the risk of gout.'
)

# 미리 지정된 개체 이름과 유형
labeled = [
    ('adenine', 'Compound'),
    ('uric acid', 'Compound'),
    ('gout', 'Disease')
]

# 1. 문장을 공백 기준으로 나누어 토큰 리스트 생성
tokens = sentence.split()

# 2. 처음에는 모든 토큰을 개체가 아닌 O로 설정
tags = ['O'] * len(tokens)

# 3. 등록된 개체를 하나씩 확인
for name, entity_type in labeled:
    # 개체 이름도 공백 기준으로 나누기
    # 예: 'uric acid' → ['uric', 'acid']
    parts = name.split()

    # 문장의 토큰을 앞에서부터 확인
    for i, token in enumerate(tokens):
        # in을 사용하면 'gout.'처럼 문장부호가 붙은 경우도 찾을 수 있음
        if parts[0] in token:
            # 첫 토큰에는 B 태그
            tags[i] = 'B-' + entity_type

            # 두 단어 이상이면 나머지 토큰에는 I 태그
            for j in range(1, len(parts)):
                tags[i + j] = 'I-' + entity_type

            # 첫 번째 위치만 태깅하고 종료
            break

# 4. 토큰과 BIO 태그를 짝지어 출력
for token, tag in zip(tokens, tags):
    print(token, tag)
```

> **보완**: 위 코드는 BIO 원리를 확인하기 위한 단순 예시임. `in` 비교는 부분 문자열도 일치시킬 수 있고, 같은 개체가 여러 번 등장해도 첫 위치만 태깅함. 실제 NER 학습에서는 모델의 토크나이저와 토큰-Span 정렬을 사용함.

## 1-3. 학습된 NER 모델 출력 읽기

직접 BIO 태그를 만드는 대신, 학습된 NER 모델이 개체와 위치 정보를 반환하도록 함.

```python
from transformers import pipeline

# NER을 적용할 문장
news_sentence = 'Daniel Park joined Elastic in Amsterdam last March.'

# 1. 기본 NER 모델 사용
ner = pipeline(
    'token-classification',
    model='dslim/bert-base-NER'
)

# 문장을 모델에 넣어 NER 예측 결과 받기
raw_tags = ner(news_sentence)

# 2. 모델이 예측한 BIO 라벨만 추출
bio_labels = []

for tag in raw_tags:
    # 예: B-PER, I-PER, B-ORG
    bio_labels.append(tag['entity'])

print(bio_labels)

# 3. 같은 개체에 속하는 토큰을 하나로 합치기
merged = pipeline(
    'token-classification',
    model='dslim/bert-base-NER',
    aggregation_strategy='simple'
)

merged_ents = merged(news_sentence)

# 4. 합쳐진 개체 결과 확인
for ent in merged_ents:
    print(ent)

    # 반환된 start/end가 실제 원문의 같은 문자열을 가리키는지 확인
    print(news_sentence[ent['start']:ent['end']])
```

### 결과

```text
['B-PER', 'I-PER', 'B-ORG', 'I-ORG', 'B-LOC']
{'entity_group': 'PER', 'score': np.float32(0.9997423), 'word': 'Daniel Park', 'start': 0, 'end': 11}
Daniel Park
{'entity_group': 'ORG', 'score': np.float32(0.9985757), 'word': 'Elastic', 'start': 19, 'end': 26}
Elastic
{'entity_group': 'LOC', 'score': np.float32(0.9995925), 'word': 'Amsterdam', 'start': 30, 'end': 39}
Amsterdam
```

`aggregation_strategy='simple'`을 사용하면 `B-PER`, `I-PER`처럼 나뉜 토큰을 `Daniel Park` 같은 하나의 개체로 합쳐 확인할 수 있음.

# 2. 개체 스키마 정의

LLM이 추출한 결과를 프로그램에서 안정적으로 다루려면 **반환 형식 자체를 스키마로 제한**하는 것이 유리함.

## 2-1. 개체 하나의 스키마 정의

```python
from typing import Literal, Optional
from pydantic import BaseModel, Field

# 개체 하나의 출력 구조
class Entity(BaseModel):
    # 원문에 나온 개체 표현
    name: str = Field(
        description='개체 이름(원문에 나온 그대로)'
    )

    # 허용할 개체 유형
    type: Literal[
        'Compound',
        'Gene',
        'Disease',
        'Symptom',
        'PharmacologicClass',
        'Other'
    ] = Field(
        description='개체 유형'
    )

    # type이 Other일 때 실제 유형을 추가 저장
    other_type: Optional[str] = Field(
        default=None,
        description='type이 Other일 때 실제 개체 유형'
    )

    # 모델이 반환하는 추출 신뢰도 값
    confidence: float = Field(
        description='개체 추출에 대한 모델의 신뢰도 점수'
    )


# 직접 Entity를 만들어 구조 확인
entity = Entity(
    name='omeprazole',
    type='Compound',
    confidence=0.9
)

print(entity)
print(entity.name)
print(entity.type)
print(entity.other_type)
print(entity.confidence)
```

### 결과

```text
name='omeprazole' type='Compound' other_type=None confidence=0.9
omeprazole
Compound
None
0.9
```

> **보완**: LLM이 직접 `confidence`를 생성하는 경우 이 값은 모델이 작성한 값일 뿐, 통계적으로 보정된 확률이라고 보기는 어려움.

## 2-2. 개체 목록 스키마 정의

개체 하나를 나타내는 `Entity`를 여러 개 담기 위해 한 단계 감싼 `EntityList`를 정의함.

```python
# 개체 여러 개를 담는 목록 스키마
class EntityList(BaseModel):
    entities: list[Entity]


# 예시 개체 생성
entity = Entity(
    name='omeprazole',
    type='Compound',
    confidence=0.9
)

# Entity를 리스트에 담아 EntityList 생성
entity_list = EntityList(
    entities=[entity]
)

# 결과 확인
print(entity_list)
print(entity_list.entities)
print(len(entity_list.entities))
```

### 결과

```text
entities=[Entity(name='omeprazole', type='Compound', other_type=None, confidence=0.9)]
[Entity(name='omeprazole', type='Compound', other_type=None, confidence=0.9)]
1
```

# 4. 정리와 집계

## 4-1. 중복 제거

같은 `(이름, 유형)` 조합이 여러 번 등장하면 하나만 남김.

```python
# 이미 본 (이름, 유형) 조합 저장
seen = set()

# 중복을 제거한 결과
deduped = []

# 개체를 하나씩 확인
for e in lv1_entities:
    key = (e['name'], e['type'])

    if key not in seen:
        seen.add(key)
        deduped.append(e)

print(deduped)
print(len(deduped))
```

## 4-2. 유형별 개수 세기

`Counter`를 사용하면 각 개체 유형이 몇 번 등장했는지 바로 집계할 수 있음.

```python
from collections import Counter

# 각 개체의 type만 모아 유형별 개수 세기
type_counts = Counter(
    e['type']
    for e in lv1_entities
)

print(type_counts)

# Gene 유형 개수 확인
print(type_counts['Gene'])
```

# 5. LLM으로 개체 추출하기

앞에서 정의한 `Entity` / `EntityList` 스키마를 LLM의 구조화 출력에 연결해, 원문에서 개체 목록을 직접 받음.

> 1절의 Span·BIO는 NER의 표현 방식을 이해하기 위한 과정이고, 아래 LLM 호출에서 직접 BIO 태그를 전달하는 것은 아님.

## 5-1. 구조화 출력 추출기 만들기

```python
from langchain_core.prompts import ChatPromptTemplate


def extract_entities(text):
    # 사용할 LLM 생성
    model = make_model()

    # LLM 출력을 EntityList 구조로 제한
    structured_model = model.with_structured_output(EntityList)

    # system 지시문 + 사용자 원문으로 프롬프트 구성
    prompt = ChatPromptTemplate.from_messages([
        ('system', EXTRACT_SYSTEM),
        ('user', '{원문}')
    ])

    # 프롬프트와 모델 연결
    chain = prompt | structured_model

    # 실제 원문을 넣어 모델 호출
    result = chain.invoke({
        '원문': text
    })

    # EntityList 안의 개체 목록만 반환
    return result.entities


# 앞에서 사용한 문장을 모델로 분석
ents = extract_entities(sentence)

# 추출된 개체의 이름만 리스트로 저장
names = [
    entity.name
    for entity in ents
]

print(ents)
print(names)
```

### 결과 예시

```text
[Entity(name='ATP', type='Compound', other_type=None, confidence=0.99),
 Entity(name='adenine', type='Compound', other_type=None, confidence=0.99),
 Entity(name='uric acid', type='Compound', other_type=None, confidence=0.99),
 Entity(name='gout', type='Disease', other_type=None, confidence=0.99)]
['ATP', 'adenine', 'uric acid', 'gout']
```

> LLM 출력은 실행 시점과 모델 설정에 따라 달라질 수 있으므로 위 결과는 **실행 예시**로 보는 것이 적절함.

## 핵심 정리

- **Span**: 개체가 원문에서 어느 문자 구간에 있는지 `start`, `end`로 표현.
- **BIO**: 토큰마다 `B-유형`, `I-유형`, `O`를 붙여 개체 경계를 표현.
- **NER 모델**: 사람이 직접 태그하지 않고 모델이 개체·유형·위치를 예측.
- **Pydantic 스키마**: LLM의 출력을 정해진 `Entity` 구조로 제한.
- **검증**: 허용 유형 확인 → 원문 존재 여부 확인 → 필요 시 중복 제거.
- **집계**: `Counter` 등으로 개체 유형의 분포 확인.
- **LLM 구조화 출력**: `with_structured_output(EntityList)`로 바로 프로그램이 다룰 수 있는 개체 목록을 반환.
