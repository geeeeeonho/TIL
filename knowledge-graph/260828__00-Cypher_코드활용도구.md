# Cypher 코드 활용 - 친구 추천·경로 진단 프로그램

SNS 친구 네트워크를 기준으로 Cypher를 Python 함수와 연결해 **친구 조회 → 친구 추천 → 리포트 생성 → 최단 경로 진단 → JSON 저장** 흐름으로 정리.

`FRIEND` 관계는 방향이 있게 저장되어 있지만, 조회에서는 `-[:FRIEND]-` 형태를 사용해 방향을 구분하지 않고 친구 관계로 처리.

## 1. 친구 추천 프로그램

핵심 흐름.

```text
사용자
  ↓
1홉 친구 조회
  ↓
친구의 친구(2홉) 탐색
  ↓
본인 + 기존 친구 제외
  ↓
추천 후보 반환
```

### 1-1. 직접 친구 조회 - `friends()`

특정 사용자의 **1홉 친구**를 찾고 이름순 리스트로 반환.

```python
def friends(name):
    """
    특정 Person을 찾고 FRIEND 관계를 방향 없이 탐색.
    직접 연결된 친구 이름을 정렬된 리스트로 반환.
    """

    friends_list = run_cypher("""
    MATCH (a:Person {name: $name})-[:FRIEND]-(b:Person)
    RETURN b.name AS n
    """, name=name)

    return sorted([r['n'] for r in friends_list])


print(friends('아리'))
```

**결과**

```python
['보미', '크리스']
```

- `-[:FRIEND]-` : 관계 방향을 구분하지 않고 탐색
- `$name` : Python에서 전달한 파라미터
- `sorted()` : 이름순 정렬

### 1-2. 2홉 친구 추천 - `recommend()`

친구의 친구까지 탐색한 뒤 **본인과 이미 직접 친구인 사람을 제외**해 추천 후보를 반환.

```python
def recommend(name):
    """
    친구의 친구까지 2홉 탐색.
    본인과 기존 친구를 제외한 추천 후보를 정렬된 리스트로 반환.
    """

    friends_list = run_cypher("""
    MATCH (a:Person {name: $name})
          -[:FRIEND]-(friend:Person)
          -[:FRIEND]-(fof:Person)

    WHERE fof <> a
      AND NOT (a)-[:FRIEND]-(fof)

    WITH DISTINCT fof.name AS n
    RETURN n
    """, name=name)

    return sorted([r['n'] for r in friends_list])


print(recommend('아리'))
```

**결과**

```python
['다나', '은수']
```

핵심 조건.

```text
fof <> a
→ 자기 자신 제외

NOT (a)-[:FRIEND]-(fof)
→ 이미 직접 친구인 사람 제외

DISTINCT
→ 여러 경로로 같은 사람이 발견되어도 한 번만 반환
```

### 1-3. 여러 사람의 추천 리포트 생성

`friends()`와 `recommend()` 결과를 사람별 사전으로 묶음.

```python
report = {}

for person in ['아리', '보미', '크리스']:
    friends_list = friends(person)
    recommend_list = recommend(person)

    report[person] = {
        "friends": friends_list,
        "recommend": recommend_list
    }


display(report)
```

**결과**

```python
{
    '아리': {
        'friends': ['보미', '크리스'],
        'recommend': ['다나', '은수']
    },
    '보미': {
        'friends': ['다나', '아리', '크리스'],
        'recommend': ['은수', '피니']
    },
    '크리스': {
        'friends': ['다나', '보미', '아리', '은수'],
        'recommend': ['가을', '피니']
    }
}
```

## 2. 경로 진단 리포트

두 사람 사이의 연결 여부와 최단 경로를 확인하는 기능.

### 2-1. 연결 상태 진단 - `diagnose()`

확인 항목.

- 연결 여부
- 최단 경로의 홉 수
- 경로에 포함된 사람
- 경로의 모든 사람이 서울인지 여부

```python
def diagnose(a, b):
    about_connect = run_cypher("""
    MATCH
      (a:Person {name: $name1}),
      (b:Person {name: $name2})

    OPTIONAL MATCH p = shortestPath(
      (a)-[:FRIEND*]-(b)
    )

    RETURN
      p IS NOT NULL AS connected,
      length(p) AS hops,
      [n IN nodes(p) | n.name] AS path,
      all(n IN nodes(p) WHERE n.city = '서울') AS all_seoul
    """, name1=a, name2=b)

    return about_connect[0]


print("아리, 가을\n", diagnose('아리', '가을'))
print("아리, 달이\n", diagnose('아리', '달이'))
```

**결과**

```text
아리, 가을
{'connected': True, 'hops': 3, 'path': ['아리', '크리스', '은수', '가을'], 'all_seoul': False}

아리, 달이
{'connected': False, 'hops': None, 'path': None, 'all_seoul': None}
```

주요 문법.

```text
shortestPath(...)
→ 두 사람 사이의 최단 경로 탐색

OPTIONAL MATCH
→ 경로가 없어도 결과 행 유지

p IS NOT NULL
→ 경로 존재 여부를 True / False로 변환

length(p)
→ 경로의 관계 개수 = 홉 수

nodes(p)
→ 경로에 포함된 노드 목록

all(...)
→ 경로의 모든 노드가 조건을 만족하는지 검사
```

연결되지 않은 경우 `OPTIONAL MATCH` 때문에 행 자체는 유지되고, 경로 관련 값은 `None`으로 반환.

### 2-2. 여러 경로 진단 후 JSON 저장

여러 사람 쌍을 `diagnose()`로 검사하고 필요한 값만 리스트로 만든 뒤 JSON 파일로 저장.

```python
import json
import os


os.makedirs("output", exist_ok=True)

path_report = []

for match in [('아리', '가을'), ('아리', '피니'), ('아리', '달이')]:
    matched = diagnose(match[0], match[1])

    append_content = {
        "a": match[0],
        "b": match[1],
        "connected": matched['connected'],
        "hops": matched['hops'],
        "path": matched['path']
    }

    path_report.append(append_content)


with open("output/sns_path_report.json", "w", encoding="utf-8") as f:
    json.dump(path_report, f, ensure_ascii=False, indent=2)


display(path_report)
```

**결과**

```python
[
    {
        'a': '아리',
        'b': '가을',
        'connected': True,
        'hops': 3,
        'path': ['아리', '크리스', '은수', '가을']
    },
    {
        'a': '아리',
        'b': '피니',
        'connected': True,
        'hops': 3,
        'path': ['아리', '크리스', '다나', '피니']
    },
    {
        'a': '아리',
        'b': '달이',
        'connected': False,
        'hops': None,
        'path': None
    }
]
```

## 전체 프로그램 흐름

```text
Neo4j SNS 그래프
      │
      ├─ friends(name)
      │    └─ 1홉 직접 친구 조회
      │
      ├─ recommend(name)
      │    └─ 2홉 탐색 → 본인·기존 친구 제외
      │
      └─ diagnose(a, b)
           └─ shortestPath()
                ├─ 연결 여부
                ├─ 홉 수
                ├─ 경로
                └─ 경로 속성 조건 확인

Python
  ├─ 추천 결과를 사전으로 구성
  └─ 진단 결과를 리스트로 구성 → JSON 저장
```

## 핵심 정리

| 목적 | 핵심 문법 | 의미 |
|---|---|---|
| 방향 없는 친구 탐색 | `-[:FRIEND]-` | 관계 방향을 무시하고 연결된 사람 탐색 |
| 2홉 탐색 | `-[:FRIEND]-()-[:FRIEND]-` | 친구의 친구 탐색 |
| 본인 제외 | `fof <> a` | 자기 자신을 후보에서 제거 |
| 기존 친구 제외 | `NOT (a)-[:FRIEND]-(fof)` | 이미 친구인 사람 제거 |
| 중복 제거 | `DISTINCT` | 같은 후보가 여러 경로로 나와도 한 번만 반환 |
| 최단 경로 | `shortestPath()` | 두 노드 사이의 가장 짧은 경로 탐색 |
| 경로가 없어도 행 유지 | `OPTIONAL MATCH` | 연결되지 않은 경우도 결과 반환 |
| 홉 수 | `length(p)` | 경로에 포함된 관계 개수 |
| 경로 노드 | `nodes(p)` | 경로에 포함된 노드 목록 |
| 전체 조건 검사 | `all(...)` | 경로의 모든 노드가 조건을 만족하는지 확인 |
| JSON 저장 | `json.dump()` | Python 객체를 JSON 파일로 저장 |
