# 추출 품질 지표와 평가 — 압축 정리

## 1. 전체 평가 흐름

```text
LLM 트리플 추출
   ├─ 스키마 검사 ───────→ 스키마 준수율
   ├─ 근거 원문 검사 ────→ 근거 원문 일치율
   │
   └─ 두 검사 통과 결과 ─→ 표본 추출 → 사람 판정 → 샘플 정밀도

원문 → 골드셋 구축 ──────→ 추출 결과와 비교 → Precision / Recall / F1
```

- **스키마 검사**: 관계와 개체 타입이 온톨로지 규칙에 맞는지 확인
- **근거 원문 검사**: `evidence`가 실제 원문에 그대로 존재하는지 확인
- **샘플 정밀도**: 통과한 트리플의 의미가 실제로 맞는지 사람이 표본 평가
- **골드 평가**: 정답 트리플 전체와 비교해 잘못 뽑은 관계와 놓친 관계까지 측정

> 스키마 준수, 원문 인용, 관계의 의미는 서로 다른 검사다.

---

## 2. 핵심 품질 지표

| 지표 | 확인하는 질문 | 계산 |
|---|---|---|
| **스키마 준수율** | 허용 관계와 타입 조합을 지켰는가? | 스키마 통과 행 / 전체 추출 행 |
| **근거 원문 일치율** | evidence가 출처 원문에 그대로 있는가? | 원문 일치 행 / 전체 추출 행 |
| **샘플 정밀도** | 추출 관계의 의미가 실제로 맞는가? | 사람 판정 1점 수 / 판정 표본 수 |
| **Precision** | 추출한 것 중 정답은 얼마나 되는가? | TP / (TP + FP) |
| **Recall** | 정답 중 얼마나 찾아냈는가? | TP / (TP + FN) |
| **F1** | Precision과 Recall을 함께 보면 어떤가? | 2TP / (2TP + FP + FN) |

### 스키마 준수율

관계별로 허용되는 **주어 타입 → 관계 → 목적어 타입**을 검사한다.

예:

```text
Drug → CONTAINS → Ingredient
Drug → TREATS → Symptom
Drug → HAS_SIDE_EFFECT → Symptom
Drug → CAUTION_FOR → RiskGroup
Drug → INTERACTS_WITH → Drug | Ingredient
```

검사 순서:

1. 허용된 관계인지 확인
2. 관계에 맞는 주어 타입인지 확인
3. 관계에 맞는 목적어 타입인지 확인

스키마를 통과해도 의미가 맞다는 뜻은 아니다. 부정·예정 문장도 타입만 맞으면 통과할 수 있다.

### 근거 원문 일치율

`evidence`가 해당 `source_doc_id`의 원문에 **문자열 그대로 포함되는지** 검사한다.

```text
근거 없음       → evidence가 비어 있음
원문 일치       → evidence가 원문에 그대로 존재
원문 확인 필요  → 요약·변형·잘못된 출처 등으로 그대로 찾을 수 없음
```

스키마 기각 여부와 별개로 전체 추출을 대상으로 계산한다.

> evidence가 원문에 있다고 해서 관계의 의미까지 맞는 것은 아니다.

### 샘플 정밀도

스키마와 근거 검사를 모두 통과한 **사용 후보**에서 표본을 뽑고 사람이 원문을 확인한다.

```text
맞는 관계 → 1
틀린 관계 → 0
```

예를 들어 원문이 `빌릴 예정`, `빌리지 않았다`인데 `빌림`으로 추출했다면 evidence는 원문과 일치해도 의미 판정은 0점이다.

## 3. 골드셋 구축

**골드셋 = 원문에서 반드시 존재해야 하는 정답 트리플 목록**

샘플 정밀도는 이미 추출된 관계만 평가하므로 **놓친 관계(FN)**를 찾을 수 없다. Recall을 계산하려면 골드셋이 필요하다.

### 구축 순서

1. 온톨로지와 허용 관계 정의
2. 포함·제외 기준 정의
3. 평가할 문서 선정
4. 추출 결과를 보지 않고 원문 전체 검토
5. 모든 정답 트리플을 출처·근거와 함께 기록
6. 관계가 0건인 문장도 검토 완료로 기록
7. LLM으로 초안을 만들 수 있지만 최종 검수는 사람이 수행

기본 형태:

```text
subject
relation
object
source_doc_id
evidence
```

중요한 점:

- 나열된 대상은 각각 별도 관계로 기록
- 부정·예정 등 제외 기준을 미리 정의
- 추출 결과에 맞춰 골드를 수정하지 않음
- 빠진 관계가 없는지 원문 전체를 다시 확인

---

## 4. TP · FP · FN과 완전일치 평가

비교 단위는 보통 다음 트리플 키를 사용한다.

```python
(subject, relation, object)
```

중복 추출은 한 번만 세기 위해 `set`으로 변환한다.

| 구분 | 의미 |
|---|---|
| **TP** | 추출했고 골드에도 있음 |
| **FP** | 추출했지만 골드에는 없음 |
| **FN** | 골드에는 있지만 추출하지 못함 |
| **TN** | 관계 후보 전체가 정해져 있지 않으면 보통 집계하지 않음 |

집합 기준으로 보면:

```text
TP = 추출 ∩ 골드
FP = 추출 - 골드
FN = 골드 - 추출
```

완전일치는 세 문자열이 모두 같아야 같은 관계로 본다. 따라서 괄호, 대소문자, 이름 표기 차이도 FP와 FN을 만들 수 있다. 의미 오류와 표기 차이는 원문을 다시 읽어 구분한다.

---

## 5. Precision · Recall · F1 해석

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2TP / (2TP + FP + FN)
```

- **Precision 낮음** → 잘못 뽑은 관계(FP)가 많음
- **Recall 낮음** → 정답 관계(FN)를 많이 놓침
- **F1 낮음** → 둘 중 하나 또는 둘 다 낮음

오답만 삭제하면 Precision은 올라갈 수 있지만, 놓친 정답을 새로 추출하지 않으면 Recall은 올라가지 않는다.

또한 맞는 트리플이라도 evidence 오류나 타입 오류로 필터링되면 최종 사용 결과에서는 빠지므로 Recall이 낮아질 수 있다.

## 6. 지표가 낮을 때 교정 방향

| 문제 | 먼저 확인 | 교정 방향 |
|---|---|---|
| 스키마 준수율 ↓ | 허용하지 않은 관계·타입 | `Literal`, `enum`, 구조화 출력으로 값 제한 |
| 스키마 준수율 ↓ | 잘못된 타입 조합 | 관계별 `주어 타입 → 목적어 타입` 검사 |
| 원문 일치율 ↓ | evidence 누락·요약 | 원문의 연속 구절을 수정 없이 복사하도록 지시 |
| 원문 일치율 ↓ | 잘못된 출처 연결 | `source_doc_id`를 코드에서 연결하고 해당 원문과 대조 |
| 샘플 정밀도 ↓ | 부정·예정·문맥 오해 | 포함·제외 조건과 잘못된 예시를 프롬프트에 추가 |
| Precision ↓ | FP | 잘못 뽑은 사례를 분석해 제외 규칙 보완 |
| Recall ↓ | FN | 나열 대상·앞뒤 문맥까지 확인하도록 추출 지시 보완 |

## 7. 실습 예시로 보는 차이

도서관 예시의 전체 추출은 8건이다.

```text
스키마 통과       : 5 / 8 = 62.5%
근거 원문 일치    : 7 / 8 = 87.5%
두 검사 통과 후보 : 4건
의미 판정         : 2 / 4 = 50%
```

골드 6관계와 스키마 통과 추출 5관계를 비교하면:

```text
TP = 3
FP = 2
FN = 3

Precision = 3 / 5 = 60%
Recall    = 3 / 6 = 50%
F1        = 6 / 11 ≈ 0.5455
```

즉, **형식을 잘 지키고 원문을 정확히 인용하는 것과 올바른 관계를 빠짐없이 추출하는 것은 별개의 품질 문제**다.

## 8. 최종 평가 프로세스

```text
1. 온톨로지·스키마 정의
        ↓
2. LLM 트리플 추출
        ↓
3. 스키마 준수율 계산 ─────────┐
4. 근거 원문 일치율 계산 ──────┤ 자동 검사
        ↓                       │
5. 두 검사 통과 후보 생성 ─────┘
        ↓
6. 후보 표본 → 사람 의미 판정 → 샘플 정밀도

원문 전체 검토
        ↓
7. 골드셋 구축
        ↓
8. 추출 ↔ 골드 완전일치 비교
        ↓
9. TP / FP / FN → Precision / Recall / F1
        ↓
10. FP·FN 원문 분석 → 프롬프트·스키마·추출 방식 개선 → 재평가
```

### 핵심 정리

- **스키마 준수율**: 형식을 지켰는지
- **근거 원문 일치율**: 인용이 원문 그대로인지
- **샘플 정밀도**: 관계 의미가 맞는지 표본으로 확인
- **Precision**: 뽑은 것 중 얼마나 맞았는지
- **Recall**: 정답을 얼마나 놓치지 않았는지
- **F1**: Precision과 Recall을 함께 평가
- **골드셋**: Recall까지 측정하기 위한 정답 기준

평가는 점수만 보는 것이 아니라 **기각 행, FP, FN을 원문으로 다시 확인하고 추출 규칙을 개선하는 과정**까지 포함한다.
