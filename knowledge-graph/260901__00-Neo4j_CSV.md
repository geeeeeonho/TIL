## 2. CP949 CSV의 헤더 확인

국내 공공데이터에서 자주 쓰이는 `CP949` 인코딩으로 CSV를 읽고 머리글만 확인한다.

**코드**

```python
import pandas as pd

# CSV 파일을 읽어 헤더만 리스트 형태로 반환
def read_headers(path):
    df = pd.read_csv(path, encoding='cp949')

headers = read_headers('data/seoul_metro_transfer_cp949.csv')
print(headers)
```

**결과**


## 3. Station의 키 제약조건 생성

`Station.name`을 노드 키로 지정해 역명이 비어 있지 않고 중복되지 않도록 제한한다.

**코드**

```python
run_cypher("""
// station_name이라는 이름의 제약조건 생성 - 없을 때만 생성
CREATE CONSTRAINT station_name IF NOT EXISTS

// Station 노드의 name을 키로 사용
FOR (s:Station)
REQUIRE s.name IS NODE KEY
""")

# 생성한 제약조건 확인
print(run_cypher("""SHOW CONSTRAINTS"""))
```

**결과**

```python
[{
    'id': 19,
    'name': 'station_name',
    'type': 'NODE_KEY',
    'entityType': 'NODE',
    'labelsOrTypes': ['Station'],
    'properties': ['name'],
    'enforcedLabel': None,
    'ownedIndex': 'station_name',
    'propertyType': None
}]
```

> `NODE KEY`는 해당 속성의 **존재성과 유일성**을 함께 보장한다.

## 4. 적재 전 오염 행 확인

CSV를 바로 적재하기 전에 전체 행 수와 역명이 비어 있는 행 수를 확인한다.

**코드**

```python
check_query = """
// 서버에서 CSV 파일 읽기
LOAD CSV WITH HEADERS FROM $path AS row

RETURN
    // 전체 행 수 세기
    count(*) AS 전체행,

    // 역명이 null, 빈 문자열, 공백뿐인 행 세기
    count(
        CASE
            WHEN trim(coalesce(row['역명'], '')) = ''
            THEN 1
        END
    ) AS 빈이름
"""

check_all = run_cypher(
    check_query,
    path='file:///seoul_metro_transfer_utf8.csv'
)

check = check_all[0]

print(check_all)
print(check)
```

**결과**

```python
[{'전체행': 73, '빈이름': 0}]
{'전체행': 73, '빈이름': 0}
```

- 전체 데이터: 73행
- 역명이 비어 있는 행: 0행

따라서 `Station.name`을 기준으로 적재해도 문제가 없는 상태다.

## 5. CSV 데이터를 Neo4j에 적재

`LOAD CSV`로 파일을 한 행씩 읽고, 역명을 기준으로 `Station` 노드를 생성한다.

**코드**

```python
# CSV 데이터를 Neo4j에 적재하는 Cypher
contain_csv = """
// 머리글이 있는 CSV 파일을 한 행씩 row에 담아 읽기
LOAD CSV WITH HEADERS FROM $path AS row

// 역명을 기준으로 Station 노드를 찾거나 생성
MERGE (s:Station {name: row['역명']})

// CSV의 문자열 숫자를 정수로 변환해 노드 속성에 저장
SET s.weekday = toInteger(row['평일(일평균)']),
    s.saturday = toInteger(row['토요일']),
    s.sunday = toInteger(row['일요일'])
"""

# CSV 데이터를 그래프에 적재
run_cypher(
    contain_csv,
    path='file:///seoul_metro_transfer_utf8.csv'
)

# 생성된 Station 노드 수 확인
rows = run_cypher("""
MATCH (s:Station)
RETURN count(s) AS n
""")

n_station = rows[0]['n']

print(rows)
print(n_station)
```

**결과**

```python
[{'n': 73}]
73
```

### 핵심

```text
LOAD CSV   -> CSV 행 읽기
MERGE      -> 같은 역명이 있으면 재사용, 없으면 생성
SET        -> 요일별 환승인원 속성 저장
```

## 6. 재적재로 멱등성 확인

`MERGE + SET` 구조에서는 같은 CSV를 다시 실행해도 동일한 역 노드가 중복 생성되지 않는다. 또한 `SET`이 CSV 값으로 속성을 다시 덮어쓰기 때문에 잘못 변경된 값을 원본 데이터 기준으로 복구할 수 있다.

### 6-1. 일부러 데이터 변경

**코드**

```python
# 모든 역의 평일 인원을 0으로 변경
run_cypher("MATCH (s:Station) SET s.weekday = 0")

broken = run_cypher(
    "MATCH (s:Station) "
    "RETURN count(s) AS n, sum(s.weekday) AS w"
)[0]

print(
    f"평일 인원 합계를 {broken['w']} 으로 바꿨습니다"
    f"(대상 {broken['n']}개)."
)
```

**결과**

```text
평일 인원 합계를 0 으로 바꿨습니다(대상 73개).
```

### 6-2. 같은 CSV 다시 적재

**코드**

```python
contain_csv = """
LOAD CSV WITH HEADERS FROM $path AS row

MERGE (s:Station {name: row['역명']})

SET s.weekday = toInteger(row['평일(일평균)']),
    s.saturday = toInteger(row['토요일']),
    s.sunday = toInteger(row['일요일'])
"""

run_cypher(
    contain_csv,
    path='file:///seoul_metro_transfer_utf8.csv'
)

rows = run_cypher("""
MATCH (s:Station)
RETURN count(s) AS n
""")

n_again = rows[0]['n']
print('적재 성공, 개수 확인:', n_again)
```

**결과**

```text
적재 성공, 개수 확인: 73
```

노드 수는 그대로 73개이며, 기존 `Station`을 재사용해 CSV의 값으로 다시 채운다.

## 7. 파라미터를 이용한 조회

Cypher 문자열에 값을 직접 넣기보다 `$파라미터`를 사용하면 쿼리를 재사용하기 쉽고 입력값과 쿼리를 분리할 수 있다.

### 7-1. 기준 이상인 역 개수 조회

**코드**

```python
busy_query = """
// weekday가 특정 값 이상인 Station 찾기
MATCH (s:Station)
WHERE s.weekday >= $threshold

// 조건에 맞는 Station 수 세기
RETURN count(s) AS n
"""

n_busy = run_cypher(
    busy_query,
    threshold=100000
)[0]['n']

print('평일 환승인원이 10만 이상인 역:', n_busy)
```

**결과**

```text
평일 환승인원이 10만 이상인 역: 12
```

**코드**

```python
sat_query = """
```

## 9. Python 리스트를 UNWIND로 소량 적재

파일 전체를 읽을 필요가 없는 소량 데이터는 Python 리스트를 파라미터로 넘긴 뒤 `UNWIND`로 한 행씩 펼쳐 처리할 수 있다.

**코드**

```python
# 추가할 데이터
extra = [
    {'name': '을지로입구'},
    {'name': '종각'}
]

# Python 리스트를 한 행씩 펼쳐 Station으로 적재
extra_q = """
UNWIND $rows AS row
MERGE (s:Station {name: row['name']})
"""

# extra 리스트를 $rows 파라미터로 전달
run_cypher(extra_q, rows=extra)

# 추가 적재 후 전체 Station 수 확인
rows = run_cypher("""
MATCH (s:Station)
RETURN count(s) AS n
""")

n_after = rows[0]['n']
print(n_after)
```

**결과**

```text
75
```

### `LOAD CSV`와 `UNWIND`의 역할

```text
LOAD CSV -> 파일 데이터를 직접 읽어 대량 적재할 때
UNWIND   -> Python 리스트처럼 이미 메모리에 있는 데이터를 행 단위로 처리할 때
```

## 10. 배치 트랜잭션으로 파생 값 채우기

많은 행을 한 번의 큰 트랜잭션으로 처리하지 않고 일정한 행 수로 나눠 처리한다. 여기서는 요일별 환승인원을 합한 `total` 속성을 만든다.

**코드**

```python
total_q = """
// CSV 파일을 한 행씩 row로 읽기
LOAD CSV WITH HEADERS
FROM 'file:///seoul_metro_transfer_utf8.csv'
AS row

// 바깥의 row를 받아 한 행씩 처리
CALL (row) {

    // CSV의 역명으로 이미 존재하는 Station 찾기
    MATCH (s:Station {name: row['역명']})

    // 세 요일의 값을 정수로 변환한 뒤 합계를 total에 저장
    SET s.total =
        toInteger(row['평일(일평균)']) +
        toInteger(row['토요일']) +
        toInteger(row['일요일'])
}

// 20행씩 나눠 트랜잭션 처리
IN TRANSACTIONS OF 20 ROWS
"""

run_cypher(total_q)

# total 값이 채워진 Station 수 확인
rows = run_cypher("""
MATCH (s:Station)
WHERE s.total IS NOT NULL
RETURN count(s) AS n
""")

n_total = rows[0]['n']
print(n_total)
```

**결과**

```text
73
```

앞에서 Python 리스트로 추가한 2개 역에는 요일별 환승인원 데이터가 없으므로, CSV에 들어 있던 73개 역에만 `total`이 채워진다.

## 11. 자료의 기준일을 날짜 노드로 분리

조사 기준일처럼 여러 역이 함께 공유하는 값은 각 역의 속성으로 반복 저장할 수도 있지만, 별도 노드로 만들면 역과 날짜의 관계를 그래프로 표현할 수 있다.

```text
(:Station)-[:SURVEYED_ON]->(:SurveyDay)
```

**코드**

```python
survey_q = """
// 날짜 자료형으로 기준일 노드를 찾거나 생성
MERGE (d:SurveyDay {date: date('2025-11-30')})

// 날짜 노드 d를 다음 MATCH까지 전달
WITH d

// 인원 데이터가 들어 있는 Station만 찾기
MATCH (s:Station)
WHERE s.weekday IS NOT NULL

// Station -> SurveyDay 관계를 찾거나 생성
MERGE (s)-[:SURVEYED_ON]->(d)
"""

run_cypher(survey_q)

# SurveyDay 노드 수 확인
day_rows = run_cypher("""
MATCH (d:SurveyDay)
RETURN count(d) AS n
""")
n_day = day_rows[0]['n']

# SURVEYED_ON 관계 수 확인
surveyed_rows = run_cypher("""
MATCH ()-[r:SURVEYED_ON]->()
RETURN count(r) AS n
""")
n_surveyed = surveyed_rows[0]['n']

print('SurveyDay 노드 수:', n_day)
print('SURVEYED_ON 관계 수:', n_surveyed)
```

**결과**

```text
SurveyDay 노드 수: 1
SURVEYED_ON 관계 수: 73
```

`weekday`가 있는 원본 CSV의 73개 역만 조사일과 연결된다.

## 12. 질문에서 노드와 관계 후보 뽑기

현재 그래프의 구조를 기준으로 자연어 질문에 등장하는 대상을 노드와 관계에 대응시켜 본다.

**코드**

```python
# 질문
# 1) 왕십리의 평일 환승인원은 몇 명인가
# 2) 이 자료는 언제를 기준으로 조사한 것인가
# 3) 어느 역들이 같은 날 조사됐나

# 질문의 주요 명사에서 노드 후보 추출
# -> 역과 조사 기준일이 노드 후보
node_labels = ['Station', 'SurveyDay']

# 질문의 의미에서 관계 타입 후보 추출
# -> 역이 특정 날짜에 조사되었다는 관계
rel_types = ['SURVEYED_ON']
```

### 현재 그래프 구조

```text
Station
  - name
  - weekday
  - saturday
  - sunday
  - total

SurveyDay
  - date

Station -[:SURVEYED_ON]-> SurveyDay
```

이 구조를 기준으로 질문을 해석하면 다음처럼 연결할 수 있다.

```text
"왕십리의 평일 환승인원" -> Station.name + Station.weekday
"언제를 기준으로 조사"   -> SurveyDay.date
"같은 날 조사된 역"      -> SURVEYED_ON 관계
```

## 전체 흐름 요약

```text
CSV 확인
  -> 헤더 확인
  -> 데이터 오염 검사
  -> 키 제약조건 생성
  -> LOAD CSV + MERGE + SET 적재
  -> 재적재로 멱등성 확인
  -> 파라미터 조회
  -> APOC 통계 확인
  -> UNWIND 소량 적재
  -> IN TRANSACTIONS 배치 처리
  -> 공유 날짜를 SurveyDay 노드로 분리
  -> 자연어 질문을 노드·관계 구조에 대응
```

### 핵심 구문

| 목적 | 핵심 구문 |
|---|---|
| CSV 읽기 | `LOAD CSV WITH HEADERS` |
| 중복 없이 노드 생성 | `MERGE` |
| 속성 저장·갱신 | `SET` |
| 문자열 숫자 변환 | `toInteger()` |
| 외부 값 전달 | `$parameter` |
| Python 리스트 펼치기 | `UNWIND` |
| 배치 처리 | `IN TRANSACTIONS OF n ROWS` |
| 날짜 자료형 생성 | `date()` |
| 공유 정보 연결 | `(:Station)-[:SURVEYED_ON]->(:SurveyDay)` |
