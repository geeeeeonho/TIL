# IE · NER · LLM 엔티티 추출 정리

## 1. GraphRAG와 정보 추출(IE)

일반적인 벡터 RAG는 **청크 자체의 의미 유사도**를 중심으로 검색한다. 반면 GraphRAG는 문서에서 추출한 **엔티티와 관계를 그래프로 연결**해, 서로 떨어진 청크의 정보도 관계를 따라 탐색할 수 있다.

- 한 청크 또는 서로 독립적인 몇 개 청크만으로 답을 찾기 쉬움 → **벡터 RAG가 적합**
- 여러 청크에 흩어진 정보의 **연결 관계**를 따라야 함 → **GraphRAG가 유리**

GraphRAG를 만들려면 먼저 비정형 문서에서 그래프에 넣을 지식을 뽑아야 한다. 이 작업이 **정보 추출(IE, Information Extraction)** 이다.

> **정보 추출(IE)**: 비정형 텍스트를 엔티티·관계처럼 다룰 수 있는 정형 지식으로 바꾸는 작업

예시:

```text
"김민준이 분석 대시보드 개편을 이끌었다"

→ (김민준)-[이끌었다]->(분석 대시보드)
```

---

## 2. IE의 전체 흐름

정보 추출은 다음 네 단계로 정리할 수 있다.

```text
[1. 개체 인식]
김민준 · pandas 같은 이름 찾기
        ↓
[2. 스키마 설계]
사용할 엔티티 타입과 관계 타입 정의
        ↓
[3. 관계 추출]
(김민준)-[이끌었다]->(대시보드) 형태로 연결
        ↓
[4. 엔티티 정규화]
pandas · 판다스처럼 같은 대상을 하나의 엔티티로 통합
```

| 단계 | 핵심 작업 | 예시 |
|---|---|---|
| 1. 개체 인식 | 문장에서 이름이 있는 대상을 찾고 타입 부여 | `김민준`, `pandas` |
| 2. 스키마 설계 | 어떤 엔티티 타입과 관계만 사용할지 정의 | `Person`, `Tool`, `LEADS` 등 |
| 3. 관계 추출 | 엔티티 사이의 관계를 추출 | `(김민준)-[이끌었다]->(대시보드)` |
| 4. 엔티티 정규화 | 표기가 달라도 같은 대상을 하나로 통합 | `pandas` = `판다스` |

핵심은 **이름 찾기 → 구조 정하기 → 관계 연결 → 중복 통합**의 순서다.

---

## 3. NER: 개체명 인식

**NER(Named Entity Recognition)** 은 문장에서 **개체명을 찾아 타입을 붙이는 작업**이다.

> **개체명**: 인물·기관·제품처럼 고유한 이름을 가진 대상

NER의 기본 흐름:

```text
이름 후보 찾기
   ↓
개체가 아닌 단어 제외
   ↓
찾은 이름마다 타입 부여
   ↓
관계 추출에서 주어·목적어 후보로 사용
```

즉, NER은 그래프를 직접 완성하는 단계가 아니라 **그래프의 노드 후보를 뽑는 단계**에 가깝다.

---

## 4. BIO 태깅

전통적인 NER에서는 문장을 토큰으로 나눈 뒤 각 토큰에 태그를 붙여 **개체의 시작과 이어짐**을 표현한다.

| 태그 | 의미 |
|---|---|
| `B` | Begin. 개체의 시작 |
| `I` | Inside. 앞 개체의 이어짐 |
| `O` | Outside. 개체가 아님 |

태그가 붙은 토큰을 앞에서부터 순서대로 훑으면, 이어진 `B-I...` 구간을 다시 하나의 개체로 복원할 수 있다.

```text
토큰 → BIO 태그 → 이어진 구간 결합 → 개체 목록
```

---

## 5. NER 방식의 발전

NER 방식은 대략 다음과 같이 발전해 왔다.

```text
규칙 기반
   ↓
통계 기반(CRF)
   ↓
딥러닝 기반(BERT 등)
   ↓
LLM 기반
```

### 규칙 기반 추출

규칙 기반에서는 주로 두 가지 방법을 사용한다.

1. **사전(gazetteer)** 에 등록된 이름과 일치하는 표현 찾기
2. **패턴(정규식)** 으로 특정 형식의 표현 찾기

단점:

- 오탐: 개체가 아닌데 개체로 잡음
- 미탐: 실제 개체를 놓침
- 오타·띄어쓰기·대소문자 차이에 약함

이 문제를 줄이기 위해 학습된 NER 모델을 사용할 수 있다. 다만 사전 학습 모델도 **학습 당시의 타입과 데이터에 맞춰져 있으므로**, 사내 서비스명이나 새로운 도메인 용어처럼 특정 조직에 필요한 개체를 정확히 잡지 못할 수 있다.

---

## 6. 학습된 NER 모델과 LLM 기반 NER

LLM 기반 NER은 별도의 모델 재학습 없이 프롬프트로 **추출할 엔티티 타입을 직접 정의**할 수 있다는 장점이 있다.

| 비교 기준 | 학습된 NER 모델 | LLM 기반 NER |
|---|---|---|
| 학습 밖 이름 | 사내 서비스·신조어 등을 놓칠 수 있음 | 문맥을 보고 추출 가능 |
| 타입 목록 | 학습 때 정해져 있어 변경이 어려움 | 프롬프트에서 직접 정의 가능 |
| 호출 비용 | 로컬 실행 시 별도 호출 비용 없음 | 일반적으로 문서 호출 수에 따라 비용 증가 |
| 출력 안정성 | 같은 입력이면 비교적 일정 | 표기·타입 배정이 실행마다 흔들릴 수 있음 |
| 확신도 점수 | 개체별 `score`가 제공되는 경우가 많음 | 기본 응답에는 없으며, 필요하면 출력 스키마에 필드로 정의 |

LLM은 유연하지만, 그만큼 **프롬프트와 출력 형식 설계가 중요**하다.

---

## 7. LLM 기반 추출과 구조화 출력

LLM으로 NER을 수행할 때는 자연어 응답을 그대로 받기보다 **구조화 출력**으로 받는 방식이 유리하다.

LangChain에서는 `with_structured_output`을 이용해 필요한 엔티티 필드만 정해진 구조로 받을 수 있다.

```text
문서
 ↓
LLM
 ↓
구조화 출력
 ↓
후처리
 ↓
지식 그래프 적재
```

단, **스키마가 보장하는 것은 출력 형식뿐**이다.

구조화 출력이어도 다음 문제는 남는다.

- **타입 오류**: 잘못된 엔티티 타입 배정
- **경계 오류**: 개체 범위를 너무 길거나 짧게 추출
- **미탐**: 필요한 개체를 놓침
- **환각**: 원문에 없는 개체를 생성

따라서 LLM 추출 결과도 **후처리와 검증 단계가 필요**하다.

---

## 8. 추출 방식의 전체 지도

원본의 추출 방식 도식은 다음처럼 텍스트 구조로 정리할 수 있다.

```text
┌─────────────┐
│   규칙 기반  │ ───────────────────────┐
└─────────────┘                         │
                                        ▼
┌─────────────┐                    ┌──────────┐
│ 학습된 NER  │ ─────────────────▶ │ 지식 그래프 │
└─────────────┘                    └──────────┘
                                        ▲
┌─────────────┐                         │
│     LLM     │                         │
└──────┬──────┘                         │
       ▼                                │
┌─────────────┐                         │
│  구조화 출력 │                         │
└──────┬──────┘                         │
       ▼                                │
┌─────────────┐                         │
│    후처리    │ ───────────────────────┘
└─────────────┘
```

정리하면:

- **규칙 기반**: 정해진 사전·패턴으로 바로 추출
- **학습된 NER**: 기존 타입과 도메인이 잘 맞고 문서가 많을 때 활용
- **LLM**: 새로운 타입이나 도메인에 유연하게 대응하고, 구조화 출력과 후처리를 함께 사용

---

## 9. 핵심 정리

```text
GraphRAG
└─ 문서의 정보를 그래프로 연결해야 함
   └─ IE: 비정형 텍스트 → 정형 지식
      ├─ 1. NER: 엔티티 찾기 + 타입 부여
      ├─ 2. 스키마 설계: 사용할 타입·관계 정의
      ├─ 3. 관계 추출: 엔티티끼리 연결
      └─ 4. 정규화: 같은 대상을 하나로 통합

NER 방식
├─ 규칙 기반: 사전 + 정규식
├─ 학습된 NER: CRF · BERT 등
└─ LLM 기반: 프롬프트로 타입 정의
   └─ 구조화 출력 → 후처리 → 지식 그래프
```

**핵심 포인트**: LLM을 사용해도 곧바로 정확한 지식 그래프가 만들어지는 것은 아니다. **추출 형식의 구조화와 결과 후처리**까지 포함해야 안정적인 그래프 적재로 이어진다.
