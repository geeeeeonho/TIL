# LangGraph 실전 코드 - 출장 AI 비서

> 출장 상담을 SQLite에 저장하고, 커널을 재시작한 뒤 기존 대화를 복원한다.  
> 이후 상담 기록으로 출장 계획을 만들고 `interrupt()`로 승인 대기를 저장한 뒤, 다시 재시작해 승인·반려를 이어서 처리한다.
>
> **정리 기준:** 원본 노트북의 작성 칸과 실행 출력은 비어 있다. 아래 코드는 **과제 지문과 자가평가 조건을 기준으로 작성 부분을 완성**했고, `결과`는 원본에 적힌 **확인 기준**을 중심으로 정리했다.

## 전체 흐름

```text
[상담 단계]
사용자 질문
   ↓
TripChatState
   ↓
answer_trip
   ↓
SQLite 저장 ── 커널 재시작 ──→ get_state() 복원
   ↓
A 출장에만 후속 질문 추가

                ↓ 상담 기록 전달

[계획 승인 단계]
TripApprovalState
   ↓
prepare_trip
   ↓
review_trip
   ↓ interrupt() : 승인 대기
   ↓
SQLite 저장 ── 커널 재시작 ──→ get_state() 복원
   ↓
Command(resume=...)
   ↓
record_trip
   ↓
승인 → 계획확정
반려 → 재검토필요
```

핵심은 **`thread_id`로 작업을 분리하고, SQLite 체크포인터로 State와 실행 위치까지 저장하는 것**이다.

## 0. 기본 준비

모델·데이터 경로·상담 DB·승인 DB를 준비한다. 복원할 때는 DB 경로와 `thread_id`를 그대로 유지해야 한다.

### 코드

```python
import os
import json
from pathlib import Path
from typing import Annotated
from typing_extensions import TypedDict

from dotenv import find_dotenv, load_dotenv
from IPython.display import Markdown, display
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.messages import AnyMessage, HumanMessage
from langgraph.graph import END, START, StateGraph
from langgraph.graph.message import add_messages
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.types import Command, interrupt

material_dir = Path(".")
data_dir = material_dir / "data"
output_dir = material_dir / "output"
output_dir.mkdir(parents=True, exist_ok=True)

load_dotenv(find_dotenv(usecwd=True))
load_dotenv(material_dir.resolve().parent / ".env")
load_dotenv(material_dir / ".env", override=True)

if not os.getenv("OPENAI_API_KEY"):
    raise RuntimeError("OPENAI_API_KEY를 .env에 설정한 뒤 진행하세요.")

llm = ChatOpenAI(
    model=os.getenv("OPENAI_CHAT_MODEL", "gpt-5.6-luna"),
    use_responses_api=True,
)

print("사용 모델:", llm.model_name)
```

### 출장 자료와 저장 경로

```python
trips = json.loads(
    (data_dir / "assignment03_trips.json").read_text(encoding="utf-8")
)

chat_db = output_dir / "assignment03_chat.sqlite"

trip_configs = {

for label, packet in trips.items():

```

```text

승인 기록   → assignment03_approval.sqlite
출장 A/B    → 서로 다른 thread_id 사용
```

## 1. 상담 State 생성

출장 자료는 유지하고, 대화 메시지는 `add_messages`로 누적한다.

### 코드

```python
class TripChatState(TypedDict):
    context: str
    messages: Annotated[list[AnyMessage], add_messages]


print("상담 필드:", TripChatState.__annotations__)
```

### 결과

```text
context  : 출장별 고정 자료
messages : HumanMessage / AIMessage 누적
```

`add_messages`를 사용하므로 노드에서는 전체 메시지를 다시 반환하지 않고 **새 메시지만 반환**하면 된다.

---

## 2. 상담 노드 생성

이전 대화와 출장 자료를 함께 LLM에 전달하고 새 답변 하나만 State에 추가한다.

### 코드

```python
trip_chat_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "사용자의 출장 준비 비서입니다. 자료와 이전 대화를 읽고 마지막 질문에 간결하게 답하세요. "
        "명시한 일정·예산·선호를 유지하고 미확정 정보를 확인할 사항으로 남기세요. "
        "자료에 없는 가격이나 예약 완료를 만들지 마세요.\n출장 자료:\n{context}",
    ),
    MessagesPlaceholder("messages"),
])

trip_chat_chain = trip_chat_prompt | llm


def answer_trip(state: TripChatState):
    """출장 자료와 이전 대화를 읽어 새 답변을 반환합니다."""
    reply = trip_chat_chain.invoke({
        "context": state["context"],
        "messages": state["messages"],
    })

    return {"messages": [reply]}
```

### 결과

```text
입력  : context + 누적 messages
출력  : 새 AI 답변 1개
누적  : add_messages가 기존 대화 뒤에 자동 병합
```

실제 LLM 답변은 4번과 6번에서 생성한다.

---

## 3. 상담 그래프 연결

한 번의 실행에서 질문 하나에 답하고 종료한다. 후속 질문은 같은 `thread_id`로 다시 호출한다.

### 코드

```python
trip_chat_builder = StateGraph(TripChatState)
trip_chat_builder.add_node("answer_trip", answer_trip)

trip_chat_builder.add_edge(START, "answer_trip")
trip_chat_builder.add_edge("answer_trip", END)
```

### 구조

```text
START
  ↓
answer_trip
  ↓
END
```

아직 체크포인터는 연결하지 않는다. SQLite를 여는 시점에 `compile()`한다.

## 4. 두 출장 상담을 SQLite에 저장

A와 B를 다른 `thread_id`로 실행해 서로의 대화가 섞이지 않게 저장한다.

### 코드

```python
with SqliteSaver.from_conn_string(str(chat_db)) as checkpointer:
    trip_chat_graph = trip_chat_builder.compile(checkpointer=checkpointer)

    for label, config in trip_configs.items():
        saved = trip_chat_graph.get_state(config)

        # 저장 기록이 없을 때만 첫 질문 실행
        if not saved.values:
            first_input = {
                "context": trips[label]["context"],
                "messages": [
                    HumanMessage(
                        content=trips[label]["question"],
                        id=f"{label}-first",
                    )
                ],
            }
            trip_chat_graph.invoke(first_input, config)

        # 입력 저장 후 중간 실패한 작업은 이어서 실행
        elif saved.next and not saved.interrupts:
            trip_chat_graph.invoke(None, config)

        current = trip_chat_graph.get_state(config)

        print("출장:", label, "/ 다음:", current.next)
        for message in current.values["messages"]:
            print(message.type)
            display(Markdown(message.text))
```

### 결과 확인

```text
출장 A : human → ai / next = ()
출장 B : human → ai / next = ()
```

첫 실행 기준 각 출장에 질문·답변 **2개 메시지**가 저장된다. 같은 셀을 다시 실행해도 첫 질문을 다시 보내지 않는다.

---

## 첫 번째 커널 재시작

여기서 커널을 재시작해 **메모리가 아니라 SQLite에서 실제로 복원되는지** 확인한다.

```text
커널 재시작
   ↓
환경·경로·State·노드·그래프 정의만 다시 실행
   ↓
4번은 실행하지 않음
   ↓
5번에서 SQLite 조회
```

## 5. 저장된 상담 복원

새 프로세스에서 `invoke()` 없이 `get_state()`만 사용해 기존 상담을 읽는다.

### 코드

```python
restored_chats = {}

with SqliteSaver.from_conn_string(str(chat_db)) as checkpointer:
    trip_chat_graph = trip_chat_builder.compile(checkpointer=checkpointer)

    for label, config in trip_configs.items():
        restored_chats[label] = trip_chat_graph.get_state(config)
```

### 결과 확인

```python
for label, saved in restored_chats.items():
    print("출장:", label, "/ 다음:", saved.next)

    if not saved.values:
        raise RuntimeError("4번 저장 여부, DB 경로, thread_id를 확인하세요.")

    print("저장 자료:", saved.values["context"])
    print("메시지 수:", len(saved.values["messages"]))
    display(Markdown(saved.values["messages"][-1].text))
```

```text
A : 부산 출장 자료 + 기존 상담 복원
B : 대전 출장 자료 + 기존 상담 복원
next : ()
```

복원 자체에서는 모델을 호출하지 않는다.

## 6. A 출장에만 후속 질문 추가

완료된 상담에 새 질문을 넣을 때는 `Command(resume=...)`가 아니라 **새 입력 딕셔너리**를 사용한다.

### 코드

```python
followup_question = HumanMessage(
    content=(
        "그 출장의 숙소는 역에서 가까운 곳으로 골라 주세요. "
        "교통과 숙박 예산 안에서 준비하고 싶어요."
    ),
    id="A-followup",
)

with SqliteSaver.from_conn_string(str(chat_db)) as checkpointer:
    trip_chat_graph = trip_chat_builder.compile(checkpointer=checkpointer)

    saved = trip_chat_graph.get_state(trip_configs["A"])

    if not saved.values:
        raise RuntimeError("저장된 A 상담이 없습니다. 4번과 DB 경로를 확인하세요.")

    # 이전 실행이 중간에 멈췄다면 먼저 마무리
    if saved.next and not saved.interrupts:
        trip_chat_graph.invoke(None, trip_configs["A"])
        saved = trip_chat_graph.get_state(trip_configs["A"])

    # 같은 ID의 질문은 한 번만 추가
    if not any(
        message.id == followup_question.id
        for message in saved.values["messages"]
    ):
        trip_chat_graph.invoke(
            {"messages": [followup_question]},
            trip_configs["A"],
        )

    for label, config in trip_configs.items():
        current = trip_chat_graph.get_state(config)
        print("출장:", label, "/ 메시지 수:", len(current.values["messages"]))
        display(Markdown(current.values["messages"][-1].text))
```

### 결과

```text
출장 A : 메시지 4개
출장 B : 메시지 2개
```

A에만 후속 조건이 추가된다. 원본 확인 기준에서는 A 답변이 **부산역 근처 숙박 후보와 교통·숙박 예산**을 반영해야 한다.

# 출장 계획 승인 흐름

상담 그래프와 승인 그래프를 분리한다. 상담 기록을 문자열로 복사해 계획 작성 입력으로 사용한다.

```text
저장된 상담
   ↓
승인용 conversation
   ↓
계획 생성
   ↓
사람 승인 대기
   ↓
승인 / 반려 기록
```

---

## 7. 출장 계획 승인 State 생성

계획 원문과 최종 확정 계획을 분리해 관리한다.

### 코드

```python
class TripApprovalState(TypedDict):
    context: str
    conversation: str
    plan: str
    pending_items: list[str]
    decision: str
    status: str
    approved_plan: str


print("승인 State:", TripApprovalState.__annotations__)
```

### 필드 역할

| 필드 | 역할 |
|---|---|
| `context` | 출장 원자료 |
| `conversation` | 저장된 상담 기록 |
| `plan` | LLM이 작성한 계획 원문 |
| `pending_items` | 아직 확인할 사항 |
| `decision` | 승인 / 반려 |
| `status` | 승인대기 / 계획확정 / 재검토필요 |
| `approved_plan` | 승인된 경우에만 저장되는 확정 계획 |

---

## 8. 구조화된 출장 계획 작성

`PreparedPlan`을 사용해 계획 본문과 미확인 사항을 분리해서 받는다.

### 코드

```python
from pydantic import BaseModel, Field


class PreparedPlan(BaseModel):
    plan: str = Field(
        description=(
            "목적, 일정, 선택한 후보 ID와 근거, "
            "확인된 비용 소계와 예산 범위를 담은 계획"
        )
    )
    pending_items: list[str] = Field(
        description="자료나 대화만으로 확정할 수 없는 사항. 없으면 빈 목록"
    )


trip_plan_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "사용자의 출장 준비 비서입니다. 자료와 상담의 최신 요구를 반영해 "
        "실행 가능한 출장 계획을 작성하세요. 주어진 후보 ID와 가격만 사용하세요. "
        "고정 일정과 예산 범위를 지키고, 확인된 비용 소계와 별도 미확정 비용을 구분하세요. "
        "조건을 만족하는 후보가 없으면 대안을 지어내지 말고 확인할 사항으로 남기세요. "
        "선택 이유를 설명하고 실제 예약이 완료됐다고 쓰지 마세요.",
    ),
    (
        "human",
        "출장 자료:\n{context}\n상담 기록:\n{conversation}",
    ),
])

trip_plan_chain = trip_plan_prompt | llm.with_structured_output(
    PreparedPlan,
    strict=True,
)


def prepare_trip(state: TripApprovalState):
    """자료와 저장된 상담으로 계획과 확인할 사항을 작성합니다."""
    response = trip_plan_chain.invoke({
        "context": state["context"],
        "conversation": state["conversation"],
    })

    return {
        "plan": response.plan,
        "pending_items": response.pending_items,
    }
```

### 결과 구조

```text
PreparedPlan
├─ plan          : 출장 계획 본문
└─ pending_items : 미확인 사항 목록
```

구조화 출력은 형식만 보장한다. 후보 ID·가격·일정이 원자료와 맞는지는 별도 확인이 필요하다.

## 9. 승인 대기와 결과 기록

`review_trip`은 `interrupt()`로 사람의 판단을 기다린다. `record_trip`은 판단에 따라 확정 계획만 분리해서 저장한다.

### 코드

```python
def review_trip(state: TripApprovalState):
    """출장 계획에 대한 사람의 승인 또는 반려를 반환합니다."""
    request = {
        "stage": "trip_approval",
        "plan": state["plan"],
        "pending_items": state["pending_items"],
        "choices": ["승인", "반려"],
    }

    decision = interrupt(request)
    return {"decision": decision}


def record_trip(state: TripApprovalState):
    """승인 여부에 따라 최종 상태와 확정 계획을 기록합니다."""
    if state["decision"] == "승인":
        return {
            "status": "계획확정",
            "approved_plan": state["plan"],
        }

    return {
        "status": "재검토필요",
        "approved_plan": "",
    }
```

### 결과

| 판단 | `status` | `approved_plan` |
|---|---|---|
| 승인 | `계획확정` | 기존 `plan` 저장 |
| 반려 | `재검토필요` | 빈 문자열 |

반려돼도 원래 `plan`은 State에 그대로 남긴다.

## 10. 계획 작성·승인 그래프 연결

승인과 반려 모두 같은 `record_trip` 노드에서 처리하므로 조건부 엣지가 필요 없다.

### 코드

```python
trip_approval_builder = StateGraph(TripApprovalState)

trip_approval_builder.add_node("prepare_trip", prepare_trip)
trip_approval_builder.add_node("review_trip", review_trip)
trip_approval_builder.add_node("record_trip", record_trip)

trip_approval_builder.add_edge(START, "prepare_trip")
trip_approval_builder.add_edge("prepare_trip", "review_trip")
trip_approval_builder.add_edge("review_trip", "record_trip")
trip_approval_builder.add_edge("record_trip", END)
```

### 구조

```text
START
  ↓
prepare_trip
  ↓
review_trip
  ↓ interrupt()
record_trip
  ↓
END
```

`interrupt()`가 발생하면 실행 위치가 `review_trip`에 저장된다.

## 11번 전. 상담 기록을 승인 입력으로 변환

상담용 `messages`를 읽기 쉬운 문자열로 바꿔 승인 그래프에 전달한다.

### 코드

```python
approval_inputs = {}

with SqliteSaver.from_conn_string(str(chat_db)) as checkpointer:
    trip_chat_graph = trip_chat_builder.compile(checkpointer=checkpointer)

    for label, config in trip_configs.items():
        saved = trip_chat_graph.get_state(config)

        if not saved.values:
            raise RuntimeError("상담 기록이 없습니다. 4~6번을 먼저 완료하세요.")

        if (
            saved.next
            or saved.interrupts
            or saved.values["messages"][-1].type != "ai"
        ):
            raise RuntimeError("끝나지 않은 상담이 있습니다.")

        if label == "A" and not any(
            message.id == "A-followup"
            for message in saved.values["messages"]
        ):
            raise RuntimeError("A의 후속 조건을 아직 저장하지 않았습니다.")

        conversation = "\n".join(
            message.type + ": " + message.text
            for message in saved.values["messages"]
        )

        approval_inputs[label] = {
            "context": saved.values["context"],
            "conversation": conversation,
            "plan": "",
            "pending_items": [],
            "decision": "",
            "status": "승인대기",
            "approved_plan": "",
        }
```

### 핵심

상담 그래프의 메시지를 그대로 누적하는 것이 아니라 **승인 시점의 상담 복사본**을 `conversation` 문자열로 저장한다.

## 11. 계획 작성 후 승인 대기로 저장

계획을 한 번 생성한 뒤 `review_trip`의 `interrupt()`에서 멈춘 상태까지 SQLite에 저장한다.

### 코드

```python
with SqliteSaver.from_conn_string(str(approval_db)) as checkpointer:
    trip_approval_graph = trip_approval_builder.compile(
        checkpointer=checkpointer
    )

    for label, config in approval_configs.items():
        saved = trip_approval_graph.get_state(config)

        # 기록이 없을 때만 새 계획 생성
        if not saved.values:
            trip_approval_graph.invoke(approval_inputs[label], config)

        # 계획 생성 중 실패한 경우 저장 지점부터 이어서 실행
        elif saved.next and not saved.interrupts:
            trip_approval_graph.invoke(None, config)

        saved = trip_approval_graph.get_state(config)

        print(
            "출장:", label,
            "/ 상태:", saved.values["status"],
            "/ 다음:", saved.next,
        )
        display(Markdown(saved.values["plan"]))
        print("확인할 사항:", saved.values["pending_items"])
        print("대기 요청:", [item.value for item in saved.interrupts])
```

### 결과 확인

```text
출장 A : status = 승인대기 / next = ('review_trip',)
출장 B : status = 승인대기 / next = ('review_trip',)
interrupts : 승인 또는 반려 응답 대기
```

원본 과제의 확인 기준은 다음과 같다.

```text
A : 역 근처 숙박 선호 반영
    교통 + 숙박 확인 비용 소계 = 210,000원

B : 교통비 = 80,000원

공통 : 식비·현지 교통비 등 미확정 비용은 pending_items로 남김
```

## 두 번째 커널 재시작

계획이 이미 생성된 상태에서 다시 시작해 **LLM을 다시 호출하지 않고 승인 대기를 복원**한다.

```text
커널 재시작
   ↓
승인 State·프롬프트·노드·그래프 정의만 다시 실행
   ↓
11번 계획 생성은 다시 실행하지 않음
   ↓
12번에서 SQLite 조회
```

## 12. 저장된 계획과 승인 대기 복원

`get_state()`로 계획뿐 아니라 `next`와 `interrupts`까지 함께 복원한다.

### 코드

```python
restored_approvals = {}

with SqliteSaver.from_conn_string(str(approval_db)) as checkpointer:
    trip_approval_graph = trip_approval_builder.compile(
        checkpointer=checkpointer
    )

    for label, config in approval_configs.items():
        restored_approvals[label] = trip_approval_graph.get_state(config)
```

### 결과 확인

```python
for label, saved in restored_approvals.items():
    if not saved.values:
        raise RuntimeError("11번 저장 여부, DB 경로, 승인 ID를 확인하세요.")

    print(
        "출장:", label,
        "/ 상태:", saved.values["status"],
        "/ 다음:", saved.next,
    )
    display(Markdown(saved.values["plan"]))
    print("미확인 사항:", saved.values["pending_items"])
    print("대기:", [item.value for item in saved.interrupts])
```

```text
plan          : 기존 계획 복원
pending_items : 기존 미확인 사항 복원
status        : 승인대기
next          : ('review_trip',)
interrupts    : 기존 승인 요청 복원
```

이 단계에서는 `invoke()`를 호출하지 않는다.

## 13. 승인·반려를 재개하고 결과 저장

사람의 대기 응답은 새 입력이 아니라 `Command(resume=...)`로 전달한다.

### 코드

```python
trip_decisions = {
    "A": "승인",
    "B": "반려",
}

trip_results = {}

with SqliteSaver.from_conn_string(str(approval_db)) as checkpointer:
    trip_approval_graph = trip_approval_builder.compile(
        checkpointer=checkpointer
    )

    for label, config in approval_configs.items():
        saved = trip_approval_graph.get_state(config)

        if not saved.values:
            raise RuntimeError(
                "저장된 승인 요청이 없습니다. 11번을 먼저 완료하세요."
            )

        # 아직 사람의 응답을 기다리는 경우에만 재개
        if saved.interrupts:
            trip_approval_graph.invoke(
                Command(resume=trip_decisions[label]),
                config,
            )

        current = trip_approval_graph.get_state(config)

        if (
            current.next
            or current.interrupts
            or current.values.get("status")
            not in {"계획확정", "재검토필요"}
        ):
            raise RuntimeError("아직 완료되지 않은 승인 건입니다.")

        trip_results[label] = current.values

        print(
            "출장:", label,
            "/ 판단:", current.values["decision"],
            "/ 상태:", current.values["status"],
        )
        print("남은 실행:", current.next, current.interrupts)
```

### 결과

```text
A : decision = 승인 / status = 계획확정
    approved_plan = plan

B : decision = 반려 / status = 재검토필요
    plan          = 기존 계획 유지
    approved_plan = ""

A·B 모두 next = (), interrupts = ()
```

이미 완료된 작업을 다시 실행할 경우 `interrupts`가 없으므로 `resume`을 다시 보내지 않는다.

### 결과 JSON 저장

```python
# 파일 저장 직전에 완료 상태를 다시 확인
with SqliteSaver.from_conn_string(str(approval_db)) as checkpointer:
    trip_approval_graph = trip_approval_builder.compile(
        checkpointer=checkpointer
    )

    for label in trip_results:
        saved = trip_approval_graph.get_state(approval_configs[label])

        if (
            saved.next
            or saved.interrupts
            or saved.values.get("status")
            not in {"계획확정", "재검토필요"}
        ):
            raise RuntimeError("미완료 승인 건은 저장할 수 없습니다.")


for label, result in trip_results.items():
    print(label, "확정 계획:")
    display(Markdown(result["approved_plan"] or "확정 계획 없음"))
    print("원래 계획 보관:", bool(result["plan"]))

    report = {
        key: result[key]
        for key in [
            "plan",
            "pending_items",
            "decision",
            "status",
            "approved_plan",
        ]
    }

    report_path = output_dir / (
        approval_configs[label]["configurable"]["thread_id"] + ".json"
    )

    report_path.write_text(
        json.dumps(report, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )

    print("결과 파일:", report_path)
```

# 핵심 정리

```text
1. thread_id
   → A/B처럼 여러 작업의 State를 분리

2. SqliteSaver
   → 프로세스 종료 후에도 State와 실행 위치 유지

3. get_state()
   → 저장된 상태 조회만 수행. 모델 호출 없음

4. 새 질문
   → graph.invoke({"messages": [...]}, config)

5. 중간 실패 재개
   → graph.invoke(None, config)

6. 사람의 interrupt 응답
   → graph.invoke(Command(resume=...), config)

7. interrupts
   → 사람이 응답해야 하는 실제 대기 상태 확인

8. next
   → 그래프에서 아직 실행할 노드가 남았는지 확인
```

## 전체 실행 순서

```text
상담 State 정의
   ↓
상담 노드·그래프 정의
   ↓
A/B 첫 상담 → chat.sqlite 저장
   ↓
[커널 재시작]
   ↓
get_state()로 상담 복원
   ↓
A에만 후속 질문 추가
   ↓
상담 기록 → 승인 입력 변환
   ↓
승인 State·계획 노드·검토 노드 정의
   ↓
계획 작성 → interrupt() 승인 대기
   ↓
approval.sqlite 저장
   ↓
[커널 재시작]
   ↓
get_state()로 계획·interrupt 복원
   ↓
Command(resume="승인" / "반려")
   ↓
record_trip
   ↓
완료 State → JSON 저장
```
