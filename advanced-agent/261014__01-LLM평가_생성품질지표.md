# LLM 평가와 생성 품질 지표 — 개념·코드 문법 정리

> **핵심:** RAG 답변은 **근거에 충실한가(Faithfulness)**, **질문에 맞는가(Answer Relevancy)**, **실제로 맞는가(Answer Correctness)**를 구분해 평가해야 함.  
> 제공된 교안의 **RAGAS 0.4.3 사용 방식**을 기준으로 정리. 검색 품질 지표는 개념만 다루고, 코드는 생성 품질 지표 3종에 집중.

## 1. LLM 평가의 기본 구조

RAG 답변이 자연스럽더라도 근거에 없는 내용을 만들거나 질문과 다른 답을 할 수 있음. **RAGAS**는 평가용 LLM을 이용해 RAG의 검색·생성 품질을 지표로 측정하는 라이브러리.

**평가 방법 4가지**

| 방법 | 평가 방식 | 핵심 한계 |
|---|---|---|
| 문자열 일치 | 정답 답변과 글자가 같은지 비교 | 의미가 같아도 표현이 다르면 낮게 평가 |
| 임베딩 유사도 | 답변과 정답 답변의 벡터 유사도 비교 | 숫자·조건이 틀려도 유사도가 높을 수 있음 |
| LLM 기반 평가 | 평가용 LLM이 주장·근거·정답을 대조 | API 비용 및 실행별 판정 차이 |
| 사람 평가 | 사람이 원문을 확인하며 판정 | 신뢰도는 높지만 반복·대량 평가에 부담 |

**RAGAS 평가 데이터의 4가지 필드**

| 필드 | 의미 | 예시 역할 |
|---|---|---|
| `user_input` | 사용자 질문 | 무엇을 물었는가 |
| `retrieved_contexts` | 검색된 문서 조각의 **리스트** | 어떤 근거가 전달됐는가 |
| `response` | RAG가 생성한 답변 | 실제 출력 |
| `reference` | 사람이 작성·검증한 정답 답변 | 답변의 사실성을 비교하는 기준 |

`user_input`과 `reference`를 질문별로 묶은 정답 데이터셋이 **골든셋(Golden Set)**. 골든셋이 없으면 정답과 직접 비교하는 지표를 사용할 수 없음.

**RAGAS의 주요 지표 6종** — 교안에서는 대체로 `0~1` 점수로 해석하며, 높을수록 양호함.

| 구분 | 지표 | 평가 대상 | 골든셋 |
|---|---|---|---|
| 생성 | **Faithfulness** | 답변 ↔ 검색 문서: 근거 충실성 | 불필요 |
| 생성 | **Answer Relevancy** | 답변 ↔ 질문: 주제 적합성 | 불필요 |
| 생성 | **Answer Correctness** | 답변 ↔ 정답 답변: 사실 정확도 | **필요** |
| 검색 | Context Precision | 검색 문서 ↔ 정답 답변: 관련 문서가 상위에 있는가 | **필요** (교안의 기본형) |
| 검색 | Context Recall | 검색 문서 ↔ 정답 답변: 필요한 내용이 빠지지 않았는가 | **필요** |
| 검색 | Context Relevancy | 검색 문서 ↔ 질문: 엉뚱한 문서가 섞였는가 | 불필요 |

- **검색 평가와 생성 평가를 구분:** `Precision@K`·`Recall@K`는 정답 **문서 ID**를 기준으로 검색 결과를 세지만, 여기서 다룬 `Context Precision`·`Context Recall`은 **정답 답변에 필요한 내용**이 검색 문서에 있는지 평가용 LLM이 판정함.
- **대표적인 조합:** 운영 중(정답 없음)에는 `Faithfulness + Answer Relevancy`, 배포 전(골든셋 있음)에는 `Answer Correctness + Context Recall` 등을 추가.

## 2. 생성 품질 지표와 오류 진단

**① Faithfulness — 검색 문서에 근거가 있는가?**

- 입력: `user_input`, `response`, `retrieved_contexts`.
- 답변을 여러 **주장(claim)**으로 분해하고, 각 주장이 검색 문서로 뒷받침되는지 검사.
- 점수 = **근거로 뒷받침되는 주장 수 / 전체 주장 수**.
- 예: 주장 3개 중 1개만 문서와 일치하면 `1 / 3 ≈ 0.33`.
- **한계:** 문서 자체가 낡거나 틀려도, 그 문서대로 답하면 높은 점수가 나올 수 있음.

**② Answer Relevancy — 질문에 맞는 답인가?**

- 입력: `user_input`, `response`. 검색 문서와 정답 답변은 사용하지 않음.
- 평가용 LLM이 **답변에서 역으로 질문 3개를 생성** → 원래 질문과 각 질문의 임베딩 코사인 유사도를 계산·평균.
- 회피성 답변(예: "상황에 따라 다름")도 감점 대상. 교안에서는 역생성한 질문 3회가 모두 회피성으로 판정되면 `0`점.
- **한계:** 숫자나 사실이 틀려도 질문 주제에 맞으면 점수가 높을 수 있음.

**③ Answer Correctness — 정답 답변과 사실이 일치하는가?**

- 입력: `user_input`, `response`, `reference`. 검색 문서는 사용하지 않음.
- 답변과 정답 답변의 주장을 비교해 `TP`(맞힌 주장), `FP`(틀리거나 덧붙인 주장), `FN`(빠뜨린 주장)으로 분류.
- 교안 기준 점수 계산:

\[
F1 = \frac{2TP}{2TP+FP+FN}
\]

\[
Answer\ Correctness = 0.75 \times F1 + 0.25 \times \text{의미 유사도}
\]

- **한계:** 정답 답변(`reference`)이 낡았다면 정확한 판정이 불가능. 의미 유사도 항목 때문에 사실 점수가 0이어도 최종 점수가 0은 아닐 수 있음. 교안 구현에서는 주장 추출이 비어 있을 때 사실 점수가 `1`로 처리될 수도 있어 확인 필요.

**할루시네이션과 지표의 관계**

- **충실성 오류:** 검색 문서에 없는 내용을 추가하거나 문서의 숫자·조건을 바꿔 답함 → `Faithfulness`로 확인.
- **사실성 오류:** 낡은 검색 문서를 그대로 따랐지만 현재 사실과 다름 → `Answer Correctness`로 확인(검증된 정답 답변 필요).
- **관련성 오류:** 받은 문서에서 질문과 무관한 내용만 골라 답함 → `Answer Relevancy`로 확인.

| 답변 결함 | 주로 낮아지는 지표 | 상대적으로 높게 남을 수 있는 지표 |
|---|---|---|
| 문서에 없는 주장 추가 | Faithfulness | Answer Relevancy, Answer Correctness |
| 숫자·조건을 잘못 변경 | Faithfulness, Answer Correctness | Answer Relevancy |
| 질문과 다른 이야기 | Answer Relevancy, Answer Correctness | Faithfulness |
| **낡은 문서를 충실하게 따름** | **Answer Correctness** | **Faithfulness** |

지표 하나로 오류 유형을 확정할 수는 없음. **여러 지표의 하락 패턴을 비교하고, 질문·답변·검색 문서 원문을 확인**해야 함.

## 3. RAGAS 핵심 코드 문법

**환경 및 평가 객체 생성** — 교안의 `ragas 0.4.x` 기준. 실행에는 `OPENAI_API_KEY`, `OPENAI_EVAL_MODEL` 환경 변수와 해당 모델 접근 권한이 필요함.

```python
import os
import json
import asyncio
from pathlib import Path

import pandas as pd
from dotenv import load_dotenv
from openai import AsyncOpenAI
from tqdm.asyncio import tqdm_asyncio
from ragas.llms import llm_factory
from ragas.embeddings.base import embedding_factory
from ragas.metrics.collections import Faithfulness, AnswerRelevancy, AnswerCorrectness

load_dotenv()
os.environ["RAGAS_DO_NOT_TRACK"] = "true"

client = AsyncOpenAI()
evaluator_llm = llm_factory(
    os.environ["OPENAI_EVAL_MODEL"],
    client=client,
    max_tokens=8192,
    system_prompt="질문·주장·이유를 한국어로 작성하세요.",
)
evaluator_embeddings = embedding_factory(
    "openai", model="text-embedding-3-large", client=client
)

faithfulness = Faithfulness(llm=evaluator_llm)
answer_relevancy = AnswerRelevancy(
    llm=evaluator_llm, embeddings=evaluator_embeddings
)
answer_correctness = AnswerCorrectness(
    llm=evaluator_llm, embeddings=evaluator_embeddings
)
```

- `llm_factory(...)`: 지표가 내부 판정을 수행할 평가용 LLM 준비.
- `embedding_factory(...)`: 문장 의미 유사도를 계산할 임베딩 모델 준비.
- `Faithfulness(...)`: LLM만 필요. `AnswerRelevancy(...)`·`AnswerCorrectness(...)`: LLM과 임베딩 모두 필요.

**단일 답변 평가 — `ascore()`와 `await`**

```python
# 교안의 데이터 구조: 질문별로 reference와 여러 답변 변형(responses)을 보관
samples = json.loads(
    Path("data/본실습/answer_samples.json").read_text(encoding="utf-8")
)
sample = samples[0]
item = sample["responses"][0]

faith = await faithfulness.ascore(
    user_input=sample["user_input"],
    response=item["response"],
    retrieved_contexts=item["retrieved_contexts"],
)

relevancy = await answer_relevancy.ascore(
    user_input=sample["user_input"],
    response=item["response"],
)

correctness = await answer_correctness.ascore(
    user_input=sample["user_input"],
    response=item["response"],
    reference=sample["reference"],
)

print(faith.value, relevancy.value, correctness.value)
```

- `ascore(...)`: 답변 **1건**을 비동기로 평가.
- `await`: 평가 작업 완료까지 기다린 뒤 결과를 받음. **Jupyter Notebook에서는 셀 최상위에서 바로 사용 가능**.
- `.value`: 결과 객체에서 점수 추출. **지표마다 요구하는 필드가 다름**.
- 위 JSON 파일은 교안의 별도 `data` 폴더에 있는 실습 자료. 해당 자료가 없으면 경로를 실제 평가 데이터로 교체해야 함.

**여러 답변 동시 평가 — `Semaphore`·`gather`**

```python
MAX_CONCURRENCY = 8               # 동시 처리 상한: API 한도에 맞춰 조절
semaphore = asyncio.Semaphore(MAX_CONCURRENCY)

async def eval_faithfulness(sample, item):
    async with semaphore:         # 작업 수 제한
        result = await faithfulness.ascore(
            user_input=sample["user_input"],
            response=item["response"],
            retrieved_contexts=item["retrieved_contexts"],
        )
        return result.value

pairs = [(s, item) for s in samples for item in s["responses"]]
scores = await tqdm_asyncio.gather(
    *(eval_faithfulness(s, item) for s, item in pairs),
    desc="Faithfulness",
)

faithfulness_rows = [
    {"질문 ID": s["question_id"], "변형": item["variant"],
     "지표": "Faithfulness", "점수": score}
    for (s, item), score in zip(pairs, scores)
]
```

- `async def`: 비동기 함수 정의. `await` 없이 만든 작업을 `gather(...)`에 전달해 병렬 처리.
- `asyncio.Semaphore(N)`: 동시에 실행되는 평가 작업 수를 제한하여 과도한 API 요청을 방지.
- `tqdm_asyncio.gather(...)`: 여러 작업의 완료를 기다리면서 진행 상황 표시. **입력 작업 순서대로 결과를 반환**.
- 나머지 두 지표도 같은 방식으로 반복하되 `ascore()` 인자만 변경하면 됨.

**결과 집계 — `pivot()`과 `pivot_table()`**

```python
# 질문 ID와 답변 변형 조합이 한 번씩만 존재할 때
faithfulness_table = pd.DataFrame(faithfulness_rows).pivot(
    index="변형", columns="질문 ID", values="점수"
).round(2)

# 세 지표의 행을 모두 모아 변형별 평균을 낼 때
all_rows = faithfulness_rows + relevancy_rows + correctness_rows
summary = pd.DataFrame(all_rows).pivot_table(
    index="변형", columns="지표", values="점수", aggfunc="mean"
).round(2)
```

`relevancy_rows`·`correctness_rows`는 각각 다른 두 지표를 평가해 같은 형태로 기록한 결과 목록임. `pivot()`은 값 재배치, `pivot_table(..., aggfunc="mean")`은 그룹별 평균 집계에 사용.

## 4. 평가 결과 해석 및 실무 적용

**평가 흐름**

```text
[배포 전]
골든셋(질문 + 검증된 정답 답변)
    → RAG 실행(답변 + 검색 문서 저장)
    → Faithfulness / Answer Relevancy / Answer Correctness 계산
    → 기존 결과와 비교 → 점수 하락 원문 검토 → 배포 결정

[운영 중]
실제 질문 + 답변 + 검색 문서 로그
    → 골든셋 없는 지표(Faithfulness / Answer Relevancy) 점검
    → 낮은 점수 원문 검토 → 확인된 사례를 골든셋에 추가
```

**점수 해석 시 주의**

- **절대 점수보다 동일 질문·동일 지표의 비교가 중요:** 평가용 LLM의 판정에 따라 실행별 점수가 달라질 수 있음.
- **`NaN`과 `0`은 다름:** Faithfulness에서 주장을 추출하지 못하면 `NaN`이 될 수 있고, 주장이 모두 근거 없음으로 판정되면 `0`이 될 수 있음. 둘 다 원문 확인이 필요하며 `0`인 결함을 임의로 제외하면 안 됨.
- **`NaN` 비교 주의:** `NaN`은 단순 크기 비교로 탐지되지 않으므로 `pd.isna(...)`로 별도 처리.
- **교안의 출시 판정 예시:** 같은 질문의 `근거대로` 점수보다 **세 지표 중 하나라도 0.2 이상 낮으면 `보류`**. 이 **0.2는 실습용 비교 규칙**이지 보편적인 합격 기준이 아님.

```python
# current와 baseline은 같은 질문·같은 지표의 점수
if pd.isna(current) or pd.isna(baseline):
    decision = "보류"
elif round(baseline - current, 2) >= 0.2:
    decision = "보류"
else:
    decision = "통과"
```

- **기준 답변도 검증해야 함:** 검색 문서가 낡으면 `근거대로` 답변도 틀릴 수 있음. 이런 경우에는 같은 질문의 기준 답변과 비교해도 이상을 찾기 어려우므로, 최신 원문으로 검증한 골든셋과 **Answer Correctness**를 확인하고 검색 문서를 갱신해야 함.
- **문제 원인에 따라 수정 위치가 다름:** 검색 누락·엉뚱한 문서 → 검색 설정, 낡은 문서 → 데이터 갱신, 근거에 없는 주장 → 생성 프롬프트·모델 확인.

**기억할 구분:** `Faithfulness = 근거`, `Answer Relevancy = 질문`, `Answer Correctness = 정답`. 세 지표를 함께 봐야 **검색 문서의 문제인지, 답변 생성의 문제인지** 좁혀갈 수 있음.
