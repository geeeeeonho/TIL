# Store로 사용자 기억 공유하기

> LangGraph의 **Store**를 이용해 사용자별 장기기억을 저장하고, 새 대화에서도 다시 조회해 사용하는 구조.

---

## 1. Store와 대화 기억의 역할 구분

### 핵심 개념

| 구분 | 역할 | 구분 기준 |
|---|---|---|
| **Checkpointer** | 현재 대화·작업의 State 저장 | `thread_id` |
| **Store** | 여러 대화에서 재사용할 장기기억 저장 | `namespace`, `key` |
| **Runtime context** | 현재 실행에 필요한 사용자 정보 전달 | `user_id` |

```text
사용자 A
 ├─ thread-1 ─┐
 ├─ thread-2 ─┼─ Checkpointer: 대화별 State 분리
 └─ thread-3 ─┘
       │
       └─ user_id = client-a
              ↓
       Store namespace
       ("counseling", "client-a", ...)
              ↓
       여러 대화에서 같은 기억 재사용
```

- `thread_id`가 바뀌면 새 대화가 됨.
- `user_id`가 같으면 새 대화에서도 같은 Store 기억을 조회 가능.
- Store의 기억은 자동으로 LLM에 전달되지 않음.
- **노드에서 조회 → State 또는 Prompt에 전달**해야 실제 답변에 사용됨.

### 장기기억에 적합한 정보

- 지속적인 사용자 선호
- 사용자 기본 정보
- 장기 목표·진행 중인 작업
- 과거 작업 결과·도움이 된 경험
- 반복 적용할 작업 규칙

반대로 **이번 대화에서만 필요한 일시적 상황**은 State에 두는 편이 적절함.

---

## 2. Store 저장 구조와 조회 방식

Store는 `namespace → key → value` 구조로 기억을 관리함.

```python
namespace = ("counseling", "client-a", "profile")
key = "support_preference"
value = {"text": "짧고 차분한 대화를 선호"}
```

- `namespace`: 기억을 묶는 공간. 문자열 튜플이며 구조는 개발자가 정함.
- `key`: namespace 안에서 기억 한 건을 구분하는 이름.
- `value`: 실제 데이터. 딕셔너리 형태.

### SQLite Store 생성

```python
import sqlite3
from langgraph.store.sqlite import SqliteStore

store_connection = sqlite3.connect(
    "output/lesson01_store.sqlite",
    check_same_thread=False,
    isolation_level=None,
)

store_connection.execute("PRAGMA foreign_keys = ON")
store = SqliteStore(store_connection)
store.setup()
```

### CRUD

```python
namespace = ("practice", "crud")

# 저장
store.put(
    namespace,
    "support_preference",
    {"text": "차분한 말투로 대화하기를 선호합니다."},
)

# 조회
item = store.get(namespace, "support_preference")
print(item.key)
print(item.value)

# 같은 namespace + key → 기존 값 교체
store.put(
    namespace,
    "support_preference",
    {"text": "짧은 문장으로 대화하기를 선호합니다."},
)

# 삭제
store.delete(namespace, "support_preference")
print(store.get(namespace, "support_preference"))
```

**결과 구조**

```text
put()    → 저장 / 같은 key면 수정
get()    → key로 한 건 조회
delete() → 삭제 후 get() 결과 None
```

> `get()`은 key를 알고 있는 기억을 직접 읽을 때 사용함.

### 기본 기억과 경험 기억 분리

| 기억 공간 | 내용 | 조회 방식 |
|---|---|---|
| `("counseling", user_id, "profile")` | 항상 참고할 기본 정보·목표·선호 | `get()` |
| `("counseling", user_id, "episodes")` | 과거 사건·시도·결과 | `search()` |

```text
기본 프로필
  └─ 항상 필요 + key를 알고 있음
      → get()

과거 경험 여러 개
  └─ 현재 질문과 관련된 것만 필요
      → embedding + search()
```

### 임베딩 검색 설정

```python
from langchain_openai import OpenAIEmbeddings

embedding_model = "text-embedding-3-large"
embedding_dims = 768

embeddings = OpenAIEmbeddings(
    model=embedding_model,
    dimensions=embedding_dims,
)

store = SqliteStore(
    store_connection,
    index={"embed": embeddings, "dims": embedding_dims},
)
store.setup()
```

#### 기본 기억: 임베딩 없이 저장

```python
store.put(
    ("counseling", "client-a", "profile"),
    "support_preference",
    {
        "text": "상황과 감정을 먼저 듣고 행동 하나를 함께 정하는 방식이 편해요.",
        "kind": "preference",
        "speaker": "user",
    },
    index=False,
)
```

`index=False`
- 임베딩 생성 안 함.
- `get()` 조회는 그대로 가능.

#### 경험 기억: 임베딩해서 저장

```python
store.put(
    ("counseling", "client-a", "episodes"),
    "meeting_preparation",
    {
        "text": "회의 전에 말할 의견을 한 문장으로 적어 갔더니 발언을 시작하기 쉬웠어요.",
        "kind": "experience",
        "speaker": "user",
    },
    index=["text"],
)
```

#### 의미 검색

```python
found = store.search(
    ("counseling", "client-a", "episodes"),
    query="내일 회의가 있는데 어떻게 준비하면 좋을까요?",
    filter={"speaker": "user"},
    limit=1,
)
```

```text
현재 질문
   ↓ embedding
Store의 episode 벡터와 비교
   ↓
관련 경험 반환
```

> 검색 점수는 의미적 유사도이며, 기억 내용이 사실인지 검증하는 점수는 아님.

## 3. State와 Runtime context 설계

현재 대화와 장기기억을 분리함.

```python
from typing import Annotated
from typing_extensions import TypedDict
from langchain_core.messages import AnyMessage
from langgraph.graph.message import add_messages

class CounselingState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    recalled_memories: list[str]
```

- `messages`: 현재 대화 기록.
- `recalled_memories`: **이번 답변에 사용할 기억만** 저장.

### 사용자 ID는 Runtime context로 전달

```python
from dataclasses import dataclass

@dataclass
class UserContext:
    user_id: str
```

```text
State
 └─ 현재 실행 데이터
    messages / recalled_memories

Runtime context
 └─ 호출할 때 전달하는 실행 정보
    user_id

Store
 └─ 여러 실행에서 공유하는 장기기억
```

### Runtime에서 사용하는 값

```text
runtime.context       → user_id, 권한, 언어 등 실행 정보
runtime.store         → 장기기억 저장소
runtime.stream_writer → 사용자 정의 스트리밍 데이터
```

## 4. 상담 Agent: 기억 조회 → 답변 생성

### Node 1. `recall_memories`

기본 정보는 `get()`, 현재 고민과 관련된 경험은 `search()`로 읽음.

```python
from langgraph.runtime import Runtime


def recall_memories(state: CounselingState, runtime: Runtime[UserContext]):
    user_id = runtime.context.user_id

    profile_namespace = ("counseling", user_id, "profile")
    episode_namespace = ("counseling", user_id, "episodes")

    memories = []

    # 항상 필요한 기본 기억
    for key in ["work_context", "counseling_goal", "support_preference"]:
        item = runtime.store.get(profile_namespace, key)
        if item:
            memories.append("사용자 기본 기억: " + item.value["text"])

    # 현재 고민과 관련된 과거 경험
    hits = runtime.store.search(
        episode_namespace,
        query=state["messages"][-1].text,
        filter={"speaker": "user"},
        limit=2,
    )

    memories += [
        "사용자가 보고한 과거 경험: " + item.value["text"]
        for item in hits
    ]

    return {"recalled_memories": memories}
```

### Node 2. `answer_counseling`

조회한 기억을 Prompt의 참고 정보로 전달함.

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

answer_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "일상 스트레스와 감정을 정리하도록 돕는 심리 상담 도우미입니다.\n"
        "현재 요청을 우선하고 저장된 사용자 정보와 경험은 참고 자료로 사용하세요.\n"
        "기억과 대화에 없는 경험·감정·원인을 단정하지 마세요.\n"
        "상담 참고 정보:\n{memories}"
    ),
    MessagesPlaceholder("messages"),
])

answer_chain = answer_prompt | llm
```

```python
def answer_counseling(state: CounselingState):
    response = answer_chain.invoke({
        "memories": "\n".join(state["recalled_memories"])
                    or "저장된 상담 정보 없음",
        "messages": state["messages"],
    })

    return {"messages": [response]}
```

### Graph 연결

```python
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.sqlite import SqliteSaver

chat_connection = sqlite3.connect(
    "output/lesson01_chat.sqlite",
    check_same_thread=False,
)
checkpointer = SqliteSaver(chat_connection)

builder = StateGraph(
    CounselingState,
    context_schema=UserContext,
)

builder.add_node("recall_memories", recall_memories)
builder.add_node("answer_counseling", answer_counseling)

builder.add_edge(START, "recall_memories")
builder.add_edge("recall_memories", "answer_counseling")
builder.add_edge("answer_counseling", END)

graph = builder.compile(
    checkpointer=checkpointer,
    store=store,
)
```

```text
START
  ↓
recall_memories
  ↓
answer_counseling
  ↓
END
```

### 전체 데이터 흐름

```text
user_id
  ↓
사용자 namespace 결정
  ↓
profile → get()
episodes → search()
  ↓
recalled_memories
  ↓
Prompt에 삽입
  ↓
LLM 답변
```

## 5. 새 대화·다른 사용자·기억 수정

### 실행

```python
from uuid import uuid4
from langchain_core.messages import HumanMessage

config = {
    "configurable": {
        "thread_id": str(uuid4())
    }
}

result = graph.invoke(
    {
        "messages": [
            HumanMessage(content="내일 회의를 생각하면 부담스러워요.")
        ]
    },
    config,
    context=UserContext(user_id="client-a"),
)
```

| 상황 | `thread_id` | `user_id` | 결과 |
|---|---|---|---|
| 같은 대화 계속 | 유지 | 유지 | 기존 대화 State + 기억 사용 |
| 같은 사용자의 새 대화 | 변경 | 유지 | 새 대화지만 기존 장기기억 재사용 |
| 다른 사용자 | 변경 | 변경 | 다른 namespace의 기억 사용 |

```text
thread_id 변경 + user_id 유지
→ 이전 메시지는 분리
→ Store의 사용자 기억은 유지

user_id 변경
→ namespace 변경
→ 다른 사용자의 기억과 분리
```

### 기억 수정

같은 `namespace + key`로 다시 `put()`하면 기존 기억을 교체함.

```python
store.put(
    ("counseling", "client-a", "profile"),
    "support_preference",
    {
        "text": "앞으로는 행동을 제안하기보다 질문 하나로 생각을 정리하도록 도와주세요.",
        "kind": "preference",
        "speaker": "user",
    },
    index=False,
)
```

```text
기존 선호
  ↓ 같은 namespace + key로 put
새 선호로 교체
  ↓
다음 대화부터 새 기억 반영
```

## 6. 실습: 취향을 기억하는 이미지 생성 Agent

같은 이미지 요청에 대해 사용자별 Store 선호를 읽어 서로 다른 결과를 만드는 예제.

```text
같은 이미지 요청
      │
      ├─ user-a → A의 기본 화풍 + 관련 피드백 조회
      │                       ↓
      │                    이미지 생성
      │
      └─ user-b → B의 기본 화풍 + 관련 피드백 조회
                              ↓
                           이미지 생성
```

### 기억 설계

```text
("image_preferences", user_id, "profile")
  └─ 기본 화풍 → get()

("image_preferences", user_id, "episodes")
  └─ 과거 피드백 → search(request)
```

```python
store.put(
    ("image_preferences", "user-a", "profile"),
    "visual_style",
    {
        "text": "종이 질감의 수채화와 부드러운 색, 넓은 여백을 선호합니다.",
        "speaker": "user",
    },
    index=False,
)

store.put(
    ("image_preferences", "user-a", "episodes"),
    "reading_event",
    {
        "text": "책과 찻잔을 작게 두고 빈 공간을 넓힌 구도가 좋았어요.",
        "speaker": "user",
    },
    index=["text"],
)
```

### State

아래 코드는 교안의 작성 지시를 기준으로 정리한 완성 형태.

```python
class ImageState(TypedDict):
    request: str
    preferences: str
    generation_prompt: str
    image_path: str

image_input = {
    "request": common_request
}
```

### Node 1. 사용자 선호 조회

```python
def load_image_preferences(state: ImageState, runtime: Runtime[UserContext]):
    user_id = runtime.context.user_id

    profile_ns = ("image_preferences", user_id, "profile")
    episode_ns = ("image_preferences", user_id, "episodes")

    preferences = []

    style = runtime.store.get(profile_ns, "visual_style")
    if style:
        preferences.append("기본 화풍: " + style.value["text"])

    hits = runtime.store.search(
        episode_ns,
        query=state["request"],
        filter={"speaker": "user"},
        limit=1,
    )

    if hits:
        preferences.append("관련 과거 피드백: " + hits[0].value["text"])

    return {"preferences": "\n".join(preferences)}
```

### Node 2. 이미지 생성

이미지 모델을 별도 `ChatOpenAI(model=...)`로 만드는 대신 기존 LLM에 이미지 생성 Tool을 연결함.

```python
import base64

image_model = "gpt-image-2.5-flare"

image_llm = llm.bind_tools(
    [{
        "type": "image_generation",
        "model": image_model,
        "size": "1024x1024",
        "quality": "medium",
        "output_format": "png",
    }],
    tool_choice={"type": "image_generation"},
)
```

```python
image_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "현재 요청을 우선하고 저장된 기본 화풍과 관련 피드백을 참고해 "
        "홍보 이미지를 한 장 생성하세요. 글자·로고·워터마크는 넣지 마세요."
    ),
    (
        "human",
        "현재 요청:\n{request}\n\n저장된 이미지 선호:\n{preferences}"
    ),
])

image_chain = image_prompt | image_llm
```

```python
def generate_image(state: ImageState):
    response = image_chain.invoke({
        "request": state["request"],
        "preferences": state["preferences"],
    })

    generation_prompt = image_prompt.format(
        request=state["request"],
        preferences=state["preferences"],
    )

    image_blocks = [
        block for block in response.content_blocks
        if block["type"] == "image"
    ]

    if not image_blocks:
        return {
            "generation_prompt": generation_prompt,
            "image_path": "",
        }

    image_path = image_dir / f"{uuid4().hex}.png"
    image_path.write_bytes(
        base64.b64decode(image_blocks[0]["base64"])
    )

    return {
        "generation_prompt": generation_prompt,
        "image_path": str(image_path),
    }
```

> 큰 Base64 이미지 자체는 State에 넣지 않고 **파일 경로만 저장**해 Checkpointer의 불필요한 용량 증가를 막음.

### Graph 연결

```python
image_builder = StateGraph(
    ImageState,
    context_schema=UserContext,
)

image_builder.add_node(
    "load_image_preferences",
    load_image_preferences,
)
image_builder.add_node(
    "generate_image",
    generate_image,
)

image_builder.add_edge(START, "load_image_preferences")
image_builder.add_edge("load_image_preferences", "generate_image")
image_builder.add_edge("generate_image", END)

image_graph = image_builder.compile(
    checkpointer=checkpointer,
    store=store,
)
```

```text
START
  ↓
load_image_preferences
  ↓
generate_image
  ↓
END
```

### 사용자별 실행 결과 비교

```python
image_results = {}

for user_id in ["user-a", "user-b"]:
    result = image_graph.invoke(
        image_input,
        {"configurable": {"thread_id": str(uuid4())}},
        context=UserContext(user_id=user_id),
    )

    image_results[user_id] = result
```

| 항목 | user-a | user-b |
|---|---|---|
| 공통 요청 | 책 2권, 머그컵, 작은 화분 | 동일 |
| 화풍 | 수채화 | 3D 일러스트 |
| 색 | 크림·연두·연분홍 | 청록·코랄 |
| 구도 | 넓은 여백 | 중앙 집중 |

```text
요청은 동일
   ↓
user_id만 변경
   ↓
각 사용자 namespace의 선호 조회
   ↓
최종 Prompt가 달라짐
   ↓
사용자별 이미지 생성
```

## 7. 전체 핵심 정리

```text
Checkpointer
  └─ thread_id 기준
     현재 대화·작업 State 저장

Store
  └─ namespace + key 기준
     여러 대화에서 사용할 장기기억 저장

Runtime context
  └─ user_id 전달
     어떤 사용자의 Store를 조회할지 결정

get()
  └─ key가 정해진 기본 기억 조회

search()
  └─ 현재 질문과 관련된 기억 의미 검색
```

### 전체 흐름

```text
사용자 요청
   ↓
Runtime context의 user_id 확인
   ↓
Store에서 사용자 기억 조회
   ├─ profile  → get()
   └─ episodes → search()
   ↓
이번 실행 State에 기억 저장
   ↓
Prompt에 기억 삽입
   ↓
LLM / 이미지 생성 Tool 실행
```

### 한 줄 정리
