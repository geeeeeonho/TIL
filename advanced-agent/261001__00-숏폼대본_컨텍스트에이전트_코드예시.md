# 숏폼 대본 컨텍스트 에이전트 — 코드·결과 중심 답안

> 선정 과제: **과제 03 — 긴 제작 대화로 숏폼 대본과 장면표를 만드는 에이전트**

## 선정 이유

세 과제 중 현재 학습한 내용을 가장 넓게 연결하는 과제다.

- **Store**: 사용자별 장기기억 조회·검색
- **Runtime Context**: `user_id` 전달
- **Checkpointer**: `thread_id`별 대화 State 유지
- **Context Engineering**: 입력 토큰 예산 계산과 `trim_messages`
- **Summary**: 오래된 대화를 누적 요약하고 최근 대화 보존
- **Conditional Edge**: 대화 길이에 따라 요약 여부 분기
- **Middleware**: `SummarizationMiddleware`, `wrap_model_call`, `PIIMiddleware`
- **후속 대화**: 같은 thread에서 최신 변경을 이어서 반영

> `Mem0`의 직접 CRUD는 과제 02가 더 강하지만, **현재 학습 범위 전체를 하나의 Agent 흐름으로 복습하기에는 과제 03이 가장 적합**하다.

# 0. 전체 구조

```text
사용자 요청
   │
   ▼
[recall_channel]
필수 채널 정보 get()
관련 과거 피드백 search()
   │
   ▼
[route_context]
   ├─ 짧은 대화 ───────────────┐
   │                           ▼
   └─ 긴 대화 → [summarize_history]
                               │
                               ▼
                       [write_storyboard]
                               │
                               ▼
                              END
```

기억과 대화 저장 범위는 다음처럼 구분한다.

```text
user_id = 장기기억 소유자
│
└─ Store
   ├─ profile  → 매번 get()
   └─ episodes → 현재 요청으로 search()

thread_id = 개별 대화/작업
│
└─ Checkpointer
   ├─ messages
   ├─ summary
   ├─ recalled_memories
   └─ input_tokens
```

# 1. 입력 토큰 예산 계산

대화와 고정 프롬프트가 차지하는 토큰을 따로 계산한다.

## 코드

```python
history_tokens = count_tokens_approximately(conversation)
fixed_tokens = count_tokens_approximately(budget_fixed)
history_budget = input_budget - fixed_tokens

print(history_tokens, fixed_tokens, history_budget)
```

## 결과

```text
대화 토큰 수 / 고정 입력 토큰 수 / 대화에 사용할 수 있는 남은 토큰 수
```

실제 숫자는 `conversation` 내용에 따라 달라진다.

## 핵심

```text
전체 입력 예산
= 고정 입력 + 대화 입력

대화 예산
= 전체 입력 예산 - 고정 입력
```

# 2. 최근 대화만 트리밍

전체 기록을 없애는 것이 아니라 **이번 모델 입력에 사용할 최근 대화만 선택**한다.

## 코드

```python
recent_only = trim_messages(
    conversation,
    max_tokens=120,
    token_counter=count_tokens_approximately,
    strategy="last",
    start_on="human",
    allow_partial=False,
)

print("원본:", len(conversation), "/ 최근:", len(recent_only))

for message in recent_only:
    print(message.type + ":", message.text)
```

## 결과

```text
원본: 전체 메시지 수 / 최근: 선택된 메시지 수

human: ...
ai: ...
human: 현재 질문
```

- 120 토큰 이내
- 첫 메시지는 `HumanMessage`
- 마지막 현재 질문은 유지
- 원본 `conversation`은 변경하지 않음

## 핵심

단순 Trim은 오래된 합의를 잃을 수 있다.

```text
전체 대화
   ↓ trim
최근 대화만 유지
   ↓
오래된 중요 합의가 사라질 수 있음
```

그래서 뒤에서 **Summary + Recent Messages** 구조를 사용한다.

# 3. State와 사용자 Context 정의

현재 작업 상태와 장기기억 소유자 ID를 분리한다.

## 코드

```python
class VideoState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    summary: str
    recalled_memories: list[str]
    input_tokens: int


@dataclass
class UserContext:
    user_id: str
```

## 결과

```text
VideoState
├─ messages            현재 thread의 대화
├─ summary             오래된 제작 합의 요약
├─ recalled_memories   Store에서 읽은 장기기억
└─ input_tokens        실제 모델 입력의 근사 토큰

UserContext
└─ user_id              장기기억 조회 범위
```

## 핵심

- `State` = 현재 작업에서 변하는 값
- `Runtime Context` = 실행 시 전달하는 사용자 식별 정보
- `add_messages` = 새 메시지를 기존 `messages`에 누적

# 4. Store에서 필수 기억과 관련 경험 조회

필수 정보는 항상 `get()`, 과거 경험은 현재 요청에 따라 `search()`한다.

## 코드

```python
def recall_channel(state: VideoState, runtime: Runtime[UserContext]):
    """필수 채널 정보는 매번 읽고, 과거 피드백은 현재 요청으로 검색합니다."""

    user_id = runtime.context.user_id

    item = runtime.store.get(
        ("video_channels", user_id, "profile"),
        "profile",
    )

    memories = ["필수 채널 정보: " + item.value["text"]] if item else []

    episodes = runtime.store.search(
        ("video_channels", user_id, "episodes"),
        query=state["messages"][-1].text,
        filter={"speaker": "user"},
        limit=1,
    )

    memories.extend(
        "관련 과거 피드백(사용자 발화): " + item.value["text"]
        for item in episodes
    )

    return {"recalled_memories": memories}
```

## 결과

```text
[
  "필수 채널 정보: ...",
  "관련 과거 피드백(사용자 발화): ..."
]
```

관련 경험이 없으면:

```text
[
  "필수 채널 정보: ..."
]
```

둘 다 없으면:

```text
[]
```

## 핵심

```text
profile
└─ 항상 필요한 정보
   → get()

episodes
└─ 현재 질문과 관련 있는 경험
   → search()
```

검색 순위 때문에 필수 정보가 빠지지 않도록 두 기억을 분리한다.

# 5. 오래된 대화를 누적 요약

최근 `keep_recent`개는 원문으로 남기고 이전 대화만 요약한다.

## 코드

```python
def summarize_history(state: VideoState):
    """기존 요약과 오래된 대화를 합쳐 요약하고 대상 메시지만 제거합니다."""

    old_messages = state["messages"][:-keep_recent]

    if not old_messages:
        return {
            "summary": state.get("summary", ""),
            "messages": [],
        }

    response = summary_chain.invoke({
        "summary": state.get("summary", ""),
        "messages": old_messages,
    })

    removals = [
        RemoveMessage(id=message.id)
        for message in old_messages
    ]

    return {
        "summary": response.text,
        "messages": removals,
    }
```

## 결과

```text
summary:
"기존 합의 + 오래된 대화에서 유지해야 할 최신 조건 ..."

messages:
[
  RemoveMessage(...),
  RemoveMessage(...),
  ...
]
```

최근 `keep_recent`개 메시지는 제거하지 않는다.

## 핵심

```text
기존 Summary
      +
오래된 Messages
      ↓
새 Summary

오래된 원문 → RemoveMessage
최근 원문   → 그대로 유지
```

즉, 단순 삭제가 아니라 **정보를 요약으로 이전한 뒤 오래된 원문을 제거**한다.

# 6. 입력 예산에 맞게 모델 호출

장기기억과 Summary는 고정 영역에 넣고, 남은 예산만 최근 대화에 사용한다.

## 코드

```python
def write_storyboard(state: VideoState):
    """기억·요약·최근 대화로 예산 안에서 대본과 장면표를 작성합니다."""

    fixed_messages = context_prompt.format_messages(
        memories="\n".join(state["recalled_memories"]),
        summary=state.get("summary", ""),
    )

    history_budget = (
        input_budget
        - count_tokens_approximately(fixed_messages)
    )

    if history_budget < count_tokens_approximately(
        [state["messages"][-1]]
    ):
        return {
            "messages": [
                AIMessage(content=over_budget_text)
            ],
            "input_tokens": 0,
        }

    recent = trim_messages(
        state["messages"],
        max_tokens=history_budget,
        token_counter=count_tokens_approximately,
        strategy="last",
        start_on="human",
        allow_partial=False,
    )

    model_input = [
        *fixed_messages,
        *recent,
    ]

    response = llm.invoke(model_input)

    return {
        "messages": [response],
        "input_tokens": count_tokens_approximately(model_input),
    }
```

## 결과

정상 호출:

```text
messages:
└─ AIMessage("최종 대본·장면표 ...")

input_tokens:
└─ 0 < 값 <= 1200
```

현재 질문조차 넣을 공간이 없으면:

```text
현재 입력 예산을 넘었습니다.
자료나 질문을 나누어 보내 주세요.
```

그리고:

```text
input_tokens = 0
```

## 핵심

```text
[필수 기억 + Summary] → 고정 입력
             +
[최근 Messages]       → 남은 예산만 사용
             ↓
          LLM 호출
```

# 7. 요약 여부 분기

대화가 충분히 길고 실제로 요약할 과거 메시지가 있을 때만 요약한다.

## 코드

```python
def route_context(state: VideoState):
    if (
        count_tokens_approximately(state["messages"]) > summary_trigger
        and len(state["messages"]) > keep_recent
    ):
        return "summarize_history"

    return "write_storyboard"
```

## 결과

```text
토큰 == summary_trigger
→ write_storyboard

토큰 > summary_trigger
+ messages > keep_recent
→ summarize_history

최근 메시지만 존재
→ write_storyboard
```

## 핵심

조건은 두 개다.

```text
1. 대화가 요약 기준보다 긴가?
2. 최근 메시지 외에 요약할 과거 메시지가 있는가?
```

# 8. LangGraph 연결

## 코드

```python
builder = StateGraph(
    VideoState,
    context_schema=UserContext,
)

builder.add_node(
    "recall_channel",
    recall_channel,
)
builder.add_node(
    "summarize_history",
    summarize_history,
)
builder.add_node(
    "write_storyboard",
    write_storyboard,
)

builder.add_edge(
    START,
    "recall_channel",
)

builder.add_conditional_edges(
    "recall_channel",
    route_context,
    {
        "summarize_history": "summarize_history",
        "write_storyboard": "write_storyboard",
    },
)

builder.add_edge(
    "summarize_history",
    "write_storyboard",
)

builder.add_edge(
    "write_storyboard",
    END,
)

graph = builder.compile(
    store=store,
    checkpointer=checkpointer,
)
```

## 결과

```text
START
  ↓
recall_channel
  ↓
route_context
  ├─ summarize_history ─┐
  │                     ↓
  └──────────────→ write_storyboard
                        ↓
                       END
```

## 핵심

두 저장소 역할이 다르다.

| 저장 | 기준 | 역할 |
|---|---|---|
| `Store` | `user_id` | 여러 thread에서 공유할 장기기억 |
| `Checkpointer` | `thread_id` | 특정 대화의 State 유지 |

# 11. SummarizationMiddleware 사용

직접 요약 노드를 만드는 대신 `create_agent`의 Middleware에서 요약할 수도 있다.

## 코드

```python

    trigger=("messages", 8),

summary_agent = create_agent(
    model=llm,
    tools=[],

summary_config = {
    "configurable": {
        "thread_id": str(uuid4())

```

## 결과

```text

  ↓

  ↓

  ↓
```

# 12. 이번 모델 요청만 Trim

State 전체는 유지하면서 **모델에 전달하는 요청만 줄인다.**

## 코드

```python
@wrap_model_call
def trim_request(
    request: ModelRequest,
    handler: Callable[
        [ModelRequest],
        ModelResponse,
    ],
) -> ModelResponse:
    """저장된 State 대신 이번 호출의 대화만 줄입니다."""

    recent = trim_messages(
        request.messages,
        max_tokens=120,
        token_counter=count_tokens_approximately,
        strategy="last",
        start_on="human",
        allow_partial=False,
    )

    return handler(
        request.override(
            messages=recent
        )
    )
```

Agent에 연결한다.

```python
trim_agent = create_agent(
    model=llm,
    tools=[],
    system_prompt=middleware_instruction,
    middleware=[trim_request],
    checkpointer=checkpointer,
)

trim_config = {
    "configurable": {
        "thread_id": str(uuid4())
    }
}

trim_result = trim_agent.invoke(
    {"messages": conversation},
    trim_config,
)
```

## 결과

State:

```text
원본 conversation 전부 유지
+
새 AI 답변
```

모델 호출:

```text
최근 120 토큰 이내 메시지만 전달
```

즉:

```text
State ≠ Model Input
```

## 핵심

이 부분이 컨텍스트 엔지니어링에서 중요하다.

```text
저장할 정보
≠
매번 모델에 전달할 정보
```

모든 기록을 보존하면서도 실제 LLM 호출 비용은 줄일 수 있다.

# 13. PII Middleware로 이메일 가리기

모델에 필요하지 않은 개인정보를 입력에서 제거한다.

## 코드

```python
pii_middleware = PIIMiddleware(
    "email",
    strategy="redact",
    apply_to_input=True,
)

pii_agent = create_agent(
    model=llm,
    tools=[],
    middleware=[pii_middleware],
    system_prompt=(
        "문의 내용을 한국어 한 문장으로 요약하세요."
    ),
)

pii_result = pii_agent.invoke({
    "messages": [
        HumanMessage(
            content=contact_request
        )
    ]
})
```

## 결과

입력:

```text
담당자 이메일: creator@example.com.
촬영 가능 날짜를 확인해야 한다고 짧게 정리해 주세요.
```

Middleware 적용 후에는 결과 메시지에:

```text
creator@example.com
```

원문 이메일이 남지 않아야 한다.

응답 예:

```text
촬영 가능한 날짜를 확인해야 합니다.
```

> 실제 redaction 표시 문자열은 사용 중인 라이브러리 버전에 따라 달라질 수 있으므로, 핵심은 **원본 이메일 주소가 모델 입력·결과 State에 그대로 남지 않는지 확인하는 것**이다.

# 14. 최종 서술형 답안

## 14-1. 최종 대본 검토

후속 요청에서는 영상 길이가 **20초**로 변경되었으므로 최종 장면표의 시간 구간이 0초부터 20초까지 끊김 없이 이어지고 전체 합계도 20초인지 확인해야 한다.

또한 기존 합의에서 정한 **두 정리 단계만 유지**해야 하며, 길이를 줄였다는 이유로 새로운 정리 장면을 임의로 추가하면 안 된다. 최신 도입과 마지막 안내를 유지하고, **손만 촬영하며 얼굴과 로고는 제외**해야 한다.

촬영일·게시일·배경음악은 원문에서 확정되지 않은 정보이므로 임의로 생성하지 않고 `확인할 사항`으로 남겨야 한다.

## 14-2. 세 종류의 컨텍스트 구분

### 필수 채널 정보

```python
runtime.store.get(
```

- 검색 순위에 맡기지 않음

```python
runtime.store.search(
```

- 제작 방식의 참고 자료
- 이번 영상의 확정 장면·일정으로 취급하면 안 됨

## 14-3. Trim과 Summary 차이

`trim_messages`는 최근 입력만 남기므로 오래된 중요한 제작 조건이 사라질 수 있다.

```text
전체 대화
   ↓ trim
최근 메시지만 남음
```

반면 누적 요약은:

```text
기존 Summary
+
오래된 Messages
   ↓
새 Summary
```

형태로 중요한 조건을 압축해 보존한다.

따라서 오래된 대화를 모델 입력에서 제거하더라도 대상 고객, 촬영 방식, 담당자, 제외 조건 같은 기존 합의를 Summary에 남길 수 있다.

---

## 14-4. 세 가지 컨텍스트 처리 방식 비교

| 방식 | State 변경 | 모델 입력 변경 | 특징 |
|---|---|---|---|
| `summarize_history` | O | O | 직접 만든 요약 노드. 오래된 메시지를 `RemoveMessage`로 제거하고 Summary 저장 |
| `SummarizationMiddleware` | O | O | Agent 호출 과정에서 요약 처리를 자동화 |
| `wrap_model_call` | X | O | State 원본은 유지하고 이번 모델 요청만 Trim |

핵심은 다음과 같다.

```text
Summary
→ 오래된 정보 자체를 압축해서 보관

wrap_model_call
→ 저장된 기록은 건드리지 않고
  이번 호출에서 읽는 범위만 조절
```

---

## 14-5. 근사 토큰과 실제 사용량

`count_tokens_approximately()`는 이름 그대로 **근사 계산**이다.

따라서:

```python
count_tokens_approximately(model_input)
```

값은 입력 예산을 설계하기 위한 기준이지, 실제 API 청구 토큰이나 모델의 전체 context window 사용량과 정확히 같다고 볼 수 없다.

실제 사용량은 모델·메시지 직렬화·시스템 내부 처리 등에 따라 차이가 날 수 있다.

---

## 14-6. PII 가림의 범위

`PIIMiddleware(..., apply_to_input=True)`는 모델이 처리하는 입력에서 이메일 같은 PII를 가리기 위한 기능이다.

이 기능을 사용했다고 해서:

```text
Store
Checkpointer DB
기존 파일
과거 모든 기록
```

에서 개인정보가 자동 삭제되는 것은 아니다.

즉:

```text
PII Masking
≠
전체 저장 데이터 삭제
```

기존 저장소에 개인정보가 있다면 별도의 삭제·정리 정책이 필요하다.

## 한 줄 구분

```text
Store        = 사용자별 장기기억
Checkpointer = thread별 대화 상태
State        = 현재 그래프의 작업 상태
Context      = user_id 같은 실행 정보
Summary      = 오래된 대화의 핵심 압축
Trim         = 이번 입력에서 읽을 최근 범위 제한
Middleware   = 모델 호출 전후의 컨텍스트 자동 처리
```

# 복습 포인트

1. **항상 필요한 기억은 `get`, 관련 기억은 `search`**
2. **`user_id`는 장기기억, `thread_id`는 개별 대화 구분**
3. **Trim만 하면 과거 합의가 사라질 수 있으므로 Summary와 조합**
4. **State에 저장된 전체 정보와 실제 Model Input은 다를 수 있음**
5. **길어진 대화는 조건부 Edge로 Summary 경로에 보낼 수 있음**
6. **`SummarizationMiddleware`는 요약 자동화**
7. **`wrap_model_call`은 State를 유지하면서 호출 입력만 변경**
8. **PII 가림은 전체 저장 기록 삭제와 다른 개념**
