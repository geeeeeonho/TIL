# 의료 데이터 하이브리드 검색 과제 통합 정리
> LV1 기초 + LV2 응용 통합  
> 중복되는 준비 코드·벡터 검색·문서 단위 중복 제거·Jev 전문 검색은 한 번만 정리함.  
> 노트북에는 실행 출력이 저장되어 있지 않으므로, 제품명·claim ID·검색 점수처럼 실제 데이터가 필요한 값은 **예상 출력 형태**로 표시함.

---

## 0. 전체 흐름

```text
원문/청크 적재
    ↓
Vector Search ─────────────┐
    ↓                      │
문서 단위 중복 제거         │
    ↓                      │
Vector + Cypher 관계 확장   │
                           ├─→ Hybrid Search
Jev 언어 판별 → Fulltext ──┘
                               ↓
                    Text-to-Cypher 관계 조건
                               ↓
                          후보 교집합/보완
                               ↓
                         PageRank 재정렬
                               ↓
                      원문 + 관계 근거 구성
                               ↓
                       근거 인용 답변 생성
                               ↓
                         인용 ID 검증
```

### 핵심 관계

- `TREATS`: 효능
- `HAS_SIDE_EFFECT`: 이상반응
- `CAUTION_FOR`: 주의 대상
- `ABOUT_DRUG`: 제품 원문 ↔ 제품
- `FROM_DOCUMENT`: 청크 ↔ 제품 원문

> 같은 증상이 효능과 이상반응 양쪽에 등장할 수 있으므로 관계 종류를 구분해야 함.

```python
def vector_documents(query_vector, top_k=12):
    """제품별 최고 점수 청크 한 건만 반환."""
    result = vector_retriever.search(
        query_vector=query_vector,

        row = item.metadata

        if row["source_id"] not in seen:

    return rows
```

# 4. 공통 효능 증상으로 다른 제품까지 확장

벡터 검색으로 찾은 제품을 기준 제품 `seed`로 사용한 뒤:

```text
DrugChunk
  ↓ FROM_DOCUMENT
DrugDocument
  ↓ ABOUT_DRUG
seed:Drug
  ↓ TREATS
Symptom
  ↑ TREATS
other:Drug
  ↑ ABOUT_DRUG
other_doc:DrugDocument
```

형태로 탐색함.

## 코드

```python
expansion_query = """
CALL (node) {
    MATCH (node)-[:FROM_DOCUMENT]->(:DrugDocument)-[:ABOUT_DRUG]->(seed:Drug)

    MATCH (seed)-[first:TREATS]->(symptom:Symptom)
          <-[second:TREATS]-(other:Drug)

    MATCH (other_doc:DrugDocument)-[:ABOUT_DRUG]->(other)

    WHERE other <> seed

    WITH
        seed,
        other_doc,
        count(DISTINCT symptom) AS shared_count,
        collect(DISTINCT {
            seed_title: seed.name,
            symptom: symptom.name,
            first_claim: first.claim_id,
            second_claim: second.claim_id
        }) AS paths

    WHERE shared_count >= $min_shared

    RETURN
        other_doc.id AS source_id,
        other_doc.title AS title,
        paths

    ORDER BY source_id
    LIMIT $max_per_seed
}

RETURN
    node.id AS seed_chunk_id,
    score AS seed_score,
    source_id,
    title,
    paths
"""
```

### 핵심

- `TREATS`만 사용함.
- `HAS_SIDE_EFFECT`는 효능 검색에 사용하지 않음.
- `other <> seed`로 자기 자신 제외.
- 후보 제품에 실제 `DrugDocument`가 존재해야 함.
- 공통 증상 수가 `$min_shared` 이상인 후보만 반환.

# 6. 중복 후보를 하나로 합치면서 경로 보존

같은 후보가 여러 seed 청크에서 검색될 수 있으므로:

- 후보 문서는 `source_id` 기준 하나로 합침.
- `seed_score`는 최댓값 유지.
- 출발 청크는 중복 없이 모두 보존.
- 서로 다른 효능 경로도 모두 보존.

## 코드

```python
def merge_expansions(result):
    """중복 후보를 합치되 모든 효능 경로를 보존."""
    merged = {}

    for item in result.items:
        row = item.metadata
        source_id = row["source_id"]

        target = merged.setdefault(
            source_id,
            {
                "source_id": source_id,
                "title": row["title"],
                "seed_score": row["seed_score"],
                "seed_chunks": [],
                "paths": [],
            },
        )

        target["seed_score"] = max(
            target["seed_score"],
            row["seed_score"],
        )

        if row["seed_chunk_id"] not in target["seed_chunks"]:
            target["seed_chunks"].append(row["seed_chunk_id"])

        for path in row["paths"]:
            if path not in target["paths"]:
                target["paths"].append(path)

    return sorted(
        merged.values(),
        key=lambda row: (
            -row["seed_score"],
            row["source_id"],
        ),
    )


expanded_documents = merge_expansions(expanded_result)

display(pd.DataFrame(expanded_documents))
```

### 판단

관계 경로는 다음처럼 읽음.

```text
기준 제품
  └─[first_claim / TREATS]→ 공통 증상
공통 증상
  ←[second_claim / TREATS]─ 후보 제품
```

즉 `first_claim`은 **기준 제품 → 증상**, `second_claim`은 **후보 제품 → 같은 증상**의 효능 근거임.

주의할 점:

> 그래프 확장 후보는 최초 질문의 `위산과다·속쓰림·신트림`을 모두 직접 포함해서 선택된 것이 아님.  
> 벡터 검색으로 찾은 기준 제품과 **효능 증상을 공유한다는 관계**로 추가된 후보임.

따라서 최종 판단에서는 후보 원문의 `효능·효과` 절을 다시 확인해야 함.

# 8. Jev 언어 판별 + Fulltext 검색

한국어 원문을 검색하므로:

- 한국어 질문 → 그대로 검색
- 영어 질문 → LLM으로 한국어 핵심어 변환 후 검색

## 코드

```python
language_classifier = TypeSafeClassifier(
    model=os.getenv("TYPESAFE_MODEL", "jev-1.13.0")
)

language_question = Choice(
    instructions="질문의 주된 언어를 선택하세요.",
    criteria={
        "ko": "한글 질문. 영문 약품명이 섞인 한글 문장도 포함합니다.",
        "en": "한글 없이 영어 단어나 문장으로 작성된 질문입니다.",
    },
)


class KoreanKeywords(BaseModel):
    keywords: list[str] = Field(
        description="중복 없는 한국어 핵심어 3~6개"
    )


lexical_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "영어로 작성된 의약품 문서 검색 질문을 "
        "한국어 핵심어 3~6개로 바꾸세요. "
        "질문에 없는 내용을 추가하지 마세요.",
    ),
    ("human", "{question}"),
])

lexical_chain = (
    lexical_prompt
    | llm.with_structured_output(KoreanKeywords)
)


def fulltext_documents(query, top_k=12):
    """언어에 맞춰 전문 검색 후 제품별 최고 청크만 반환."""
    decision = language_classifier.invoke({
        "state": query,
        "questions": {
            "language": language_question,
        },
    })

    language = decision.choices["language"].choice

    if language == "en":
        terms = lexical_chain.invoke({
            "question": query,
        })

        search_text = " OR ".join(
            f'"{word}"'
            for word in terms.keywords
        )
    else:
        search_text = query

    print(
        "질문 언어:",
        language,
        "| 전문 검색어:",
        search_text,
    )

    hits = run_cypher(
        """
        MATCH (node:DrugChunk)
        SEARCH node IN (
            FULLTEXT INDEX drug_fulltext
            FOR $search_text
            LIMIT $top_k
        ) SCORE AS score

        RETURN
            node.source_id AS source_id,
            node.id AS chunk_id,
            score

        ORDER BY score DESC, chunk_id
        """,
        search_text=search_text,
        top_k=top_k,
    )

    rows = []
    seen = set()

    for row in hits:
        if row["source_id"] not in seen:
            seen.add(row["source_id"])
            rows.append(row)

    return rows


fulltext_rows = fulltext_documents(semantic_query)

display(pd.DataFrame(fulltext_rows))
```

## 예상 결과

```text

전문 검색어: 위산과다 속쓰림 신트림
```


### 판단

`위산과다·속쓰림·신트림`이 실제로 **효능·효과 절**에 적힌 문서가 질문에 직접 맞는 결과임.

- Fulltext: 해당 단어가 직접 등장하는 문서를 찾는 데 유리.
- Dense: 표현이 다르더라도 의미가 유사한 문서를 찾는 데 유리.
- 검색 결과에 단어가 있어도 `주의사항`, `이상반응` 절에만 있다면 효능 근거로 사용하면 안 됨.

```cypher
MATCH (anchor:Drug)-[first:TREATS]->(symptom:Symptom)
      <-[second:TREATS]-(candidate:Drug)

MATCH (d:DrugDocument)-[:ABOUT_DRUG]->(candidate)

MATCH (candidate)-[caution:CAUTION_FOR]->(risk:RiskGroup)

WHERE
    anchor.name = '게보린정(수출명:돌로린정)'
    AND risk.name = '임부'
    AND candidate <> anchor

WITH
    d.id AS source_id,

WHERE shared_count >= 3

RETURN
    source_id,
    title,
    drug_id,
    shared_count,
    paths,
    caution_claims

LIMIT 100
```

# 13. EnsembleRetriever로 Dense + Fulltext 결합

두 검색 결과는 이미 실행했으므로 재검색하지 않고 기존 결과만 RRF로 합침.

## 코드

```python
def as_documents(rows):
    return [
        Document(
            page_content=documents_by_id[
                row["source_id"]
            ]["text"],
            metadata={
                "source_id": row["source_id"],
            },
        )
        for row in rows
    ]


fulltext_retriever = RunnableLambda(
    lambda query: as_documents(
        fulltext_documents(
            query,
            top_k=20,
        )
    )
)

dense_retriever = RunnableLambda(
    lambda query: as_documents(
        vector_documents(
            embedding_model.embed_query(query),
            top_k=20,
        )
    )
)


ensemble_retriever = EnsembleRetriever(
    retrievers=[
        fulltext_retriever,
        dense_retriever,
    ],
    weights=[
        0.4,
        0.6,
    ],
    c=60,
    id_key="source_id",
)


fulltext_docs = as_documents(fulltext_rows)
dense_docs = as_documents(dense_rows)

fused_docs = (
    ensemble_retriever
    .weighted_reciprocal_rank([
        fulltext_docs,
        dense_docs,
    ])
)


fused_rows = [
    {
        "source_id": doc.metadata["source_id"],
        "search_rank": rank,
        "search_score": 1 / rank,
    }
    for rank, doc in enumerate(
        fused_docs,
        1,
    )
]

display(pd.DataFrame(fused_rows))
```

## 결과 구조

| source_id | search_rank | search_score |
|---|---:|---:|
| ... | 1 | 1.000 |
| ... | 2 | 0.500 |
| ... | 3 | 0.333 |
| ... | ... | ... |

> 여기서는 RRF 자체 점수를 후속 PageRank 결합에 직접 사용하지 않고, **통합 결과의 순위 역수 `1 / rank`**를 검색 점수로 다시 정의함.

# 16. Search Score + PageRank 재정렬

전체 14개 제품 PageRank의 중앙값을 고정 기준으로 사용함.

## 코드

```python
pagerank_pivot = median(
    pagerank_by_id.values()
)


def rerank_candidates(rows, weight):
    """검색 점수와 PageRank를 결합해 재정렬."""
    ranked = []

    for row in rows:
        pagerank = pagerank_by_id[
            row["source_id"]
        ]

        pagerank_score = (
            pagerank
            / (
                pagerank
                + pagerank_pivot
            )
        )

        ranked.append({
            **row,
            "pagerank_score": pagerank_score,
            "final_score": (
                (1 - weight)
                * row["search_score"]
                + weight
                * pagerank_score
            ),
        })

    return sorted(
        ranked,
        key=lambda row: (
            -row["final_score"],
            row["search_rank"]
            or float("inf"),
            row["source_id"],
        ),
    )


rankings = {
    weight: rerank_candidates(
        candidates,
        weight,
    )
    for weight in [
        0,
        0.25,
        0.65,
    ]
}


for weight, rows in rankings.items():
    print(
        "PageRank 비중:",
        weight,
    )

    display(
        pd.DataFrame([
            {
                **row,
                "title": documents_by_id[
                    row["source_id"]
                ]["title"],
            }
            for row in rows
        ])
    )
```

## 점수 의미

```text
weight = 0
→ 검색 결과 순위만 사용

weight = 0.25
→ 검색 관련성 75% + 그래프 중심성 25%

weight = 0.65
→ 그래프 중심성의 영향이 더 큼
```

### 판단

이 과제의 최종 답변에는 `weight=0.25`가 가장 자연스러움.

이유:

1. 질문과 직접 맞는 원문 검색 결과를 우선 유지함.
2. PageRank는 후보 간 보조 신호로만 사용함.
3. 중심성이 높은 제품이라는 이유만으로 질문과 덜 관련된 제품이 과도하게 올라오는 것을 방지함.

노트북도 이후 근거 생성 단계에서 다음 결과를 사용함.

```python
ranked = rankings[0.25]
```

세 비중에서 첫 제품이 같다면 제품 선택 자체보다 `final_score` 변화만 비교하면 됨.

# 17. 상위 후보의 원문 + 관계 근거 구성

제품 원문과 관계 claim을 하나의 `evidence` 목록으로 구성함.

## 코드

```python
relations_by_id = {
    row["claim_id"]: row
    for row in drugs["relations"]
}


def build_evidence(
    ranked,
    graph_rows,
    top_n=3,
):
    """상위 제품의 원문·공통 효능·주의 근거를 수집."""
    graph_by_id = {
        row["source_id"]: row
        for row in graph_rows
    }

    evidence = []
    claim_ids = set()

    for row in ranked[:top_n]:
        source_id = row["source_id"]
        doc = documents_by_id[source_id]
        candidate = graph_by_id[source_id]

        evidence.append({
            "evidence_id": source_id,
            "kind": "product_document",
            "title": doc["title"],
            "url": doc["url"],
            "text": doc["text"],
            "shared_paths": candidate["paths"],
        })

        for path in candidate["paths"]:
            claim_ids.update([
                path["first_claim"],
                path["second_claim"],
            ])

        claim_ids.update(
            candidate["caution_claims"]
        )

    for claim_id in sorted(claim_ids):
        claim = relations_by_id[claim_id]

        evidence.append({
            "evidence_id": claim_id,
            "kind": (
                "treats_relation"
                if claim["relation"] == "TREATS"
                else "caution_relation"
            ),
            "title": nodes_by_id[
                claim["subject_id"]
            ]["name"],
            "target": nodes_by_id[
                claim["object_id"]
            ]["name"],
            "url": claim["source_url"],
            "text": claim["evidence"],
        })

    return evidence


ranked = rankings[0.25]

evidence = build_evidence(
    ranked,
    graph_rows,
    top_n=3,
)

display(
    pd.DataFrame(evidence)[
        [
            "evidence_id",
            "kind",
            "url",
        ]
    ]
)
```

## LV2

최종 선택 제품은 다음 조건을 모두 만족해야 함.

```text
1. 콧물·코막힘·재채기·기침·가래 관련 원문 검색 결과
```

### PageRank만으로 검색 누락을 해결할 수 있는가?

```text
불가능
```

PageRank는 이미 만들어진 `candidates`의 **순서만 바꾸는 단계**임.

즉 필요한 원문이 후보 집합 자체에 없다면:

```text
PageRank weight 변경
→ 해결되지 않음
```

대신 앞 단계에서 사용한:

```python
graph_added_ids
```

처럼 그래프 조건으로 찾은 누락 후보를 후보 집합에 다시 추가하거나, 원문 데이터 자체가 없다면 데이터를 추가 적재해야 함.

---

# 21. 전체 코드 흐름 요약

```text
[1] 데이터 적재
      ↓
[2] VectorRetriever
      ↓
[3] 제품별 청크 중복 제거
      ↓
[4] VectorCypherRetriever
    └─ 공통 TREATS 증상으로 확장
      ↓
[5] Jev + Fulltext Search
      ↓
[6] Dense / Fulltext 비교
      ↓
[7] Dense + Fulltext RRF
      ↓
[8] GraphCypherQAChain
    └─ 공통 증상 수 + 임부 조건
      ↓
[9] Graph 후보로 검색 후보 제한
    └─ 누락 후보 추가
      ↓
[10] PageRank
      ↓
[11] Search Score + PageRank 재정렬
      ↓
[12] 제품 원문 + TREATS + CAUTION_FOR 근거 구성
      ↓
[13] GroundedAnswer 생성
      ↓
[14] 인용 ID 검증
```

---

# 핵심 정리

| 기능 | 역할 |
|---|---|
| Vector Search | 의미가 비슷한 문서 탐색 |
| Fulltext Search | 실제 단어가 포함된 문서 탐색 |
| VectorCypherRetriever | 벡터 결과에서 그래프 관계로 확장 |
| GraphCypherQAChain | 자연어 관계 조건을 Cypher로 변환 |
| RRF | Dense + Fulltext 순위 결합 |
| Graph 후보 제한 | 관계 조건을 만족하는 문서만 유지 |
| PageRank | 효능 그래프의 구조적 중심성을 보조 점수로 사용 |
| Evidence 구성 | 원문과 관계 claim을 실제 ID로 연결 |
| Structured Output | 답변 + 인용 ID를 구조화 |
| Citation Check | 존재하지 않는 근거 ID와 인용 누락 검사 |

> 이 과제의 핵심은 **검색 점수만으로 답하지 않고, 문서 검색 → 그래프 조건 → 구조 점수 → 실제 원문 근거 → 인용 검증까지 연결하는 것**임.
