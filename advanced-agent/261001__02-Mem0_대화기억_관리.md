# Mem0로 대화 기억 관리하기

> **핵심:** 사용자 발화에서 장기 기억을 자동 추출하고, 사용자별로 저장·검색·수정·삭제하는 구조

---

## 1. Mem0 핵심 개념

Mem0는 **대화에서 기억할 사실을 LLM으로 추출한 뒤 저장·검색하는 기억 관리 라이브러리**다.

```text
사용자 발화
   ↓
기억 추출 기준(prompt)
   ↓
LLM이 기억할 사실 추출
   ↓
임베딩 + 원문 저장
   ↓
새 질문에서 사용자 기억 조회/검색
   ↓
답변에 활용
```

### LangGraph Store와 차이

| 구분 | LangGraph Store | Mem0 |
|---|---|---|
| 핵심 역할 | 전달받은 데이터를 저장·조회 | 대화에서 기억을 추출하고 저장·검색 |
| 저장 | 정리한 데이터를 `put()` | 대화를 `add()`에 전달 → LLM이 기억 추출 |
| 직접 설계 | 추출·선택·갱신 규칙 전체 | 추출 지침 + 수정·삭제 기준 |
| 검색 | key 또는 의미 검색 | 사용자별 의미 검색 |

이 실습은 기억을 두 공간으로 분리한다.

| 기억 공간 | 내용 | 조회 방식 |
|---|---|---|
| `profile` | 업무 환경, 지속 목표, 도움 방식 등 항상 참고할 정보 | `get_all()` |
| `episodes` | 과거에 직접 해 보고 효과가 있었다고 말한 경험 | `search()` |

```text
현재 대화/감정/일정 → State
지속적인 사용자 정보 → profile
관련 과거 경험       → episodes
```

> `add()`는 기본적으로 **새 기억 추가**다. 기존 기억을 자동으로 수정·삭제하지 않으므로 변경은 `update()` / `delete()`로 별도 처리한다.

## 3. State와 사용자 Context

### State

```python
from typing import Annotated
from typing_extensions import TypedDict
from langchain_core.messages import AnyMessage
from langgraph.graph.message import add_messages

class MemoryState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    user_message: str
    memory_events: list[dict]
    profile_memories: list[dict]
    recalled_memories: list[dict]
```

### 사용자 Context

```python
from dataclasses import dataclass

@dataclass
class UserContext:
    user_id: str
```

- `thread_id`: **현재 대화 흐름** 구분
- `user_id`: **장기 기억의 소유자** 구분

따라서 새 대화를 시작해 `thread_id`가 바뀌어도 같은 `user_id`면 이전 장기 기억을 다시 사용할 수 있다.

## 4. 상담 Agent: 기억 조회 → 답변 → 저장

전체 흐름은 다음과 같다.

```text
START
  ↓
recall_memories
  ├─ profile 전체 조회
  └─ 관련 episodes 검색
  ↓
answer_counseling
  └─ 현재 대화 + 장기 기억으로 답변
  ↓
remember_user_facts
  └─ 이번 사용자 발화에서 새 기억 추출
  ↓
END
```

### 4.1 기억 조회 노드

`profile`은 항상 읽고, `episodes`만 현재 질문과 유사한 기억을 검색한다.

```python
from langgraph.runtime import Runtime

def recall_memories(state: MemoryState, runtime: Runtime[UserContext]):
    question = state["messages"][-1].text

    profile = memory.get_all(
        filters={
            "user_id": runtime.context.user_id,
            "memory_space": "profile",
        },
        top_k=50,
    )["results"]

    found = memory.search(
        question,
        filters={
            "user_id": runtime.context.user_id,
            "memory_space": "episodes",
        },
        top_k=3,
    )

    return {
        "user_message": question,
        "profile_memories": profile,
        "recalled_memories": found["results"],
    }
```

### 4.2 기억을 활용한 답변 노드

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

answer_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "사용자의 현재 요청을 우선해 답하세요. "
        "저장된 사용자 정보와 관련 경험을 참고하되, "
        "기억에 없는 사실은 만들지 마세요.\n"
        "사용자 정보:\n{profile}\n"
        "관련 경험:\n{memories}"
    ),
    MessagesPlaceholder("messages"),
])

answer_chain = answer_prompt | llm
```

```python
def answer_counseling(state: MemoryState):
    response = answer_chain.invoke({
        "profile": json.dumps(
            state["profile_memories"], ensure_ascii=False
        ),
        "memories": json.dumps(
            state["recalled_memories"], ensure_ascii=False
        ),
        "messages": state["messages"],
    })

    return {"messages": [response]}
```

### 4.3 사용자 발화에서 기억 저장

AI 답변이 아니라 앞 노드에서 보관한 `user_message`만 저장 대상으로 사용한다.

```python
def remember_user_facts(
    state: MemoryState,
    runtime: Runtime[UserContext],
):
    message = [
        {"role": "user", "content": state["user_message"]}
    ]

    profile = memory.add(
        message,
        user_id=runtime.context.user_id,
        prompt=profile_policy,
        metadata={
            "memory_space": "profile",
            "source": "user_statement",
        },
    )

    episodes = memory.add(
        message,
        user_id=runtime.context.user_id,
        prompt=episode_policy,
        metadata={
            "memory_space": "episodes",
            "source": "user_statement",
        },
    )

    events = []

    for space, result in [
        ("profile", profile),
        ("episodes", episodes),
    ]:
        for item in result["results"]:
            event = item.copy()
            event["memory_space"] = space
            events.append(event)

    return {"memory_events": events}
```

> 대화가 충분히 누적된 뒤 여러 발화를 모아서 장기기억 추출 로직을 실행하는 구조로도 확장 가능하다.

### 그래프 생성

```python
builder = StateGraph(
    MemoryState,
    context_schema=UserContext,
)

builder.add_node("answer_counseling", answer_counseling)
builder.add_node("remember_user_facts", remember_user_facts)

builder.add_edge("recall_memories", "answer_counseling")
builder.add_edge("answer_counseling", "remember_user_facts")
builder.add_edge("remember_user_facts", END)
```

### 6.3 새 발화와 기존 기억 비교 후 갱신

단순히 `add()`만 계속 사용하면 과거 정보와 새 정보가 함께 남을 수 있다.

예시:

```text
기존 기억: 2020년 대전 거주
새 발화  : 2026년 서울 거주

→ 같은 속성의 최신 값이라면 기존 기억 update
```

전체 갱신 흐름:

```text
새 사용자 발화
      +
기존 profile
      ↓
LLM 비교 판단
      ↓
┌────────┬────────┬────────┬────────┐
│  add   │ update │ delete │  keep  │
└────────┴────────┴────────┴────────┘
      ↓
Mem0 메서드 실행
      ↓
history()로 변경 이력 확인
```

### 구조화 출력 정의

```python
from typing import Literal
from pydantic import BaseModel, Field

class MemoryChange(BaseModel):
    action: Literal["add", "update", "delete", "keep"]
    memory_id: str | None
    new_text: str | None
    reason: str

class MemoryPlan(BaseModel):
    changes: list[MemoryChange]
```

판단 기준:

| action | 의미 |
|---|---|
| `add` | 기존에 없던 지속적인 사용자 정보 |
| `update` | 같은 정보의 값이 변경됨 |
| `delete` | 기존 목표·조건이 명확히 종료됨 |
| `keep` | 동일 내용, 일시적 감정, 모호한 변화 등 |

```python
change_chain = (
    change_prompt
    | llm.with_structured_output(MemoryPlan, strict=True)
)
```

### 기존 기억 가져오기

```python
stored = memory.get_all(
    filters={
        "user_id": change_user_id,
        "memory_space": "profile",
    },
    top_k=50,
)["results"]

memories_by_id = {
    item["id"]: item["memory"]
    for item in stored
}
```

### 변경 판단

```python
plan = change_chain.invoke({
    "message": new_message,
    "memories": json.dumps(
        memories_by_id,
        ensure_ascii=False,
    ),
})
```

예시 발화에는 다음 정보가 함께 포함된다.

```text
고객지원팀 → 교육운영팀        → update
짧은 답변 → 충분한 설명 선호   → update
회의 발언 목표 달성            → delete
메모할 시간 선호               → add
오늘 피곤함                     → keep
```

### 판단 적용

```python
for change in plan.changes:
    if change.action == "add":
        memory.add(
            change.new_text,
            user_id=change_user_id,
            infer=False,
            metadata={
                "memory_space": "profile",
                "source": "user_statement",
            },
        )

    elif change.action == "update":
        memory.update(
            memory_id=change.memory_id,
            text=change.new_text,
        )

    elif change.action == "delete":
        memory.delete(change.memory_id)

    else:
        # keep
        pass
```


## 7. 함께 따라하기: 여행 취향 기억 Agent

상담 Agent와 같은 패턴을 여행 플래너에 적용한다.

```text
사용자 요청
   ↓
recall_travel_memories
   ├─ profile: 평소 여행 취향 전체 조회
   └─ episodes: 관련 과거 여행 경험 검색
   ↓
plan_trip
   ↓
remember_travel_facts
   ↓
END
```

### 기억 기준

```text
profile
- 평소 이동 방식
- 활동 선호
- 일정 밀도

제외
- 이번 목적지
- 날짜/기간
- 예산
- 동행 인원
- 귀가 시각


episodes
- 실제로 다녀온 장소
- 직접 해 본 활동
- 좋거나 불편했다고 말한 경험
```

### State

```python
class TravelState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    user_message: str
    memory_events: list[dict]
    profile_memories: list[dict]
    recalled_memories: list[dict]
```

### 기억 조회

```python
def recall_travel_memories(
    state: TravelState,
    runtime: Runtime[UserContext],
):
    question = state["messages"][-1].text

    profile = memory.get_all(
        filters={
            "user_id": runtime.context.user_id,
            "memory_space": "profile",
        },
        top_k=50,
    )["results"]

    hits = memory.search(
        question,
        filters={
            "user_id": runtime.context.user_id,
            "memory_space": "episodes",
        },
        top_k=3,
    )["results"]

    return {
        "user_message": question,
        "profile_memories": profile,
        "recalled_memories": hits,
    }
```

```python
        },
    )

    episode = memory.add(
        message,
        user_id=runtime.context.user_id,
        prompt=travel_episode_policy,
        metadata={
            "memory_space": "episodes",
            "source": "user_statement",
        },
    )

    events = []

    for space, result in [
        ("profile", profile),
        ("episodes", episode),
    ]:
        for item in result["results"]:
            event = item.copy()
            event["memory_space"] = space
            events.append(event)

    return {"memory_events": events}
```

### 실행 흐름

```text
[첫 부산 여행]
기억 없음
→ 현재 요청만으로 계획
→ 대중교통 / 하루 두 곳 취향 저장
→ 강릉 여행 경험 저장

        ↓ 같은 thread_id

[부산 일정 수정]
기존 대화 유지
+ 저장된 취향 조회
→ 일정 수정

        ↓ 새 thread_id / 같은 user_id

[새 강릉 여행]
부산 대화 기록은 사용하지 않음
+ 사용자 장기 취향은 유지
+ 강릉 관련 경험 검색
→ 새 여행 계획
```

즉, **대화 조건과 장기 취향을 분리**하는 것이 핵심이다.

## 핵심 정리

```text
Mem0
├─ add()       : 사용자 발화에서 기억 추출·추가
├─ get_all()   : 사용자 기억 전체 조회
├─ search()    : 현재 질문과 관련된 기억 의미 검색
├─ get(id)     : 특정 기억 조회
├─ update(id)  : 기존 기억 수정
├─ delete(id)  : 기억 삭제
└─ history(id) : 변경 이력 조회
```

```text
LangGraph + Mem0 기본 패턴

1. 기억 조회
   ├─ 항상 필요한 profile → get_all()
   └─ 질문 관련 episodes → search()

2. 현재 대화 + 기억으로 답변

3. 사용자 발화에서 새 기억 추출
   └─ memory.add()

4. 기존 정보와 충돌하면
   └─ add / update / delete / keep 판단 후 갱신
```

### 가장 중요한 구분

| 항목 | 역할 |
|---|---|
| `State` | 현재 실행·현재 대화 정보 |
| `thread_id` | 한 대화 흐름 식별 |
| `user_id` | 사용자의 장기 기억 식별 |
| `profile` | 매번 참고할 장기 사용자 정보 |
| `episodes` | 현재 질문과 관련 있을 때 검색할 경험 |
| Checkpointer | 대화 상태 저장 |
| Mem0 | 대화를 넘어 유지되는 사용자 기억 관리 |

> **현재 발화는 지금 답변에 바로 사용하고, 답변 뒤 저장된 장기 기억은 다음 요청부터 조회한다.**
