# 벡터 진입점 기반 관계 확장 검색 정리

## 0. 핵심 요약

이 교안의 핵심은 **벡터 검색으로 기준 대상을 찾고, 그래프 관계를 따라 관련 대상을 확장하는 검색 구조**다.

```text
사용자 질문
   ↓
질문 임베딩
   ↓
VectorRetriever
   ↓
유사한 Chunk 탐색
   ↓
Document → 기준 Movie(seed)
   ↓
공통 배우 관계 확장
   ↓
다른 Movie(other)
   ↓
Document ID(source_id) 기준으로 중복 통합
```

별도로 **전문 검색(Full-text Search)**도 수행하고, 벡터 검색과 동일한 `source_id`를 사용해 결과를 비교·통합한다.

---

# 1. 전체 데이터 구조

실습 데이터는 영화 그래프와 영화 원문을 함께 사용한다.

- 그래프 개체: `Movie`, `Person`
- 검색용 문서: `Document`, `Chunk`
- 공통 ID 관리용 레이블: `RAGEntity`
- 주요 관계
  - `Chunk -[:FROM_DOCUMENT]-> Document`
  - `Document -[:ABOUT_MOVIE]-> Movie`
  - `Person -[:ACTED_IN]-> Movie`

## 텍스트 도식

```text
[Chunk]
   │ FROM_DOCUMENT
   ▼
[Document]
   │ ABOUT_MOVIE
   ▼
[Movie A]  ←──────── ACTED_IN ──────── [Person]
                                        │
                                        │ ACTED_IN
                                        ▼
                                    [Movie B]
                                        ▲
                                        │ ABOUT_MOVIE
                                  [Document B]
```

검색 인덱스는 `Chunk`에 적용한다.

```text
Chunk.text      → Full-text Index
Chunk.embedding → Vector Index
```

---

# 2. 검색에서 사용하는 핵심 개념

## 2.1 진입 청크와 진입 영화

**진입 청크(seed chunk)**  
질문과 의미적으로 비슷해서 벡터 검색으로 처음 찾은 `Chunk`.

**진입 영화(seed movie)**  
진입 청크가 속한 원문이 설명하는 영화.

**확장 후보(other movie)**  
진입 영화에서 그래프 관계를 따라 추가로 찾은 영화.

```text
질문
 ↓
진입 Chunk
 ↓
Document
 ↓
진입 Movie
 ↓ 관계 탐색
확장 Movie
```

---

## 2.2 `top_k` 의미

```python
vector_retriever.search(
    query_vector=query_vector,
    top_k=12,
)
```

`top_k=12`는 **영화 12편이 아니라 청크 최대 12개**를 의미한다.

한 영화에서 여러 청크가 동시에 검색될 수 있으므로:

```text
검색 Chunk 12개
        ↓
중복 source_id 제거
        ↓
고유 영화 4편
```

이 결과는 검색 실패가 아니다.

---

## 2.3 `source_id`

`source_id`는 청크가 어느 원문에 속하는지 나타내는 ID다.

벡터 검색, 전문 검색, 관계 확장 결과를 같은 문서 단위로 합칠 때 사용한다.

```python
row["source_id"]
```

```text
Chunk A ─┐
Chunk B ─┼─ 같은 source_id → 같은 Document
Chunk C ─┘
```

# 3. 그래프·문서 적재 핵심 문법

## 3.1 고유 제약

```cypher
CREATE CONSTRAINT rag_entity_id IF NOT EXISTS
FOR (n:RAGEntity)
REQUIRE n.standard_id IS UNIQUE
```

```cypher
CREATE CONSTRAINT document_id IF NOT EXISTS
FOR (n:Document)
REQUIRE n.id IS UNIQUE
```

```cypher
CREATE CONSTRAINT chunk_id IF NOT EXISTS
FOR (n:Chunk)
REQUIRE n.id IS UNIQUE
```

중복 노드 생성을 막기 위한 제약이다.

---

## 3.2 `UNWIND + MERGE`

여러 데이터를 Neo4j에 한 번에 적재할 때 사용하는 핵심 패턴.

```cypher
UNWIND $rows AS item

MERGE (n:RAGEntity {standard_id: item.standard_id})

SET n:Movie,
    n += item.properties,
    n.name = item.name
```

- `UNWIND`: 리스트를 행 단위로 펼침
- `MERGE`: 있으면 재사용, 없으면 생성
- `SET`: 속성 또는 레이블 추가

---

## 3.3 관계 적재

```cypher
MATCH (a:RAGEntity {standard_id: item.subject_id})
MATCH (b:RAGEntity {standard_id: item.object_id})

MERGE (a)-[r:ACTED_IN {claim_id: item.claim_id}]->(b)

SET r.evidence = item.evidence,
    r.source_url = item.source_url
```

관계에도 `claim_id`, `evidence`, `source_url` 등을 저장해 **관계 근거를 보존**한다.

# 4. 검색 인덱스

## 4.1 Vector Index

```cypher
CREATE VECTOR INDEX movie_chunks IF NOT EXISTS
FOR (c:Chunk) ON c.embedding
OPTIONS {
    indexConfig: {
        `vector.dimensions`: 768,
        `vector.similarity_function`: 'cosine'
    }
}
```

구조:

```text
질문 → embedding
        ↓ cosine similarity
Chunk.embedding
```

---

## 4.2 Full-text Index

```cypher
CREATE FULLTEXT INDEX movie_fulltext IF NOT EXISTS
FOR (c:Chunk) ON EACH [c.text]
OPTIONS {
    indexConfig: {
        `fulltext.analyzer`: 'english',
        `fulltext.eventually_consistent`: false
    }
}
```

`Chunk.text`를 대상으로 단어 기반 검색을 수행한다.

교안에서는 Neo4j Full-text Search가 Lucene을 사용하며 기본 점수 모델은 BM25라고 설명한다.

# 5. VectorRetriever: 의미 기반 진입점 검색

## 5.1 검색 결과 형식 지정

```python
def format_vector(record):

    return RetrieverResultItem(

        metadata={

            "source_id": node["source_id"],
```

# 6. 청크 결과를 문서 단위로 통합

한 영화의 여러 청크가 동시에 검색될 수 있으므로 `source_id`를 기준으로 중복을 제거한다.

```python
def vector_documents(query_vector, top_k=12):
    result = vector_retriever.search(
        query_vector=query_vector,
        top_k=top_k,
    )

    rows = []
    seen = set()

    for item in result.items:
        row = item.metadata

        if row["source_id"] not in seen:
            seen.add(row["source_id"])
            rows.append(dict(row))

    return rows
```

검색 결과가 점수순으로 들어오므로 같은 영화에서는 **처음 나온 최고 점수 청크**가 대표가 된다.

```text
Chunk 1  Movie A  score 0.91  ← 유지
Chunk 2  Movie A  score 0.87
Chunk 3  Movie B  score 0.82  ← 유지
```

# 7. VectorCypherRetriever: 벡터 검색 + 관계 확장

`VectorCypherRetriever`는 두 단계를 연결한다.

```text
1. Vector Search
   질문과 비슷한 Chunk 탐색

2. Cypher Expansion
   해당 Chunk에서 그래프 관계 탐색
```

## 전체 관계 확장

```text
Chunk
  ↓ FROM_DOCUMENT
Document
  ↓ ABOUT_MOVIE
Movie A(seed)
  ↑ ACTED_IN
Person(actor)
  ↓ ACTED_IN
Movie B(other)
  ↑ ABOUT_MOVIE
Document B
```

확장 영화는 **질문과 줄거리가 비슷해서 선택되는 것이 아니다.**

선정 기준은 이 실습에서는 **공통 출연 배우**다.

---

# 8. 관계 확장 Cypher

```cypher
CALL (node) {

    MATCH (node)
          -[:FROM_DOCUMENT]->
          (:Document)
          -[:ABOUT_MOVIE]->
          (seed:Movie)

    MATCH (seed)
          <-[first:ACTED_IN]-
          (actor:Person)
          -[second:ACTED_IN]->
          (other:Movie)

    MATCH (other_doc:Document)
          -[:ABOUT_MOVIE]->
          (other)

    WHERE other <> seed
      AND other.released >= $min_year

    RETURN
        other_doc.id AS source_id,
        other_doc.title AS title,

        collect(DISTINCT {
            seed_title: seed.title,
            actor: actor.name,
            first_claim: first.claim_id,
            second_claim: second.claim_id
        }) AS paths

    ORDER BY source_id
    LIMIT $max_per_seed
}

RETURN
    node.id AS seed_chunk_id,
    score AS seed_score,
    source_id,
    title,
    paths
```

---

## 8.1 `CALL (node) { ... }`

벡터 검색으로 찾은 **각 Chunk마다 내부 Cypher를 실행**한다.

```text
Chunk 1 → 관계 확장
Chunk 2 → 관계 확장
Chunk 3 → 관계 확장
```

---

## 8.2 주요 변수

| 변수 | 의미 |
|---|---|
| `node` | 벡터 검색으로 찾은 Chunk |
| `score` | 질문 ↔ 진입 Chunk 유사도 |
| `seed` | 기준 영화 |
| `actor` | 공통 출연 배우 |
| `other` | 확장 후보 영화 |
| `min_year` | 최소 개봉연도 |
| `max_per_seed` | 진입 청크별 최대 확장 영화 수 |

---

## 8.3 `collect(DISTINCT ...)`

```cypher
collect(DISTINCT {
    seed_title: seed.title,
    actor: actor.name,
    first_claim: first.claim_id,
    second_claim: second.claim_id
}) AS paths
```

하나의 후보 영화가 여러 배우로 연결될 수 있으므로 관계 경로를 목록으로 보존한다.

```text
Movie A
 ├─ Actor 1 → Movie B
 └─ Actor 2 → Movie B
```

결과:

```python
paths = [
    {
        "seed_title": "...",
        "actor": "Actor 1",
        "first_claim": "...",
        "second_claim": "...",
    },
    {
        "seed_title": "...",
        "actor": "Actor 2",
        "first_claim": "...",
        "second_claim": "...",
    },
]
```

즉 `paths`는 **왜 이 후보가 검색됐는지 설명하는 근거**다.

# 11. 확장 결과 중복 통합

여러 진입 청크에서 동일한 후보 영화가 발견될 수 있다.

```python
def merge_expansions(result):
    merged = {}

    for item in result.items:
        row = item.metadata
        source_id = row["source_id"]

        target = merged.setdefault(
            source_id,
            {
                "source_id": source_id,
                "title": row["title"],
                "seed_score": row["seed_score"],
                "seed_chunks": [],
                "paths": [],
            },
        )

        target["seed_score"] = max(
            target["seed_score"],
            row["seed_score"],
        )

        if row["seed_chunk_id"] not in target["seed_chunks"]:
            target["seed_chunks"].append(row["seed_chunk_id"])

        for path in row["paths"]:
            if path not in target["paths"]:
                target["paths"].append(path)

    return sorted(
        merged.values(),
        key=lambda row: (-row["seed_score"], row["source_id"]),
    )
```

통합 규칙:

```text
같은 source_id
   ├─ seed_score  → 가장 높은 값 유지
   ├─ seed_chunks → 서로 다른 시작 청크 모두 보존
   └─ paths       → 서로 다른 관계 경로 모두 보존
```

---

# 12. `seed_score` 해석 주의

`seed_score`는 **확장 후보 영화의 줄거리 유사도 점수**가 아니다.

```text
질문
 ↓
진입 Chunk ── similarity = seed_score
 ↓
관계 확장
 ↓
후보 Movie
```

즉:

> `seed_score = 질문과 진입 청크의 유사도`

공통 배우가 여러 명이라고 점수를 더하면 안 된다.

```text
배우 3명 공유
≠
seed_score × 3
```

관계 수는 `paths`로 보존하고, 유사도는 별도로 유지한다.


# 16. Full-text 검색 핵심 문법

교안 마지막의 **핵심 코드 이어서 보기**에서는 Cypher 25의 `SEARCH ... FULLTEXT INDEX` 형태를 사용한다.

```cypher
MATCH (node:Chunk)

SEARCH node IN (
    FULLTEXT INDEX movie_fulltext
    FOR $search_text
    LIMIT $top_k
) SCORE AS score

RETURN
    node.source_id AS source_id,
    node.id AS chunk_id,
    score

ORDER BY score DESC, chunk_id
```

그 후 `source_id` 중복을 제거해 문서별 최고 점수 청크만 남긴다.

> 참고: 노트북 본문 중간에는 `CALL db.index.fulltext.queryNodes(...)` 형태도 등장한다.  
> 마지막 핵심 코드에서는 `SEARCH ... FULLTEXT INDEX` 문법을 사용하므로 이 정리에서는 후자를 기준으로 둔다.

# 17. 세 검색 경로 비교

이 교안에서는 결과적으로 세 가지 검색 경로를 다룬다.

| 검색 | 역할 | 기준 |
|---|---|---|
| `VectorRetriever` | 의미 기반 검색 | 질문 ↔ Chunk 의미 유사도 |
| `VectorCypherRetriever` | 의미 검색 후 관계 확장 | 유사 Chunk + 그래프 관계 |
| Full-text Search | 단어 기반 검색 | 검색어 ↔ Chunk 텍스트 |

## 구조

```text
                         ┌─ VectorRetriever
사용자 질문 ─────────────┤
                         │
                         ├─ VectorCypherRetriever
                         │   └─ Vector Search → Cypher 관계 확장
                         │
                         └─ Full-text Search
                             └─ 언어 처리 → 키워드 검색
```

벡터 검색과 전문 검색은 **기준 영화를 찾는 역할**이고,

관계 확장은 **기준 영화와 연결된 다른 대상을 찾는 역할**이다.

---

```text

                      │   사용자 질문      │
                      └─────────┬──────────┘
                                │
                        질문 임베딩 생성
                                │
              ┌─────────────────┴─────────────────┐
              │                                   │
       VectorRetriever                    Full-text Search
              │                                   │
         유사 Chunk                           단어 일치 Chunk
              │                                   │
       source_id 중복 제거                 source_id 중복 제거
              │                                   │
         기준 Document                       기준 Document
              │
              ▼
      VectorCypherRetriever
              │
      Movie → Actor → Movie
              │
       확장 후보 Document
              │
      source_id 기준 병합
              │
       paths 관계 근거 보존
```

# 19. 일반화 가능한 패턴

영화가 아니어도 동일한 방식으로 사용할 수 있다.

예를 들어:

```text
사용자 증상
   ↓
Vector Search
   ↓
증상과 관련된 Chunk
   ↓
관련 질병
   ↓ Graph Relationship
표적 유전자
```

즉 핵심 패턴은 다음과 같다.

```text
비정형 질문
   ↓
벡터 검색으로 진입점 탐색
   ↓
구조화된 그래프 관계 확장
   ↓
연관 대상 + 관계 근거 반환
```

# 20. 시험·복습용 핵심

### `VectorRetriever`

```text
질문과 의미가 비슷한 Chunk를 찾음
```

### `VectorCypherRetriever`

```text
Vector Search 결과를 시작점으로 Cypher 관계를 추가 탐색
```

### `source_id`

```text
여러 Chunk를 동일 원문 단위로 묶는 공통 ID
```

### `top_k`

```text
검색할 진입 Chunk 수
```

### `max_per_seed`

```text
진입 Chunk 하나에서 관계로 확장할 최대 후보 수
```

### `seed_score`

```text
질문 ↔ 진입 Chunk 유사도
확장 후보 자체의 유사도가 아님
```

### `paths`

```text
후보가 어떤 관계 경로로 검색됐는지 기록한 근거
```

### 최종 한 줄

> **Vector Search로 비정형 질문의 진입점을 찾고, Cypher로 구조화된 관계를 확장하며, `source_id`와 `paths`로 문서 중복과 관계 근거를 관리한다.**
