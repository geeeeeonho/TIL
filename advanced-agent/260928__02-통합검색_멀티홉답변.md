# 통합 검색 + 멀티홉 근거 답변 정리

## 0. 핵심 요약

이 교안의 핵심은 **서로 역할이 다른 검색 경로를 분리해 실행한 뒤 하나의 원문 ID로 통합하고, 그래프 조건·검색 관련성·그래프 중심성을 순서대로 적용해 근거 기반 답변을 만드는 것**이다.

```text
사용자 질문
   │
   ├─ 줄거리 조건 ───────────────┐
   │                             │
   │                    ┌─ Full-text Search
   │                    │
   │                    └─ Vector Search
   │                             │
   │                        가중 RRF 결합
   │                             │
   └─ 배우·연도 조건 → Text-to-Cypher
                                 │
                       관계 조건 후보 집합
                                 │
              RRF 결과 ∩ 관계 조건 후보
                                 │
                 + 그래프 전용 후보 보완
                                 │
                       PageRank 재정렬
                                 │
        ┌────────────────────────┼───────────────────────┐
        │                        │                       │
     줄거리 원문             영화·연도               출연 관계
       plot               movie_record             cast_relation
        │                        │                       │
        └──────────────── evidence_id ──────────────────┘
                                 │
                           LLM 답변 생성
                                 │
                           인용 ID 검증
```

# 1. 교안 01과 차이

| 구조 | 검색 방식 | 그래프 역할 |
|---|---|---|
| 교안 01 | `VectorCypherRetriever` | 벡터 검색으로 진입점을 찾은 뒤 관계를 따라 후보 확장 |
| 교안 02 | `GraphCypherQAChain` + 전문·벡터 검색 | 관계 조건 후보를 별도 검색한 뒤 검색 결과와 결합 |

교안 02에서는 **줄거리 검색과 관계 조건 검색을 분리**한다.

예제 질문:

```text
The Matrix와 배우를 공유하고
1999년 이전에 개봉한 다른 영화 중,
뇌에 기밀 데이터를 저장·운반하다 위험에 빠지는 작품은?
```

질문 분해:

```text
줄거리 의미 조건
→ "기밀 정보를 뇌 속 장치에 저장해 운반하는 사람이 위험에 빠지는 영화"

관계 조건
→ The Matrix와 배우 최소 1명 공유
→ 1999년 이전 개봉
→ The Matrix 자체는 제외
```

# 2. 데이터와 그래프 구조

검색 대상은 `Chunk`, 원문은 `Document`, 영화·배우 관계는 `Movie`, `Person`으로 관리한다.

```text
[Chunk]
   │ FROM_DOCUMENT
   ▼
[Document]
   │ ABOUT_MOVIE
   ▼
[Movie A]
   ▲
   │ ACTED_IN
[Person]
   │ ACTED_IN
   ▼
[Movie B]
```

검색 인덱스:

```text
Day49MovieChunk.embedding
        ↓
Vector Index: movie_chunks

Day49MovieChunk.text
        ↓
Full-text Index: movie_fulltext
```

`source_id`는 모든 검색 결과를 **같은 원문 단위로 연결하는 공통 키**다.

```python
semantic_query = "기밀 정보를 뇌 속 장치에 저장해 운반하는 사람이 위험에 빠지는 영화"
```

```python
for item in result.items:
    row = item.metadata
```

# 5. Text-to-Cypher: 관계 조건 후보 검색

## 5.1 핵심 개념

`GraphCypherQAChain`의 역할:

```text
자연어 관계 질문
      ↓
LLM
      ↓
Cypher 생성
      ↓
Neo4j 실행
      ↓
관계 조건 후보 + 관계 근거
```

이 단계는 **줄거리 유사도를 판단하지 않는다.**

```text
그래프 검색
→ The Matrix와 배우 공유?
→ 1999년 이전?
→ 조건을 만족하는 영화는?

전문·벡터 검색
→ 줄거리가 질문과 비슷한가?
```

---

## 5.3 Cypher 생성 프롬프트

```python
cypher_prompt = PromptTemplate.from_template("""
다음 스키마만 사용해 조회용 Cypher 하나를 작성하세요.
{schema}

사용할 관계 경로:
(base:Movie)<-[first:ACTED_IN]-(actor:Person)
-[second:ACTED_IN]->(candidate:Movie)
<-[:ABOUT_MOVIE]-(d:Document)

기준 영화명·개봉연도·최소 공유 배우 수는 질문에서 읽으세요.

RETURN
    d.id AS source_id,
    candidate.title AS title,
    candidate.released AS released,
    candidate.standard_id AS movie_id,
    shared_count,
    paths
ORDER BY source_id
LIMIT 100

질문: {question}
""")
```

## 5.4 GraphCypherQAChain

```python
graph_chain = GraphCypherQAChain.from_llm(
    llm=llm,
    graph=graph,
    cypher_prompt=cypher_prompt,
    include_types=[
        "Movie",
        "Person",
        "Document",
        "ACTED_IN",
        "ABOUT_MOVIE",
    ],
    return_direct=True,
    return_intermediate_steps=True,
    top_k=100,
    allow_dangerous_requests=True,
)
```

주요 설정:

| 옵션 | 의미 |
|---|---|
| `return_direct=True` | 별도 LLM 답변 없이 DB 조회 결과 반환 |
| `return_intermediate_steps=True` | 생성된 Cypher 확인 |
| `include_types` | 사용할 그래프 스키마 범위 제한 |
| `top_k=100` | 관계 조건 후보가 중간에서 잘리지 않도록 충분히 확보 |

> `allow_dangerous_requests=True`는 권한 제한 기능이 아니다.  
> LLM이 생성한 Cypher를 실제로 확인해야 한다.

최종 코드에서는 생성 Cypher를 볼 필요가 없으면:

```python
return_intermediate_steps=False
```

로 둘 수 있다.

# 6. 생성되는 관계 검색 Cypher

```cypher
MATCH
    (base:Movie)
    <-[first:ACTED_IN]-
    (actor:Person)
    -[second:ACTED_IN]->
    (candidate:Movie)
    <-[:ABOUT_MOVIE]-
    (d:Document)

WHERE
    base.title = "The Matrix"
    AND candidate.released < 1999
    AND candidate <> base

WITH
    candidate,
    d,
    count(DISTINCT actor) AS shared_count,
    collect(DISTINCT {
        actor: actor.name,
        first_claim: first.claim_id,
        second_claim: second.claim_id
    }) AS paths

WHERE shared_count >= 1

RETURN
    d.id AS source_id,
    candidate.title AS title,
    candidate.released AS released,
    candidate.standard_id AS movie_id,
    shared_count,
    paths
```

예제 관계 후보:

```text
The Devil's Advocate
Johnny Mnemonic
```

둘 다 관계 조건은 만족하지만 **줄거리까지 질문과 맞는 것은 별도로 검색 결과와 원문에서 판단**한다.

# 9. 전문 + 벡터 검색을 EnsembleRetriever로 결합

## 9.1 Document 형식으로 통일

```python
def as_documents(rows):
    return [
        Document(
            page_content=
                documents_by_id[
                    row["source_id"]
                ]["text"],
            metadata={
                "source_id":
                    row["source_id"]
            },
        )
        for row in rows
    ]
```

---

## 9.2 기존 함수를 Runnable로 연결

```python
fulltext_retriever = RunnableLambda(
    lambda query:
        as_documents(
            fulltext_documents(
                query,
                top_k=30,
            )
        )
)

dense_retriever = RunnableLambda(
    lambda query:
        as_documents(
            vector_documents(
                embedding_model.embed_query(query),
                top_k=30,
            )
        )
)
```

---

## 9.3 EnsembleRetriever

```python
ensemble_retriever = EnsembleRetriever(
    retrievers=[
        fulltext_retriever,
        dense_retriever,
    ],
    weights=[0.4, 0.6],
    c=60,
    id_key="source_id",
)
```

의미:

```text
Full-text 순위 ── 0.4 ─┐
                       ├─ Weighted RRF → 통합 순위
Vector 순위 ───── 0.6 ─┘
```

RRF 기본 형태:

```text
점수 += weight / (c + rank)
```

여기서는:

```text
c = 60
Full-text weight = 0.4
Vector weight    = 0.6
```

`id_key="source_id"`로 두 검색에서 같은 원문을 하나로 합친다.

# 10. RRF 결과 만들기

```python
fulltext_docs = fulltext_retriever.invoke(
    semantic_query
)

dense_docs = as_documents(
    vector_documents(
        query_vector,
        top_k=30,
    )
)

fused_docs = (
    ensemble_retriever
    .weighted_reciprocal_rank(
        [
            fulltext_docs,
            dense_docs,
        ]
    )
)
```

통합 순위를 저장:

```python
fused_rows = [
    {
        "source_id":
            doc.metadata["source_id"],
        "search_rank": rank,
        "search_score": 1 / rank,
    }
    for rank, doc
    in enumerate(
        fused_docs,
        start=1,
    )
]
```

## 중요

여기서:

```python
search_score = 1 / rank
```

은 **실제 RRF 점수 자체가 아니다.**

```text
EnsembleRetriever
→ RRF로 순서 결정

그 결과의 최종 rank
→ 1 / rank
→ 이후 PageRank와 결합하기 위한 간단한 검색 순위 점수
```

즉:

```text
RRF = 검색 결과 융합 방식
search_score = 융합 후 순위를 다시 0~1 형태로 표현한 값
```


# 12. 그래프 전용 후보 보완

전문·벡터 검색에서 빠졌지만 그래프 조건은 만족한 영화도 버리지 않는다.

```python
fused_ids = {
    row["source_id"]
    for row in fused_rows
}

graph_only_ids = (
    allowed_ids - fused_ids
)
```

```python
candidate_rows += [
    {
        "source_id": source_id,
        "search_rank": None,
        "search_score": 0.0,
    }
    for source_id
    in sorted(graph_only_ids)
]
```

즉:

```text
Hybrid/RRF : A, B
Graph      : B, C

최종 후보
B → 검색 점수 유지
C → search_score = 0
```

그래프 결과에는 **RRF 점수를 임의로 만들지 않는다.**

그래프는:

```text
후보 조건
+
관계 근거
```

를 제공한다.

# 13. 세 검색 경로의 역할

| 경로 | 찾는 것 | 최종 역할 |
|---|---|---|
| Full-text | 단어가 맞는 줄거리 | 검색 순위 |
| Vector | 의미가 비슷한 줄거리 | 검색 순위 |
| Graph / Text-to-Cypher | 배우·연도 등 구조화 조건 | 후보 필터 + 관계 근거 |

핵심:

```text

```

그래프 후보라고 해서 줄거리까지 정답인 것은 아니다.

# 15. PageRank 포화 변환

PageRank 원점수를 그대로 검색 점수와 합치지 않는다.

전체 영화 PageRank 중앙값:

```python
pagerank_pivot = median(
    pagerank_by_id.values()
)
```

포화 함수:

```python
pagerank_score = (
    pagerank
    / (pagerank + pagerank_pivot)
)
```

특성:

```text
PageRank = 중앙값
→ score = 0.5

PageRank가 매우 커짐
→ score는 1에 접근

큰 PageRank 차이
→ 최종 점수 차이가 과도하게 커지는 것을 억제
```

---

# 16. 검색 점수 + PageRank 재정렬

```python
final_score = (
    (1 - weight) * search_score
    + weight * pagerank_score
)
```

코드:

```python
def rerank_candidates(rows, weight):
    ranked = []

    for row in rows:
        pagerank = pagerank_by_id[
            row["source_id"]
        ]

        pagerank_score = (
            pagerank
            / (
                pagerank
                + pagerank_pivot
            )
        )

        final_score = (
            (1 - weight)
            * row["search_score"]
            + weight
            * pagerank_score
        )

        ranked.append({
            **row,
            "pagerank_score":
                pagerank_score,
            "final_score":
                final_score,
        })

    return sorted(
        ranked,
        key=lambda row: (
            -row["final_score"],
            row["search_rank"]
            or float("inf"),
            row["source_id"],
        ),
    )
```

# 17. PageRank 비중의 의미

```python
for weight in [

    0.6,
```

```text
weight = 0
→ 검색 관련성만 사용

weight = 0.2
→ 검색 관련성 중심 + PageRank 약간 반영

weight = 0.6
→ 그래프 중심성 영향이 커짐
```

주의:

> PageRank는 **그래프에서 중심적인 영화인지**를 나타낸다.  
> 질문의 줄거리와 얼마나 비슷한지를 나타내는 점수가 아니다.

따라서 PageRank 비중이 너무 크면 **관계망 중심 영화가 질문 관련성을 덮을 수 있다.**

# 18. 멀티홉 근거 구성

최종 답변에서는 서로 다른 종류의 근거를 함께 사용한다.

```text
후보 영화
   │
   ├─ Document 원문
   │      └─ plot
   │
   ├─ Movie 속성
   │      └─ movie_record
```

| `kind` | 확인 내용 |
|---|---|
| `plot` | 질문의 줄거리 조건 |
| `movie_record` | 제목·개봉연도 |
| `cast_relation` | 기준 영화와 후보 영화의 공통 배우 관계 |

# 20. `build_evidence()`

```python
def build_evidence(
    ranked,
    graph_rows,
    top_n=3,
):
    graph_by_id = {
        row["source_id"]: row
        for row in graph_rows
    }

    evidence = []
    claim_ids = set()

    for row in ranked[:top_n]:
        source_id = row["source_id"]

        doc = documents_by_id[
            source_id
        ]

        movie = graph_by_id[
            source_id
        ]

        evidence.extend([
            {
                "evidence_id":
                    source_id,
                "kind":
                    "plot",
                "title":
                    doc["title"],
                "url":
                    doc["url"],
                "text":
                    doc["text"],
            },
            {
                "evidence_id":
                    "movie:"
                    + movie["movie_id"],
                "kind":
                    "movie_record",
                "text":
                    f"{movie['title']} / "
                    f"개봉연도: "
                    f"{movie['released']}",
            },
        ])

        for path in movie["paths"]:
            claim_ids.update([
                path["first_claim"],
                path["second_claim"],
            ])

    for claim_id in sorted(
        claim_ids
    ):
        claim = relations_by_id[
            claim_id
        ]

        evidence.append({
            "evidence_id":
                claim_id,
            "kind":
                "cast_relation",
            "text":
                claim["evidence"],
        })

    return evidence
```

구조:

```text
상위 후보
 ↓
source_id
 ├─ 원문 줄거리
 ├─ 영화 속성
 └─ paths
      ├─ 기준 영화 출연 claim_id
      └─ 후보 영화 출연 claim_id
            ↓
        실제 관계 근거
```

# 23. 인용 검증

LLM이 존재하지 않는 ID를 만들거나, 본문과 `evidence_ids` 목록이 다를 수 있으므로 검증한다.

본문의 `[ID]` 추출:

```python
inline_ids = set(
    re.findall(
        r"\[([^\[\]]+)\]",
        answer.answer,
    )
)
```

제공하지 않은 ID 탐지:

```python
unknown_ids = (
    inline_ids
    | set(answer.evidence_ids)
) - set(evidence_by_id)
```

본문과 목록 차이:

```python
citation_gap = (
    inline_ids
    ^ set(answer.evidence_ids)
)
```

정상 결과:

```text
제공하지 않은 인용 ID: set()
본문과 목록의 차이: set()
```

즉:

```text
본문 인용 ID
=
evidence_ids
=
실제로 제공한 근거 ID
```

가 되어야 한다.

# 24. 전체 코드 실행 흐름

```python
# 1. 질문 분리
question = "..."
semantic_query = "줄거리 의미 검색용 질문"
graph_request = "배우·연도 관계 조건 질문"


# 2. 질문 임베딩
query_vector = (
    embedding_model
    .embed_query(
        semantic_query
    )
)


# 3. 그래프 조건 검색
graph_result = graph_chain.invoke({
    "query": graph_request
})

graph_rows = graph_result["result"]

allowed_ids = {
    row["source_id"]
    for row in graph_rows
}


# 4. 전문 검색
fulltext_docs = (
    fulltext_retriever
    .invoke(
        semantic_query
    )
)


# 5. 벡터 검색
dense_docs = as_documents(
    vector_documents(
        query_vector,
        top_k=30,
    )
)


# 6. RRF 통합
fused_docs = (
    ensemble_retriever
    .weighted_reciprocal_rank(
        [
            fulltext_docs,
            dense_docs,
        ]
    )
)


# 7. 통합 순위 저장
fused_rows = [
    {
        "source_id":
            doc.metadata["source_id"],
        "search_rank":
            rank,
        "search_score":
            1 / rank,
    }
    for rank, doc
    in enumerate(
        fused_docs,
        start=1,
    )
]


# 8. 관계 조건 적용
candidate_rows = [
    row
    for row in fused_rows
    if row["source_id"]
    in allowed_ids
]


# 9. 그래프 전용 후보 추가
fused_ids = {
    row["source_id"]
    for row in fused_rows
}

candidate_rows += [
    {
        "source_id":
            source_id,
        "search_rank":
            None,
        "search_score":
            0.0,
    }
    for source_id
    in sorted(
        allowed_ids - fused_ids
    )
]


# 10. PageRank 재정렬
final_ranked = rerank_candidates(
    candidate_rows,
    weight=0.2,
)


# 11. 근거 생성
evidence = build_evidence(
    final_ranked,
    graph_rows,
    top_n=3,
)


# 12. 답변 생성
answer = answer_chain.invoke({
    "question": question,
    "context": json.dumps(
        evidence,
        ensure_ascii=False,
    ),
})
```

# 26. 점수와 역할 구분

| 값 | 의미 |
|---|---|
| Vector `score` | 질문과 Chunk 의미 유사도 |
| Full-text `score` | 전문 검색 점수 |
| RRF | 전문·벡터 검색 순위를 결합하는 방식 |
| `search_rank` | RRF 결합 후 최종 검색 순위 |
| `search_score` | `1 / search_rank` |
| `pagerank` | 영화·배우 관계망에서의 중심성 |
| `pagerank_score` | PageRank를 포화 함수로 변환한 값 |
| `final_score` | 검색 순위 점수 + PageRank 점수의 가중 결합 |
| `shared_count` | 기준 영화와 공유하는 배우 수 |

특히:

```text
PageRank ≠ 의미 유사도
shared_count ≠ 의미 유사도
search_score ≠ 실제 RRF 원점수
```

# 27. 결과가 이상할 때 확인 순서

| 문제 | 확인할 부분 |
|---|---|
| 필요한 영화가 검색 후보에 없음 | `top_k`, 검색 언어, 검색어 |
| 그래프 후보가 이상함 | 생성된 Cypher의 기준 영화·연도·배우 수 |
| 통합 후 필요한 후보가 사라짐 | `allowed_ids`, 연도 경계, 기준 영화 제외 조건 |
| 후보는 있는데 최종 순위가 이상함 | RRF 가중치, PageRank `weight` |
| 중심적인 영화만 계속 올라옴 | PageRank 비중 낮추기 |
| 배우·연도 설명이 틀림 | `paths`, `claim_id`, Movie 속성 |
| 인용이 근거와 맞지 않음 | `evidence_id`가 실제 주장을 뒷받침하는지 확인 |

한 번에 여러 설정을 바꾸지 말고 **같은 질문·후보 수를 유지한 채 한 요소씩 비교**한다.
