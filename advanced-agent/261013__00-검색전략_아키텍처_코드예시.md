# 의약품 상담 검색 전략·아키텍처 선정 — 코드·결과 정리

의약품 안내문 **394건**, 평가 질문 **60개**(묘사·이름·조건·관계·집계 각 12개)를 대상으로 검색 전략부터 저장소까지 결정한다. 임베딩 모델은 이전 과제에서 선택한 **KURE-v1(1024차원)**으로 고정한다.

> **결과 표기:** 원본 `.ipynb`에는 코드 셀의 실제 실행 출력이 없음. 아래 검색 성능 수치는 노트북의 **「결과 읽기」에 제공된 참고값**으로 구성했고, 일부 질문별 집계표와 실행 시간·비용은 **해당 수치와 일치하도록 만든 예시 결과**다. 실제 데이터와 환경에서 실행하면 바뀔 수 있음. 실제 검색 및 GPU/CPU 실행은 수행하지 않았으며, 뒤의 비용·선정 계산은 예시 가정으로 별도 검산함.
>
> **선행 조건:** `data/과제/docs.jsonl`, `questions.json`, 이전 과제 결과 JSON(또는 제공 사본), `nlpai-lab/KURE-v1` 다운로드 및 관련 라이브러리가 준비되어 있어야 함. 이 실습에서 최종 Neo4j에 연결하는 코드는 실행하지 않음.

**전체 흐름**

```text
질문 입력
  ├─ 묘사·이름·조건 → 문서 검색 (BM25 / Dense / Hybrid 비교)
  │                   └─ 단일 Dense 선택 (검색 전략 라우터 생략)
  └─ 관계·집계     → 구조화 질의 (Text2Cypher)
                          ↓
       벡터 정밀도 결정(binary) → 저장소 판정(Neo4j)
                          ↓
     후보 A/B/C 네 축 평가 → 제약·지배·점수 → 시나리오·민감도
                          ↓
                 최종 ADR-004 작성
```

## 1. 데이터 준비와 질문별 처리 경로

### 1-1. 문서·평가셋 및 임베딩 모델 준비

`source_id`에 원문 ID를 저장한다. 검색 결과를 정답 ID와 대조하기 위한 필수 정보.

**코드**

```python
# 실습에 필요한 라이브러리를 불러옵니다. 나머지는 처음 쓰는 셀에서 불러옵니다.
import json
from pathlib import Path

import numpy as np
import pandas as pd

# 단원 폴더(material_dir) 아래 data·output 폴더 경로
material_dir = Path(".").resolve()
data_dir = material_dir / "data"
output_dir = material_dir / "output"
output_dir.mkdir(parents=True, exist_ok=True)

# 과제 자료 폴더가 있는지
print("과제 자료 폴더 있음:", (data_dir / "과제").exists())

def read_json(name):
    """data 폴더의 JSON 파일을 목록 또는 딕셔너리로 읽습니다."""
    return json.loads((data_dir / name).read_text(encoding="utf-8"))

# 의약품 안내문(JSON Lines라 한 줄씩 읽기)과 평가 질문
docs = [json.loads(line) for line in (data_dir / "과제" / "docs.jsonl").read_text(encoding="utf-8").splitlines()]
questions = read_json("과제/questions.json")
drug_ids = [doc["doc_id"] for doc in docs]  # 원문 ID(안내문 순서)
print("안내문:", len(docs), "| 질문:", len(questions))

# 유형별 질문 수
question_table = pd.DataFrame(questions)
display(question_table["question_type"].value_counts().rename("질문 수").to_frame())

# 과제 01 결과 파일이 있으면 사용하고, 없으면 제공 사본 사용
choice_path = output_dir / "gwaje01_embedding_choice.json"
if choice_path.exists():
    embedding_choice = json.loads(choice_path.read_text(encoding="utf-8"))
else:
    embedding_choice = read_json("과제/gwaje01_embedding_choice.json")
print("선택된 모델:", embedding_choice["model"])

from kiwipiepy import Kiwi
from langchain_core.documents import Document
from langchain_huggingface import HuggingFaceEmbeddings

kiwi = Kiwi()

# 검색 품질 평가 단원의 함수(predicted: 검색 결과 ID 순위순, relevant: 정답 ID 목록)
def recall_at_k(predicted, relevant, k):
    """전체 관련 문서 중 상위 k개가 찾아낸 비율(관련 수 / 전체 관련 수)."""
    hits = sum(1 for p in predicted[:k] if p in relevant)
    return hits / len(relevant)

def kiwi_tokenize(text):
    """문서와 질문에서 명사·외국어·숫자를 같은 기준으로 추출합니다."""
    return [token.form.lower() for token in kiwi.tokenize(text.replace("･", "·"))
            if token.tag.startswith("N") or token.tag in {"SL", "SN"}]

# 안내문마다 Document 하나(본문은 제목 + 줄바꿈 + 본문, 과제 01과 같음)
drug_documents = []
for doc in docs:
    drug_documents.append(Document(id=doc["doc_id"], page_content=doc["title"] + "\n" + doc["text"],
                                   metadata={"source_id": doc["doc_id"]}))

# 과제 01이 고른 임베딩 모델(벡터 길이를 1로 맞춰 거리 순서가 코사인 유사도 순서와 같음)
embedding_model = HuggingFaceEmbeddings(model_name="nlpai-lab/KURE-v1", encode_kwargs={"normalize_embeddings": True})
print("문서:", len(drug_documents), "| 임베딩 모델:", embedding_model.model_name)
```

**결과 예시**

```text
과제 자료 폴더 있음: True
안내문: 394 | 질문: 60
묘사 12 / 이름 12 / 조건 12 / 관계 12 / 집계 12
선택된 모델: KURE-v1 (1024)
문서: 394 | 임베딩 모델: nlpai-lab/KURE-v1
```

`recall_at_k()`는 **관련 문서 전체 중 상위 k개에 포함된 비율**, `kiwi_tokenize()`는 BM25에 쓰는 한국어 토큰 함수.

### 1-2. 검색과 구조화 질의 분리

상위 5개 안내문에 근거가 들어오면 문서 검색, 제품 간 성분 관계를 따라가거나 전체 개수를 세야 하면 구조화 질의를 사용.

## 2. 세 검색기 생성과 유형별 Recall@5 비교

### 2-1. BM25 · Dense · Hybrid

- `bm25`: Kiwi 형태소 기반 키워드 검색.
- `dense`: Chroma + KURE-v1 벡터 검색.
- `hybrid`: BM25와 Dense 검색 결과를 RRF(`c=60`)로 결합.

**코드**

```python
import time
from langchain_chroma import Chroma
from langchain_classic.retrievers import EnsembleRetriever
from langchain_community.retrievers import BM25Retriever

index_seconds = {}

# 1) 키워드 색인
start = time.perf_counter()
bm25 = BM25Retriever.from_documents(
    drug_documents, preprocess_func=kiwi_tokenize, k=10
)
index_seconds["BM25"] = time.perf_counter() - start

# 2) Chroma 메모리 컬렉션 생성 → 초기화 → 문서 적재
vector_store = Chroma(
    collection_name="gwaje58_drugs",
    embedding_function=embedding_model,
)
vector_store.reset_collection()
start = time.perf_counter()
vector_store.add_documents(drug_documents)
index_seconds["KURE-v1"] = time.perf_counter() - start

# 3) 의미 검색 및 RRF 하이브리드
# 주의: from_documents가 아니라 vector_store 객체에서 검색기 생성
dense = vector_store.as_retriever(search_kwargs={"k": 10})
hybrid = EnsembleRetriever(
    retrievers=[bm25, dense],
    weights=[0.5, 0.5],
    c=60,
    id_key="source_id",
)

retrievers = {"bm25": bm25, "dense": dense, "hybrid": hybrid}
print("색인 시간(초):", {k: round(v, 3) for k, v in index_seconds.items()})

# 기본 동작 확인
for name, retriever in retrievers.items():
    found = retriever.invoke(questions[0]["question"])
    print(name, "검색 건수:", len(found))
```

**결과 예시** *(색인 시간은 실제 측정이 아닌 이후 계산용 가정: BM25 2초, KURE-v1 60초)*

```text
색인 시간(초): {'BM25': 2.0, 'KURE-v1': 60.0}
bm25 검색 건수: 10
dense 검색 건수: 10
hybrid 검색 건수: 10 이상
```

`reset_collection()`은 셀을 재실행해도 394건만 남게 하는 처리. 하이브리드 결과는 RRF로 결합하므로 결과 수가 10보다 많을 수 있음.

### 2-2. 유형 × 전략 평가

검색 질문 36개에 세 전략을 모두 적용해 **108행** 평가표를 만든다. 조건 질문도 여기서는 별도 메타데이터 필터 없이 원문 질문으로 검색.

**코드**

```python
strategies = ["bm25", "dense", "hybrid"]
rows = []

for question in questions:
    if question["question_type"] not in search_types:
        continue

    for strategy in strategies:
        found_docs = retrievers[strategy].invoke(question["question"])
        found_ids = [doc.metadata["source_id"] for doc in found_docs]
        recall = recall_at_k(found_ids, question["relevant_doc_ids"], 5)

        rows.append({
            "question_id": question["question_id"],
            "question_type": question["question_type"],
            "strategy": strategy,
            "recall_at_5": recall,
            "맞힌 문항": int(recall > 0),
        })

results = pd.DataFrame(rows)
type_table = (
    results.pivot_table(
        index="question_type", columns="strategy",
        values="recall_at_5", aggfunc="mean",
    )
    .round(3)
    .reindex(index=search_types, columns=strategies)
)
display(type_table)
```

**결과 예시 — 유형별 평균 Recall@5**

| 질문 유형 | bm25 | dense | hybrid |
|---|---:|---:|---:|
| 묘사 | 0.167 | **0.583** | 0.375 |
| 이름 | 0.750 | **0.833** | **0.833** |
| 조건 | 0.278 | 0.250 | **0.431** |

- 묘사: 문서와 표현이 다른 의미 기반 질문 → Dense 우세.
- 이름: 특이한 이름·표현 검색 → Dense와 Hybrid 동률.
- 조건: 필터를 붙이지 않은 상태 → Hybrid가 가장 높은 Recall@5.
- Recall@5와 `맞힌 문항`은 구별해야 함. 관련 문서가 여럿일 때는 Recall이 증가해도 추가로 맞힌 **질문 수**는 같을 수 있음.

## 3. 유형별 라우터의 가치 판단과 ADR-002

유형마다 전략을 달리 쓰면 성능 상한은 오르지만, **맞힌 질문이 2개 이상 증가**해야 라우터를 채택한다.

**코드**

```python
# 유형별 최고 Recall@5 전략(동률이면 strategies의 앞쪽 전략)
routed_plan = type_table.idxmax(axis=1).to_dict()

# 전체 Recall@5: 유형별 질문 수가 12개로 동일하므로 유형 평균의 평균 사용
overall = {strategy: round(float(type_table[strategy].mean()), 3)
           for strategy in strategies}
overall["유형별"] = round(float(type_table.max(axis=1).mean()), 3)

# 전체 맞힌 질문 수
hit_counts = {
    strategy: int(results.loc[results["strategy"] == strategy, "맞힌 문항"].sum())
    for strategy in strategies
}
is_routed_row = results["strategy"] == results["question_type"].map(routed_plan)
hit_counts["유형별"] = int(results.loc[is_routed_row, "맞힌 문항"].sum())

best_single = max(strategies, key=lambda strategy: overall[strategy])
use_router = (hit_counts["유형별"] - hit_counts[best_single]) >= 2

print("유형별 전략:", routed_plan)
print("단일 전략:", best_single, "| 검색 전략 라우터 사용:", use_router)
display(pd.DataFrame({"전체 Recall@5": overall, "맞힌 문항": hit_counts}))
```

**결과 예시**

```text
유형별 전략: {'묘사': 'dense', '이름': 'dense', '조건': 'hybrid'}
단일 전략: dense | 검색 전략 라우터 사용: False
```

| 처리 방식 | 전체 Recall@5 | 맞힌 문항 / 36 |
|---|---:|---:|
| bm25 | 0.398 | 15 |
| **dense** | **0.555** | **23** |
| hybrid | 0.546 | 21 |
| 유형별 최적 선택 | 0.616 | 24 |

유형별 최적 선택은 **단일 Dense 대비 1문항만 증가** → 라우터를 둘 기준(2문항)에 미달. 따라서 검색용 전략은 `dense` 한 개로 결정.

### ADR-002: 검색 질문에 Dense 단일 전략 사용

- **상태:** 채택
- **맥락:** 의약품 안내문 394건과 검색 질문 36개를 KURE-v1 기반 Dense, BM25, Hybrid로 비교. 검색 단계에서 LLM 라우팅 비용을 추가하지 않고, 유형별 라우터는 맞힌 문항 2개 이상 개선일 때만 사용.
- **결정:** 묘사·이름·조건의 문서 검색에 **Dense 단일 전략**을 쓴다. 관계·집계는 구조화 질의로 분리한다.
  - **BM25 제외:** Recall@5 0.398, 15문항으로 낮음.
  - **Hybrid 제외:** Recall@5 0.546, 21문항으로 Dense보다 낮음.
  - **유형별 전략 라우터 제외:** Recall@5는 0.616으로 높지만 맞힌 문항 증가가 1개(23→24)에 그침.
  - **Dense 채택:** Recall@5 0.555, 23문항으로 단일 전략 중 최고.
- **결과:**
  - **얻는 것:** 검색 구조 단순화, 유형별 검색기 분기 불필요.
  - **감수하는 것:** 조건 질문은 Hybrid(0.431)가 Dense(0.250)보다 우세. 현재 조건 필터를 사용하지 않은 측정.
  - **다시 검토할 조건:** Self-Query 메타데이터 필터 도입, 평가 질문 확대·변경, 네 축 운영 비용이 달라질 때 정확도·라우터 필요성 재평가.

## 4. 벡터 정밀도와 저장소 결정

### 4-1. 메모리 예산으로 정밀도 결정

품목 **5만 건**, KURE-v1 **1024차원**, 벡터 메모리 예산 **60MB**. 문서·질문 임베딩을 **같은 정밀도**로 낮춘 뒤 상위 5개를 비교한다.

**코드 — 제공된 평가 함수**

```python
# 정밀도별 값 하나의 바이트(binary는 1비트 = 1/8바이트)
BYTES_PER_VALUE = {"float32": 4, "float16": 2, "binary": 1 / 8}
PRECISIONS = ["float32", "float16", "binary"]

# 서비스 가정: 품목 5만 건, 검색 서버가 벡터에 줄 수 있는 메모리 60MB
ASSUMED_DOCS = 50_000
BUDGET_MB = 60

def lower_precision(vectors, precision):
    """벡터(문서 또는 질문)를 precision 정밀도로 낮춘 값을 담은 float32 배열을 반환합니다."""
    vectors = np.asarray(vectors, dtype=np.float32)
    # float16: 값 하나를 2바이트 정밀도로 반올림(거리 계산은 float32로 하므로 다시 float32 배열로 둠)
    if precision == "float16":
        return vectors.astype(np.float16).astype(np.float32)
    # binary: 부호만 남겨 1과 -1로(저장은 1비트, 1과 -1의 내적은 해밍 거리와 순위가 같음)
    if precision == "binary":
        return (vectors > 0).astype(np.float32) * 2 - 1
    return vectors

def storage_mb(n_docs, dimension, precision):
    """벡터만 센 저장 크기(MB, 100만 바이트)를 소수 첫째 자리로 반환합니다."""
    return round(n_docs * dimension * BYTES_PER_VALUE[precision] / 1e6, 1)

def top5_ids(question_vector, doc_vectors):
    """질문 하나를 모든 문서와 내적해(길이 1이면 코사인 유사도) 큰 순서로 원문 ID 5개를 반환합니다."""
    scores = np.asarray(doc_vectors) @ np.asarray(question_vector)
    top_positions = np.argsort(-scores, kind="stable")[:5]  # 동점은 문서 순서를 지켜 실행마다 같은 결과
    return [drug_ids[position] for position in top_positions]

# 2번에서 Chroma에 넣은 KURE-v1 문서 벡터를 drug_ids 순서로 꺼내기(다시 임베딩하지 않음)
stored = vector_store.get(include=["embeddings"])
vector_by_id = dict(zip(stored["ids"], stored["embeddings"]))
doc_vectors = np.array([vector_by_id[doc_id] for doc_id in drug_ids], dtype=np.float32)

        eval_positions.append(index)

def count_found(found_id_lists):
    """검색 질문마다 정답이 상위 5개 안에 하나라도 있으면 맞힌 문항으로 세어 반환합니다."""
    found = 0
    for index, found_ids in zip(eval_positions, found_id_lists, strict=True):
        found += int(recall_at_k(found_ids, questions[index]["relevant_doc_ids"], 5) > 0)
    return found

print("문서 벡터:", doc_vectors.shape, "| 질문 벡터:", question_vectors.shape)
```

### ADR-003: Neo4j에 binary 벡터 인덱스 적용

- **상태:** 채택
- **맥락:** 5만 건 × 1024차원 벡터를 60MB 이내 메모리에 두고, Dense·조건 필터·성분 관계·집계·재점수 질의를 처리해야 함. 정밀도 3종과 저장소 3종을 검토했고, 본사는 Neo4j를 운영 중.
- **결정:** 벡터 검색 인덱스에는 **binary 정밀도**를 사용하고, 관계·집계 검색을 포함하는 저장소는 **Neo4j**를 쓴다.
  - **float32(204.8MB)·float16(102.4MB) 제외:** 60MB 예산 초과.
  - **binary 채택:** 6.4MB로 예산 통과. 단, 1단계 검색은 16문항으로 float32·float16의 23문항보다 낮음.
  - **Chroma 제외:** 성분 관계·조건 개수는 코드 우회가 필요하고 요구된 binary 재점수 구성이 불가.
  - **pgvector 대신 Neo4j:** 두 저장소 모두 필요 질의를 한 질의로 처리할 수 있다는 기능표 판정. 이미 운영 중인 Neo4j 채택.
- **결과:**
  - **얻는 것:** 벡터 인덱스용 메모리 예산 충족, 한 저장소에서 그래프 관계와 벡터 검색 처리 가능.
  - **감수하는 것:** 원래 벡터 별도 저장에 따른 디스크 사용, binary 1단계 검색 성능 하락. 재점수 정확도는 미측정.
  - **다시 검토할 조건:** binary 후보 재점수 측정, 취급 품목·메모리 예산 변경, Neo4j 인덱스 지원 버전 확인, Text2Cypher 실제 경로·집계 질의 연결 시 재검증.

## 5. 세 후보의 네 축 비교표

네 축은 정확도(높을수록), 지연·월 비용·저장 공간(낮을수록). 검색기 조합만 다르고 임베딩 모델은 KURE-v1으로 동일.

- A: Dense = 벡터 검색만 실행.
- B: Hybrid = BM25 + 벡터 검색.
- C: BM25 = 키워드 검색만 실행.

**코드 — 제공된 비용·후보표 함수**

```python
# (가정) 운영 장비(CPU)에서의 시간(ms): KURE-v1 질문 1건 임베딩, BM25 낱말 점수 계산, 5만 건 검색 한 번
assumed_embed_ms = 60.0
assumed_bm25_ms = 1.0
assumed_search_ms = 30.0

# (가정) 질문 임베딩 장비 1시간 가격과 한 달 켜 두는 시간
machine_usd_per_hour = 0.35
machine_hours_per_month = 730

# 원래 벡터 + HNSW 인덱스는 원래 벡터의 3.0배(교안 02 4-2에서 측정), (가정) BM25 낱말 하나 12바이트, 1년에 한 번 재색인
vector_index_factor = 3.0
bm25_bytes_per_term = 12
reindex_months = 12
unique_terms_per_doc = float(np.mean([len(set(kiwi_tokenize(document.page_content))) for document in drug_documents]))  # 문서당 고유 낱말 수(측정)

def monthly_cost(index_seconds_per_doc, n_docs, machine_usd_per_hour, needs_machine):
    """색인 1회(index_usd)와 월 질의(monthly_query_usd) 비용(달러)을 dict로 반환합니다."""
    # 색인 1회: 문서당 초 x 문서 수를 시간으로 바꿔 장비 가격을 곱함
    index_cost = index_seconds_per_doc * n_docs / 3600 * machine_usd_per_hour

    # 월 질의: 질문을 임베딩하는 전략은 질문 임베딩 장비를 한 달 내내 켜 둠(BM25는 검색 서버에서 바로 계산)
    query_cost = 0.0
    if needs_machine:
        query_cost = machine_usd_per_hour * machine_hours_per_month
    return {"index_usd": round(index_cost, 3), "monthly_query_usd": round(query_cost, 3)}

def build_candidates(uses_by_strategy, accuracy_by_strategy, n_docs, machine_usd_per_hour):
    """품목 수가 n_docs, 장비 가격이 machine_usd_per_hour일 때 후보 A~C의 네 축을 담은 후보표를 반환합니다."""
    rows = []
    for name, strategy in [("A", "dense"), ("B", "hybrid"), ("C", "bm25")]:
        uses_vectors = uses_by_strategy[strategy]["vectors"]  # 벡터 인덱스(KURE-v1)를 쓰는가
        uses_bm25 = uses_by_strategy[strategy]["bm25"]  # BM25 색인을 쓰는가

        # 지연: 쓰는 검색기만큼 가정 시간을 더하고 검색 시간을 더함
        latency_ms = uses_vectors * assumed_embed_ms + uses_bm25 * assumed_bm25_ms + assumed_search_ms

        # 비용: 쓰는 검색기만큼 색인 시간을 더하고, 질문을 임베딩하는 전략만 장비를 늘 켜 둠
        index_seconds_per_doc = (uses_vectors * index_seconds["KURE-v1"] + uses_bm25 * index_seconds["BM25"]) / len(drug_documents)
        cost = monthly_cost(index_seconds_per_doc, n_docs, machine_usd_per_hour, uses_vectors)

        # 저장: 원래 벡터 x 인덱스 배율 + BM25 색인
        storage_gb = (uses_vectors * n_docs * 1024 * 4 * vector_index_factor
                      + uses_bm25 * n_docs * unique_terms_per_doc * bm25_bytes_per_term) / 1e9

        rows.append({"candidate": name, "strategy": strategy, "accuracy": accuracy_by_strategy[strategy],
                     "latency_ms": round(latency_ms, 3),
                     "cost_usd": round(cost["index_usd"] / reindex_months + cost["monthly_query_usd"], 3),
                     "storage_gb": round(storage_gb, 3)})
    return pd.DataFrame(rows)
```

## 6. 제약·지배·가중치 및 변화 시나리오

### 6-1. 후보 선정 함수와 기준

1. **제약:** 지연 500ms, 저장 공간 2GB 이하.
2. **지배 제거:** 모든 축에서 같거나 우세하고 최소 한 축이 더 나은 후보가 있으면 제거.
3. **점수화:** 정확도 0.7 / 지연 0.1 / 비용 0.1 / 저장 0.1의 고정 기준 가중 합.

**코드 — 제공된 선정 함수**

```python
def apply_constraints(candidates, limits):
    """한도를 넘지 않은 후보 표와, 넘은 후보에 이유(drop_reason)를 붙인 표 두 개를 반환합니다."""
    passed_rows = []
    dropped_rows = []

    # 후보마다 한도(상한)를 하나씩 확인해 탈락 이유 모으기
    for row in candidates.to_dict("records"):
        reasons = []
        for column, limit in limits.items():
            if row[column] > limit:
                reasons.append(f"{column}>{limit}")

        # 이유가 하나라도 있으면 탈락
        if reasons:
            row["drop_reason"] = ", ".join(reasons)
            dropped_rows.append(row)
        else:
            passed_rows.append(row)

    # 탈락 후보가 없어도 candidate 열이 있도록 열 이름 지정
    return pd.DataFrame(passed_rows), pd.DataFrame(dropped_rows, columns=list(candidates.columns) + ["drop_reason"])

# 네 축과 좋은 방향
axes = {"accuracy": "max", "latency_ms": "min", "cost_usd": "min", "storage_gb": "min"}

def remove_dominated(candidates, axes):
    """지배당한 후보를 지운 표와 {지배당한 후보: [이긴 후보 목록]} dict를 반환합니다."""
    rows = candidates.to_dict("records")
    kept = []
    dominated = {}

    # 후보(row)마다 다른 모든 후보(other)와 비교해 row를 지배하는 후보 모으기
    for row in rows:
        winners = []
        for other in rows:
            if other["candidate"] == row["candidate"]:
                continue
            no_worse = True   # other가 모든 축에서 row보다 같거나 좋은가
            better = False    # other가 한 축 이상에서 row보다 좋은가
            for axis, direction in axes.items():
                # 차이가 양수면 other가 그 축에서 좋음(작을수록 좋은 축은 부호를 뒤집음)
                difference = other[axis] - row[axis]
                if direction == "min":
                    difference = -difference
                if difference < 0:
                    no_worse = False
                if difference > 0:
                    better = True
            if no_worse and better:
                winners.append(other["candidate"])

        # 이긴 후보가 있으면 지배당한 후보, 없으면 남김
        if winners:
            dominated[row["candidate"]] = winners
        else:
            kept.append(row)
    return pd.DataFrame(kept), dominated

def score_candidates(candidates, weights, references):
    """축마다 0~1 점수로 바꾸고 가중치를 곱해 더한 점수표(점수 높은 순)를 반환합니다."""
    rows = []
    # 후보마다 축 점수에 가중치를 곱해 더하기
    for row in candidates.to_dict("records"):
        scored = {"candidate": row["candidate"]}
        total = 0.0
        for axis, weight in weights.items():
            if axis in references:
                # 작을수록 좋은 축: 기준보다 작을수록 1에 가깝고, 기준을 넘으면 0점
                value = 1 - row[axis] / references[axis]
                if value < 0:
                    value = 0.0
            else:
                # 정확도는 이미 0~1
                value = row[axis]
            scored[axis + " 점수"] = round(value, 3)
            total += weight * value

        # 합계는 반올림하지 않아 격차를 정확히 계산함(화면에서만 반올림)
        scored["score"] = total
        rows.append(scored)

    # 점수 높은 순, 동점이면 후보 이름 순
    return pd.DataFrame(rows).sort_values(["score", "candidate"], ascending=[False, True]).reset_index(drop=True)

def run_selection(candidates, limits, weights, references):
    """제약 -> 지배 제거 -> 고정 기준 점수를 실행해 단계별 결과와 1위·격차를 dict로 반환합니다."""
    passed, dropped = apply_constraints(candidates, limits)
    front, dominated = remove_dominated(passed, axes)
    scored = score_candidates(front, weights, references)

    # 1위와 2위의 점수 차(0.001보다 작은 차이도 보이게 소수 넷째 자리까지, 후보가 하나면 None)
    gap = None
    if len(scored) > 1:
        gap = round(float(scored.loc[0, "score"] - scored.loc[1, "score"]), 4)
    return {"dropped": dropped, "dominated": dominated, "scored": scored, "winner": scored.loc[0, "candidate"], "gap": gap}

def exchange_rates(weights, references):
    """정확도 1%p와 같은 점수가 되는 각 축의 양(지연 ms, 월 비용 $, 저장 GB)을 dict로 반환합니다."""
    rates = {}
    # 정확도 1%p가 올리는 점수(0.01 x 정확도 가중치)를 축 값 1이 깎는 점수(축 가중치 / 기준)로 나눔
    for axis in references:
        rates[axis] = round(0.01 * weights["accuracy"] / (weights[axis] / references[axis]), 3)
    return rates
```

### 6-3. 가중치 민감도 분석

4개 가중치마다 7개 배수 → **총 28개 경우**를 다시 평가. 변경한 가중치는 합계가 1이 되도록 재정규화.

**코드 — 제공 함수**

```python
# 가중치에 곱할 배수(교안의 0.8·1.2보다 넓게)
FLIP_FACTORS = (0.5, 0.75, 1.25, 1.5, 2.0, 3.0, 5.0)

def check_sensitivity(candidates, limits, weights, references, factors=(0.8, 1.2)):
    """가중치 하나씩 factors의 배수로 바꾼 조합마다 1위와 격차를 담은 표를 반환합니다."""
    rows = []
    # 가중치 하나를 factors의 배수로 바꾼 조합마다 선정 다시 실행
    for axis in weights:
        for factor in factors:
            changed = dict(weights)
            changed[axis] = weights[axis] * factor

            # 합으로 나눠 가중치 합을 다시 1로
            total = sum(changed.values())
            for name in changed:
                changed[name] = changed[name] / total

            result = run_selection(candidates, limits, changed, references)
            rows.append({"changed_weight": f"{axis} x{factor}", "winner": result["winner"], "gap": result["gap"]})
    return pd.DataFrame(rows)
```

**코드 — 뒤집히는 조합 찾기 답안**

```python

    candidates, limits, weights, references, factors=FLIP_FACTORS
)

flip_weights = dict(weights)

print("재정규화 가중치:", {k: round(v, 3) for k, v in flip_weights.items()})
print("변경 환율:", exchange_rates(flip_weights, references))
```

### ADR-004: KURE-v1 + Dense + Neo4j 중심 아키텍처 채택

- **상태:** 채택
- **맥락:** 약국 본사의 의약품 상담 검색에서 문서·성분 관계·집계를 다뤄야 함. 5만 품목, 월 300만 질문, 지연 500ms 이하, 저장 2GB 이하, 벡터 인덱스 메모리 60MB를 가정. ADR-001(KURE-v1), ADR-002(Dense 단일 검색), ADR-003(binary·Neo4j)를 바탕으로 A(Dense)·B(Hybrid)·C(BM25)를 정확도·지연·비용·저장 공간으로 비교.
- **결정:** **KURE-v1 임베딩 + Dense 단일 검색 + Neo4j 저장소**를 쓴다. 묘사·이름·조건은 문서 검색으로, 관계·집계는 Text2Cypher 구조화 질의로 처리한다. 별도의 검색 전략 선택 라우터는 두지 않고, binary 인덱스와 원본 벡터 재점수 구조를 채택한다.
  - **A(Dense) 채택:** 정확도 0.555, 지연 90ms, 월 약 $255.6, 저장 약 0.614GB. 네 축 점수 약 0.608로 최고.
  - **B(Hybrid) 제외:** A보다 정확도가 낮고 지연·비용·저장 공간이 같거나 나빠 **A에 의해 지배**됨.
  - **C(BM25) 제외:** 월 비용·지연·저장 공간은 유리하지만 정확도 0.398로 A보다 15.7%p 낮음. 비용·지연·저장 이점을 팀 가중치의 환율로 환산해도 정확도 손실을 보완하지 못함(점수 약 0.568).
  - **유지되는 가정:** 질문 임베딩 장비 비용이 없거나 장비 가격이 두 배가 되어도 A가 1위. 다만 가격 두 배에서는 격차가 약 0.0077로 감소.
- **결과:**
  - **얻는 것:** 문서 검색 정확도를 우선한 단순한 검색 전략과 관계·집계 처리를 결합. 기존 Neo4j 활용.
  - **감수하는 것:** KURE-v1 CPU 임베딩·인덱싱 비용, 원본 벡터 별도 저장, binary 인덱스의 1단계 정확도 손실 및 재점수 효과 미측정, 운영 시간·비용이 가정값에 의존.
  - **다시 검토할 조건:**
    - **품목 수 50만 건 도달** → 저장 2GB 제약으로 A·B 탈락 가능. 저장 구조·인덱스 크기 재평가.
    - **정확도 가중치 0.5배, 비용·저장 가중치 3배 이상 또는 지연 가중치 5배** → BM25가 우세해지는지 재선정. 이때 정확도 1%p의 환율은 기본 35ms/$56/0.14GB에서 17.5ms/$28/0.07GB(정확도 0.5배 기준)로 낮아짐.
    - **Self-Query 조건 필터 추가 또는 평가셋 변경** → 36문항 Recall@5·맞힌 문항을 다시 측정해 전략·라우터 재판정.
    - **실제 운영 환경 도입** → Neo4j 바이너리 양자화 지원 버전, 재점수 정확도, 지연·메모리·비용의 실측 필요.

**구현 단계에서 구별할 점:** 본 실습의 `Chroma`는 **성능 비교용 임시 저장소**. 최종 선정인 `Neo4j`로 벡터·성분 관계를 적재하고 실제 Cypher를 실행하는 코드는 이 문서에 없으며, 과제 자체도 기능표로만 저장소를 판정함. 또한 최종 답변 생성 품질이나 의약품 상담의 임상적 안전성은 여기서 평가하지 않음.
