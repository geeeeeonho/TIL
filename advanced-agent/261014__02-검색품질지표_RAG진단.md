# 검색 품질 지표와 RAG 진단 — 개념·코드 문법

> 기준: 교안 02 / Ragas 0.4.3, LangChain, Chroma 실습. 코드 예시는 교안의 핵심 문법만 추린 형태. 실행에는 API 키와 교안의 `data/` 폴더가 필요함. 점수 예시는 **계산 원리 설명용**이며 실제 평가 결과가 아님.

## 1. RAG 검색 품질 평가 개념

RAG는 **검색(Retrieval) → 답변 생성(Generation)**으로 구성됨. 답변이 틀렸을 때 검색이 문제인지, 검색한 문서를 활용하는 생성 단계가 문제인지 따로 진단해야 함.

```text
질문(user_input)
   ↓
검색기 → 검색 문서(retrieved_contexts) ──┐
   │                                     ├→ 답변 모델 → 답변(response)
   └── 검색 품질 평가                    │                 │
                                         └─────────────────┘
정답 답변(reference) ───── 검색·답변 정확도 평가에 사용
```

**평가 샘플의 4개 필드**

| 필드 | 의미 |
|---|---|
| `user_input` | 사용자 질문 |
| `retrieved_contexts` | 검색된 문서 **본문의 리스트**. 순서 유지 |
| `response` | RAG가 생성한 답변 |
| `reference` | 사람이 확인해 작성한 정답 답변(골든셋) |

**검색 품질 지표 3개**

| 지표 | 무엇을 보는가 | 계산 핵심 | `reference` 필요 |
|---|---|---|---|
| **Context Precision** | 쓸모 있는 문서가 **앞 순위**에 있는가 | 관련 문서가 나온 각 순위의 정밀도 평균 | O |
| **Context Recall** | 답변에 필요한 **정보를 빠뜨리지** 않았는가 | 검색 문서로 뒷받침되는 정답 주장 ÷ 전체 정답 주장 | O |
| **Context Relevancy** | 검색 문서 묶음이 **질문과 관련** 있는가 | 0·1·2점 판정 2회 → 0~1 정규화 후 평균 | X |

- **Precision — 순위 반영:** 쓸모 판정 `[1, 1, 0, 0]`이면 `(1/1 + 2/2) / 2 = 1.0`. 같은 문서라도 `[0, 1, 1, 0]`이면 `(1/2 + 2/3) / 2 ≈ 0.58`. **문서가 빠졌는지는 알 수 없음.**
- **Recall — 누락 반영:** 정답 답변의 주장 2개 중 검색 문서로 입증할 수 있는 주장이 1개면 `0.5`. 문서 순위는 반영하지 않음. 문서 ID가 달라도 같은 정보를 담으면 점수가 높을 수 있음.
- **Relevancy — 관련성 반영:** 두 판정이 `2점`, `1점`이면 `(2/2 + 1/2) / 2 = 0.75`. 가능한 점수는 `0 / 0.25 / 0.5 / 0.75 / 1`의 다섯 단계. **어떤 정보가 빠졌는지**까지는 알 수 없음.

> 코드에서는 교안의 **Context Relevancy**를 `ContextRelevance` 클래스로 사용함. `ContextPrecisionWithoutReference`는 정답 답변 대신 생성 답변으로 유용성을 판단하는 변형이지만, 생성 답변이 근거를 벗어나면 검색 품질 판단도 왜곡될 수 있음.

**기존 ID 기반 검색 평가와의 차이**

| 구분 | Precision@K · Recall@K · MRR | Ragas 검색 지표 |
|---|---|---|
| 기준 | 정답 문서 ID(`relevant_doc_ids`) | 문서 본문, 질문, 정답 답변(지표에 따라 다름) |
| 판정 | 검색 결과에 문서 ID가 있는지 계산 | 평가용 LLM이 문서 내용을 판정 |
| 특징 | 빠르고 재현성 높음 | 호출 비용·판정 변동 발생, 내용 중복이나 청크 변경에 대응 가능 |

`relevant_doc_ids`는 이 교안의 Ragas `ascore()`에는 전달하지 않음. **정답 문서 ID와 정답 답변은 서로 다른 평가 기준**임.

## 2. RAG 실행과 평가 환경: 핵심 코드

교안은 유연근무 매뉴얼 **44개 절**을 저장한 Chroma를 사용하고, 평가 질문 **6개 × 4개 설정 = 24개 실행**을 비교함.

**평가 환경 및 검색기**

```python
import os, json, asyncio
from pathlib import Path
import pandas as pd
from dotenv import load_dotenv
from openai import AsyncOpenAI
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate
from ragas.llms import llm_factory
from ragas.embeddings.base import embedding_factory
from ragas.metrics.collections import (
    ContextPrecision, ContextRecall, ContextRelevance,
    Faithfulness, AnswerRelevancy, AnswerCorrectness,
)
from tqdm.asyncio import tqdm_asyncio

load_dotenv()
os.environ["RAGAS_DO_NOT_TRACK"] = "true"
data_dir = Path("data")

# 답변 생성 모델
llm = ChatOpenAI(
    model=os.getenv("OPENAI_CHAT_MODEL", "gpt-5.6-luna"),
    use_responses_api=True,
)

# 평가 모델: 교안의 Ragas 0.4.3 방식
client = AsyncOpenAI()
evaluator_llm = llm_factory(
    os.getenv("OPENAI_EVAL_MODEL", "gpt-6-luna"),
    client=client,
    max_tokens=8192,
    system_prompt="평가 문장과 이유를 한국어로 작성하세요.",
)
evaluator_embeddings = embedding_factory(
    "openai", model="text-embedding-3-large", client=client
)

# 검색 임베딩은 기존 Chroma 문서 벡터의 모델·차원과 일치해야 함
embedding_model = OpenAIEmbeddings(
    model="text-embedding-3-large", dimensions=768,
    check_embedding_ctx_length=False,
)
vector_store = Chroma(
    collection_name="flexwork_manual",
    persist_directory=str(data_dir / "본실습" / "chroma"),
    embedding_function=embedding_model,
    create_collection_if_not_exists=False,
)
retriever = vector_store.as_retriever(search_kwargs={"k": 4})
questions = json.loads(
    (data_dir / "본실습" / "questions.json").read_text(encoding="utf-8")
)
```

- `as_retriever(search_kwargs={"k": 4})`: 질문당 상위 문서 4개를 검색.
- `llm_factory(...)`: Ragas 평가용 LLM 구성. 교안은 `AsyncOpenAI`를 사용.
- `embedding_factory(...)`: Answer Relevancy·Answer Correctness의 의미 유사도 평가에 사용. **검색용 768차원 임베딩과 별개**.
- `create_collection_if_not_exists=False`: 저장된 Chroma 컬렉션이 없으면 새로 생성하지 않고 오류 처리.

**검색→답변→평가 샘플 생성**

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", "아래 문서에 있는 내용만 근거로 답하세요. 추측하지 마세요."),
    ("human", "문서:\n{context}\n\n질문: {question}"),
])
chain = prompt | llm

# 네 설정의 차이는 검색 문서와 답변 프롬프트 중 한 요소에만 줌
def pick_documents(setting, top4):
    if setting == "순위 흐트림":
        return list(reversed(top4))  # 같은 문서, 역순
    if setting == "검색 누락":
        return top4[:1]             # 첫 문서만
    return top4                     # 기준선 / 근거 이탈

# 정상 프롬프트와 달리 근거 밖 지식을 덧붙이게 한 프롬프트(고장 재현용)
loose_prompt = ChatPromptTemplate.from_messages([
    ("system", "아래 문서에 일반 지식과 구체적인 수치를 적극 덧붙여 답하세요."),
    ("human", "문서:\n{context}\n\n질문: {question}"),
])
loose_chain = loose_prompt | llm

configs = ["기준선", "순위 흐트림", "검색 누락", "근거 이탈"]
runs = []

for q in questions:
    top4 = retriever.invoke(q["question"])  # 질문당 검색은 한 번
    for setting in configs:
        docs = pick_documents(setting, top4)
        context = "\n\n".join(doc.page_content for doc in docs)
        selected_chain = loose_chain if setting == "근거 이탈" else chain
        answer = selected_chain.invoke({"question": q["question"], "context": context})

        runs.append({
            "config": setting,
            "question_id": q["question_id"],
            "user_input": q["question"],
            "retrieved_contexts": [doc.page_content for doc in docs],
            "retrieved_ids": [doc.metadata["source_id"] for doc in docs],
            "response": answer.text.strip(),
            "reference": q["reference"],
        })
```

```text
기준선        : 문서 1→2→3→4 / 기본 프롬프트
순위 흐트림   : 문서 4→3→2→1 / 기본 프롬프트 → 순위 문제
검색 누락     : 문서 1만 전달 / 기본 프롬프트 → 정보 누락
근거 이탈     : 문서 1→2→3→4 / 느슨한 프롬프트 → 생성 환각
```

`runs`의 각 원소는 **설정 + 질문 하나에 대한 평가 샘플**. 실제 교안에서는 `batch(..., config={"max_concurrency": ...})`로 답변 생성 호출을 묶지만, 위 코드는 구조 파악을 위해 순차 호출로 압축함.

## 3. Ragas 지표 계산과 결과 표 문법

**지표별 필수 입력** (`.ascore(...)` 결과는 `.value`로 점수 접근)

| 지표 객체 | 핵심 호출 인자 |
|---|---|
| `ContextPrecision(llm=...)` | `user_input`, `retrieved_contexts`, `reference` |
| `ContextRecall(llm=...)` | `user_input`, `retrieved_contexts`, `reference` |
| `ContextRelevance(llm=...)` | `user_input`, `retrieved_contexts` |
| `Faithfulness(llm=...)` | `user_input`, `response`, `retrieved_contexts` |
| `AnswerRelevancy(llm=..., embeddings=...)` | `user_input`, `response` |
| `AnswerCorrectness(llm=..., embeddings=...)` | `user_input`, `response`, `reference` |

**6개 지표를 한 실행에 적용하는 코드** (Jupyter 셀의 `await` 사용 방식)

```python
context_precision = ContextPrecision(llm=evaluator_llm)
context_recall = ContextRecall(llm=evaluator_llm)
context_relevance = ContextRelevance(llm=evaluator_llm)
faithfulness = Faithfulness(llm=evaluator_llm)
answer_relevancy = AnswerRelevancy(llm=evaluator_llm, embeddings=evaluator_embeddings)
answer_correctness = AnswerCorrectness(llm=evaluator_llm, embeddings=evaluator_embeddings)

# 결과 표의 열 순서: 최종 결과 → 검색 → 생성
metric_order = [
    "Answer Correctness", "Context Recall", "Context Precision",
    "Context Relevancy", "Faithfulness", "Answer Relevancy",
]

# 평가 API 요청이 동시에 지나치게 많이 실행되지 않도록 제한
semaphore = asyncio.Semaphore(32)

async def run_limited(coroutine):
    async with semaphore:
        return await coroutine

async def score_one(run):
    return await asyncio.gather(
        run_limited(answer_correctness.ascore(
            user_input=run["user_input"], response=run["response"], reference=run["reference"])),
        run_limited(context_recall.ascore(
            user_input=run["user_input"], retrieved_contexts=run["retrieved_contexts"], reference=run["reference"])),
        run_limited(context_precision.ascore(
            user_input=run["user_input"], reference=run["reference"], retrieved_contexts=run["retrieved_contexts"])),
        run_limited(context_relevance.ascore(
            user_input=run["user_input"], retrieved_contexts=run["retrieved_contexts"])),
        run_limited(faithfulness.ascore(
            user_input=run["user_input"], response=run["response"], retrieved_contexts=run["retrieved_contexts"])),
        run_limited(answer_relevancy.ascore(
            user_input=run["user_input"], response=run["response"])),
    )

# 실행별 결과의 순서는 runs 순서, 각 지표 결과의 순서는 metric_order 순서
all_results = await tqdm_asyncio.gather(
    *[score_one(run) for run in runs], desc="RAG 평가"
)

score_rows = []
for run, results in zip(runs, all_results):
    for name, result in zip(metric_order, results):
        score_rows.append({
            "설정": run["config"], "질문 ID": run["question_id"],
            "지표": name, "점수": result.value,
        })
```

- `await`: 비동기 평가 작업이 끝나 점수가 돌아올 때까지 대기.
- `asyncio.gather(...)`: 여러 평가를 함께 실행하고 **입력 순서대로** 결과 반환.
- `asyncio.Semaphore(32)`: 동시에 실행하는 평가 작업 수 제한. API `429` 발생 시 감소.
- `tqdm_asyncio.gather(...)`: 진행률 표시. **지표 호출 비용과 판정 수는 지표마다 다름**.

**Pandas로 평가 결과 집계**

```python
df = pd.DataFrame(score_rows)

# 설정별 지표 평균 (전체 상태 파악)
overall_table = df.pivot_table(
    index="설정", columns="지표", values="점수", aggfunc="mean"
).reindex(index=configs, columns=metric_order).round(2)

# 질문별 점수 (평균에 가려진 실패 확인)
per_question_table = df.pivot_table(
    index=["설정", "질문 ID"], columns="지표", values="점수"
)[metric_order].round(2)

# 질문 유형별 점수 (복합 질문 등 특정 유형에서만 실패하는지 확인)
question_types = {q["question_id"]: q["question_type"] for q in questions}
df["유형"] = df["질문 ID"].map(question_types)
by_type_table = df.pivot_table(
    index=["유형", "설정"], columns="지표", values="점수", aggfunc="mean"
)[metric_order].round(2)
```

**합격선(절대 판정)과 기준선(상대 판정)은 별도 개념**

- **합격선:** 품질이 사용 가능한 수준인가? 지표마다 팀이 정한 기준값과 비교. Ragas 자체의 공식 합격선은 없음.
- **기준선:** 변경 전 설정보다 나빠졌는가? `기준선 점수 - 변경 설정 점수`를 계산.

```python
# 교안에서만 사용하는 예시 합격선 (보편적인 공식 기준 아님)
THRESHOLDS = {
    "Answer Correctness": 0.60,
    "Context Recall": 0.80,
    "Context Precision": 0.70,
    "Context Relevancy": 0.75,
    "Faithfulness": 0.80,
}  # Answer Relevancy는 절대 합격선을 두지 않음

pass_rows = []
for row in score_rows:
    if row["지표"] in THRESHOLDS:
        passed = int(row["점수"] >= THRESHOLDS[row["지표"]])
        pass_rows.append({"설정": row["설정"], "지표": row["지표"], "합격": passed})

# 질문 수 중 합격한 건수
pass_table = pd.DataFrame(pass_rows).pivot_table(
    index="설정", columns="지표", values="합격", aggfunc="sum"
)
```

**주의:** `NaN`은 0점이 아니라 **평가 실패 또는 계산 불가**를 뜻함. 표에서 평균을 낼 때 누락될 수 있으므로 실패 건수를 별도로 확인해야 함.

## 4. 점수로 RAG 고장 위치 진단하기

**확인 순서: 정답 정확도(현상 확인) → 검색 지표(원인) → 생성 지표(원인)**. 진단 이름을 정할 때는 아래 순서대로 **기준선 대비 하락**을 보고 첫 번째 해당 항목을 채택함.

| 우선 | 기준선 대비 크게 하락한 지표 | 진단 | 먼저 고칠 곳 |
|---|---|---|---|
| 1 | Context Recall | **검색 누락** | `k`, 청크 분할, 검색 방식 |
| 2 | Context Relevancy | **엉뚱한 검색** | 검색 방식·검색 대상 확인 |
| 3 | Context Precision | **순위 문제** | 리랭킹·상위 문서 순서 |
| 4 | Faithfulness | **생성 환각** | 근거 외 내용 억제 프롬프트 |
| 5 | Answer Relevancy | **질문 이탈** | 질문에 직접 답하도록 프롬프트 수정 |
| 6 | Answer Correctness | **답 불일치** | 원문 최신성·추출 능력·모델 확인 |

```python
# 교안의 상대 판정 규칙: 0.2 이상 하락한 첫 지표로 진단
DIAGNOSIS_ORDER = [
    ("Context Recall", "검색 누락"),
    ("Context Relevancy", "엉뚱한 검색"),
    ("Context Precision", "순위 문제"),
    ("Faithfulness", "생성 환각"),
    ("Answer Relevancy", "질문 이탈"),
    ("Answer Correctness", "답 불일치"),
]

def diagnose(baseline, current, gap=0.2):
    for metric, label in DIAGNOSIS_ORDER:
        if pd.notna(baseline[metric]) and pd.notna(current[metric]):
            if baseline[metric] - current[metric] >= gap:
                return label
    return "기준선과 비슷"

baseline = overall_table.loc["기준선"]
for setting in configs[1:]:
    print(setting, diagnose(baseline, overall_table.loc[setting]))
```

`0.2`는 **교안의 실습용 차이 기준**. 합격선도 공식 기준이 아니며, 평균 차이만으로 결론 내리지 말고 질문별 점수와 검색 원문을 확인해야 함.

**대표 진단: 검색 문서 수 `k=5 → 3` 변경** (교안의 출산·육아 지원금 따라하기)

```python
baseline_retriever = practice_vector_store.as_retriever(search_kwargs={"k": 5})
changed_retriever = practice_vector_store.as_retriever(search_kwargs={"k": 3})
```

```text
복합 질문(정답 문서 2~3개): 4·5위 문서가 빠짐 → Context Recall 하락
단일 질문(정답 문서 1개): 정답 문서가 1위 → 상대적으로 변화 적음

Context Precision은 오히려 높아질 수도 있음(상위 문서만 남음).
Faithfulness도 높을 수 있음(가져온 문서에만 근거해 답변함).
하지만 질문의 일부를 빠뜨렸다면 Answer Correctness는 낮아질 수 있음.
```

- **해결:** `k`를 다시 5로 높이거나, 리랭킹으로 필요한 문서를 상위 3개 안으로 올림.
- **검증:** 동일 골든셋으로 재평가하고 복합·단일 질문을 나눠 변화 확인.
- **핵심:** `Faithfulness ↑`가 곧 `Answer Correctness ↑`는 아님. **근거는 정확하더라도 필요한 근거 자체가 빠질 수 있음.**

**실무용 지표 선택**

| 상황 | 우선 지표 |
|---|---|
| 검색기·청크·임베딩·리랭커 튜닝 | 정답 문서 ID가 있으면 `Recall@K`·`MRR`, 없으면 `Context Recall`·`Context Precision` |
| 프롬프트·답변 모델 변경 | `Faithfulness`·`Answer Relevancy`·`Answer Correctness` |
| 운영 중 실제 질문(정답 답변 없음) | `Faithfulness`·`Answer Relevancy`·`Context Relevancy` |
| 정확성이 특히 중요한 서비스 | 전문가 정답 기반 `Answer Correctness` + `Faithfulness`·`Context Recall` |

**최종 기억할 것:** 검색 순위는 **Precision**, 정보 누락은 **Recall**, 질문 관련성은 **Relevancy**. RAG 진단은 **최종 답변 정확도 확인 → 검색 먼저 → 생성 확인 → 원문 검증** 순서.
