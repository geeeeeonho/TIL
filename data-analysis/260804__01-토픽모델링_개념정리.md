# 토픽 모델링과 BERTopic

## 1. 토픽 모델링

**토픽 모델링(Topic Modeling)**은 라벨이 없는 문서 묶음에서 다음을 자동으로 찾는 비지도 학습 방법.

- 어떤 주제들이 존재하는지
- 각 문서가 어느 주제에 속하는지
- 각 주제를 대표하는 단어가 무엇인지

일반 군집화가 비슷한 문서를 묶는 데서 끝난다면, 토픽 모델링은 각 군집에 **대표 키워드와 토픽 이름**까지 붙임.

### BERTopic 전체 흐름

```text
문서
→ 임베딩
→ 차원 축소
→ 군집화
→ 토큰화
→ 토픽 표현
→ 토픽 다듬기·시각화·이름 붙이기
```

| 단계 | 역할 | 도구 |
|---|---|---|
| 1. 임베딩 | 문서를 의미가 담긴 벡터로 변환 | ko-sroberta |
| 2. 차원 축소 | 768차원 벡터를 약 5차원으로 축소 | UMAP |
| 3. 군집화 | 비슷한 문서가 몰린 영역을 토픽으로 분류 | HDBSCAN |
| 4. 토큰화 | 군집 안의 문서를 단어 단위로 분리 | Kiwi + CountVectorizer |
| 5. 토픽 표현 | 각 군집을 대표하는 단어 추출 | c-TF-IDF |

---

## 2. BERTopic의 5단계

### 1단계: 임베딩

문장을 컴퓨터가 비교할 수 있는 숫자 벡터로 변환.

```text
문서 → 의미를 표현하는 768개 숫자
```

단어가 정확히 같지 않아도 문장의 의미가 비슷하면 벡터도 비슷해짐.

```python
# 문서 목록
docs = [...]

# 문서를 768차원 임베딩으로 변환
emb = model.encode(docs)
```

---

### 2단계: UMAP 차원 축소

768차원 벡터를 그대로 군집화하면 점 사이의 거리 차이가 불분명해질 수 있음.  
이를 **차원의 저주**라고 함.

UMAP으로 차원을 줄이면 비슷한 문서가 가까이 모여 군집화가 쉬워짐.

```python
from umap import UMAP

umap_model = UMAP(
    n_neighbors=15,
    n_components=5,
    min_dist=0.0,
    metric="cosine",
    random_state=42
)
```

| 파라미터 | 의미 | 예시값 |
|---|---|---:|
| `n_neighbors` | 주변 이웃을 몇 개까지 참고할지 | `15` |
| `n_components` | 축소 후 차원 수 | `5` |
| `min_dist` | 축소된 점 사이의 최소 거리 | `0.0` |
| `metric` | 원래 벡터의 거리를 계산하는 방식 | `"cosine"` |
| `random_state` | 실행할 때마다 결과가 달라지지 않도록 고정 | `42` |

- 시각화 목적: 주로 2차원
- 군집화 목적: 약 5차원

---

### 3단계: HDBSCAN 군집화

HDBSCAN은 문서가 밀집된 영역을 찾아 자동으로 군집을 만듦.

KMeans와 달리 **군집 개수를 미리 지정하지 않음.**  
대신 어느 정도로 모여야 군집으로 인정할지를 설정.

```python
from hdbscan import HDBSCAN

hdb_model = HDBSCAN(
    min_cluster_size=25
)
```

#### `min_cluster_size`

하나의 군집으로 인정할 최소 문서 수.

```text
값이 작음 → 작은 군집까지 인정 → 토픽이 잘게 나뉨
값이 큼   → 큰 군집 위주 생성 → 굵직한 토픽 생성
```

#### 라벨 `-1`

어느 군집에도 포함되지 못한 문서는 `-1`로 분류.

```text
Topic -1 = 노이즈 또는 아웃라이어 문서
```

오류가 아니라 HDBSCAN의 정상 결과.

---

### 4단계: 토큰화

같은 군집의 문서에서 단어를 세기 위해 문장을 토큰으로 분리.

CountVectorizer의 기본 토큰화는 주로 띄어쓰기 기준.  
한국어는 조사와 어미가 붙으므로 Kiwi 형태소 분석기를 토크나이저로 사용 가능.

```text
기본 토큰화
"서울에서 여행했다"
→ 서울에서 / 여행했다

Kiwi 형태소 분석
→ 서울 / 여행
```

```python
vectorizer = CountVectorizer(
    tokenizer=kiwi_tokenizer
)
```

Kiwi와 `CountVectorizer`를 함께 사용하면 필요한 품사만 추출해 빈도를 계산할 수 있음.

---

### 5단계: c-TF-IDF 토픽 표현

같은 군집의 문서를 모두 이어 붙여 **군집 하나를 하나의 긴 문서처럼 처리**.

```text
토픽 0의 모든 문서 → 하나로 합침
토픽 1의 모든 문서 → 하나로 합침
토픽 2의 모든 문서 → 하나로 합침
```

이후 토픽별 단어 점수를 계산.

- 해당 토픽에서 자주 등장하면 점수 증가: `TF`
- 다른 토픽에서도 흔하게 등장하면 점수 감소: `IDF`

따라서 특정 토픽에서만 자주 나오는 단어가 대표 키워드가 됨.

| 구분 | 일반 TF-IDF | c-TF-IDF |
|---|---|---|
| 점수를 계산하는 대상 | 문서 한 건 | 토픽 하나 |
| 문서 구성 | 각각의 원본 문서 | 같은 군집의 문서를 합친 문서 |
| 흔한 단어 감점 기준 | 전체 문서에서 흔한 단어 | 전체 토픽에서 흔한 단어 |
| 결과 | 문서의 핵심어 | 토픽의 대표 단어 |

## 3. BERTopic 실행과 결과 해석

### 기본 실행

```python
from bertopic import BERTopic

topic_model = BERTopic(
    embedding_model=model,       # 문서 임베딩
    umap_model=umap_model,       # 차원 축소
    hdbscan_model=hdb_model,     # 군집화
    vectorizer_model=vectorizer  # 한국어 토큰화·단어 빈도
)

topics, probabilities = topic_model.fit_transform(
    docs,
    embeddings=emb
)
```

- `topics`: 각 문서에 배정된 토픽 번호
- `probabilities`: 토픽 배정 관련 확률값
- `docs`: 원본 문서 목록
- `emb`: 미리 계산한 문서 임베딩

### 토픽 정보 확인

```python
topic_info = topic_model.get_topic_info()

print(
    topic_info[["Topic", "Count", "Name"]]
    .to_string(index=False)
)
```

예시 결과:

```text
 Topic  Count  Name
    -1     56  -1_우주_개최_관광객_돌파
     0    612  0_출시_개발_시장_작년
     1    294  1_여행_서울_해제_제주
     2    294  2_시즌_대표_리그_월드컵
     3    244  3_이란_터키_사망_정부
```

| 열 | 의미 |
|---|---|
| `Topic` | 토픽 번호 |
| `Count` | 해당 토픽에 포함된 문서 수 |
| `Name` | 토픽 번호와 대표 단어를 조합한 기본 이름 |

## 4. 아웃라이어와 토픽 병합

### `-1` 아웃라이어 그대로 유지

```text
장점: 애매한 문서를 억지로 넣지 않아 나머지 토픽이 깨끗함
단점: 분석에서 제외되는 문서가 생김
```

### 가까운 토픽으로 재배정

```python
new_topics = topic_model.reduce_outliers(
    docs,
    topics
)
```

`reduce_outliers()`는 아웃라이어 문서를 가장 가까운 토픽으로 다시 배정.

### 군집 기준 변경

```python
hdb_model = HDBSCAN(
    min_cluster_size=15
)
```

`min_cluster_size`를 줄이면 작은 토픽이 더 생길 수 있음.  
단, `-1` 문서 수가 반드시 줄어드는 것은 아님.

### 사람이 직접 토픽 합치기

```python
topic_model.merge_topics(
    docs,
    topics_to_merge=[0, 2]
)
```

### 자동으로 토픽 수 줄이기

```python
topic_model.reduce_topics(
    docs,
    nr_topics=4
)
```

```text
min_cluster_size → 처음 군집을 만드는 기준
merge_topics()   → 만들어진 토픽을 사람이 직접 병합
reduce_topics()  → 만들어진 토픽을 거리 기준으로 자동 병합
```

## 5. 토픽 확인과 이름 붙이기

### 대표 문서 확인

대표 키워드만 보고 토픽을 판단하면 의미를 잘못 해석할 수 있음.  
각 토픽의 대표 문서도 함께 확인.

```python
for topic_number in [0, 2]:
    representative_doc = (
        topic_model
        .get_representative_docs(topic_number)[0]
    )

    print(topic_number, "|", representative_doc)
```

예시:

```text
0 | LG유플러스 통신사 첫 알뜰폰 고객 멤버십 출시
2 | 토트넘 손흥민 3경기 연속골 폭발
```

### 토픽 이름 직접 지정

```python
topic_model.set_topic_labels({
    0: "신제품 출시·시장",
    1: "주말 여행·문화",
    2: "스포츠 경기",
    3: "국제 정세"
})
```

```python
info = topic_model.get_topic_info()

print(
    info[["Topic", "Count", "CustomName"]]
    .to_string(index=False)
)
```

- `Name`: 대표 단어로 자동 생성된 이름
- `CustomName`: 사용자가 직접 지정한 이름

## 6. 대표 키워드 추출 방식

대표 키워드를 뽑는 방식에 따라 결과가 달라짐.

| 방식 | 기준 | 특징 |
|---|---|---|
| `c-TF-IDF` | 단어 빈도 | 특정 토픽에서 자주 등장하는 단어 선택 |
| `KeyBERTInspired` | 의미 유사도 | 토픽 전체 의미와 가까운 단어 선택 |
| `MMR` | 의미와 다양성 | 비슷한 단어가 반복되지 않도록 분산 |

```text
c-TF-IDF
출시 · 개발 · 시장 · 작년

KeyBERTInspired
출시 · 도입 · 가격 · 시작

MMR
출시 · 개발 · 최대 · 증가
```

`MMR`의 `diversity` 값으로 키워드 다양성 조절.

```python
from bertopic.representation import MaximalMarginalRelevance

representation_model = MaximalMarginalRelevance(
    diversity=0.3
)

topic_model.update_topics(
    docs,
    representation_model=representation_model
)
```

- `update_topics()`: 대표 키워드 표현 방식 변경
- `set_topic_labels()`: 사람이 토픽 이름 직접 지정

## 7. BERTopic 시각화

| 확인할 내용 | 메서드 |
|---|---|
| 토픽별 대표 단어와 점수 | `visualize_barchart()` |
| 문서들이 흩어진 위치 | `visualize_documents()` |
| 토픽 사이의 거리 | `visualize_topics()` |
| 토픽이 합쳐지는 계층 구조 | `visualize_hierarchy()` |
| 시간에 따른 토픽 변화 | `visualize_topics_over_time()` |

```python
# 토픽별 대표 단어
topic_model.visualize_barchart(
    top_n_topics=4,
    n_words=6
)

# 문서 분포
topic_model.visualize_documents(
    docs,
    embeddings=emb
)

# 토픽 사이의 거리
topic_model.visualize_topics()

# 토픽 계층 구조
topic_model.visualize_hierarchy()
```

시간에 따른 토픽 변화:

```python
topics_over_time = topic_model.topics_over_time(
    docs,
    dates
)

topic_model.visualize_topics_over_time(
    topics_over_time
)
```

## 핵심 치트시트

| 하고 싶은 것 | 핵심 기술 |
|---|---|
| 문서를 의미 벡터로 변환 | Sentence Transformers · ko-sroberta |
| 768차원을 작은 차원으로 축소 | `UMAP` |
| 비슷한 문서를 자동으로 묶기 | `HDBSCAN` |
| 한국어 형태소와 단어 추출 | `Kiwi + CountVectorizer` |
| 토픽별 대표 단어 추출 | `c-TF-IDF` |
| 전체 모델 실행 | `BERTopic(...).fit_transform()` |
| `-1` 문서를 다른 토픽에 배정 | `reduce_outliers()` |
| 토픽을 직접 병합 | `merge_topics()` |
| 토픽을 자동 병합 | `reduce_topics()` |
| 대표 키워드 방식 변경 | `update_topics()` |
| 토픽 이름 직접 지정 | `set_topic_labels()` |
| 토픽별 대표 문서 확인 | `get_representative_docs()` |
| 토픽 결과표 확인 | `get_topic_info()` |
| 결과 시각화 | `visualize_barchart()` 등 |

## 한 줄 정리

```text
BERTopic =
문서 임베딩
→ UMAP 차원 축소
→ HDBSCAN 군집화
→ Kiwi 토큰화
→ c-TF-IDF 대표 단어 추출
→ 토픽 병합·시각화·이름 지정
```
