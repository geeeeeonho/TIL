# 자연어 처리 - BERTopic 토픽 모델링

## 1. BERTopic 개념과 전체 흐름

**BERTopic**은 문서를 의미가 비슷한 것끼리 묶고, 각 묶음을 대표하는 키워드를 추출하는 토픽 모델링 방법.

```text
문서
-> 임베딩: 문장을 의미 벡터로 변환
-> UMAP: 벡터 차원 축소
-> HDBSCAN: 밀도 기반 군집화
-> c-TF-IDF: 토픽별 대표 키워드 추출
```

| 단계 | 역할 | 도구 |
|---|---|---|
| 임베딩 | 문장의 의미를 숫자 벡터로 표현 | Sentence Transformer |
| 차원 축소 | 고차원 임베딩을 군집화하기 쉬운 차원으로 축소 | UMAP |
| 군집화 | 비슷한 문서를 토픽으로 묶고 애매한 문서는 `-1` 처리 | HDBSCAN |
| 토픽 표현 | 각 토픽에서 특징적인 단어를 추출 | c-TF-IDF |

일반 임베딩 군집화에 **대표 키워드 추출 과정**을 추가한 구조.

## 2. 표준 BERTopic 모델 구성

같은 설정을 반복해서 사용하려면 모델 생성 과정을 함수로 묶는 것이 편함.

```python
from bertopic import BERTopic
from umap import UMAP
from hdbscan import HDBSCAN
from sklearn.feature_extraction.text import CountVectorizer


def make_bertopic(min_topic_size=15, representation_model=None):
    """한국어 문서용 BERTopic 모델 생성.

    Parameters
    ----------
    min_topic_size : int
        하나의 토픽으로 인정할 최소 문서 수.
    representation_model : object | None
        대표 키워드를 선택하는 방식을 변경할 때 사용.

    Returns
    -------
    BERTopic
        아직 학습하지 않은 BERTopic 모델.
    """

    umap_model = UMAP(
        n_components=5,
        n_neighbors=15,
        min_dist=0.0,
        metric="cosine",
        random_state=42
    )

    hdbscan_model = HDBSCAN(
        min_cluster_size=min_topic_size,
        metric="euclidean",
        cluster_selection_method="eom",
        prediction_data=True
    )

    vectorizer_model = CountVectorizer(
        tokenizer=korean_tokenizer,
        max_df=0.85
    )

    return BERTopic(
        embedding_model=emb_model,
        umap_model=umap_model,
        hdbscan_model=hdbscan_model,
        vectorizer_model=vectorizer_model,
        representation_model=representation_model,
        verbose=False
    )
```

### 주요 설정

| 설정 | 의미 |
|---|---|
| `n_components=5` | 시각화용 2차원이 아니라 군집화용 5차원으로 축소 |
| `n_neighbors=15` | 주변 이웃 15개를 참고해 데이터 구조 파악 |
| `min_dist=0.0` | 비슷한 문서를 촘촘하게 모아 밀도 군집화에 활용 |
| `metric="cosine"` | 원래 임베딩의 방향 유사도를 기준으로 거리 계산 |
| `min_cluster_size` | 하나의 토픽으로 인정할 최소 문서 수 |
| `prediction_data=True` | 학습 후 새 문서를 `transform()`으로 배정할 때 필요한 정보 저장 |
| `max_df=0.85` | 전체 문서의 85%보다 많이 등장하는 흔한 단어 제외 |

> UMAP에서는 임베딩을 비교하므로 `cosine`, 축소된 좌표를 군집화하는 HDBSCAN에서는 `euclidean`을 사용한 구성.

## 3. 토픽 학습과 결과 해석

### 모델 학습

```python
topic_model = make_bertopic(min_topic_size=15)

topics, probs = topic_model.fit_transform(
    docs,
    embeddings=embeddings
)
```

| 변수 | 의미 |
|---|---|
| `docs` | 원본 문서 목록 |
| `embeddings` | 각 문서의 임베딩 |
| `topics[i]` | `i`번째 문서에 배정된 토픽 번호 |
| `probs[i]` | `i`번째 문서가 해당 군집에 속하는 정도 |

`fit_transform()`은 다음을 한 번에 수행.

```text
UMAP 학습
-> HDBSCAN 군집 생성
-> 문서별 토픽 번호 배정
-> c-TF-IDF 키워드 계산
```

### 전체 토픽 표 확인

```python
info = topic_model.get_topic_info()
display(info)
```

주요 열:

| 열 | 의미 |
|---|---|
| `Topic` | 토픽 번호. `-1`은 노이즈 |
| `Count` | 토픽에 포함된 문서 수 |
| `Name` | 토픽 번호와 대표 키워드를 조합한 기본 이름 |
| `Representation` | 대표 키워드 목록 |
| `Representative_Docs` | 토픽을 잘 대표하는 실제 문서 |

노이즈를 제외한 가장 큰 토픽 확인:

```python
real_topics = info[info["Topic"] != -1]
largest = real_topics.iloc[0]

print("토픽 번호:", largest["Topic"])
print("문서 수:", largest["Count"])
```

`get_topic_info()`는 일반적으로 문서 수가 큰 토픽부터 정렬되어 있으므로 첫 행을 사용. 단, `-1`이 첫 행일 수 있으므로 먼저 제외.

### 특정 토픽 해석

```python
topic_id = 0

# 대표 키워드와 c-TF-IDF 점수
for word, score in topic_model.get_topic(topic_id):
    print(f"{word:10s} {score:.3f}")

# 대표 문서
for doc in topic_model.get_representative_docs(topic_id):
    print("-", doc)
```

- `get_topic(topic_id)`: `(단어, 점수)` 목록 반환
- 점수가 높을수록 해당 토픽을 더 특징적으로 나타내는 단어
- `get_representative_docs(topic_id)`: 토픽 중심에 가까운 실제 문서 반환

토픽 이름은 키워드만 보고 정하지 말고 대표 문서까지 함께 확인해야 함.

```text
키워드 확인
-> 대표 문서 확인
-> 문서들의 공통 내용 파악
-> 사람이 읽기 좋은 토픽 이름 지정
```

## 4. 한국어 토크나이저와 c-TF-IDF

### 한국어 토크나이저가 필요한 이유

CountVectorizer의 기본 방식은 띄어쓰기 중심. 한국어에서는 조사·어미가 붙거나 불필요한 한 글자 토큰이 포함되어 키워드 품질이 떨어질 수 있음.

```python
vectorizer_model = CountVectorizer(
    tokenizer=korean_tokenizer,
    max_df=0.85
)
```

형태소 분석 기반 토크나이저를 사용하면 필요한 명사·동사·형용사 등을 선택하고 조사나 불필요한 토큰을 제거 가능.

### c-TF-IDF 작동 방식

일반 TF-IDF는 **문서 한 건**의 특징 단어를 찾음. c-TF-IDF는 같은 토픽의 문서를 모두 합쳐 **토픽 하나를 하나의 문서처럼** 처리.

```text
토픽 0의 문서 전체 -> 하나로 합침
토픽 1의 문서 전체 -> 하나로 합침
토픽 2의 문서 전체 -> 하나로 합침
```

그 뒤 다음 기준으로 키워드 점수를 계산.

- 해당 토픽에서 자주 나오면 점수 증가
- 다른 토픽에서도 흔하게 나오면 점수 감소

| 구분 | TF-IDF | c-TF-IDF |
|---|---|---|
| 계산 단위 | 원본 문서 | 토픽 전체 |
| 결과 | 문서의 핵심어 | 토픽의 대표 키워드 |
| 흔한 단어 감점 기준 | 전체 문서 | 전체 토픽 |

`max_df=0.85`는 대부분의 문서에 반복되는 단어를 제외해 토픽끼리 더 잘 구별되게 함.

## 5. 토픽 크기와 개수 조절

### `min_topic_size`

`min_topic_size`는 내부적으로 HDBSCAN의 `min_cluster_size`에 전달되는 값.

```python
model = make_bertopic(min_topic_size=30)
```

일반적인 변화:

```text
작은 값 -> 작은 문서 묶음도 토픽으로 인정 -> 토픽이 세분화됨
큰 값   -> 큰 문서 묶음만 토픽으로 인정 -> 토픽이 굵어짐
```

토픽 수와 노이즈 수 확인:

```python
topic_array = np.array(topics)

n_topics = len(set(topic_array) - {-1})
n_noise = int((topic_array == -1).sum())

print("토픽 수:", n_topics)
print("노이즈 수:", n_noise)
```

> 원문 비교 결과에서는 `min_topic_size`가 커질수록 토픽 수는 줄었지만, 노이즈 수는 단순히 증가하지 않았음. 노이즈는 데이터의 밀도 구조와 설정 조합에 따라 달라지므로 실제 결과를 직접 확인해야 함.

### 자동으로 토픽 수 줄이기

이미 학습한 모델의 비슷한 토픽을 자동 병합.

```python
before = (
    topic_model.get_topic_info()["Topic"] != -1
).sum()

topic_model.reduce_topics(
    docs,
    nr_topics=8
)

after = (
    topic_model.get_topic_info()["Topic"] != -1
).sum()

print("병합 전:", before)
print("병합 후:", after)
```

### 특정 토픽 직접 합치기

```python
topic_model.merge_topics(
    docs,
    topics_to_merge=[[0, 1], [5, 6]]
)
```

| 방법 | 사용 시점 | 방식 |
|---|---|---|
| `nr_topics=n` | 모델을 처음 만들 때 | 학습 과정에서 비슷한 토픽 자동 병합 |
| `reduce_topics(docs, nr_topics=n)` | 학습 후 | 기존 토픽을 목표 개수 근처까지 자동 병합 |
| `merge_topics(docs, [[a, b]])` | 학습 후 | 지정한 토픽을 사람이 직접 병합 |

> 원문 실행 결과에서는 `nr_topics=8`을 지정했지만 노이즈를 제외한 실제 토픽이 7개로 표시됨. 목표값을 지정한 뒤에도 `get_topic_info()`로 최종 개수를 확인해야 함.

토픽을 무리하게 합치면 서로 다른 주제가 한 토픽에 섞일 수 있으므로 병합 후 키워드와 대표 문서를 다시 확인.

## 7. 새 문서에 기존 토픽 배정

### `fit_transform()`과 `transform()` 차이

| 메서드 | 역할 | 토픽 구조 |
|---|---|---|
| `fit_transform(docs)` | 처음부터 토픽을 새로 학습 | 토픽 번호와 내용이 새로 생성됨 |
| `transform(new_docs)` | 기존 토픽 중 하나에 새 문서만 배정 | 기존 토픽 구조 유지 |

새 문서가 들어왔을 때 `fit_transform()`을 다시 실행하면 전체 군집이 다시 만들어져 기존 토픽 번호와 내용이 바뀔 수 있음.

```text
최초 학습 -> fit_transform()
새 문서 추론 -> transform()
```

### 새 문서 배정 코드

```python
new_titles = [
    "손흥민 멀티골로 팀 역전승",
    "한국은행 기준금리 동결 결정",
    "차세대 인공지능 반도체 양산 시작"
]

# 학습 때와 같은 임베딩 모델 사용
new_embeddings = emb_model.encode(new_titles)

new_topics, new_probs = topic_model.transform(
    new_titles,
    embeddings=new_embeddings
)

for title, topic_id, probability in zip(
    new_titles,
    new_topics,
    new_probs
):
    topic_id = int(topic_id)

    if topic_id == -1:
        keywords = ["노이즈"]
    else:
        keywords = [
            word
            for word, _ in topic_model.get_topic(topic_id)[:5]
        ]

    print(title)
    print("토픽:", topic_id)
    print("키워드:", keywords)
    print("배정 정도:", probability)
    print()
```

새 문서도 기존 토픽과 충분히 가깝지 않으면 `-1`로 분류될 수 있음.

## 8. 대표 키워드 선택 방식 변경

BERTopic의 군집 결과는 유지하면서 **토픽에 어떤 키워드를 붙일지**만 바꿀 수 있음.

| 방식 | 선택 기준 | 특징 |
|---|---|---|
| c-TF-IDF | 해당 토픽에서 특징적으로 자주 등장하는 단어 | 기본 방식 |
| `KeyBERTInspired` | 토픽 문서의 의미와 가까운 단어 | 빈도보다 의미 중심 |
| `MaximalMarginalRelevance` | 관련성이 높으면서 서로 겹치지 않는 단어 | 중복 키워드 감소 |

### MMR의 `diversity`

| 값 | 성격 |
|---:|---|
| `0.0` | 관련성 중심. 키워드 중복 허용 |
| `0.3` | 관련성을 유지하며 일부 중복 제거 |
| `0.7` | 서로 다른 측면의 단어를 더 많이 선택 |
| `1.0` | 다양성 중심. 관련성이 낮은 단어가 섞일 위험 |

### 학습 후 표현 방식만 변경

같은 군집 결과에서 키워드 방식만 비교하려면 모델을 다시 군집화하기보다 `update_topics()` 사용.

```python
import copy
from bertopic.representation import (
    KeyBERTInspired,
    MaximalMarginalRelevance
)

representations = {
    "KeyBERT": KeyBERTInspired(),
    "MMR 0.3": MaximalMarginalRelevance(diversity=0.3),
    "MMR 0.7": MaximalMarginalRelevance(diversity=0.7)
}

models = {}

for name, representation in representations.items():
    copied_model = copy.deepcopy(topic_model)

    copied_model.update_topics(
        docs,
        representation_model=representation
    )

    models[name] = copied_model
```

`update_topics()`는 기존 토픽 번호와 문서 배정을 유지하고 대표 키워드만 다시 계산.

### 키워드 비교

```python
rows = []

for topic_id in range(4):
    row = {
        "토픽": topic_id,
        "c-TF-IDF": ", ".join(
            word
            for word, _ in topic_model.get_topic(topic_id)[:5]
        )
    }

    for name, model in models.items():
        row[name] = ", ".join(
            word
            for word, _ in model.get_topic(topic_id)[:5]
        )

    rows.append(row)

comparison = pd.DataFrame(rows).set_index("토픽")
display(comparison)
```

키워드 목록만 보고 가장 좋은 방식을 정하지 말고 대표 문서와 함께 비교해야 함.

## 9. LLM으로 토픽 이름 자동 생성

키워드 나열 대신 LLM에 대표 키워드와 대표 문서를 전달해 사람이 읽기 좋은 토픽 이름을 생성할 수 있음.

```text
입력
- 토픽 대표 문서
- 토픽 대표 키워드

출력
- 금융 시장 동향
- 과학 기술 발전
- 축구 뉴스
```

구성 흐름:

```python
from openai import OpenAI
from bertopic.representation import OpenAI as OpenAIRepresentation

prompt = (
    "다음은 한국어 뉴스 헤드라인 토픽입니다.\n"
    "대표 헤드라인:\n[DOCUMENTS]\n"
    "키워드: [KEYWORDS]\n"
    "토픽 이름을 한국어 10자 이내로 하나만 답하세요."
)

llm_representation = OpenAIRepresentation(
    client=OpenAI(),
    model="사용할_모델명",
    chat=True,
    nr_docs=4,
    prompt=prompt
)

named_model = copy.deepcopy(topic_model)

named_model.update_topics(
    docs,
    representation_model=llm_representation
)
```

- `[DOCUMENTS]`: BERTopic이 대표 문서로 교체
- `[KEYWORDS]`: BERTopic이 대표 키워드로 교체
- `nr_docs=4`: 프롬프트에 넣을 대표 문서 수
- 군집화를 다시 하지 않고 토픽 표현만 변경 가능

LLM 이름은 자동 생성 결과이므로 대표 문서와 비교해 사람이 최종 검토해야 함.

## 전체 코드 흐름

```python
# 1. 모델 생성
topic_model = make_bertopic(min_topic_size=15)

# 2. 최초 토픽 학습
topics, probs = topic_model.fit_transform(
    docs,
    embeddings=embeddings
)

# 3. 토픽 표 확인
info = topic_model.get_topic_info()
display(info)

# 4. 특정 토픽 해석
topic_id = 0
print(topic_model.get_topic(topic_id))
print(topic_model.get_representative_docs(topic_id))

# 5. 필요하면 토픽 병합
topic_model.reduce_topics(docs, nr_topics=8)

# 6. 시각화
topic_model.visualize_barchart(top_n_topics=8)

# 7. 새 문서 추론
new_embeddings = emb_model.encode(new_titles)
new_topics, new_probs = topic_model.transform(
    new_titles,
    embeddings=new_embeddings
)

# 8. 필요하면 대표 키워드 방식 변경
topic_model.update_topics(
    docs,
    representation_model=MaximalMarginalRelevance(
        diversity=0.3
    )
)
```

## 핵심 치트시트

| 하고 싶은 일 | 핵심 코드 |
|---|---|
| BERTopic 모델 생성 | `BERTopic(...)` |
| 최초 토픽 학습 | `fit_transform(docs, embeddings=...)` |
| 전체 토픽 표 | `get_topic_info()` |
| 토픽 대표 키워드 | `get_topic(topic_id)` |
| 토픽 대표 문서 | `get_representative_docs(topic_id)` |
| 한국어 키워드 품질 개선 | `CountVectorizer(tokenizer=korean_tokenizer)` |
| 흔한 단어 제외 | `max_df=0.85` |
| 토픽 굵기 조절 | `min_topic_size` / `min_cluster_size` |
| 토픽 자동 병합 | `reduce_topics()` |
| 특정 토픽 병합 | `merge_topics()` |
| 새 문서 배정 | `transform()` |
| 키워드 표현 변경 | `update_topics(representation_model=...)` |
| 토픽별 키워드 시각화 | `visualize_barchart()` |
| 토픽 간 유사도 | `visualize_heatmap()` |
| 토픽 계층 구조 | `visualize_hierarchy()` |
| 문서 분포 | `visualize_documents()` |
