# Jev 출력과 쿼리 분기 RAG

> 핵심: **Jev가 질문을 판단하고 → Python이 실행 경로를 선택하고 → 질의 변환 + Hybrid Search를 수행하고 → LLM이 검색된 원문으로 답변**하는 구조

---

## 1. 전체 흐름

```text
사용자 질문
   ↓
Jev에 state + questions 전달
   ↓
┌───────────────────────────────┐
│ Noul   : 예/아니요 확률 판단 │
│ Choice : 항목 하나 선택       │
│ Score  : 정의한 수준 점수     │
└───────────────────────────────┘
   ↓
Python 조건문 / 라우팅
   ↓
질의 변환 방법 선택
   ├─ Self-Query
   ├─ HyDE
   ├─ Multi-Query
   ├─ Step-back
   └─ Decomposition
   ↓
Hybrid Search
(BM25 + Dense + RRF)
   ↓
검색된 실제 원문
   ↓
LLM 최종 답변
```

**중요**

- Jev는 최종 답변 생성보다 **좁은 판단·분류**에 사용
- 실제 실행 여부와 분기는 Python 코드에서 결정
- 질의 변환 결과는 **검색 입력**
- 최종 답변의 근거는 **검색된 실제 원문**

---

# 2. Jev 기본 구조

Jev 호출의 핵심 입력은 `state`, `questions`, `model`이다.

| 입력 | 역할 |
|---|---|
| `state` | 판단할 상황과 필요한 참고 정보 |
| `questions` | Noul·Choice·Score 질문 객체 |
| `model` | 사용할 Jev 모델 |

## state

문자열뿐 아니라 JSON 형태의 딕셔너리·리스트도 전달 가능하다.

```python
state = {
    "user_query": "그중에서 초보자가 볼 책을 찾아 주세요.",
    "conversation": [
        "사용자: 파이썬 데이터 분석 책을 찾고 있어요."
    ],
    "service_scope": "도서 목록에서 관련 책 찾기",
    "user_context": {
        "experience": "파이썬 기초 문법을 배운 상태"
    },
}
```

`user_query`, `conversation`, `service_scope` 등은 API 고정 키가 아니라 **작업에 맞게 직접 정의한 키**다.

# 4. Jev의 세 가지 출력

## 4-1. Noul — 예/아니요 확률

`Noul`은 **질문에 대한 답이 "예"일 확률**을 반환한다.

```python
needs_documents_question = Noul(
    instructions="사용자 문의에 답하려면 도서관의 자료 또는 공간 이용 규정을 확인해야 하나요?"
)

response = jev_client.system_one(
    model=jev_model,
    state="도서관 그룹 학습실은 몇 명부터 이용할 수 있나요?",
    questions={"needs_documents": needs_documents_question},
)

value = response.answers["needs_documents"].noul
```

### 실행 결과

```text
noul = 0.92
```

해석:

```text
1에 가까움 → 예
0에 가까움 → 아니요
0.5 근처   → 판단이 애매함
```

0.1도 Python에서는 `True`로 바뀔 수 있으므로 `bool()`로 처리하지 않고 **직접 임계값을 비교**한다.

```python
if value >= 0.8:
    print("규정을 조회")
elif value <= 0.2:
    print("규정 조회 불필요")
else:
    print("추가 확인 필요")
```

> `0.2`, `0.8`은 교안에서 정한 수업용 정책값이다.

---

## 4-2. Choice — 정해진 항목 중 하나 선택

`Choice`는 **순서가 없는 여러 종류 중 하나를 고르는 분류**에 사용한다.

```python
topic_question = Choice(
    instructions="사용자의 도서관 문의가 주로 다루는 주제는 무엇인가요?",
    criteria={
        "loan": "대출 권수, 기간, 연장, 연체",
        "return": "반납 장소, 반납함, 파손 또는 분실",
        "space": "열람실 또는 그룹 학습실 예약과 이용",
        "digital": "전자책, 학술 DB, 교외 인증",
        "other": "분류하기 어려운 문의",
    },
)
```

### 실행 결과

```text
choice     = space
confidence = 1.0
```

`Choice`의 항목은 **종류**일 뿐 순위가 아니다.

```text
loan > space
```

같은 의미는 존재하지 않는다.

### confidence 주의

`confidence`는 확률 분포가 한쪽으로 얼마나 모였는지를 나타낸다.

```text
confidence = 0.9
```

를 곧바로

```text
정답일 확률 = 90%
```

로 해석하지 않는다.

---

## 4-3. Score — 순서가 있는 수준 판단

`Score`는 **미리 순서를 정한 기준**에서 어느 수준에 가까운지 판단한다.

예:

| 점수 | 의미 |
|---:|---|
| 0 | 사실 하나 |
| 1 | 규칙 하나 + 조건·예외 |
| 2 | 같은 주제의 여러 규칙 |
| 3 | 서로 다른 여러 주제 |

```python
breadth_question = Score(
    instructions="사용자 질문에 답하려면 어느 범위의 정보를 모아야 하나요?",
    criteria=[
        "특정 사실 하나",
        "규칙 하나와 조건·예외",
        "같은 주제의 여러 규칙",
        "서로 다른 여러 주제",
    ],
)
```

예제 질문:

```text
도서관의 대출, 반납, 공간, 전자 자료 이용 규칙을
한 번에 정리해 주세요.
```

실행 결과:

```text
score      = 3.0
confidence = 1.0
```

### Score 계산

Score는 각 수준 번호에 해당 수준의 확률을 곱해 합산한 값이다.

```text
Score = Σ(수준 점수 × 해당 수준 확률)
```

예:

```text
2점 확률 = 0.2
3점 확률 = 0.8

Score
= 2 × 0.2 + 3 × 0.8
= 2.8
```

**Score가 높다고 답변 품질이나 정답률이 높은 것은 아니다.**

점수의 의미는 `criteria`를 어떻게 정의했는지에 따라 달라진다.

# 5. Noul / Choice / Score 비교

| 종류 | 반환값 | 용도 |
|---|---|---|
| `Noul` | 예일 확률 `0~1` | 참/거짓 판단 |
| `Choice` | 선택 항목 | 순서 없는 분류 |
| `Score` | 정의한 수준의 점수 | 단계·강도·범위 판단 |
| `confidence` | 판단 분포의 집중 정도 | Choice/Score 판단 확인 |

```text
Noul      → "예인가?"
Choice    → "어느 종류인가?"
Score     → "어느 수준인가?"
confidence → "판단이 얼마나 한쪽에 집중됐는가?"
```

# 6. 독립적인 판단은 한 번에 요청 가능

동일한 `state`에 여러 질문을 넣을 수 있다.

```python
response = jev_client.system_one(
    model=jev_model,
    state=basic_query,
    questions={
        "topic": topic_question,
        "breadth": breadth_question,
        "needs_documents": needs_documents_question,
    },
)
```

실제 예제 결과:

```text
Choice : space
Score  : 0.08
Noul   : 0.92
```

### 중요한 구조

```text
                 같은 state
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
    Choice         Score          Noul
       ↓             ↓             ↓
    topic         breadth   needs_documents
       └─────────────┼─────────────┘
                     ↓
              Python에서 조합
```

각 질문이 **앞 질문의 결과를 전달받는 순차 체인 구조는 아니다.**

따라서 다음과 같은 의존 로직은 호출 후 Python에서 처리한다.

```python
if topic == "space" and needs_documents >= 0.8:
    ...
```

# 7. Jev를 RAG 라우터로 사용

교안의 핵심 응용은 Jev의 `Choice`를 이용해 **질문에 맞는 질의 변환 방법 하나를 고르는 것**이다.

```text
사용자 질문
   ↓
Jev Choice
   ↓
질의 변환 방법 선택
   ↓
선택된 방법만 실행
   ↓
Hybrid Search
   ↓
검색 원문
   ↓
LLM 답변
```

## 라우팅 기준

| 방법 | 선택 기준 | 실제 검색 입력 |
|---|---|---|
| `self_query` | 분야·연도 같은 명시적 조건 존재 | 검색어 + 메타데이터 필터 |
| `hyde` | 전문 용어 없이 상황·목표로 설명 | 가상 소개문을 Dense 검색에 사용 |
| `multi_query` | 같은 의미를 다양한 표현으로 검색 | 원질문 + 변형 질문 |
| `step_back` | 구체적 문제의 배경 원리까지 필요 | 원질문 + 기초 개념 질문 |
| `decomposition` | 서로 다른 요구가 여러 개 존재 | 독립 하위 질문 |
| `clarify` | 검색 범위 밖 또는 대상 불명확 | 검색 보류 |

교안에서 겹치는 조건의 우선순위는 다음과 같이 정의한다.

```text
명시적 메타데이터 조건
        ↓
독립적인 여러 정보 요구
        ↓
배경 원리
        ↓
용어 부족
        ↓
같은 의미의 표현 확장
```

# 9. 질의 변환 방법 선택 코드

```python
route_question = Choice(
    instructions=(
        "도서 검색 질문에 적용할 질의 변환 방법 하나를 고르세요. "
        "도서 검색과 무관하거나 대상을 알 수 없으면 clarify입니다."
    ),
    criteria={
        "self_query": "분류 또는 출판 연도 조건이 명시됨",
        "decomposition": "독립적인 여러 주제를 각각 검색해야 함",
        "step_back": "배경 원리나 기초 개념 이해가 필요함",
        "hyde": "전문 용어 없이 상황이나 목표만 설명함",
        "multi_query": "같은 의미를 여러 표현으로 검색함",
        "clarify": "검색 범위 밖 또는 검색 대상이 불명확함",
    },
)
```

질문과 서비스 범위를 `state`에 넣는다.

```python
def route_query(question):
    return jev_client.system_one(
        model=jev_model,
        state={
            "user_query": question,
            "service_scope": (
                "컴퓨터·수학·과학·역사·문학 분야의 "
                "가상 도서 목록에서 관련 책 찾기"
            ),
        },
        questions={"method": route_question},
    )
```

# 10. confidence 기준으로 검색 실행 여부 결정

교안에서는 `confidence < 0.6`이면 검색하지 않고 확인 질문으로 돌린다.

```python
def select_method(decision, threshold=0.6):
    answer = decision.answers["method"]

    methods = {
        "self_query",
        "hyde",
        "multi_query",
        "step_back",
        "decomposition",
    }

    if (
        answer.choice in methods
        and answer.confidence >= threshold
    ):
        return answer.choice

    return "clarify"
```

> `0.6`은 수업용 정책값이며 공식 정답 보장 기준은 아니다.

# 11. 선택 결과를 실제 RAG 실행으로 연결

가장 중요한 연결은 다음 한 줄이다.

```python
found, trace = retrieve(
    question,
    method,
    retrieval,
)
```

반환값:

```text
found
└─ 실제 검색된 원문 Document

trace
└─ 검색에 사용한 변환 질문 / 필터 / HyDE 가상 문서
```

### 최종 답변에서는 역할을 분리

```text
trace
→ 검색 과정 확인용
→ 최종 근거 X

found
→ 실제 검색 원문
→ 최종 답변 근거 O
```

# 12. 전체 RAG 함수

핵심만 압축하면 다음 구조다.

```python
def run_rag(question):
    # 1. Jev가 검색 방법 판단
    decision = route_query(question)

    # 2. confidence까지 확인해 실제 실행 방법 결정
    method = select_method(decision)

    # 3. 불명확하면 검색 중단
    if method == "clarify":
        return {
            "status": "clarify",
            "answer": "어떤 주제나 조건의 책을 찾는지 구체적으로 알려 주세요.",
        }

    # 4. 선택한 질의 변환 + 검색
    found, trace = retrieve(
        question,
        method,
        retrieval,
    )

    # 5. 근거가 없으면 답변 생성 중단
    if not found:
        return {
            "status": "no_evidence",
            "method": method,
            "transformation": trace,
            "answer": "조건에 맞는 근거를 찾지 못했습니다.",
        }

    # 6. 검색된 실제 원문으로 답변
    answer = answer_chain.invoke({
        "question": question,
        "context": format_context(found),
    })

    return {
        "status": "answered",
        "method": method,
        "transformation": trace,
        "answer": answer,
    }
```

# 13. 다섯 질의 변환의 실제 분기 결과

## ① Self-Query

질문:

```text
2018년 이전 과학 분야에서
천체의 일생을 설명하는 책을 찾아 주세요.
```

Jev 결과:

```text
method     = self_query
confidence = 0.99
```

검색 입력:

```text
검색어 : 천체의 일생

필터:
year < 2018
AND
category = 과학
```

주요 검색 결과:

```text
book05 코스모스 우주와 별의 세계
```

→ **명시적 메타데이터 조건을 분리해 검색**

## ② HyDE

질문:

```text
용어를 몰라요.
직원 설문에서 일부 사람의 답변으로
회사 전체 경향을 짐작하는 방법을 배울 책을 찾아 주세요.
```

Jev 결과:

```text
method     = hyde
confidence = 0.98
```

검색 구조:

```text
원질문
 ├─ BM25 → 원질문 그대로
 └─ Dense → LLM이 생성한 가상 설명문
```

가상 설명문에는 `표본조사`, `통계적 추론`, `표본오차` 등의 관련 용어가 생성됐다.

주요 검색 결과:

```text
book03 그림으로 이해하는 통계학 기초
```

→ **사용자가 전문 용어를 몰라도 가상 문서를 통해 Dense 검색을 보강**

> 가상 설명문은 검색을 위한 입력일 뿐 최종 답변의 사실 근거가 아니다.

## ④ Step-back

# 14. 전체 라우팅 구조 정리

```text
사용자 질문
     │
     ▼
┌──────────────┐
│  Jev Choice  │
└──────┬───────┘
       │
       ├─ 메타데이터 조건 ──────→ Self-Query
       │
       ├─ 독립 요구 여러 개 ────→ Decomposition
       │
       ├─ 배경 원리 필요 ───────→ Step-back
       │
       ├─ 전문 용어 부족 ───────→ HyDE
       │
       ├─ 같은 의미 표현 확장 ──→ Multi-Query
       │
       └─ 불명확 / 범위 밖 ─────→ Clarify
                                     │
                                     └─ 검색 중단
```

선택된 경우:

```text
질의 변환
   ↓
BM25 + Dense
   ↓
RRF
   ↓
실제 검색 원문
   ↓
LLM
   ↓
근거 기반 최종 답변
```

# 15. 구현 시 핵심 원칙

### 1. Jev는 판단만 담당

```text
Jev
→ 어떤 경로를 실행할지 판단

Python
→ 실제 조건과 실행 제어

검색기
→ 근거 문서 검색

LLM
→ 검색된 원문을 바탕으로 답변
```

---

### 2. 질의 변환 결과와 답변 근거를 구분

```text
Self-Query 필터
HyDE 가상 문서
Multi-Query 변형 질문
Step-back 질문
Decomposition 하위 질문

        ↓

모두 검색을 위한 입력
```

최종 답변은 다음을 근거로 사용한다.

```text
검색된 실제 원문 Document
```

---

### 3. confidence는 실행 정책으로 사용 가능

```python
if confidence >= threshold:
    검색 실행
else:
    clarify
```

단, threshold 자체는 서비스 상황에 맞게 검증해서 정해야 한다.

---

### 4. 여러 Jev 질문은 독립적

한 번의 API 요청에 여러 질문을 넣어도:

```text
질문 A → 질문 B → 질문 C
```

처럼 연결되는 것이 아니다.

```text
          state
      ┌────┼────┐
      ↓    ↓    ↓
      A    B    C
```

각각 독립적으로 판단한 뒤 결과를 Python에서 조합한다.

# 16. 핵심 요약

| 개념 | 핵심 |
|---|---|
| `Noul` | 예일 확률 반환 |
| `Choice` | 순서 없는 항목 하나 선택 |
| `Score` | 정의된 순서 기준의 점수 |
| `confidence` | 판단 분포의 집중 정도 |
| Jev 역할 | 질문의 성격 판단 |
| Python 역할 | 실행 분기와 정책 처리 |
| 질의 변환 | 검색 성능을 높이기 위한 입력 변환 |
| Hybrid Search | BM25 + Dense + RRF |
| `trace` | 질의 변환·검색 입력 기록 |
| `found` | 실제 검색된 원문 |
| 최종 답변 | `found`의 실제 원문만 근거로 생성 |

## 한 줄 구조

```text
질문 → Jev 판단 → Python 분기 → 질의 변환 → Hybrid Search → 실제 원문 → LLM 답변
```
