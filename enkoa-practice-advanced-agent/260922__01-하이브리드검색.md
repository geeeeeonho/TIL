# 하이브리드 검색 압축 정리

## 1. 핵심 개념

**하이브리드 검색(Hybrid Search)**은 서로 다른 검색 방식의 결과를 합쳐 최종 검색 결과를 만드는 방법이다.

이 교안에서는 같은 문서 집합을 다음 두 방식으로 검색한다.

| 방식 | 기준 | 강점 |
|---|---|---|
| **BM25** | 같은 토큰의 등장 여부·희귀도·빈도·문서 길이 | 제품명, 오류 코드, 전문용어 등 **정확한 표현** |
| **Dense** | 질문·문서 임베딩 벡터의 거리 | 표현이 달라도 **의미가 비슷한 문서** |

두 결과는 **RRF(Reciprocal Rank Fusion)**로 합친다.

### 전체 흐름

```text
                 ┌─ BM25 검색 ──> 순위 목록 ─┐
질문 ────────────┤                         ├─> RRF ─> 중복 제거 ─> 최종 Top-K
                 └─ Dense 검색 ─> 순위 목록 ─┘

                   같은 원문은 source_id로 식별
```

Advanced RAG 흐름에서 보면 다음 위치에 해당한다.

```text
검색 전(Pre-retrieval)
청킹 · RAPTOR · 질의 변환
        ↓
검색(Retrieval)
BM25 · Dense · Hybrid   ← 이번 교안
        ↓
검색 후(Post-retrieval)
리랭킹 · 컨텍스트 압축
```

```python

```

원문 ID는 검색 결과를 결합할 때 다시 사용한다.

```python
def make_documents(records):

                "title": record["title"],
                "url": record["url"],
                "source": record["source"],
                **record["metadata"],
            },
        )
        for record in records
    ]
```

# 3. BM25 검색

## BM25의 핵심

BM25는 질문과 문서를 토큰으로 나눈 뒤 **문자열이 같은 토큰**을 기준으로 점수를 계산한다.

주요 요소는 다음 세 가지다.

- **DF(Document Frequency)**: 해당 토큰이 등장한 문서 수
- **TF(Term Frequency)**: 한 문서 안에서 해당 토큰이 반복된 횟수
- **문서 길이**: 현재 문서 길이를 전체 평균 문서 길이와 비교해 보정

### 이미지 내용 텍스트화

```text
질문: [프로그래밍, 파이썬]

문서 A : 프로그래밍 + 파이썬 3회
문서 B : 프로그래밍
문서 C : 프로그래밍
문서 D : 파이썬 1회

프로그래밍
└─ 여러 문서에 등장 → 희귀도(IDF) 낮음

파이썬
└─ 적은 문서에 등장 → 희귀도(IDF) 높음

A 문서
└─ 높은 파이썬 IDF + 높은 TF의 영향을 함께 받음
```

## 한국어 토큰화

한국어는 조사가 붙기 때문에 단순 공백 분리보다 형태소 분석이 유리하다.

```python
kiwi = Kiwi()


def kiwi_tokenize(text):
    text = text.replace("･", "·")
    return [
        token.form.lower()
        for token in kiwi.tokenize(text)
        if token.tag.startswith("N") or token.tag in {"SL", "SN"}
    ]
```

### 결과

```text
공백 분리  : ['미적분을', '배우는', '책']
형태소 분리: ['미적분', '책']
```

**문서와 질문 모두 같은 토큰화 함수를 사용해야 한다.**

---

## BM25 수식

```math
BM25(Q,d)
= \sum_{t\in Q}
IDF(t)
\cdot
\frac{f(t,d)(k_1+1)}
{f(t,d)+k_1\left(1-b+b\frac{|d|}{avgdl}\right)}
```

의미만 압축하면 다음과 같다.

```text
문서 점수
= 질문 토큰별 [희귀도 × 반복 횟수·문서 길이 보정]의 합
```

| 값 | 의미 |
|---|---|
| `IDF(t)` | 희귀한 토큰일수록 크게 반영 |
| `f(t,d)` | 문서 안의 토큰 반복 횟수(TF) |
| `k1` | 반복 횟수를 얼마나 강하게 반영할지 조절 |
| `b` | 문서 길이 보정 정도 |
| `k` | BM25 수식 파라미터가 아니라 **반환할 문서 개수** |

> BM25 점수는 정답 확률이 아니다.

---

## BM25 검색기 생성

```python
bm25 = BM25Retriever.from_documents(
    documents,
    preprocess_func=kiwi_tokenize,
    bm25_params={"k1": 1.5, "b": 0.75},
    k=3,
)

bm25_results = bm25.invoke("미적분")
```

### 실행 결과 핵심

`미적분` 질문에서는 `book04`만 실제 점수를 받았다.

```text
BM25 점수
book04 = 1.83
나머지 = 0
```

하지만 `k=3`이므로 검색 결과는 3개까지 반환된다.

```text
1. book04  미적분의 정석 개념편   ← 실제 점수 존재
2. book09  어린 왕자 다시 읽기     ← 0점
3. book08  총 균 쇠 문명의 역사    ← 0점
```

**중요:** BM25 결과가 반환됐다는 사실만으로 관련 근거가 있다는 뜻은 아니다. 점수가 모두 0이어도 `k`개를 채워 반환할 수 있다.

# 4. Dense 검색

Dense 검색은 질문과 문서를 임베딩 벡터로 바꾼 뒤 가까운 문서를 찾는다.

```text
문서 ──> Embedding ──> Vector Store
질문 ──> Embedding ──> 유사한 벡터 검색
```

문자열이 정확히 같지 않아도 의미가 가까우면 검색될 수 있다.

```python
vector_store = Chroma(
    collection_name="day47_lesson01_books",
    embedding_function=embedding_model,
)

vector_store.reset_collection()
vector_store.add_documents(documents)

dense = vector_store.as_retriever(search_kwargs={"k": 3})
```

## BM25와 Dense 비교

질문:

```text
컴퓨터가 예시에서 규칙을 배우는 방법
```

BM25는 질문 토큰이 문서에 없어 **모든 점수가 0**이었다.

Dense 결과에는 의미적으로 관련된 딥러닝 문서가 포함됐다.

```text
Dense Top-3
1. book00  파이썬으로 배우는 자료구조와 알고리즘
2. book03  그림으로 이해하는 통계학 기초
3. book01  밑바닥부터 시작하는 딥러닝 신경망 원리
```

### 매뉴얼 예시

질문:

```text
집에서 일할 때 회사 자료를 안전하게 다루려면?
```

Dense 결과:

```text
1. hr_security             재택근무의 보안대책
2. hr_feedback             성과 저조 시 대응과 협업
3. hr_remote_daily_routine 재택근무의 하루 계획·시간 경계·동료와의 일정 공유
```

BM25 Top-3에는 `hr_security`가 포함되지 않았다.

즉, 원문이 질문의 `자료·안전` 대신 `보안`이라는 표현을 사용할 때 Dense가 이를 보완할 수 있다.

# 5. RRF로 검색 순위 합치기

BM25 점수와 Dense의 거리·유사도 값은 계산 방식과 범위가 다르므로 **원래 점수를 그대로 더하지 않는다.**

RRF는 검색 결과의 **등수**를 새 점수로 변환한다.

```math
RRF(d)
= \sum_{j:d\in L_j}
\frac{w_j}{c+r_j(d)}
```

```text
검색기 한 개의 기여점수
= 검색기 가중치 / (c + 문서 등수)
```

- `w_j`: 검색기 가중치
- `r_j(d)`: 해당 검색기에서 문서의 등수. 1부터 시작
- `c`: 등수 차이를 완화하는 상수. 교안에서는 60
- `c`와 검색 개수 `k`는 서로 다른 값

## 이미지 내용 텍스트화

```text
BM25 순위          Dense 순위
1. B               1. D
2. A               2. A
3. C               3. E
       \           /
        \         /
           RRF
            │
            ├─ A : 두 검색기의 2위 점수를 합산
            ├─ B : BM25 1위 점수만 받음
            └─ D : Dense 1위 점수만 받음
```

가중치가 각각 0.5일 때:

```text
A = 0.5/62 + 0.5/62 ≈ 0.01613
B = 0.5/61          ≈ 0.00820
```

따라서 **두 검색기에 동시에 등장한 A가 한 검색기의 1위 B보다 앞설 수 있다.**

# 6. EnsembleRetriever로 Hybrid 검색

```python
hybrid = EnsembleRetriever(
    retrievers=[bm25, dense],
    weights=[0.3, 0.7],
    c=60,
    id_key="source_id",
)

hybrid_results = hybrid.invoke(query)
```

### 동작

```text
BM25 Top-K ─┐
            ├─ RRF 점수 계산
Dense Top-K ┘
        ↓
source_id 기준 중복 제거
        ↓
RRF 점수 내림차순 정렬
```

`id_key="source_id"`를 지정하면 같은 원문인지 원문 ID로 판단한다.

각 검색기가 3개씩 반환하면 합쳐진 후보 수는 다음 범위가 된다.

```text
완전히 동일한 결과 → 3개
전혀 겹치지 않음   → 6개
```

## 주의할 점

BM25 점수가 0인 문서라도 BM25 반환 목록에 포함되면 RRF에서는 다음 점수를 받는다.

```text
가중치 / (c + 등수)
```

즉, **RRF는 원래 BM25 점수가 0인지 확인하지 않는다.**

따라서 하이브리드 검색은 단순 결합만으로 끝내지 않고 실제 질문 세트로 성능을 평가해야 한다.

# 7. Recall@3으로 검색 품질 비교

```text
Recall@3
= 상위 3개에서 찾은 정답 문서 수
  ─────────────────────────
        전체 정답 문서 수
```

```python
def source_recall(documents, expected_ids):
    expected = set(expected_ids)
    retrieved_ids = {
        doc.metadata["source_id"] for doc in documents
    }
    return len(retrieved_ids & expected) / len(expected)
```

## 가상 도서 데이터 결과

| 질문 유형 | BM25 | Dense | Hybrid 0.5/0.5 | Hybrid 0.3/0.7 |
|---|---:|---:|---:|---:|
| 정확한 용어 | 1.000 | 1.000 | 1.000 | 1.000 |
| 어휘가 다른 질문 | 0.000 | 1.000 | 1.000 | 1.000 |
| 두 가지 요구 | 0.500 | 1.000 | 1.000 | 1.000 |
| 세 가지 요구 | 0.667 | 0.667 | 0.667 | 0.667 |
| **평균** | **0.542** | **0.917** | **0.917** | **0.917** |

이 데이터에서는 Dense와 Hybrid가 BM25보다 높은 평균 Recall@3을 보였다.

---

## 실제 매뉴얼 6개 질문 결과

| 질문 | BM25 | Dense | Hybrid 0.5/0.5 | Hybrid 0.3/0.7 |
|---|---:|---:|---:|---:|
| q1 | 1.000 | 0.000 | 1.000 | 0.000 |
| q4 | 1.000 | 1.000 | 1.000 | 1.000 |
| q6 | 1.000 | 1.000 | 1.000 | 1.000 |
| q11 | 0.000 | 1.000 | 1.000 | 1.000 |
| q31 | 0.000 | 1.000 | 0.500 | 1.000 |
| q32 | 0.667 | 0.667 | 1.000 | 1.000 |
| **평균** | **0.611** | **0.778** | **0.917** | **0.833** |

이 실습에서는 `Hybrid 0.5/0.5`의 평균 Recall@3이 가장 높았다.

**핵심:** 가중치의 최적값은 고정되어 있지 않다. 문서와 실제 질문 세트로 비교해 결정해야 한다.

# 9. 원본 노트북에서 확인할 부분

원본의 실습 지시와 실제 실행 셀 사이에 일부 차이가 있다.

### 1) BM25 따라하기

지시문은 `시차출퇴근 취업규칙` 검색에서 첫 결과가 `hr_stagger_rules`라고 적혀 있다.

하지만 실제 코드에서는 질문을 다음처럼 실행했다.

```python
prac_bm25.invoke("시차출퇴근 및 취업규칙")
```

실행 결과는 다음 순서다.

```text
1. hr_stagger_consent
2. hr_stagger_hours
3. hr_stagger_rules
```

따라서 **지시문의 확인 기준과 실제 실행 결과가 일치하지 않는다.**

### 2) Hybrid 따라하기

지시문:

```text
weights = [0.3, 0.7]
c = 60
id_key = 'source_id'
```

실제 실행 셀:

```python
prac_hybrid = EnsembleRetriever(
    retrievers=[prac_bm25, prac_dense],
    weights=[0.5, 0.5],
    id_key="source_id",
)
```

즉, 실제 코드는 가중치가 다르고 `c=60`도 명시하지 않았다.

# 10. 최종 핵심 정리

| 개념 | 기억할 핵심 |
|---|---|
| **BM25** | 정확한 토큰 일치. IDF·TF·문서 길이 반영 |
| **Kiwi** | 한국어 조사 등을 분리해 질문과 문서의 토큰화를 통일 |
| **Dense** | 표현이 달라도 의미가 가까운 문서를 검색 가능 |
| **RRF** | 원래 점수가 아니라 **검색 등수**를 이용해 서로 다른 검색 결과 결합 |
| **Hybrid** | BM25와 Dense의 상보성을 이용하고 `source_id`로 중복 제거 |
| **Recall@K** | 실제 정답 문서를 얼마나 놓치지 않았는지 평가 |
| **가중치** | 고정 정답 없음. 실제 질문 세트로 비교해서 결정 |

```text
정확한 단어가 중요함 ──────────> BM25 강점
표현이 달라도 의미가 중요함 ───> Dense 강점
둘 다 필요함 ──────────────────> Hybrid + RRF
```
