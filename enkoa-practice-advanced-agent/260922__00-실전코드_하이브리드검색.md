# 하이브리드 검색 실전 코드 정리

BM25와 Dense 검색을 각각 수행하고, `EnsembleRetriever`로 결합해 하이브리드 검색을 구성하는 흐름.

> 전제: `documents`, `kiwi_tokenize()`, `show_results()`, `vector_store`, `source_recall()`은 앞선 코드에서 이미 정의되어 있다고 가정.

---

## 1. 한국어 질문을 형태소 토큰으로 변환

공백 분리와 형태소 분석 결과를 비교한다.

### 코드

```python
# 같은 질문을 두 방식으로 나누어 비교
question = "관계형 데이터베이스를 설명해 주세요"

# 공백 분리 -> 단어에 붙은 조사가 그대로 남음
space_tokens = question.split()

# 문서와 질문에 같은 전처리를 적용해야 같은 토큰끼리 비교 가능
query_tokens = kiwi_tokenize(question)

print("공백 분리:", space_tokens)
print("형태소 토큰:", query_tokens)
```

### 결과

```text
공백 분리: ['관계형', '데이터베이스를', '설명해', '주세요']
형태소 토큰: ['관계', '데이터베이스', '설명']
```

형태소 분석을 사용하면 조사와 어미를 제거해 `데이터베이스를`을 `데이터베이스`처럼 검색에 유리한 형태로 비교할 수 있음.

---

## 2. 형태소 전처리를 적용한 BM25 검색

한국어 문서 검색에서 `kiwi_tokenize`를 BM25의 전처리 함수로 연결한다.

### 코드

```python
# 검색할 질문
bm25_question = "GeoJSON 형식을 설명한 문서를 찾아 주세요."

# BM25 검색기 생성
bm25 = BM25Retriever.from_documents(
    documents=documents,
    preprocess_func=kiwi_tokenize,
    bm25_params={"k1": 1.5, "b": 0.75},
    k=2,
)

# 검색 수행
bm25_results = bm25.invoke(bm25_question)

# 결과 확인
show_results(bm25_results)
```

### 결과

원본에서는 긴 DataFrame 형태로 출력됨. 핵심 정보만 표시.

```text
1. source_id: wiki4
   title: GeoJSON
   category: 데이터
   text: "GeoJSON은 위치 정보를 표현하기 위한 공개 표준 형식이며 ..."

2. source_id: wiki1
   title: 관계형 데이터베이스
   category: 데이터
   text: "관계형 데이터베이스는 데이터를 행과 열 구조로 저장하며 ..."
```

`k=2`이므로 BM25 점수가 높은 상위 2개 문서만 반환됨.

## 3. 각 문서의 BM25 점수 직접 확인

Retriever의 최종 결과만 보는 대신 모든 문서의 BM25 점수를 확인한다.

### 코드

```python
# get_scores()는 문자열이 아니라 토큰 목록을 입력받음
score_tokens = kiwi_tokenize(
    "GeoJSON 형식을 설명한 문서를 찾아 주세요."
)

# 모든 문서의 BM25 점수 계산
bm25_scores = bm25.vectorizer.get_scores(score_tokens)

# documents 순서와 점수 순서가 같으므로 source_id와 묶음
score_by_id = {}

for doc, score in zip(documents, bm25_scores):
    source_id = doc.metadata["source_id"]
    score_by_id[source_id] = float(score)

print("원문 ID별 BM25 점수:", score_by_id)
print(
    "검색 결과 ID:",
    [doc.metadata["source_id"] for doc in bm25_results],
)
```

### 결과

```text
원문 ID별 BM25 점수:
{
    'wiki4': 2.075058202863026,
    'wiki3': 0.0,
    'wiki2': 0.0,
    'wiki1': 0.36473300595695013,
    'wiki0': 0.0
}

검색 결과 ID: ['wiki4', 'wiki1']
```

`get_scores()`는 전체 문서의 점수를 반환하고, Retriever는 그중 상위 `k`개를 반환함.

## 4. Dense 검색과 BM25 결과 비교

동일한 질문을 Dense와 BM25에 넣어 검색 방식에 따른 차이를 확인한다.

### 코드

```python
# 두 검색기에 같은 질문 사용
# 5번 하이브리드 검색에서도 그대로 사용
dense_question = "표 모양으로 정보를 정리해 두고 SQL로 꺼내 보는 시스템"

# Vector Store -> Retriever
dense = vector_store.as_retriever(
    search_kwargs={"k": 2}
)

# Dense 검색
dense_results = dense.invoke(dense_question)

# BM25 검색
bm25_compare_results = bm25.invoke(dense_question)

# source_id 기준 공통 문서 확인
dense_ids = {
    doc.metadata["source_id"]
    for doc in dense_results
}

bm25_ids = {
    doc.metadata["source_id"]
    for doc in bm25_compare_results
}

common_ids = dense_ids & bm25_ids

print("Dense 결과")
show_results(dense_results)

print("BM25 결과")
show_results(bm25_compare_results)

print("두 결과에 모두 있는 ID:", common_ids)
```

### 결과

긴 표 대신 검색 순위와 핵심 문서만 표시.

```text
Dense 결과
1. wiki2 | 데이터베이스 | "데이터를 체계적으로 관리하고 저장하는 시스템 ..."
2. wiki1 | 관계형 데이터베이스 | "행과 열 형태로 데이터를 저장하며 SQL을 사용 ..."

BM25 결과
1. wiki1 | 관계형 데이터베이스 | "행과 열 형태로 데이터를 저장하며 SQL을 사용 ..."
2. wiki4 | GeoJSON | "위치 정보를 표현하기 위한 형식 ..."

두 결과에 모두 있는 ID: {'wiki1'}
```

- BM25: 질문과 문서의 **단어가 얼마나 직접 겹치는지**에 강함.
- Dense: 표현이 달라도 **의미가 가까운 문서**를 찾는 데 강함.

## 5. BM25 + Dense 하이브리드 검색

두 검색기의 순위를 `EnsembleRetriever`로 결합한다.

### 코드

```python
hybrid = EnsembleRetriever(
    retrievers=[bm25, dense],
    weights=[0.3, 0.7],
    c=60,
    id_key="source_id",
)

# 같은 질문으로 하이브리드 검색
hybrid_results = hybrid.invoke(dense_question)

# 상위 2개만 사용
hybrid_top = hybrid_results[:2]

print("합친 결과 수:", len(hybrid_results))
show_results(hybrid_top)
```

### 결과

```text
합친 결과 수: 3

1. wiki1 | 관계형 데이터베이스 | "행과 열 구조로 데이터를 저장하며 SQL을 사용 ..."
2. wiki2 | 데이터베이스 | "데이터를 체계적으로 저장하고 관리하는 시스템 ..."
```

### 핵심 설정

- `retrievers=[bm25, dense]`: 결합할 검색기.
- `weights=[0.3, 0.7]`: BM25 30%, Dense 70% 비중.
- `c=60`: RRF(Reciprocal Rank Fusion)의 순위 계산 상수.
- `id_key="source_id"`: 같은 원문에서 나온 결과를 하나로 통합.

> `weights`는 각 검색기의 원래 유사도 점수를 단순 합산하는 값이 아니라, RRF로 계산되는 **순위 기여도**에 적용됨.

## 6. 검색기 가중치 비교

같은 후보를 사용해 BM25, Dense, 하이브리드 가중치 조합의 `Recall@2`를 비교한다.

### 6-1. 비교용 질문과 후보 생성

```python
compare_question = (
    "코미디 프로그램에서 이름을 딴 언어와 "
    "행과 열로 자료를 저장하는 시스템을 알려 주세요"
)

# 정답으로 기대하는 원문 ID
expected_ids = {"wiki0", "wiki1"}

# BM25와 Dense 검색은 각각 한 번만 수행
candidates = [
    bm25.invoke(compare_question),
    dense.invoke(compare_question),
]
```

같은 `candidates`를 재사용하면 가중치 외의 조건을 동일하게 유지한 상태에서 비교할 수 있음.

### 6-2. 0.5 / 0.5 하이브리드 생성

```python
hybrid_even = EnsembleRetriever(
    retrievers=[bm25, dense],
    weights=[0.5, 0.5],
    c=60,
    id_key="source_id",
)
```

### 6-3. 검색 방식별 결과 비교

```python
method_results = {
    "BM25": candidates[0][:2],
    "Dense": candidates[1][:2],
    "Hybrid 0.3/0.7": hybrid.weighted_reciprocal_rank(candidates)[:2],
    "Hybrid 0.5/0.5": hybrid_even.weighted_reciprocal_rank(candidates)[:2],
}

# Recall@2 계산
recall_by_method = {}

for name, results in method_results.items():
    recall_by_method[name] = source_recall(
        results,
        expected_ids,
    )

# 검색된 원문 ID와 Recall@2 확인
for name, results in method_results.items():
    source_ids = [
        doc.metadata["source_id"]
        for doc in results
    ]

    print(
        name,
        "/ 원문 ID:", source_ids,
        "/ Recall@2:", recall_by_method[name],
    )
```

### 결과

```text
BM25 / 원문 ID: ['wiki1', 'wiki0'] / Recall@2: 1.0
Dense / 원문 ID: ['wiki3', 'wiki2'] / Recall@2: 0.0
Hybrid 0.3/0.7 / 원문 ID: ['wiki3', 'wiki2'] / Recall@2: 0.0
Hybrid 0.5/0.5 / 원문 ID: ['wiki1', 'wiki3'] / Recall@2: 0.5
```

이 예시에서는 질문에 정답 문서의 핵심 단어가 직접 포함되어 있어 BM25가 가장 높은 `Recall@2`를 기록함.

단, 한 질문의 결과만으로 검색기 성능을 일반화하면 안 됨. 실제 하이브리드 가중치는 여러 평가 질문의 `Recall@K`, `MRR@K` 등을 기준으로 조정하는 것이 적절함.

---

## 전체 흐름

```text
한국어 질문
   ↓
형태소 토큰화
   ↓
┌─────────────────┬─────────────────┐
│ BM25            │ Dense           │
│ 키워드 기반 검색 │ 의미 기반 검색  │
└────────┬────────┴────────┬────────┘
         │                 │
         └──────┬──────────┘
                ↓
        EnsembleRetriever
        + RRF 순위 결합
                ↓
        Hybrid Search 결과
                ↓
      Recall@K 등으로 평가
```

### 핵심 정리

- 한국어 BM25는 형태소 토큰화를 적용해 조사·어미 때문에 단어 매칭이 깨지는 문제를 줄임.
- BM25는 키워드 일치, Dense는 의미 유사성을 중심으로 검색함.
- 하이브리드 검색은 두 검색기의 결과 순위를 RRF 방식으로 결합함.
- 가중치는 고정된 정답이 아니라 평가 데이터에 맞춰 조정해야 함.
