# 리랭킹(Reranking) 압축 정리

> 1차 검색 후보를 질문과 다시 비교해 **관련성이 높은 순서로 재정렬하고 상위 문서를 선택**하는 후처리 단계.
> 후보 안의 순서만 바꾸므로 **후보에 없는 문서를 새로 찾지는 못함**.

---

## 1. 전체 흐름

리랭킹은 Advanced RAG의 **검색 후(Post-retrieval)** 단계에 위치함.

```text
질의 변환
   ↓
BM25 + Dense 검색
   ↓
후보 문서 확보
   ↓
리랭킹
   ↓
상위 문서 선택
   ↓
컨텍스트 압축
   ↓
LLM 답변
```

교안 01은 **리랭킹 + 문서 선택**, 다음 교안은 **선택한 문서의 내용 압축**을 다룸.

### 후보 수와 최종 문서 수

```text
BM25 (k=5) ─┐
             ├─> 합치기 + 중복 제거 ─> 후보 최대 10개
Dense (k=5) ─┘                         ↓
                                      Reranker
                                         ↓
                                     top_n=3
                                         ↓
                                    최종 3개
```

| 설정 | 의미 |
|---|---|
| `k`, `top_k` | 리랭커에 넘길 **후보 수** |
| `top_n` | 리랭킹 후 **최종 남길 문서 수** |

- 일반적인 시작 예시: 후보 약 20개 → 최종 3~5개.
- 필요한 근거가 후보에 없으면 `top_n`이 아니라 **검색 후보 수**를 늘려야 함.
- 후보 수가 늘면 근거 포함 가능성은 커지지만 리랭킹 비용도 증가함.

---

## 2. Bi-Encoder · Cross-Encoder · ColBERT

| 방식 | 문서 쪽 준비 | 질문 처리 | 특징 |
|---|---|---|---|
| **Bi-Encoder(Dense)** | 문서당 벡터 1개 | 질문 벡터와 유사도 비교 | 빠른 1차 검색 |
| **Cross-Encoder** | 원문 | 질문+문서를 함께 입력해 점수 계산 | 후보마다 다시 계산 |
| **ColBERT** | 문서 토큰별 벡터 | 질문 토큰과 문서 토큰 비교 | 토큰 단위 비교, 저장량 증가 |

```text
Bi-Encoder
질문 → [질문 벡터] ─┐
                    ├→ 유사도
문서 → [문서 벡터] ─┘

Cross-Encoder
[질문 + 문서] → 모델 → 관련성 점수

ColBERT
질문 → [q1][q2][q3]...
          ↕   ↕   ↕   MaxSim
문서 → [d1][d2][d3]...
```

어떤 방식이 항상 더 정확하거나 빠르다고 단정하지 않음. 언어, 문서 길이, 모델, 후보 수에 따라 달라짐.

---

## 3. Cross-Encoder 리랭킹

실습 모델은 `Qwen/Qwen3-Reranker-0.6B`.

- CPU 사용
- 최대 입력 `1024` 토큰
- 최초 가중치 약 `1.19GB`
- 긴 입력은 뒤쪽이 잘릴 수 있음

### 3-1. 모델 준비

```python
from langchain_community.cross_encoders import HuggingFaceCrossEncoder

cross_encoder = HuggingFaceCrossEncoder(
    model_name="Qwen/Qwen3-Reranker-0.6B",
    model_kwargs={"device": "cpu", "max_length": 1024},
)
```

### 3-2. 질문-문서 쌍 점수 계산

```python
pairs = [
    (question, doc.page_content)
    for doc in candidates
]

scores = cross_encoder.score(pairs)
```

```text
(question, doc1) → score1
(question, doc2) → score2
(question, doc3) → score3
```

`score()`는 **입력한 후보 순서대로 점수만 반환**함. 정렬은 별도로 해야 함.

점수 해석:

- 높은 점수 = 해당 모델이 질문과 더 관련 있다고 판단.
- 정답 확률로 해석하지 않음.
- Dense 점수나 다른 리랭커 점수와 그대로 합치지 않음.
- 최종 판단은 `source_id`와 실제 원문을 확인해야 함.

### 3-3. `CrossEncoderReranker`로 정렬 + 상위 N개 선택

```python
from langchain_classic.retrievers.document_compressors import CrossEncoderReranker

reranker = CrossEncoderReranker(
    model=cross_encoder,
    top_n=3,
)

reranked = list(
    reranker.compress_documents(candidates, question)
)
```

```text
후보 Documents
      ↓
CrossEncoderReranker
      ├─ 점수 계산
      ├─ 점수순 정렬
      └─ top_n개 선택
      ↓
상위 Documents
```

`compress_documents()`는 여기서 본문을 줄이는 것이 아니라 **후보를 재정렬하고 상위 문서를 선택**함.

| API | 반환 |
|---|---|
| `cross_encoder.score()` | 입력 순서의 점수 목록 |
| `reranker.compress_documents()` | 점수순 상위 `Document` 목록 |

전후 비교는 문서 제목보다 **`source_id` 기준**으로 연결하는 것이 안전함.

## 4. ColBERT 방식 리랭킹

Cross-Encoder는 질문과 문서를 함께 읽지만, ColBERT는 둘을 **각각 토큰별 벡터로 만든 뒤 비교**함.

실습 설정:

- 모델: `BAAI/bge-m3`
- `FlagEmbedding==1.4.2`
- CPU 사용
- 최초 가중치 약 `2.3GB`
- `return_colbert_vecs=True`

### 4-1. 모델 준비

```python
from FlagEmbedding import BGEM3FlagModel

colbert_model = BGEM3FlagModel(
    "BAAI/bge-m3",
    devices="cpu",
    batch_size=2,
    passage_max_length=1024,
    return_dense=False,
    return_colbert_vecs=True,
)
```

### 4-2. 질문과 문서 인코딩

```python
query_output = colbert_model.encode_queries([question])
query_vectors = query_output["colbert_vecs"][0]

candidate_texts = [doc.page_content for doc in candidates]
document_output = colbert_model.encode_corpus(candidate_texts)
document_vectors = document_output["colbert_vecs"]
```

`colbert_vecs`는 텍스트 하나를 벡터 하나로 만드는 것이 아니라:

```text
문장
 ↓
[token1 vector]
[token2 vector]
[token3 vector]
...
```

형태로 토큰별 벡터를 보관함.

### 4-3. MaxSim 점수

질문의 각 토큰마다 문서 토큰 중 가장 잘 맞는 값을 선택해 점수화함.

```text
q1 → max(d1, d2, d3, ...)
q2 → max(d1, d2, d3, ...)
q3 → max(d1, d2, d3, ...)
             ↓
          점수 집계
```

BGE-M3 구현은 이 값을 질문 토큰 수로 나눈 평균을 사용함.
같은 질문 안에서는 후보 간 순위 비교에 사용 가능함.

```python
colbert_scores = []

for vectors in document_vectors:
    score = colbert_model.colbert_score(
        query_vectors,
        vectors,
    )
    colbert_scores.append(float(score))
```

### 4-4. 상위 문서 선택

```python
colbert_order = sorted(
    range(len(candidates)),
    key=lambda i: colbert_scores[i],
    reverse=True,
)

colbert_reranked = [
    candidates[i]
    for i in colbert_order[:3]
]
```

특징:

- 문서 토큰 벡터를 미리 저장해 재사용 가능.
- Dense보다 저장량이 증가함.
- 전체 검색뿐 아니라 **이미 검색한 후보의 재정렬**에도 사용할 수 있음.

## 5. 검색 + 리랭킹 연결

`ContextualCompressionRetriever`로 검색기와 리랭커를 하나의 검색 흐름으로 묶을 수 있음.

```python
from langchain_classic.retrievers import ContextualCompressionRetriever

ranked_retriever = ContextualCompressionRetriever(
    base_retriever=hybrid,
    base_compressor=reranker,
)

results = ranked_retriever.invoke(new_question)
```

```text
new_question
     ↓
ContextualCompressionRetriever
     ↓
base_retriever = hybrid
     ↓
1차 후보 검색
     ↓
base_compressor = reranker
     ↓
재정렬 + top_n 선택
     ↓
최종 Documents
```

주의:

- `.invoke()`할 때마다 **1차 검색부터 다시 실행**함.
- Cross-Encoder와 ColBERT처럼 리랭커 자체를 공정하게 비교하려면 **같은 `candidates`를 고정**해서 사용해야 함.

## 6. 결과 판단 기준

```text
필요한 문서가 후보에 없음
        ↓
검색 단계 문제
→ k / top_k 확대, 검색 방식 점검

후보에는 있는데 리랭킹 후 빠짐
        ↓
리랭킹 단계 문제
→ 점수·원문 확인, top_n 확대, 모델 점검
```

| 구분 | 확인할 것 |
|---|---|
| 후보 검색 | 필요한 원문이 후보 안에 있는가 |
| 리랭킹 | 같은 후보에서 더 적절한 근거가 위로 올라왔는가 |
| Cross-Encoder | 질문의 여러 조건을 함께 만족하는 문서를 골랐는가 |
| ColBERT | 토큰 단위 비교 후 실제 원문 품질이 좋아졌는가 |
| 최종 검증 | `source_id`와 원문을 직접 대조했는가 |

---

## 7. 핵심 코드 흐름

```python
# 1. 후보 검색
candidates = hybrid.invoke(question)

# 2. Cross-Encoder 준비
cross_encoder = HuggingFaceCrossEncoder(
    model_name="Qwen/Qwen3-Reranker-0.6B",
    model_kwargs={"device": "cpu", "max_length": 1024},
)

# 3. 상위 3개 선택
reranker = CrossEncoderReranker(
    model=cross_encoder,
    top_n=3,
)

reranked = list(
    reranker.compress_documents(candidates, question)
)

# 4. 검색 + 리랭킹 묶기
ranked_retriever = ContextualCompressionRetriever(
    base_retriever=hybrid,
    base_compressor=reranker,
)

results = ranked_retriever.invoke(new_question)
```

```text
Hybrid Search
   → Candidates
   → Reranker
   → Top-N Documents
   → Context Compression
   → LLM Answer
```

---

## 8. 핵심 정리

- 리랭킹 = **검색 후보를 다시 평가하는 후처리**.
- `k/top_k` = 후보 수, `top_n` = 최종 문서 수.
- 후보에 없는 문서는 리랭킹으로 복구할 수 없음.
- Cross-Encoder = 질문+문서를 함께 읽어 점수 계산.
- ColBERT = 질문·문서를 토큰별 벡터로 만들고 MaxSim으로 비교.
- 공정한 비교는 **동일한 후보 집합**에서 수행.
- 자동 연결은 `ContextualCompressionRetriever` 사용.
- 점수보다 중요한 것은 **최종 원문이 질문 조건을 실제로 만족하는지 확인하는 것**.
