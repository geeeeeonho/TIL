# 질의 변환 실전 코드 정리

사용자 질문을 그대로 검색하지 않고, 검색 목적에 맞게 **조건 추출·확장·일반화·분해**한 뒤 검색 결과를 실제 답변 근거로 연결하는 흐름.

> 전제: `llm`, `vector_store`, `bm25`, `dense`, `hybrid`, `TOP_K`, `query_schema_prompt`, `show_results()`, `compare_recall()`, `unique_documents()`, `save_json()` 등은 앞선 코드에서 이미 정의되어 있다고 가정.

---

## 1. Self-Query로 메타데이터 조건 추출

질문에서 **실제 검색어**와 **메타데이터 필터 조건**을 분리한 뒤, 조건에 맞는 문서만 Dense 검색한다.

### 코드

```python
# 조건으로 사용할 메타데이터 필드 정의
metadata_field_info = [
    AttributeInfo(
        name="category",
        description="안내 분야: 배송, 교환반품, 주문결제, 회원",
        type="string",
    ),
    AttributeInfo(
        name="channel",
        description="구매 경로: 온라인, 매장",
        type="string",
    ),
]

question = (
    "온라인 구매의 배송 분야 안내에서 "
    "합배송 조건과 배송 상태 확인 방법을 찾아 주세요."
)

# 질문에서 검색어와 메타데이터 조건을 추출하는 검색기
self_query = SelfQueryRetriever.from_llm(
    llm=llm,
    vectorstore=vector_store,
    document_contents="생활용품 쇼핑몰의 배송·교환·반품·결제 안내",
    metadata_field_info=metadata_field_info,
    chain_kwargs={"schema_prompt": query_schema_prompt},
    structured_query_translator=ChromaTranslator(),
    search_kwargs={"k": TOP_K},
)

# 질문을 검색어 + 조건으로 구조화
parsed = self_query.query_constructor.invoke({"query": question})

# Chroma 검색 형식으로 변환
query_text, search_kwargs = ChromaTranslator().visit_structured_query(parsed)
where = search_kwargs.get("filter")

print("검색어:", query_text)
print("조건:", where)

# 검색어와 필터를 함께 적용
self_query_results = vector_store.similarity_search(
    query_text,
    k=TOP_K,
    filter=where,
)

show_results(self_query_results)
```

### 결과

```text
검색어: 합배송 조건과 배송 상태 확인 방법
조건: {
    '$and': [
        {'category': {'$eq': '배송'}},
        {'channel': {'$eq': '온라인'}}
    ]
}

1. shop03 | 온라인 상품 함께 보내는 합배송 조건
   category: 배송 | channel: 온라인
   text: "온라인 상품을 함께 보내는 합배송 조건은 ..."

2. shop12 | 온라인 주문의 배송 조회와 미수령 문의
   category: 배송 | channel: 온라인
   text: "온라인 주문의 배송 조회와 미수령 문의는 ..."
```

Self-Query는 질문 전체를 그대로 검색하지 않고 다음처럼 나눠 사용할 수 있음.

```text
사용자 질문
   ↓
검색어: "합배송 조건과 배송 상태 확인 방법"
   +
메타데이터 조건: category=배송 AND channel=온라인
   ↓
조건을 만족하는 문서만 검색
```

## 2. BM25와 Dense에 같은 메타데이터 조건 적용

Self-Query에서 만든 `where` 조건을 BM25와 Dense 양쪽에 동일하게 적용한다.

### 코드

```python
# 1번의 where 조건을 만족하는 원문 ID 조회
matched = vector_store.get(
    where=where,
    include=["metadatas"],
)

allowed_ids = {
    item["source_id"]
    for item in matched["metadatas"]
}

# BM25 전체 문서 점수 계산
scores = bm25.vectorizer.get_scores(
    bm25.preprocess_func(query_text)
)

# 허용된 문서만 BM25 후보로 남김
scored_candidates = [
    (doc, score)
    for doc, score in zip(bm25.docs, scores)
    if doc.metadata["source_id"] in allowed_ids
]

# Dense에도 같은 조건 적용
filtered_dense = vector_store.similarity_search(
    query_text,
    k=TOP_K,
    filter=where,
)

# BM25 후보를 점수순으로 정렬
scored_candidates.sort(
    key=lambda item: item[1],
    reverse=True,
)

filtered_bm25 = [
    doc
    for doc, score in scored_candidates[:TOP_K]
]

# 필터링한 BM25 + Dense 결과를 RRF로 결합
filtered_results = hybrid.weighted_reciprocal_rank(
    [filtered_bm25, filtered_dense]
)[:TOP_K]

# 조건 적용 전후 비교
expected_ids = {"shop03", "shop12"}

before_results = hybrid.invoke(question)[:TOP_K]

print("조건 없이 검색")
show_results(before_results)

print("같은 조건으로 검색")
show_results(filtered_results)

compare_recall(
    before_results,
    filtered_results,
    expected_ids,
)
```

### 결과

긴 표는 핵심만 표시.

```text
[조건 없이 검색]
1. shop03 | 온라인 상품 함께 보내는 합배송 조건 | ...
2. shop12 | 온라인 주문의 배송 조회와 미수령 문의 | ...

[같은 조건으로 검색]
1. shop03 | 온라인 상품 함께 보내는 합배송 조건 | ...
2. shop02 | 온라인 주문의 배송지 변경 | ...

Recall 비교
- 변환 전: 1.0
- 변환 후: 0.5
- 변환 후 누락 ID: ['shop12']
```

이 예시에서는 같은 메타데이터 조건을 적용했지만 최종 `TOP_K` 결과의 `Recall`은 오히려 감소함.

즉, **필터 조건 적용 자체와 검색 품질 향상은 동일한 의미가 아니므로 실제 결과를 평가해야 함.**

## 3. HyDE: 질문을 검색용 가상문단으로 변환

사용자 질문에 검색 문서에서 사용될 만한 표현이 부족할 때, 질문을 **가상의 문서 형태**로 바꿔 Dense 검색에 사용한다.

> 가상문서는 검색에만 사용하고, 최종 답변은 실제 검색 원문을 근거로 작성함.

### 3-1. HyDE 프롬프트 생성

```python
hyde_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "질문에 답할 내용이 담긴 가상의 원문을 3문장 이내로 작성하세요. "
        "각 요구에 필요한 핵심 개념을 해당 분야의 표준 용어로 명시하고 설명하세요. "
        "질문을 다시 쓰거나 관련 주제를 추가하지 마세요. "
        "도서 검색 질문에는 해당 내용을 가르치는 책의 소개문을 쓰되 "
        "책 제목·저자·출판사는 만들지 마세요. "
        "확인되지 않은 구체적인 수치나 규정을 지어내지 마세요. "
        "요청문·검색어 목록 없이 한글 원문만 출력하세요."
    ),
    ("human", "{question}"),
])
```

### 3-2. 가상문단을 Dense 검색에 사용

```python
hyde_question = "물건을 돌려보낸 뒤 돈은 어떤 과정을 거쳐 돌아오나요?"
hyde_expected_ids = {"shop06", "shop07"}

# 질문 -> 가상문단
hyde_chain = hyde_prompt | llm | StrOutputParser()

hypothesis = hyde_chain.invoke({
    "question": hyde_question,
})

print("검색용 가상문단:", hypothesis)

# BM25는 원질문 사용
hyde_bm25 = bm25.invoke(hyde_question)

# Dense는 가상문단 사용
hyde_dense = dense.invoke(hypothesis)

# 비교용: 원질문으로 Dense 검색
question_dense = dense.invoke(hyde_question)

print(
    "Dense(가상문단):",
    [doc.metadata["source_id"] for doc in hyde_dense],
)

print(
    "Dense(원질문):",
    [doc.metadata["source_id"] for doc in question_dense],
)

# BM25 + HyDE Dense 결과 결합
hyde_results = hybrid.weighted_reciprocal_rank(
    [hyde_bm25, hyde_dense]
)[:TOP_K]

show_results(hyde_results)

# 적용 전후 Recall 비교
hyde_before = hybrid.invoke(hyde_question)[:TOP_K]

compare_recall(
    hyde_before,
    hyde_results,
    hyde_expected_ids,
)
```

### 결과

```text
검색용 가상문단:
"반품된 상품이 판매자에게 도착해 검수되면, 판매자는 반품 승인 후
결제대행사나 금융기관에 환불을 요청합니다. 환불은 원칙적으로
결제에 사용한 수단으로 이루어지며 ..."

Dense(가상문단): ['shop07', 'shop06']
Dense(원질문): ['shop07', 'shop06']

Hybrid 결과
1. shop02 | ...
2. shop07 | ...

Recall 비교
- 변환 전: 0.5
- 변환 후: 0.5
- 누락 ID: ['shop06']
```

이 예시에서는 가상문단과 원질문 Dense 검색 결과가 동일했고, 최종 `Recall`도 개선되지 않음.

## 4. Multi-Query: 같은 질문을 여러 표현으로 확장

하나의 질문을 서로 다른 표현의 검색 질문으로 여러 개 생성하고, **생성 질문 + 원질문**을 모두 검색한다.

### 코드

```python
# 검색 질문 생성 규칙
multi_prompt = ChatPromptTemplate.from_template(
    "질문과 같은 의미를 유지하는 검색 질문을 서로 다른 표현으로 정확히 3개 작성하세요. "
    "일상 표현을 관련 분야의 표준 용어로 바꾼 질문도 포함하세요. "
    "원문의 정보 요구·고유명사·조건을 유지하세요. 질문의 언어를 유지하세요. "
    "설명·번호·빈 줄 없이 한 줄에 질문 하나만 출력하세요.\n"
    "질문: {question}"
)


def show_queries(queries):
    """생성된 검색 질문을 출력하고 그대로 전달합니다."""
    print("생성 질문:", queries)
    return queries


multi_question = "여러 물건을 한 상자로 묶어 받는 조건이 궁금해요."
multi_expected_ids = {"shop03"}

# 생성 질문 + 원질문을 함께 검색
multi_query = MultiQueryRetriever.from_llm(
    retriever=hybrid,
    llm=llm,
    prompt=multi_prompt,
    include_original=True,
)

# 생성 질문 확인
multi_query.llm_chain = (
    multi_query.llm_chain
    | show_queries
)

# 중복 문서 제거
multi_query_chain = (
    multi_query
    | unique_documents
)

multi_results = multi_query_chain.invoke(
    multi_question
)

# 적용 전후 비교
multi_before = hybrid.invoke(multi_question)

show_results(multi_results)
compare_recall(
    multi_before,
    multi_results,
    multi_expected_ids,
)
```

### 결과

```text
생성 질문:
1. 여러 상품을 하나의 상자에 합포장하여 받을 수 있는 조건이 궁금합니다.
2. 복수의 물품을 한 박스로 묶음배송받으려면 어떤 조건이 필요한가요?
3. 여러 주문 상품을 단일 박스로 통합 포장해 수령할 수 있는 기준은 무엇인가요?

검색 결과:
shop01, shop04, shop05, shop07, shop12, ...

Recall 비교
- 변환 전: 1.0 / 검색 문서 수: 1
- 변환 후: 1.0 / 검색 문서 수: 5
```

이 예시에서는 정답 문서의 `Recall`은 그대로지만, 여러 표현으로 검색하면서 검색 후보 범위가 넓어짐.

## 5. Step-Back: 원질문 + 일반화한 배경 질문 검색

구체적인 질문 하나만 검색하지 않고, 질문을 더 일반화한 **배경 질문**을 추가로 생성해 함께 검색한다.

### 코드

```python
stepback_question = (
    "반품한 상품을 확인한 다음에 환불하는 이유는 무엇이며, "
    "어떤 절차를 거치나요?"
)

stepback_expected_ids = {"shop06", "shop07"}

# 구체적인 질문 -> 일반적인 배경 질문
stepback_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "원질문의 특정 상품이나 주문 상황을 일반화해, "
        "그 배경 개념을 묻는 질문 하나를 작성하세요. "
        "구매·배송·교환·반품이라는 업무 범위를 유지하고, "
        "질문의 핵심 처리와 그 목적을 남기세요. "
        "관련 없는 법률·경제 이론으로 주제를 넓히지 마세요. "
        "답변이나 설명 없이 한글 질문만 출력하세요."
    ),
    (
        "human",
        "택배가 어디까지 왔는지 알려면 왜 운송장번호가 필요한가요?"
    ),
    (
        "ai",
        "운송장 식별자와 배송 이력 추적은 어떤 관계인가요?"
    ),
    ("human", "{question}"),
])

# Step-Back 체인
stepback_chain = (
    stepback_prompt
    | llm
    | StrOutputParser()
)

# 배경 질문 생성
background_question = stepback_chain.invoke({
    "question": stepback_question,
})

print("배경 질문:", background_question)

# 원질문과 배경 질문을 각각 Hybrid 검색
question_results = hybrid.batch([
    stepback_question,
    background_question,
])

direct_results = question_results[0][:TOP_K]
background_results = question_results[1][:TOP_K]

# 배경 질문으로 새로 검색된 문서 확인
direct_ids = {
    doc.metadata["source_id"]
    for doc in direct_results
}

background_ids = {
    doc.metadata["source_id"]
    for doc in background_results
}

added_ids = background_ids - direct_ids

print("배경 질문으로 추가된 원문 ID:", added_ids)

# 두 결과를 합치고 중복 제거
stepback_results = unique_documents(
    direct_results + background_results
)

show_results(stepback_results)

compare_recall(
    direct_results,
    stepback_results,
    stepback_expected_ids,
)
```

### 결과

```text
배경 질문:
반품 상품을 확인한 뒤 환불을 처리하는 이유와 일반적인 절차는 무엇인가요?

배경 질문으로 추가된 원문 ID: set()

검색 결과
1. shop07 | 반품 검수 및 환불 대상 판정 | ...
2. shop06 | 온라인 반품 접수부터 환불까지의 절차 | ...

Recall 비교
- 변환 전: 1.0
- 변환 후: 1.0
```

이 예시에서는 원질문 검색만으로 필요한 문서가 이미 검색되어 Step-Back으로 새 문서가 추가되지는 않음.

## 6. Decomposition: 복합 질문을 하위 질문으로 분해

하나의 질문에 서로 다른 정보 요구가 포함되어 있을 때, 질문을 **독립적으로 검색 가능한 하위 질문**으로 나눈다.

### 6-1. 구조화 출력 스키마 정의

```python
class SubQuestions(BaseModel):
    """원질문을 나누어 검색할 하위 질문 목록입니다."""

    questions: list[str] = Field(
        description=(
            "원질문의 서로 다른 정보 요구를 하나씩 묻는 질문 2~3개. "
            "각 질문만으로 검색할 수 있게 대상과 조건을 포함하고, "
            "원질문에 없는 요구를 추가하지 않으며 같은 언어로 작성."
        ),
        min_length=2,
        max_length=3,
    )
```

### 6-2. 질문 분해 및 검색

```python
decomposition_question = (
    "깨진 컵을 교환하려면 어떤 자료를 제출해야 하나요? "
    "배송지를 바꿀 수 있는 시점도 알려 주세요."
)

decomposition_expected_ids = {
    "shop04",
    "shop02",
}

# 질문 분해 프롬프트
decompose_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "원질문의 서로 다른 정보 요구를 하나씩 묻는 질문 2~3개로 나누세요. "
        "각 질문만으로 검색할 수 있게 대상과 조건을 포함하세요. "
        "원질문에 없는 요구를 추가하지 말고 같은 언어로 작성하세요."
    ),
    ("human", "{question}"),
])

# 구조화 출력 체인
decompose_chain = (
    decompose_prompt
    | llm.with_structured_output(
        schema=SubQuestions,
        method="json_schema",
    )
)

# 원질문 -> 하위 질문
subquestions = decompose_chain.invoke({
    "question": decomposition_question,
})

print("하위 질문:", subquestions.questions)

# 각각의 하위 질문을 검색
subquestion_results = hybrid.batch(
    subquestions.questions
)

# 질문별 상위 TOP_K 결과를 하나로 합침
all_results = []

for results in subquestion_results:
    all_results.extend(results[:TOP_K])

# 중복 문서 제거
decomposition_results = unique_documents(
    all_results
)

show_results(decomposition_results)

# 원질문 검색과 비교
decomposition_before = hybrid.invoke(
    decomposition_question
)[:TOP_K]

compare_recall(
    decomposition_before,
    decomposition_results,
    decomposition_expected_ids,
)
```

## 7. 실제 검색 원문을 최종 답변 근거로 연결

질의 변환은 **검색을 위한 과정**으로 사용하고, 최종 답변은 실제로 검색된 원문만 근거로 작성한다.

### 7-1. 검색 문서를 답변용 문맥으로 변환

```python
def format_context(documents):
    """실제 검색 문서의 본문·메타데이터·출처를 답변 문맥으로 만듭니다."""

    return "\n\n".join(
        f"[{doc.metadata['source_id']}] {doc.metadata['title']}\n"
        f"메타데이터: {doc.metadata}\n"
        f"본문: {doc.page_content}"
        for doc in documents
    )
```

### 7-2. 원문 기반 답변 체인 생성

```python
answer_prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "제공된 본문과 메타데이터에서 직접 확인되는 내용만 한글로 답하세요. "
        "질문에 직접 답하는 내용만 최대 3개 항목으로 쓰고, "
        "항목마다 1~2문장과 [원문 ID] 인용을 넣으세요. "
        "관련 없는 문서는 언급하지 마세요. "
        "원문에 없는 절차·조건·조언을 추가하지 마세요. "
        "원문의 권고나 가능성을 의무로 바꾸지 말고, "
        "수치·단위·비율·조건을 그대로 보존하세요. "
        "사용자가 제시한 방안을 원문이 허용하거나 정당화한다고 추론하지 마세요. "
        "근거가 부족한 부분은 확인할 수 없다고 말하고, 추가 결론은 쓰지 마세요."
    ),
    (
        "human",
        "질문: {question}\n\n원문 근거:\n{context}"
    ),
])

answer_chain = (
    answer_prompt
```

## 전체 흐름

```text
사용자 질문
   │
   ├─ Self-Query
   │   └─ 검색어 + 메타데이터 조건 추출
   │
   ├─ HyDE
   │   └─ 질문 → 검색용 가상문단
   │
   ├─ Multi-Query
   │   └─ 같은 의미의 여러 검색 질문 생성
   │
   ├─ Step-Back
   │   └─ 구체적 질문 + 일반화한 배경 질문
   │
   └─ Decomposition
       └─ 복합 질문 → 독립적인 하위 질문
                ↓
         BM25 / Dense / Hybrid 검색
                ↓
           실제 원문 Document
                ↓
         원문 기반 최종 답변 생성
                ↓
         source_id와 함께 결과 저장
```

### 핵심 정리

- **Self-Query**: 질문에서 검색어와 메타데이터 조건을 분리함.
- **HyDE**: 질문을 검색 문서와 유사한 가상문단으로 변환해 Dense 검색에 사용함.
- **Multi-Query**: 같은 의미의 여러 표현을 검색해 검색 범위를 확장함.
- **Step-Back**: 구체적인 질문과 더 일반적인 배경 질문을 함께 검색함.
- **Decomposition**: 여러 요구가 섞인 질문을 독립적인 하위 질문으로 나눔.
- 질의 변환 결과는 **검색용**으로 사용하고, 최종 답변은 실제 검색된 원문을 근거로 작성함.
- 질의 변환 기법이 항상 `Recall`을 높이는 것은 아니므로 적용 전후를 실제 평가 결과로 비교해야 함.
