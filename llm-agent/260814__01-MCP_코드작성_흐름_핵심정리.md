# 1. MCP 핵심

**MCP(Model Context Protocol)**  
AI 앱이 파일·검색·DB·브라우저·코드 실행 같은 외부 도구를 **공통 규격으로 연결**하는 방식.

```text
사용자
 ↓
Agent(Host)
 ↓
MultiServerMCPClient
 ↓
MCP Server
 ↓
파일 / 검색 / 브라우저 / DB / 코드 실행
```

실습에서 가장 중요한 특징:

```python
await tool.ainvoke({...})
await agent.ainvoke({"messages": question})
```

- MCP 도구는 비동기 호출 사용
- 결과는 일반 문자열이 아니라 콘텐츠 블록 형태
- 교안에서는 `block_text(result)`로 문자열 추출

# 2. 공통 코드 작성 흐름

모든 실습의 기본 구조는 거의 동일.

```text
① 경로·환경 준비
↓
② MCP 서버 설정
↓
③ Client 생성
↓
④ tools 로드
↓
⑤ 도구 이름·인자 확인
↓
⑥ 필요한 도구만 선택
↓
⑦ 직접 ainvoke로 테스트
↓
⑧ create_agent에 연결
↓
⑨ agent.ainvoke 실행
↓
⑩ 실제 결과 검증
```

## 기본 뼈대

```python
from langchain.agents import create_agent
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain_openai import ChatOpenAI

# 1. 서버 설정
SERVER = {
    "command": "...",       # npx / uvx
    "args": [...],
    "transport": "stdio",
}

# 2. 연결
client = MultiServerMCPClient({"server": SERVER})
tools = await client.get_tools()

# 3. 이름으로 찾기
by_name = {tool.name: tool for tool in tools}

# 4. 직접 호출
result = await by_name["도구명"].ainvoke({...})

# 5. 에이전트
model = ChatOpenAI(model="...", temperature=0)

agent = create_agent(
    model,
    tools,
    system_prompt="도구 사용 규칙",
)

# 6. 실행
result = await agent.ainvoke({"messages": "질문"})
```

### 서버 실행 방식

```python
# 로컬 서버
{
    "command": "npx",   # Node 패키지
    # 또는 "uvx"       # Python 패키지
    "args": [...],
    "transport": "stdio",
}
```

원격 서버는 `url + streamable_http` 구조 사용.

# 3. 서버별 코드 흐름

## 3-1. 파일시스템 MCP

**목적:** 허용한 폴더 안의 파일 조회·읽기·쓰기.

```python
FILESYSTEM = {
    "command": "npx",
    "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        str(DAY_DIR),
    ],
    "transport": "stdio",
}

client = MultiServerMCPClient({"files": FILESYSTEM})
tools = await client.get_tools(server_name="files")
by_name = {tool.name: tool for tool in tools}
```

직접 호출:

```python
result = await by_name["list_directory"].ainvoke({
    "path": str(DATA_DIR)
})
```

에이전트에는 필요한 권한만 전달.

```python
read_only = [
    by_name["list_directory"],
    by_name["read_text_file"],
    by_name["get_file_info"],
]
```

```text
허용 폴더 = 접근 범위
넘긴 도구 = 실제 권한
```

---

## 3-2. 웹 검색 MCP

**목적:** 검색 → 필요한 페이지 본문 확인.

```text
search
→ URL 확인
→ fetch_content
→ 본문 근거로 답 생성
```

```python
WEB_SEARCH = {
    "command": "uvx",
    "args": ["duckduckgo-mcp-server"],
    "transport": "stdio",
}
```

```python
found = await by_name["search"].ainvoke({
    "query": "MCP 개념",
    "max_results": 3,
})

body = await by_name["fetch_content"].ainvoke({
    "url": "검색 결과 URL"
})
```

핵심:

- `search` = 결과 목록
- `fetch_content` = 실제 본문
- 필요한 결과만 가져와 모델 입력량 줄이기
- 프롬프트에 **검색 후 근거 URL 제시** 규칙 지정

## 3-3. Playwright MCP

**목적:** 클릭·스크롤·동적 로딩처럼 실제 브라우저 조작이 필요한 작업.

브라우저는 **상태 유지**가 필요하므로 세션을 계속 열어 둠.

```python
client = MultiServerMCPClient({"web": PLAYWRIGHT})

ctx = client.session("web")
session = await ctx.__aenter__()

tools = await load_mcp_tools(session)
by_name = {tool.name: tool for tool in tools}
```

기본 흐름:

```python
# 페이지 열기
await by_name["browser_navigate"].ainvoke({"url": SITE})

# 스크롤
await by_name["browser_press_key"].ainvoke({"key": "End"})

# 로딩 대기
await by_name["browser_wait_for"].ainvoke({"time": 2})

# 현재 페이지 값 확인
await by_name["browser_evaluate"].ainvoke({
    "function": "() => document.querySelectorAll('img').length"
})
```

종료:

```python
await ctx.__aexit__(None, None, None)
```

```text
navigate
→ evaluate/snapshot
→ 조작
→ wait
→ evaluate
→ 반복
```

도구가 많으므로 필요한 것만 선택.

---

## 3-4. SQLite MCP

**목적:** 모델이 DB 구조를 확인한 뒤 SQL을 작성해 조회.

```text
list_tables
→ describe_table
→ SELECT 작성
→ read_query
→ 결과 해석
```

```python
await by_name["list_tables"].ainvoke({})

await by_name["describe_table"].ainvoke({
    "table_name": "invoices"
})

await by_name["read_query"].ainvoke({
    "query": """
        SELECT BillingCountry,
               SUM(Total) AS total_sales
        FROM invoices
        GROUP BY BillingCountry
    """
})
```

분석 에이전트에는 읽기 도구만 전달.

```python
read_only_names = {
    "list_tables",
    "describe_table",
    "read_query",
}

read_tools = [
    tool for tool in tools
    if tool.name in read_only_names
]
```

핵심:

```text
열 이름 추측 금지
→ 스키마 먼저 확인
→ SELECT 실행
→ 조회된 값만 사용
```

조인 후 개체 수를 셀 때 중복 제거가 필요하면:

```sql
COUNT(DISTINCT id)
```

## 3-5. 코드 실행 MCP

**목적:** 모델이 Python 코드를 작성·실행해 계산 검증.

```text
문제
→ 코드 작성
→ run-code
→ print 출력
→ 결과 사용
```

```python
CODE_RUNNER = {
    "command": "npx",
    "args": ["-y", "mcp-server-code-runner"],
    "transport": "stdio",
    "env": CHILD_ENV,
}
```

```python
run_code = by_name["run-code"]

result = await run_code.ainvoke({
    "code": "print(sum([1, 2, 3, 4, 5]))",
    "languageId": "python",
})
```

가장 중요한 규칙:

```python
1 + 1          # 출력 없음
print(1 + 1)   # 결과 반환
```

**표준 출력만 반환하므로 `print` 필수.**

호출마다 독립적으로 실행되므로 필요한 `import`와 데이터도 코드 안에 포함.

# 4. 여러 MCP 서버 결합

최종 실습의 핵심.

```text
DB 조회
↓
Python 계산·그래프
↓
파일 저장
```

여러 서버를 한 번에 연결.

```python
client = MultiServerMCPClient(
    {
        "db": SQLITE,
        "code": CODE_RUNNER,
        "files": FILESYSTEM,
    },
    tool_name_prefix=True,
)

tools = await client.get_tools()
```

`tool_name_prefix=True`:

```text
db_read_query
db_list_tables
code_run-code
files_write_file
```

서버 간 도구 이름 충돌 방지.

## 역할 분담

| 작업 | 도구 |
|---|---|
| DB 구조 확인 | `db_list_tables`, `db_describe_table` |
| 집계·필터·조인 | `db_read_query` |
| 계산·통계 | `code_run-code` |
| 그래프 | `code_run-code` |
| Markdown 저장 | `files_write_file` |

에이전트에는 필요한 도구만 전달.

```python
analysis_tools = [
    t for t in tools
    if t.name in {
        "db_list_tables",
        "db_describe_table",
        "db_read_query",
        "code_run-code",
        "files_write_file",
    }
]
```

# 5. 데이터 분석 자동화 전체 흐름

```text
사용자 질문
↓
1. DB 스키마 확인
↓
2. SQL로 필요한 값만 조회
↓
3. Python으로 추가 계산
↓
4. 표·그래프 생성
↓
5. 파일 저장
↓
6. 실제 산출물 존재 여부 확인
```

그래프 저장 시 교안의 핵심 설정:

```python
import matplotlib
matplotlib.use("Agg")
```

화면 대신 파일로 저장.

한글 폰트 지정 후 저장하고, 실제 파일로 검증.

```python
CHART_PATH.exists()
REPORT_PATH.exists()
```

**모델이 "저장했다"고 말한 것보다 실제 파일 존재 여부가 기준.**

# 6. 에이전트 설계 원칙

## 필요한 도구만 전달

```text
도구 선택
= 권한 설계
= 모델의 선택지 제한
```

예:

- 파일 분석 → 읽기 도구만
- DB 분석 → SELECT 관련 도구만
- 저장 필요 → 그때 `write_file` 추가

## 프롬프트에 실행 순서 명시

```text
DB      → 스키마 확인 후 SELECT
검색    → search 후 필요하면 fetch_content
브라우저 → 조작 후 실제 화면 값 확인
코드    → 계산 후 반드시 print
파일    → 실제 도구로 확인한 내용만 사용
```

## 결과 검증

```text
에이전트 답변
≠ 최종 검증

도구 실행 결과 / SQL / 실제 파일
= 검증 기준
```

필요하면 `ModelCallLimitMiddleware`로 반복 호출 상한 설정.

# 7. 최종 암기

```text
[공통]

서버 설정
→ Client
→ get_tools()
→ 필요한 도구 선택
→ tool.ainvoke()
→ create_agent()
→ agent.ainvoke()
→ 결과 검증
```

```text
[종합 분석]

DB로 조회
→ Python으로 계산
→ FileSystem으로 저장
→ 실제 산출물 확인
```

> **핵심: MCP는 도구를 많이 붙이는 기술이 아니라, 기능별 도구를 연결하고 필요한 권한만 골라 에이전트가 올바른 순서로 사용하게 만드는 구조.**

## `.ipynb` 기준

노트북에서는 셀에서 직접:

```python
await agent.ainvoke(...)
```

스크립트(`.py`)에서는:

```python
async def main():
    ...

asyncio.run(main())
```

브라우저처럼 상태 유지가 필요한 서버만 세션을 계속 유지.
