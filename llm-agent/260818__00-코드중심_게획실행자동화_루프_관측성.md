# 계획·실행 자동화 실전 정리

> 목적: 코드를 보면서 **에이전트가 어떻게 계획하고, 도구를 연결하고, 결과를 저장·검증하는지** 바로 파악하기.
>
> 예제의 `SQLITE`, `CODE_RUNNER`, `FILESYSTEM`, `ALLOWED`, 각종 프롬프트와 질문(`Q1`, `Q3`, `Q4`, `QUESTION`)은 프로젝트에 이미 정의되어 있다고 가정.

## 전체 흐름

```text
계획 관리        TodoListMiddleware
    ↓
여러 도구 실행   DB → 계산/그래프 → 파일 저장
    ↓
결과 정형화      자유 문장 → Pydantic → DataFrame → JSON
    ↓
품질 개선        생성 → 비평 → 수정
    ↓
운영 관측        Langfuse callback → 도구 호출/토큰 추적
```

---

# 1. 계획을 세우고 실행하는 에이전트

## 1-1. `TodoListMiddleware`로 계획 관리

### 언제 사용?

한 번의 답변으로 끝나지 않고 **조회 → 계산 → 파일 생성**처럼 여러 작업을 순서대로 수행해야 할 때 사용.

`TodoListMiddleware`를 붙이면 에이전트가 `write_todos`를 사용해 계획을 만들고 상태를 갱신할 수 있음.

> 단, 미들웨어를 붙였다고 항상 계획을 만드는 것은 아님. 실제 계획 수립 여부는 작업 난이도와 모델 판단에 따라 달라질 수 있음.

### 실행 흐름

```text
사용자 질문
   ↓
write_todos        계획 생성
   ↓
DB 조회
   ↓
계산 / 그래프 생성
   ↓
write_todos        완료 상태 갱신
   ↓
최종 답변
```

### 핵심 코드

```python
async def main():
    # 1. 여러 MCP 서버를 하나의 클라이언트에 연결
    client = MultiServerMCPClient(
        {
            "db": SQLITE,
            "code": CODE_RUNNER,
            "files": FILESYSTEM,
        },
        tool_name_prefix=True,
    )

    # 2. 필요한 도구만 에이전트에 전달
    all_tools = await client.get_tools()
    tools = [tool for tool in all_tools if tool.name in ALLOWED]

    # 3. 모델 생성
    model = ChatOpenAI(
        model="gpt-4o-mini",
        temperature=0,
        timeout=60,
    )

    # 4. 계획 기능을 가진 에이전트 생성
    analyst = create_agent(
        model=model,
        tools=tools,
        system_prompt=SYSTEM_PROMPT,
        middleware=[
            TodoListMiddleware(),
            ModelCallLimitMiddleware(
                run_limit=30,
                exit_behavior="end",
            ),
        ],
    )

    # 5. 실행
    result = await analyst.ainvoke({"messages": Q1})

    # 6. 도구 호출 순서와 마지막 계획 확인
    print_trajectory(result)
    pprint(result.get("todos", []))
```

### 코드에서 볼 것

- `MultiServerMCPClient`: 여러 MCP 서버의 도구를 한 에이전트에 연결.
- `tool_name_prefix=True`: `db_read_query`, `files_write_file`처럼 서버별 도구 이름 충돌 방지.
- `ALLOWED`: 에이전트가 실제로 사용할 도구만 제한.
- `TodoListMiddleware()`: 계획 생성·갱신용 `write_todos` 사용 가능.
- `ModelCallLimitMiddleware`: 무한 호출이나 과도한 모델 호출 방지.
- `print_trajectory(result)`: 실제 도구 호출 순서 확인.

### 원문 실행 결과

```text
write_todos
→ db_list_tables
→ db_describe_table
→ db_describe_table
→ db_describe_table
→ db_read_query
→ db_read_query
→ code_run-code
→ write_todos
```

최종 계획 상태:

```text
[completed] 필요한 테이블 확인
[completed] 장르별 총 매출 SQL 실행
[completed] 상위 3개 장르 추출
[completed] 1위 장르 매출 비중 계산
[completed] 막대그래프 생성 및 저장
```

최종 결과:

```text
Rock  : $826.65
Latin : $382.14
Metal : $261.36

전체 매출: $2328.60
Rock 비중: 약 35.5%
그래프: 장르별_매출.png
```

### 핵심

`TodoListMiddleware`의 핵심은 **계획을 한 번 만드는 것보다, 실행하면서 상태를 갱신하는 것**.

## 1-2. 조회 → 계산 → 그래프 → 리포트 파이프라인

### 언제 사용?

하나의 요청에서 여러 종류의 도구를 **정해진 업무 흐름으로 연결**해야 할 때 사용.

예:

```text
DB 조회
→ 수치 계산
→ 그래프 생성
→ Markdown 리포트 저장
```

이 경우 프롬프트에도 작업 순서를 명확하게 적어 두는 것이 중요.

### 핵심 코드

```python
async def main():
    client = MultiServerMCPClient(
        {
            "db": SQLITE,
            "code": CODE_RUNNER,
            "files": FILESYSTEM,
        },
        tool_name_prefix=True,
    )

    all_tools = await client.get_tools()
    tools = [tool for tool in all_tools if tool.name in ALLOWED]

    model = ChatOpenAI(
        model="gpt-4o-mini",
        temperature=0,
        timeout=60,
    )

    analyst = create_agent(
        model=model,
        tools=tools,
        system_prompt=SYSTEM_BASE + PLAN_RULE,
        middleware=[
            TodoListMiddleware(),
            ModelCallLimitMiddleware(
                run_limit=30,
                exit_behavior="end",
            ),
        ],
    )

    result = await analyst.ainvoke(
        {
            "messages": [
                {"role": "user", "content": Q3}
            ]
        }
    )

    print_trajectory(result)
```

### 실제 도구 역할

```text
db_read_query
→ 데이터 조회

code_run-code
→ 계산 + matplotlib 그래프 생성

files_write_file
→ Markdown 리포트 저장
```

> 그래프 파일은 파일 쓰기 도구로 텍스트를 저장하는 것이 아니라, 코드 실행 환경에서 `plt.savefig()` 같은 방식으로 생성.

상위 10개 장르:

| 1 | Rock | 826.65 |
| 2 | Latin | 382.14 |

```text
write_todos

→ DB 조회
```

### 핵심

에이전트 자동화는 **도구가 많다는 것보다 각 도구의 역할과 순서가 명확한 것**이 중요.

# 2. 자유 문장 결과를 구조화해서 저장

## 2-1. 자유 문장 → Pydantic → DataFrame → JSON

### 언제 사용?

에이전트의 최종 답변을 사람이 읽는 문장으로만 끝내지 않고, 이후 프로그램에서 다시 사용할 데이터로 저장해야 할 때 사용.

### 흐름

```text
Q4
↓
에이전트 + DB 조회
↓
자유 문장 답변
↓
answer_text
↓
with_structured_output()
↓
AnalysisResult
↓
DataFrame
↓
JSON
```

### 핵심 코드

```python
class AnalysisResult(BaseModel):
    metric: str = Field(
        description="분석 지표 또는 대상 이름"
    )
    value: float = Field(
        description="분석 결과의 핵심 수치 하나"
    )
    interpretation: str = Field(
        description="수치에 대한 한 문장 해석"
    )


async def main():
    # 1. DB 도구 연결
    client = MultiServerMCPClient(
        {"db": SQLITE},
        tool_name_prefix=True,
    )

    all_tools = await client.get_tools()
    tools = [tool for tool in all_tools if tool.name in ALLOWED]

    model = ChatOpenAI(
        model="gpt-4o-mini",
        temperature=0,
        timeout=60,
    )

    analyst = create_agent(
        model=model,
        tools=tools,
        system_prompt=SYSTEM_BASE + PLAN_RULE,
        middleware=[
            TodoListMiddleware(),
            ModelCallLimitMiddleware(
                run_limit=20,
                exit_behavior="end",
            ),
        ],
    )

    # 2. 먼저 일반 에이전트로 분석
    result = await analyst.ainvoke(
        {
            "messages": [
                {"role": "user", "content": Q4}
            ]
        }
    )

    answer_text = result["messages"][-1].text

    # 3. 자유 문장을 정해진 스키마로 다시 변환
    structured_model = model.with_structured_output(AnalysisResult)
    info = structured_model.invoke(answer_text)

    # 4. 저장 가능한 데이터 형태로 변환
    metrics_df = pd.DataFrame([info.model_dump()])

    metrics_df.to_json(
        METRICS_PATH,
        orient="records",
        force_ascii=False,
    )
```

### 원문 실행 결과

자유 문장:

```text
가장 매출이 큰 장르는 Rock이며,
그 매출 합계는 826.65입니다.
```

구조화 결과의 핵심 값:

```text
metric = Rock
value = 826.65
```

저장되는 JSON 형태는 다음과 같은 구조.

```json
[
  {
    "metric": "Rock",
    "value": 826.65,
    "interpretation": "Rock이 가장 높은 매출을 기록한 장르다."
  }
]
```

> 위 JSON의 `metric`, `value`는 원문 실행값을 사용했고, `interpretation` 문장은 구조 설명을 위한 정리용 예시.

### 핵심

`with_structured_output()`은 **모델의 자유 문장을 후속 코드가 처리하기 쉬운 데이터 구조로 바꾸는 단계**.

# 3. 생성 결과를 스스로 평가하고 수정하는 성찰 루프

## 3-1. DB 요약 → 리포트 생성 → 비평 → 수정 → 저장

### 언제 사용?

한 번 생성한 답변을 그대로 쓰기보다 **품질 기준으로 평가한 뒤 부족하면 다시 수정**해야 할 때 사용.

예:

```text
DB 데이터
↓
요약
↓
초안 생성
↓
비평
├─ 8점 이상 → 종료
└─ 8점 미만 → 개선점 반영 → 다시 비평
↓
최종 리포트
↓
파일 저장
```

---

## 3-2. DB 요약 도구

```python
@tool
def summarize_country_sales(limit: int) -> str:
    """DB에서 국가별 매출을 조회하여 매출 상위 국가를 요약 문자열로 반환합니다."""

    conn = sqlite3.connect(DB_PATH)

    rows = conn.execute(
        """
        SELECT BillingCountry, ROUND(SUM(Total), 2) AS 매출
        FROM invoices
        GROUP BY BillingCountry
        ORDER BY 매출 DESC
        LIMIT ?
        """,
        (limit,),
    ).fetchall()

    conn.close()

    sales = [
        f"{country} {amount}"
        for country, amount in rows
    ]

    return f"매출 상위 {limit}개 국가(단위: 달러): {', '.join(sales)}"
```

`DESC`는 큰 값부터 정렬하는 **내림차순**.

결과 예:

```text
매출 상위 10개 국가(단위: 달러):
USA 523.06, Canada 303.96, France 195.1, Brazil 190.1, Germany 156.4, ...
```

## 3-3. 생성·비평·수정 체인

```python
class Critique(BaseModel):
    score: int = Field(
        ge=1,
        le=10,
        description="1~10 종합 점수",
    )
    issues: list[str] = Field(
        description="개선점 목록",
    )


# 초안 생성
generate_chain = (
    GEN_PROMPT
    | model
    | StrOutputParser()
)

# 초안 평가
critic_chain = (
    CRITIC_PROMPT
    | model.with_structured_output(Critique)
)

# 개선점 반영
revise_chain = (
    REVISE_PROMPT
    | model
    | StrOutputParser()
)
```

### 역할

```text
generate_chain
→ 최초 리포트 생성

critic_chain
→ score + issues 반환

revise_chain
→ 기존 리포트 + issues를 받아 수정본 생성
```

---

## 3-4. 성찰 루프

```python
def reflect(summary):
    # 최초 초안
    report = generate_chain.invoke({"summary": summary})
    scores = []

    # 최대 2회 평가
    for _ in range(2):
        critique = critic_chain.invoke({"report": report})
        scores.append(critique.score)

        # 기준 충족 시 종료
        if critique.score >= 8:
            break

        # 개선점 목록을 수정 프롬프트에 넣기 좋은 문자열로 변환
        issues_text = "\n".join(
            f"- {issue}"
            for issue in critique.issues
        )

        # 개선점 반영
        report = revise_chain.invoke(
            {
                "report": report,
                "issues": issues_text,
            }
        )

    return report, scores
```

### 핵심 조건문

```python
if critique.score >= 8:
    break
```

```text
8점 이상
→ 충분한 품질로 판단하고 종료

8점 미만
→ issues를 반영해 다시 작성
```

## 3-5. 성찰 기능 자체를 도구로 만들기

```python
@tool
def write_report(summary: str) -> str:
    """수치 요약을 받아 성찰 과정을 거친 최종 리포트를 작성합니다."""

    report, scores = reflect(summary)
    print("평가 점수:", scores)

    return report
```

이제 에이전트 입장에서는 내부의 생성·비평·수정 과정을 몰라도 `write_report()` 하나만 호출하면 됨.

```text
에이전트
↓
write_report(summary)
↓
내부에서 generate → critic → revise 반복
↓
최종 report 반환
```

## 3-6. 전체 파이프라인을 에이전트에 연결

```python
async def main():
    client = MultiServerMCPClient(
        {"files": FILESYSTEM},
        tool_name_prefix=True,
    )

    file_tools = [
        tool
        for tool in await client.get_tools()
        if tool.name == "files_write_file"
    ]

    reporter_tools = [
        summarize_country_sales,
        write_report,
        *file_tools,
    ]

    reporter = create_agent(
        model=model,
        tools=reporter_tools,
        system_prompt=SYSTEM_PROMPT,
        middleware=[
            ModelCallLimitMiddleware(
                run_limit=10,
                exit_behavior="end",
            )
        ],
    )

    result = await reporter.ainvoke(
        {"messages": QUESTION}
    )

    print_trajectory(result)
```

### 원문 실행 순서

```text
summarize_country_sales
→ write_report
→ files_write_file
```

즉, 사람이 중간 함수를 직접 부르지 않아도 에이전트가 필요한 도구를 순서대로 선택.

### 원문 실행 결과

```text
1. summarize_country_sales
   → USA 523.06, Canada 303.96, France 195.1, ...

2. write_report
   → 리포트 생성 + 내부 성찰 루프 실행

3. files_write_file
   → country_sales_report.md 저장
```

비평 점수 이력:

```text
[6, 5]
```

이 실행에서는 두 번째 평가 점수가 오히려 낮아짐.

따라서 성찰 루프는 **반복 자체가 품질 향상을 보장하는 구조가 아니라, 평가 프롬프트와 수정 기준까지 잘 설계해야 효과가 나는 구조**로 봐야 함.

# 4. 관측성과 운영 견고성

## 4-1. Langfuse callback으로 실행 추적

### 언제 사용?

에이전트가 실제 서비스에서 어떤 도구를 선택했고, 모델을 얼마나 호출했으며, 토큰을 얼마나 썼는지 확인해야 할 때 사용.

특히 다음 문제를 찾는 데 유용.

```text
왜 엉뚱한 도구를 불렀는가?
어떤 순서로 실행했는가?
토큰은 얼마나 사용했는가?
같은 요청에서 도구 설명을 바꾸면 행동이 달라지는가?
```

---

## 4-2. 모호한 도구 정의의 문제

```python
@tool
def info(plan: str) -> str:
    """회원 정보를 조회한다."""
    return str(fee_of(plan))


@tool
def gym_guide(plan: str) -> str:
    """회원권 상품을 안내한다."""
    return f"{plan} 회원권은 헬스장 전 구역을 이용할 수 있는 상품입니다."
```

`info()`는 실제로 **회원권 요금**을 반환하지만 이름과 설명에는 그 정보가 없음.

모델 입장에서는 도구 용도를 정확히 판단하기 어려움.

---

## 4-3. 실행 시점에 Langfuse callback 넣기

```python
def observed_invoke(agent, question):
    return agent.invoke(
        {"messages": question},
        config={"callbacks": handlers},
    )
```

핵심:

```python
config={"callbacks": handlers}
```

에이전트 정의 자체를 바꾸지 않고 **호출 시점에 관측 기능을 추가**.

## 4-4. 도구 이름과 설명을 명확하게 수정

```python
@tool
def membership_fee(plan: str) -> int:
    """회원권 이름을 받아 정가를 원 단위로 돌려준다."""
    return fee_of(plan)
```

비교:

```text
info
→ 무슨 정보를 주는지 불명확

membership_fee
→ 이름만 보고도 회원권 요금 조회임을 알 수 있음
```

에이전트 도구는 함수 내부 구현뿐 아니라 **도구 이름 + docstring 자체가 라우팅 정보**가 됨.

# 5. 실전 선택 기준

| 목적 | 핵심 방법 | 대표 요소 |
|---|---|---|
| 복잡한 작업을 단계별로 수행 | 계획 관리 | `TodoListMiddleware` |
| 여러 도구를 업무 순서대로 연결 | 멀티툴 파이프라인 | DB → Code → File |
| 모델 답변을 프로그램에서 재사용 | 구조화 출력 | `with_structured_output()` |
| 초안을 평가하고 다시 수정 | 성찰 루프 | Generate → Critic → Revise |
| 실제 운영 과정을 추적 | 관측성 | Langfuse callback |
| 엉뚱한 도구 호출 감소 | 도구 명세 개선 | 함수명 + docstring |
| 호출 비용·폭주 제한 | 실행 제한 | `ModelCallLimitMiddleware` |

## 핵심 요약

```text
TodoListMiddleware
= 복잡한 작업의 계획과 진행 상태 관리

MCP + 여러 Tool
= 에이전트가 외부 기능을 조합해 작업 수행

Structured Output
= 자연어 결과를 안정적인 데이터 구조로 변환

Reflection Loop
= 생성 결과를 평가하고 필요하면 다시 수정

Langfuse
= 실제 실행 과정, 도구 호출, 토큰 사용량 관측

도구 이름 / docstring
= 단순 설명이 아니라 에이전트의 도구 선택 정확도에 직접 영향
```
