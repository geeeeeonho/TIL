# RAG 결과 기반 답 생성 정리

## 1. 이번 단원의 목표

벡터 DB에서 찾은 문서를 LLM에 근거로 전달해 답을 생성하는 단계.

```text
사용자 질문
→ 질문 임베딩
→ 관련 문서 Top-K 검색
→ 컨텍스트 조립
→ LLM에 규칙·자료·질문 전달
→ 근거 기반 답변 생성
```

핵심:

- 검색 결과를 LLM이 읽을 수 있는 문자열로 변환
- 원문과 메타데이터를 함께 전달
- 자료에 없는 내용은 답하지 못하게 규칙 설정
- 답변과 출처 문서를 함께 반환

# 5. 여러 검색 결과를 컨텍스트로 만들기

실제 RAG에서는 보통 Top-K 문서 3~5개를 검색.

여러 문서를 하나의 문자열로 합친 결과를 **컨텍스트(context)**라고 함.

```text
검색 결과 여러 개
→ 문서별로 한 줄씩 정리
→ 하나의 문자열로 결합
```

## 5.1 작성 원칙

- 원문과 메타데이터를 함께 넣기
- 각 문서 앞에 `-`나 번호 붙이기
- 문서 ID를 포함해 출처 추적 가능하게 만들기

## 5.2 `build_context()` 함수

```python
def build_context(res):
    """
    ChromaDB 검색 결과를
    LLM에 전달할 문자열로 변환.
    """
    lines = []

    for doc_id, doc, meta in zip(
        res["ids"][0],
        res["documents"][0],
        res["metadatas"][0],
    ):
        line = (
            f"- 문서 ID {doc_id} | "
            f"{meta['name']} "
            f"(지역 {meta['region']}, "
            f"유형 {meta['type']}, "
            f"입장료 {meta['entrance_fee']}원): "
            f"{doc}"
        )

        lines.append(line)

    return "\n".join(lines)
```

`"\n".join(lines)`:

```text
문자열 목록
→ 줄바꿈으로 이어진 하나의 문자열
```

# 7. 검색부터 답 생성까지 함수로 묶기

```python
def rag_answer(question, k=3):
    """
    질문 입력
    → 임베딩
    → Top-K 검색
    → 컨텍스트 생성
    → LLM 답변
    """

    # 1. 질문 임베딩
    q_emb = emb_model.encode(
        [question],
        normalize_embeddings=True,
    )

    # 2. 관련 문서 Top-K 검색
    res = travel_col.query(
        query_embeddings=q_emb,
        n_results=k,
    )

    # 3. 검색 결과를 컨텍스트로 변환
    context = build_context(res)

    # 4. LLM에 규칙·자료·질문 전달
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {
                "role": "system",
                "content": SYSTEM_RULE,
            },
            {
                "role": "user",
                "content": (
                    f"[자료]\n{context}\n\n"
                    f"[질문]\n{question}"
                ),
            },
        ],
        temperature=0,
        max_tokens=400,
    )

    return resp.choices[0].message.content
```

## 7.1 변수 의미

| 변수 | 의미 |
|---|---|
| `question` | 사용자 질문 |
| `k` | 검색할 문서 수 |
| `q_emb` | 질문 임베딩 벡터 |
| `res` | ChromaDB 검색 결과 |
| `context` | LLM에 전달할 근거 문자열 |
| `resp` | OpenAI API 전체 응답 |
| `message.content` | 최종 답변 문자열 |

# 9. 답변과 출처 함께 반환

```python
def rag_answer_with_sources(
    question,
    k=3,
):
    """
    답변과 검색에 사용한 출처를 함께 반환.
    """

    q_emb = emb_model.encode(
        [question],
        normalize_embeddings=True,
    )

    res = travel_col.query(
        query_embeddings=q_emb,
        n_results=k,
    )

    context = build_context(res)

    sources = [
        {
            "id": doc_id,
            "name": meta["name"],
            "region": meta["region"],
            "type": meta["type"],
            "entrance_fee": meta["entrance_fee"],
            "description": doc,
        }
        for doc_id, doc, meta in zip(
            res["ids"][0],
            res["documents"][0],
            res["metadatas"][0],
        )
    ]

    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {
                "role": "system",
                "content": SYSTEM_RULE,
            },
            {
                "role": "user",
                "content": (
                    f"[자료]\n{context}\n\n"
                    f"[질문]\n{question}"
                ),
            },
        ],
        temperature=0,
        max_tokens=400,
    )

    answer = (
        resp.choices[0]
        .message.content
    )

    return answer, sources
```

## 9.1 반환값 받기

```python
question = (
    "역사 유적을 둘러보고 싶어. "
    "어디가 좋을까?"
)

answer, sources = (
    rag_answer_with_sources(question)
)
```

```text
answer
→ LLM 답변

sources
→ 검색된 근거 문서 목록
```

## 9.2 출처 출력

```python
print("Q.", question)
print("A.", answer)

print("\n[근거 문서]")

for i, source in enumerate(

```

출처를 별도 데이터로 반환하면 답변 검증과 디버깅이 쉬워짐.

# 10. 원본 예제의 반복문 오류

원본의 다음 구조는 모든 관광지에 첫 번째 문서 설명만 붙임.

```python
for meta in hit["metadatas"]:
    fact = (
        f"{meta['name']} | "
        f"{hit['documents'][0]}"
    )
```

문제:

```text
meta는 매번 바뀜
hit["documents"][0]은 계속 첫 문서
```

## 수정 코드

```python
facts = []

for doc, meta in zip(
    hit["documents"],
    hit["metadatas"],
):
    fact = (
        f"- {meta['name']} "
        f"| 지역 {meta['region']} "
        f"| 입장료 "
        f"{meta['entrance_fee']}원 "
        f"| {doc}"
    )

    facts.append(fact)

context = "\n".join(facts)
```

핵심:

```text
documents[i]
↔
metadatas[i]

같은 위치의 값끼리 한 문서
```

# 12. 전체 흐름

```text
1. 질문 입력
2. 질문을 임베딩
3. 벡터 DB에서 Top-K 문서 검색
4. 원문과 메타데이터를 컨텍스트로 조립
5. system 메시지로 답변 규칙 설정
6. user 메시지에 자료와 질문 전달
7. LLM이 자료를 근거로 답변 생성
8. 답변과 출처 목록 반환
```

# 13. 실전 점검 순서

```text
1. 검색 문서가 질문과 관련 있는가
2. Top-K가 너무 크거나 작지 않은가
3. 메타데이터가 컨텍스트에 포함됐는가
4. 문서와 메타데이터가 같은 순서로 묶였는가
5. system 규칙이 적용됐는가
6. 자료 밖 질문을 거절하는가
7. 출처가 실제 검색 결과와 일치하는가
```

# 핵심 요약

| 단계 | 핵심 |
|---|---|
| 검색 | 질문 임베딩으로 관련 문서 Top-K 반환 |
| 컨텍스트 | 원문과 메타데이터를 문서별로 결합 |
| 규칙 | 자료에 없는 내용은 답하지 않도록 설정 |
| 생성 | system + 자료 + 질문을 LLM에 전달 |
| 검증 | 답변과 출처 문서를 함께 반환 |
| 주의 | 검색기는 관련 문서가 없어도 K개를 반환 가능 |
| 계산 | 최댓값·정렬은 LLM보다 Python 처리 권장 |

> **핵심:** RAG 답변 품질은 검색 결과, 컨텍스트 구조, 시스템 규칙, 출처 반환을 함께 설계해야 함.
