# RAG 벡터 검색 정리

## 1. 이번 단원의 목표

여행지 문서를 임베딩하고, 질문과 의미가 가까운 문서를 검색하는 전체 흐름.

```text
문서 준비
→ 문서 임베딩
→ 벡터 DB 저장
→ 질문 임베딩
→ 유사 문서 Top-K 검색
→ 메타데이터 필터
```

다루는 핵심:

- 문서·질문 임베딩
- 코사인 유사도 기반 검색
- 키워드 검색과 의미 검색 비교
- ChromaDB 구축·적재·검색
- 메타데이터 필터
- HNSW 설정
- Qdrant 기본 사용

---

## 2. 기본 라이브러리와 임베딩 모델

```python
import numpy as np
import pandas as pd
import chromadb

from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity
```

한국어 임베딩 모델 준비:

```python
emb_model = SentenceTransformer(
    "jhgan/ko-sroberta-multitask"
)

print(
    "임베딩 벡터 차원:",
    emb_model.get_embedding_dimension()
)
```

출력:

```text
임베딩 벡터 차원: 768
```

이 모델은 문장 하나를 **768차원 벡터**로 변환.

> 모델을 처음 실행하면 다운로드 때문에 시간이 걸릴 수 있음.

# 3. 문서 임베딩

## 3.1 문서 텍스트 추출

```python
doc_texts = spots["description"].tolist()
```

- `spots["description"]`: 여행지 설명 열
- `.tolist()`: Pandas Series를 일반 리스트로 변환

## 3.2 전체 문서 임베딩

```python
doc_emb = emb_model.encode(
    doc_texts,
    normalize_embeddings=True
)
```

- 문서 100개
- 문서마다 768차원 벡터
- 결과 모양: `(100, 768)`

```python
print("문서 임베딩 행렬:", doc_emb.shape)
```

```text
문서 임베딩 행렬: (100, 768)
```

## 3.3 벡터 정규화

```python
normalize_embeddings=True
```

각 벡터의 길이를 `1`로 맞춤.

```python
print(
    np.linalg.norm(doc_emb[0])
)
```

```text
1.0
```

벡터를 길이 1로 정규화하면:

```text
코사인 유사도 = 두 벡터의 내적
```

따라서 다음 두 계산 결과가 같아짐.

```python
cosine_similarity(query_emb, doc_emb)
```

```python
query_emb @ doc_emb.T
```

# 4. 질문 임베딩과 Top-K 검색

## 4.1 질문 임베딩

```python
query = "바다에서 시원하게 물놀이하기 좋은 곳"

query_emb = emb_model.encode(
    [query],
    normalize_embeddings=True
)
```

`encode()`는 여러 문장을 입력받는 구조라 질문 하나도 리스트로 감쌈.

```python
[query]
```

결과 모양:

```text
(1, 768)
```

---

## 4.2 코사인 유사도 계산

```python
sims = cosine_similarity(
    query_emb,
    doc_emb
)[0]
```

계산 결과는 처음에 `(1, 문서 수)` 구조.

```python
[0]
```

첫 번째 질문의 유사도 배열만 꺼냄.

결과:

```text
(100,)
```

---

## 4.3 유사도 높은 문서 3개 찾기

```python
top3 = np.argsort(-sims)[:3]
```

동작:

```text
sims
→ 유사도 배열

-sims
→ 값의 부호를 반대로 변경

np.argsort(-sims)
→ 유사도가 높은 순서의 인덱스 반환

[:3]
→ 상위 3개만 선택
```

`np.argsort()`는 기본이 오름차순이라 `-sims`를 사용해 내림차순 효과를 냄.

---

## 4.4 검색 결과 출력

```python
for rank, i in enumerate(top3, 1):
    print(
        f"{rank}위 "
        f"유사도 {sims[i]:.3f} | "
        f"{spots.loc[i, 'name']} "
        f"({spots.loc[i, 'type']}) : "
        f"{spots.loc[i, 'description']}"
    )
```

예시 결과:

```text
1위 0.756 | 해운대 해수욕장
2위 0.681 | 다대포 해수욕장
3위 0.680 | 월정리 해변
```

---

## 4.5 내적으로 직접 계산

문서와 질문 벡터가 길이 1로 정규화된 경우:

```python
sims = np.array(query_emb) @ np.array(doc_emb).T
sims = sims[0]
```

행렬 모양:

```text
query_emb: (1, 768)
doc_emb.T: (768, 100)

결과: (1, 100)
```

# 5. 키워드 검색과 의미 기반 검색

## 5.1 키워드 검색

```python
query = "옛 임금이 살던 집"

keywords = ["임금", "살던", "집"]
pattern = "|".join(keywords)

keyword_hits = spots[
    spots["description"].str.contains(pattern)
]
```

`pattern`:

```text
임금|살던|집
```

정규표현식에서 `|`는 **또는**.

```text
임금 또는 살던 또는 집
```

### 한계

키워드 검색은 글자가 포함됐는지만 확인.

질문의 의도와 관계없이 `"집"`이 들어간 문서가 검색될 수 있음.

예:

- 카페와 편집숍
- 초가집
- 찻집
- 술집
- 알록달록한 집

질문은 궁궐을 찾지만, 실제 단어가 겹치는 다른 장소가 섞임.

---

## 5.2 의미 기반 검색

```python
query_emb = emb_model.encode(
    [query],
    normalize_embeddings=True
)

sims = cosine_similarity(
    query_emb,
    doc_emb
)[0]

top3 = np.argsort(-sims)[:3]
```

예시 결과:

```text
경복궁
낙안읍성
안동 하회마을
```

질문에 `"궁궐"`이라는 단어가 없어도 의미를 이용해 경복궁을 찾음.

---

## 5.3 비교

| 구분 | 키워드 검색 | 의미 기반 검색 |
|---|---|---|
| 기준 | 같은 글자 포함 여부 | 문장의 의미 |
| 장점 | 빠르고 단순함 | 표현이 달라도 검색 가능 |
| 단점 | 동의어·문맥 파악 어려움 | 임베딩 계산과 벡터 DB 필요 |
| 예시 | `집`이 포함된 문서 | 임금이 살던 곳 → 경복궁 |

예시:

```text
질문: 등산화를 신고 오를 만한 곳
```

키워드 검색:

```text
0건
```

의미 검색:

```text
지리산 노고단
설악산 울산바위
내장산 단풍길
```

# 6. ChromaDB 기본 구축

## 6.1 메모리 기반 클라이언트

```python
client = chromadb.EphemeralClient()
```

특징:

- RAM에 저장
- 디스크 파일 생성 안 됨
- 커널을 끄면 데이터 삭제
- 반복 실습에 적합

---

## 6.2 컬렉션 생성

```python
travel_col = client.get_or_create_collection(
    name="travel_guide",
    metadata={
        "hnsw:space": "cosine"
    }
)
```

- `travel_guide`: 컬렉션 이름
- `get_or_create_collection()`: 있으면 가져오고, 없으면 생성
- `hnsw:space="cosine"`: 코사인 거리 사용

> ChromaDB 기본 거리 기준은 `l2`. 문장 임베딩 검색에서는 `cosine`을 명시하는 것이 중요.

---

## 6.3 메타데이터 생성

### 리스트 컴프리헨션 방식

```python
metadatas = [
    {
        "name": name,
        "region": region,
        "type": place_type,
        "entrance_fee": int(fee),
    }
    for name, region, place_type, fee in zip(
        spots["name"],
        spots["region"],
        spots["type"],
        spots["entrance_fee"],
    )
]
```

### DataFrame 방식

```python
META_COLS = [
    "name",
    "region",
    "type",
    "entrance_fee",
]

meta_dict = (
    spots[META_COLS]
    .astype({"entrance_fee": int})
    .to_dict("records")
)
```

`to_dict("records")`:

```text
DataFrame의 각 행
→ 하나의 딕셔너리
→ 딕셔너리 목록으로 변환
```

---

## 6.4 문서 적재

```python
travel_col.add(
    ids=spots["id"].tolist(),
    embeddings=doc_emb,
    documents=spots["description"].tolist(),
    metadatas=meta_dict,
)
```

네 인자의 같은 위치가 한 문서를 구성.

```text
ids[0]
embeddings[0]
documents[0]
metadatas[0]
```

모두 첫 번째 문서에 해당.

저장 개수 확인:

```python
print(
    "저장된 문서 수:",
    travel_col.count()
)
```

# 7. ChromaDB 데이터 조회

## 7.1 ID로 직접 조회: `get()`

```python
result = travel_col.get(
    ids=["t04"]
)
```

`get()`은 의미 검색이 아님.

```text
ID를 정확히 지정
→ 해당 문서를 직접 꺼냄
```

결과는 딕셔너리.

```python
print(result["documents"][0])
print(result["metadatas"][0])
```

---

## 7.2 반환 항목 지정

```python
result = travel_col.get(
    ids=["t01", "t02"],
    include=[
        "embeddings",
        "metadatas",
    ]
)
```

`include`로 필요한 정보만 반환.

```python
include=[]
```

ID만 받고 싶을 때 사용.  
원문과 벡터를 받지 않아 가벼움.

# 8. ChromaDB 벡터 검색

## 8.1 기본 검색

```python
query = "바다에서 시원하게 물놀이하기 좋은 곳"

query_emb = emb_model.encode(
    [query],
    normalize_embeddings=True
)

res = travel_col.query(
    query_embeddings=query_emb,
    n_results=3,
)
```

- `query_embeddings`: 질문 벡터
- `n_results`: 반환할 Top-K 개수

---

## 8.2 검색 결과 구조

```python
res["ids"][0]
res["documents"][0]
res["metadatas"][0]
res["distances"][0]
```

질문을 여러 개 넣을 수 있는 구조라 결과가 이중 리스트.

```text
[
    [첫 질문의 검색 결과],
    [두 번째 질문의 검색 결과],
]
```

질문 하나만 넣었다면 `[0]`으로 첫 겹을 벗김.

---

## 8.3 결과 출력

```python
for doc_id, dist, meta in zip(
    res["ids"][0],
    res["distances"][0],
    res["metadatas"][0],
):
    print(
        f"거리 {dist:.3f} | "
        f"{doc_id} "
        f"{meta['name']} "
        f"({meta['type']})"
    )
```

---

## 8.4 거리와 유사도

코사인 거리 사용 시:

```text
코사인 거리 = 1 - 코사인 유사도
```

따라서:

```text
유사도는 클수록 가까움
거리는 작을수록 가까움
```

예:

| 문서 | 유사도 | 거리 |
|---|---:|---:|
| 해운대 해수욕장 | 0.756 | 0.244 |
| 다대포 해수욕장 | 0.681 | 0.319 |
| 월정리 해변 | 0.680 | 0.320 |

# 9. 메타데이터 필터링

메타데이터 조건에 맞는 문서만 후보로 남긴 뒤 의미 검색.

```text
전체 문서
→ 메타데이터 필터
→ 남은 문서에서 벡터 검색
→ Top-K
```

필터는 점수를 낮추는 방식이 아님.

```text
조건 불일치
→ 검색 후보에서 완전히 제외
```

---

## 9.1 문자열 조건

```python
res = travel_col.query(
    query_embeddings=query_emb,
    n_results=3,
    where={"type": "역사"},
)
```

뜻:

```text
type이 역사인 문서 안에서만 검색
```

정식 표현:

```python
where={
    "type": {
        "$eq": "역사"
    }
}
```

축약 표현:

```python
where={"type": "역사"}
```

두 방식은 같은 의미.

---

## 9.2 숫자 조건

입장료가 0원보다 큰 문서:

```python
where={
    "entrance_fee": {
        "$gt": 0
    }
}
```

> 숫자 비교는 반드시 비교 연산자로 감싸야 함.

```python
{"entrance_fee": 3000}
```

위 조건은 `3000원 이상`이 아니라 **정확히 3000원**.

---

## 9.3 비교 연산자

| 연산자 | 의미 | 예시 |
|---|---|---|
| `$eq` | 같다 | `{"type": {"$eq": "역사"}}` |
| `$ne` | 같지 않다 | `{"type": {"$ne": "역사"}}` |
| `$gt` | 초과 | `{"entrance_fee": {"$gt": 0}}` |
| `$gte` | 이상 | `{"entrance_fee": {"$gte": 3000}}` |
| `$lt` | 미만 | `{"entrance_fee": {"$lt": 3000}}` |
| `$lte` | 이하 | `{"entrance_fee": {"$lte": 1000}}` |
| `$in` | 목록 안에 있음 | `{"region": {"$in": ["제주", "부산"]}}` |
| `$nin` | 목록 안에 없음 | `{"region": {"$nin": ["서울"]}}` |

---

## 9.4 여러 조건 결합

### AND

모든 조건을 만족.

```python
where={
    "$and": [
        {"type": "역사"},
        {
            "entrance_fee": {
                "$gt": 0
            }
        },
    ]
}
```

뜻:

```text
유형이 역사
그리고
입장료가 0원 초과
```

### OR

조건 중 하나 이상 만족.

```python
where={
    "$or": [
        {"region": "제주"},
        {"region": "부산"},
    ]
}
```

---

## 9.5 숫자 범위

3000원 이상, 10000원 이하:

```python
where={
    "$and": [
        {
            "entrance_fee": {
                "$gte": 3000
            }
        },
        {
            "entrance_fee": {
                "$lte": 10000
            }
        },
    ]
}
```

잘못된 예:

```python
where={
    "entrance_fee": {
        "$gte": 3000,
        "$lte": 10000,
    }
}
```

한 조건 딕셔너리 안에는 연산자 하나만 사용.  
범위는 `$and`로 두 조건을 묶음.

# 10. 문서 본문 필터

메타데이터가 아닌 원문 내용을 검사할 때 사용.

## 10.1 특정 단어 포함

```python
where_document={
    "$contains": "해변"
}
```

## 10.2 특정 단어 미포함

```python
where_document={
    "$not_contains": "해변"
}
```

`where_document`는 의미 검색이 아니라 글자 포함 여부를 검사하는 키워드 필터.

---

## 10.3 메타데이터와 본문 필터 함께 사용

```python
result = travel_col.get(
    where={
        "type": "해변"
    },
    where_document={
        "$contains": "해변"
    },
    include=[],
)
```

뜻:

```text
메타데이터 type이 해변
그리고
본문에 "해변"이라는 글자가 포함
```

---

## 10.4 `where`와 `where_document`

| 인자 | 검사 대상 | 방식 |
|---|---|---|
| `where` | 메타데이터 | 값 비교 |
| `where_document` | 문서 원문 | 글자 포함 여부 |

둘은 서로 다른 인자라 따로 또는 함께 사용 가능.

---

## 10.5 필터 사용 시 주의점

1. 필터는 후보 문서를 완전히 제거.
2. 조건이 너무 강하면 요청한 K보다 결과가 적을 수 있음.
3. 복수 조건은 `$and` 또는 `$or`로 묶음.
4. 숫자 조건은 비교 연산자를 명확히 사용.
5. `where_document`는 의미가 아니라 실제 글자를 확인.

---

# 11. ChromaDB 클라이언트 종류

| 클라이언트 | 저장 위치 | 프로그램 종료 후 |
|---|---|---|
| `EphemeralClient()` | 메모리 RAM | 사라짐 |
| `PersistentClient(path=...)` | 지정한 폴더 | 유지됨 |
| `HttpClient(host=..., port=...)` | 서버 디스크 | 서버에 유지 |

---

## 11.1 EphemeralClient

```python
client = chromadb.EphemeralClient()
```

- 디스크 파일 없음
- 커널 종료 시 삭제
- 반복 실습에 적합

---

## 11.2 PersistentClient

```python
client = chromadb.PersistentClient(
    path="./chroma_db"
)
```

- 폴더가 없으면 자동 생성
- 커널을 꺼도 데이터 유지
- 다시 열면 기존 컬렉션 사용 가능

예상 폴더 구조:

```text
chroma_db/
├── chroma.sqlite3
└── 컬렉션_UUID/
    ├── data_level0.bin
    ├── header.bin
    ├── length.bin
    └── link_lists.bin
```

파일 역할:

| 파일 | 내용 |
|---|---|
| `chroma.sqlite3` | 원문·메타데이터·컬렉션 목록 |
| `data_level0.bin` | 벡터 본체와 HNSW 아래층 |
| `header.bin` | 벡터 차원·개수 정보 |
| `length.bin` | 벡터 길이 정보 |
| `link_lists.bin` | HNSW 위층 연결 정보 |

원문과 메타데이터는 SQLite에 저장.  
벡터와 HNSW 그래프는 `.bin` 파일에 저장.

# 12. HNSW 설정

HNSW는 모든 벡터를 전부 비교하지 않고 그래프를 따라 가까운 문서를 탐색.

```text
정확도 일부 포기
↔
검색 속도 향상
```

## 12.1 주요 설정

| 설정 | 역할 | 기본값 |
|---|---|---:|
| `hnsw:space` | 거리 계산 방식 | `l2` |
| `hnsw:search_ef` | 검색 시 확인할 후보 수 | 100 |
| `hnsw:M` | 각 벡터의 이웃 연결 수 | 16 |

---

## 12.2 `hnsw:space`

```python
metadata={
    "hnsw:space": "cosine"
}
```

선택 가능:

- `cosine`: 각도 기반
- `l2`: 유클리드 거리
- `ip`: 내적

문장 임베딩을 정규화해 사용할 때는 `cosine`을 명시.

---

## 12.3 `hnsw:search_ef`

검색할 때 후보를 얼마나 넓게 확인할지 결정.

```text
값 증가
→ 정확도 증가
→ 검색 속도 감소
```

```text
값 감소
→ 검색 속도 증가
→ 가까운 문서를 놓칠 가능성 증가
```

---

## 12.4 `hnsw:M`

각 벡터가 몇 개의 이웃과 연결되는지 결정.

```text
값 증가
→ 그래프가 촘촘함
→ 검색 정확도 증가
→ 메모리와 색인 시간 증가
```

문서를 넣을 때 그래프를 만드는 설정.  
나중에 바꾸려면 컬렉션을 다시 만들어야 할 수 있음.

---

# 13. Qdrant로 같은 검색 구현

벡터 DB 도구가 달라도 기본 흐름은 같음.

```text
클라이언트 생성
→ 컬렉션 생성
→ 벡터 적재
→ 질문 벡터 검색
```

---

## 13.1 기본 라이브러리

```python
from qdrant_client import QdrantClient
from qdrant_client.models import (
    Distance,
    VectorParams,
    PointStruct,
)
```

---

## 13.2 메모리 클라이언트

```python
qclient = QdrantClient(":memory:")
```

ChromaDB의 다음 코드와 비슷함.

```python
chromadb.EphemeralClient()
```

---

## 13.3 컬렉션 생성

Qdrant는 벡터 차원을 미리 지정.

```python
dim = doc_emb.shape[1]
```

기존 컬렉션이 있으면 삭제:

```python
if qclient.collection_exists("travel_guide"):
    qclient.delete_collection("travel_guide")
```

컬렉션 생성:

```python
qclient.create_collection(
    collection_name="travel_guide",
    vectors_config=VectorParams(
        size=dim,
        distance=Distance.COSINE,
    ),
)
```

---

## 13.4 데이터 적재

Qdrant에서는 문서 하나를 `PointStruct` 하나로 표현.

```python
points = [
    PointStruct(
        id=i,
        vector=doc_emb[i],
        payload={
            "name": spots.loc[i, "name"],
            "type": spots.loc[i, "type"],
            "region": spots.loc[i, "region"],
            "description": spots.loc[i, "description"],
        },
    )
    for i in range(len(spots))
]
```

적재:

```python
qclient.upsert(
    collection_name="travel_guide",
    points=points,
)
```

같은 ID로 다시 `upsert()`하면 기존 데이터가 덮어써짐.

---

## 13.5 Qdrant 검색

```python
query = "바다에서 시원하게 물놀이하기 좋은 곳"

query_emb = emb_model.encode(
    [query],
    normalize_embeddings=True
)

hits = qclient.query_points(
    collection_name="travel_guide",
    query=query_emb[0],
    limit=3,
).points
```

Qdrant에는 질문 벡터 하나를 전달하므로:

```python
query_emb[0]
```

사용.

---

## 13.6 검색 결과 출력

```python
for hit in hits:
    print(
        f"점수 {hit.score:.3f} | "
        f"{hit.payload['name']} "
        f"({hit.payload['type']})"
    )
```

Qdrant의 `score`:

```text
클수록 가까움
```

ChromaDB의 `distance`:

```text
작을수록 가까움
```

# 14. ChromaDB와 Qdrant 비교

| 구분 | ChromaDB | Qdrant |
|---|---|---|
| 메모리 모드 | `EphemeralClient()` | `QdrantClient(":memory:")` |
| 로컬 저장 | `PersistentClient(path=...)` | `QdrantClient(path=...)` |
| 서버 연결 | `HttpClient(...)` | `QdrantClient(url=...)` |
| 컬렉션 생성 | `get_or_create_collection()` | `create_collection()` |
| 데이터 적재 | `add()` | `upsert()` |
| 검색 | `query()` | `query_points()` |
| 메타데이터 | `metadatas` | `payload` |
| 검색 결과 | `distance` 작을수록 가까움 | `score` 클수록 가까움 |

---

## 14.1 Qdrant 로컬 저장 구조

```text
qdrant_db/
├── meta.json
├── .lock
└── collection/
    └── travel_guide/
        └── storage.sqlite
```

| 파일 | 역할 |
|---|---|
| `meta.json` | 컬렉션 목록·차원·거리 설정 |
| `.lock` | 여러 프로세스의 동시 접근 방지 |
| `storage.sqlite` | 벡터와 payload 저장 |

ChromaDB는 원문과 벡터 파일을 나눠 저장.  
Qdrant 로컬 모드는 `storage.sqlite`에 함께 저장.

# 15. 전체 코드 흐름

## 15.1 문서 임베딩

```python
doc_texts = spots["description"].tolist()

doc_emb = emb_model.encode(
    doc_texts,
    normalize_embeddings=True,
)
```

## 15.2 ChromaDB 생성

```python
client = chromadb.EphemeralClient()

travel_col = client.get_or_create_collection(
    name="travel_guide",
    metadata={
        "hnsw:space": "cosine"
    },
)
```

## 15.3 메타데이터 생성

```python
META_COLS = [
    "name",
    "region",
    "type",
    "entrance_fee",
]

meta_dict = (
    spots[META_COLS]
    .astype({"entrance_fee": int})
    .to_dict("records")
)
```

## 15.4 데이터 적재

```python
travel_col.add(
    ids=spots["id"].tolist(),
    embeddings=doc_emb,
    documents=spots["description"].tolist(),
    metadatas=meta_dict,
)
```

## 15.5 질문 검색

```python
query = "전통 음식을 파는 시장"

query_emb = emb_model.encode(
    [query],
    normalize_embeddings=True,
)

results = travel_col.query(
    query_embeddings=query_emb,
    n_results=3,
)
```

## 15.6 결과 출력

```python
for doc_id, dist, meta, doc in zip(
    results["ids"][0],
    results["distances"][0],
    results["metadatas"][0],
    results["documents"][0],
):
    print(
        f"{doc_id} | "
        f"거리 {dist:.3f} | "
        f"{meta['name']} | "
        f"{doc}"
    )
```

# 16. 자주 발생하는 실수

## 질문을 리스트로 감싸지 않음

```python
emb_model.encode(query)
```

권장:

```python
emb_model.encode([query])
```

## 문서와 질문의 임베딩 옵션이 다름

문서:

```python
normalize_embeddings=True
```

질문:

```python
normalize_embeddings=False
```

문서와 질문은 같은 모델과 같은 옵션 사용.

## ChromaDB 거리 기준을 지정하지 않음

```python
client.get_or_create_collection(
    name="travel_guide"
)
```

기본값은 `l2`.

권장:

```python
metadata={
    "hnsw:space": "cosine"
}
```

## 거리와 유사도를 반대로 해석

```text
ChromaDB distance
→ 작을수록 가까움

Qdrant score
→ 클수록 가까움
```

## 숫자 조건을 범위 조건으로 착각

```python
{"entrance_fee": 3000}
```

뜻:

```text
입장료가 정확히 3000원
```

3000원 이상:

```python
{
    "entrance_fee": {
        "$gte": 3000
    }
}
```

---

## 여러 조건을 한 딕셔너리에 바로 작성

```python
{
    "type": "역사",
    "entrance_fee": {
        "$gt": 0
    }
}
```

복수 조건은 명확하게 `$and` 사용.

```python
{
    "$and": [
        {"type": "역사"},
        {
            "entrance_fee": {
                "$gt": 0
            }
        },
    ]
}
```

## PersistentClient에서 데이터를 반복 추가

같은 ID를 다시 `add()`하면 충돌할 수 있음.

반복 실습에서는:

- `EphemeralClient()` 사용
- 기존 컬렉션 삭제
- `upsert()` 지원 여부 확인
- 중복 ID 관리

# 핵심 요약

| 단계 | 핵심 |
|---|---|
| 문서 임베딩 | 문서를 768차원 벡터로 변환 |
| 정규화 | 벡터 길이를 1로 맞춤 |
| 질문 임베딩 | 문서와 같은 모델·옵션 사용 |
| 유사도 계산 | 코사인 유사도 또는 정규화 벡터의 내적 |
| Top-K | 유사도가 높은 문서 K개 선택 |
| ChromaDB 적재 | ID·벡터·원문·메타데이터 저장 |
| ChromaDB 검색 | `query_embeddings`와 `n_results` 사용 |
| 필터 | `where`와 `where_document` 사용 |
| HNSW | 정확도와 속도를 조절하는 근사 검색 |
| Qdrant | 구조는 다르지만 색인·검색 원리는 같음 |
| 저장 방식 | 메모리 클라이언트는 종료 시 삭제, 로컬 클라이언트는 파일 유지 |

> **핵심:** 키워드가 겹치지 않아도 임베딩 벡터의 의미가 가까우면 관련 문서를 검색할 수 있음.
