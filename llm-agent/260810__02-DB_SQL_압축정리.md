# SQL 실전 개념 압축 정리

> 기준: PostgreSQL 예시  
> 흐름: **표 만들기 → 데이터 넣기 → 조회·필터 → 집계 → 수정·삭제 → JOIN·서브쿼리 → 벡터 검색**

---

## 1. SQL 명령어 분류

| 분류 | 역할 | 대표 명령 |
|---|---|---|
| **DDL** | 표 구조 생성·변경·삭제 | `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE` |
| **DML** | 데이터 조회·추가·수정·삭제 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| **TCL** | 여러 변경을 확정·취소 | `COMMIT`, `ROLLBACK` |
| **DCL** | 접근 권한 관리 | `GRANT`, `REVOKE` |

- 보통 SQL 문법어는 대문자, 테이블·열 이름은 소문자로 작성.
- SQL 표준은 있지만 DB 제품별로 문법 차이가 일부 존재.

## 2. 표 만들기: `CREATE TABLE`

```sql
CREATE TABLE customers (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name text NOT NULL,
    email text NOT NULL UNIQUE,
    city text,
    created_at timestamptz NOT NULL DEFAULT now()
);
```

핵심 제약:

- `PRIMARY KEY` : 행을 구분하는 대표 키
- `NOT NULL` : 빈 값 금지
- `UNIQUE` : 중복 금지
- `DEFAULT` : 값 생략 시 기본값
- `CHECK` : 값의 조건 검사
- `REFERENCES` : 다른 표의 키를 참조하는 외래키

### 외래키로 표 연결

```sql
CREATE TABLE orders (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id bigint NOT NULL REFERENCES customers(id),
    product text NOT NULL,
    amount integer NOT NULL CHECK (amount >= 0),
    created_at timestamptz NOT NULL DEFAULT now()
);
```

- `orders.customer_id → customers.id`
- 없는 고객 번호는 저장 불가.
- **1:N 관계에서는 외래키를 N쪽에 둠.**
- 참조 대상인 부모 표를 먼저 만들고 자식 표를 나중에 만듦.

## 3. 데이터 추가: `INSERT`

```sql
INSERT INTO customers (name, email, city) VALUES
('김민수', 'minsu@shop.com', '서울'),
('이지은', 'jieun@shop.com', '부산');
```

```sql
INSERT INTO orders (customer_id, product, amount) VALUES
(1, '노트북', 1290000),
(1, '마우스', 29000);
```

- 여러 행을 한 번에 추가 가능.
- 외래키 관계에서는 **부모 데이터 → 자식 데이터** 순서.
- 뒤에 `RETURNING id`를 붙이면 새로 생성된 값을 바로 확인 가능.

# 4. 데이터 조회

## `SELECT` = 열 선택 / `WHERE` = 행 선택

이미지의 핵심 구조:

```text
SELECT → 세로 방향으로 필요한 열 선택
WHERE  → 가로 방향으로 조건에 맞는 행 선택
```

```sql
SELECT name, city
FROM customers;
```

```sql
SELECT *
FROM orders
WHERE amount >= 100000;
```

### 기본 조회 구조

```sql
SELECT 열
FROM 표
WHERE 조건
ORDER BY 정렬기준
LIMIT 개수
OFFSET 건너뛸개수;
```

논리적인 처리 흐름:

```text
거르기(WHERE)
    ↓
정렬(ORDER BY)
    ↓
자르기(LIMIT / OFFSET)
```

```sql
SELECT product, amount
FROM orders
WHERE amount >= 50000
ORDER BY amount DESC
LIMIT 2;
```

## 5. 조건식

### 범위·목록·패턴

| 문법 | 의미 | 예 |
|---|---|---|
| `BETWEEN a AND b` | a~b, 양끝 포함 | `amount BETWEEN 29000 AND 89000` |
| `IN (...)` | 목록 중 하나 | `city IN ('서울', '대구')` |
| `NOT IN (...)` | 목록에 없는 값 | `city NOT IN (...)` |
| `LIKE` | 문자열 패턴 검색 | `product LIKE '%보드%'` |
| `DISTINCT` | 중복 제거 | `SELECT DISTINCT product ...` |

`LIKE` 패턴:

- `%` : 글자 0개 이상
- `_` : 정확히 한 글자

```sql
WHERE product LIKE '%보드%'
```

### 조건 결합

```sql
WHERE 조건1 AND 조건2
WHERE 조건1 OR 조건2
WHERE NOT 조건
```

- `AND`가 `OR`보다 먼저 처리됨.
- 섞을 때는 괄호를 사용하는 편이 안전.

```sql
WHERE (product = '마우스' OR product = '키보드')
  AND amount >= 50000;
```

같은 열의 여러 값은 `IN`으로 단순화 가능.

```sql
WHERE product IN ('마우스', '키보드');
```

## 6. `NULL` 다루기

`NULL` = 값이 없거나 아직 알 수 없는 상태.

```sql
WHERE city = NULL       -- 사용 X
WHERE city IS NULL      -- NULL 찾기
WHERE city IS NOT NULL  -- NULL 제외
```

`WHERE`는 조건이 참인 행만 남기므로 `NULL`과의 일반 비교는 원하는 결과가 나오지 않음.

빈 값을 표시용 값으로 바꾸려면:

```sql
coalesce(city, '미입력')
```

# 7. 함수와 집계

## 자주 쓰는 함수

| 종류 | 함수 |
|---|---|
| 문자열 | `upper`, `lower`, `length`, `trim` |
| 숫자 | `round`, `ceil`, `floor`, `abs` |
| 날짜 | `now`, `current_date`, `date_trunc`, `extract` |
| NULL 처리 | `coalesce` |

## 집계 함수

여러 행을 계산해 하나의 값으로 만듦.

```sql
SELECT
    count(*) AS 주문수,
    sum(amount) AS 총매출,
    round(avg(amount), 2) AS 평균금액,
    max(amount) AS 최고금액,
    min(amount) AS 최저금액
FROM orders;
```

### `count` 차이

| 문법 | 세는 대상 |
|---|---|
| `count(*)` | 모든 행 |
| `count(열)` | 해당 열이 `NULL`이 아닌 행 |
| `count(DISTINCT 열)` | 서로 다른 값의 개수 |

# 8. 그룹별 집계: `GROUP BY`

같은 값을 가진 행을 묶어서 집계.

```sql
SELECT
    customer_id,
    count(*) AS 주문수,
    sum(amount) AS 합계
FROM orders
GROUP BY customer_id
ORDER BY customer_id;
```

`SELECT`에는 기본적으로:

- `GROUP BY` 기준 열
- 집계 함수

를 사용.

## `WHERE` vs `HAVING`

```text
WHERE  → 그룹으로 묶기 전에 개별 행 필터
HAVING → GROUP BY 후 만들어진 그룹 필터
```

```sql
SELECT
    customer_id,
    count(*) AS 주문수,
    sum(amount) AS 합계
FROM orders
WHERE amount >= 50000
GROUP BY customer_id
HAVING sum(amount) >= 500000
ORDER BY 합계 DESC;
```

### SQL 작성 순서와 논리적 실행 순서

작성:

```text
SELECT
FROM
WHERE
GROUP BY
HAVING
ORDER BY
LIMIT
```

논리적 실행:

```text
FROM
 ↓
WHERE
 ↓
GROUP BY
 ↓
HAVING
 ↓
SELECT
 ↓
ORDER BY
 ↓
LIMIT
```

따라서 `SELECT`에서 만든 별칭은 `WHERE`에서는 아직 사용할 수 없음.

# 9. 데이터 수정: `UPDATE`

```sql
UPDATE orders
SET amount = amount + 1000
WHERE id = 2
RETURNING id, product, amount;
```

구조:

```text
UPDATE 표
SET 열 = 새값
WHERE 바꿀 행
```

- `WHERE`가 없으면 모든 행이 수정될 수 있음.
- `SET` 오른쪽에 기존 값을 이용한 계산식도 사용 가능.
- `RETURNING`으로 변경 결과 즉시 확인 가능.

# 10. 트랜잭션

여러 변경을 하나의 작업으로 묶음.

```sql
BEGIN;

UPDATE customers
SET city = '광주'
WHERE name = '박하늘';

COMMIT;
```

잘못되었으면:

```sql
ROLLBACK;
```

흐름:

```text
BEGIN
  ↓
INSERT / UPDATE / DELETE
  ↓
확인
 ├─ 정상 → COMMIT
 └─ 오류 → ROLLBACK
```

특히 `UPDATE`, `DELETE`처럼 위험한 작업에서 유용.

# 11. 데이터 삭제

## `DELETE`

조건에 맞는 **행** 삭제.

```sql
DELETE FROM orders
WHERE id = 2;
```

- `WHERE`가 없으면 모든 행 삭제.
- 표 구조는 유지.

안전한 흐름:

```sql
SELECT ... WHERE 조건; -- 먼저 대상 확인

BEGIN;
DELETE ... WHERE 조건;
-- 결과 확인
ROLLBACK;               -- 연습·오류라면 복구
```

## `TRUNCATE`

```sql
TRUNCATE TABLE orders;
```

- 표의 모든 행을 한꺼번에 삭제.
- `WHERE` 사용 불가.

## `DROP TABLE`

```sql
DROP TABLE orders;
```

- 데이터뿐 아니라 **표 구조 자체를 삭제**.

## 외래키와 삭제

부모를 자식이 참조 중이면 삭제가 막힐 수 있음.

```text
customers(id=1)
      ↑
orders.customer_id
```

기본 처리:

```text
자식 행 삭제 → 부모 행 삭제
```

표 생성 시 삭제 규칙을 지정할 수도 있음.

```sql
customer_id bigint
REFERENCES customers(id)
ON DELETE CASCADE
```

| 옵션 | 동작 |
|---|---|
| `CASCADE` | 부모 삭제 시 연결된 자식도 삭제 |
| `SET NULL` | 자식은 남기고 외래키를 NULL로 변경 |

`SET NULL`을 쓰려면 해당 외래키 열이 `NOT NULL`이면 안 됨.

# 12. 표 연결: `JOIN`

두 표를 관계 키로 연결.

```sql
SELECT
    c.name,
    o.product,
    o.amount
FROM customers c
JOIN orders o
    ON o.customer_id = c.id
ORDER BY o.id;
```

핵심:

```text
orders.customer_id = customers.id
       FK                 PK
```

- `JOIN`만 쓰면 일반적으로 `INNER JOIN`.
- 테이블 별칭 사용 권장: `customers c`, `orders o`
- 같은 이름의 열이 여러 표에 있으면 `c.id`, `o.id`처럼 소속을 명확히 표시.

## `LEFT JOIN`

왼쪽 표의 행을 모두 유지.

```sql
SELECT
    c.name,
    count(o.id) AS 주문수,
    coalesce(sum(o.amount), 0) AS 총매출
FROM customers c
LEFT JOIN orders o
    ON o.customer_id = c.id
GROUP BY c.id, c.name;
```

주문이 없는 고객도 결과에 포함.

주의:

```text
count(*)    → JOIN 결과 행 자체를 셈
count(o.id) → 실제 주문 id가 있는 행만 셈 → 주문 없는 고객 = 0
```

# 13. 서브쿼리

SQL 안에 다시 `SELECT`를 넣는 방식.

| 위치 | 역할 |
|---|---|
| `SELECT` | 행마다 값 하나 붙이기 |
| `FROM` | 중간 결과표 만들기 |
| `WHERE` | 계산 결과를 조건으로 사용 |
| `WHERE EXISTS` | 관련 행 존재 여부 확인 |

### `SELECT` 자리

```sql
SELECT
    c.name,
    (
        SELECT count(*)
        FROM orders o
        WHERE o.customer_id = c.id
    ) AS 주문수
FROM customers c;
```

### `FROM` 자리

```sql
SELECT *
FROM (
    SELECT customer_id, sum(amount) AS 합계
    FROM orders
    GROUP BY customer_id
) t
WHERE t.합계 >= 400000;
```

`FROM` 안의 서브쿼리에는 `t` 같은 별칭을 붙임.

### `EXISTS`

```sql
SELECT name
FROM customers c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.id
);
```

→ 주문이 하나라도 있는 고객만 조회.

### JOIN vs 서브쿼리

- 단순히 **존재 여부**만 확인 → `EXISTS`가 자연스러움.
- 여러 행을 한 번에 묶어 값을 가져옴 → `JOIN + GROUP BY`가 유용.
- 실제 성능은 쿼리와 실행 계획에 따라 달라짐.

확인:

```sql
EXPLAIN ANALYZE
SELECT ...;
```

# 14. pgvector: 의미 기반 검색

문장을 임베딩 모델로 변환하면 숫자 배열인 **벡터**가 생성됨.

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

```sql
CREATE TABLE documents (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    content text NOT NULL,
    category text,
    published_date date,
    embedding vector(3)
);
```

> `vector(3)`은 예시용 3차원 벡터. 실제 차원 수는 사용하는 임베딩 모델에 맞춰야 함.

## 유사한 문서 찾기

질문도 같은 임베딩 모델로 벡터화한 뒤 거리순 정렬.

```sql
SELECT
    content,
    1 - (embedding <=> '[0.85, 0.15, 0.15]') AS similarity
FROM documents
ORDER BY embedding <=> '[0.85, 0.15, 0.15]'
LIMIT 3;
```

교안의 흐름:

```text
질문
 ↓
임베딩 모델
 ↓
질문 벡터
 ↓
DB 벡터와 거리 계산
 ↓
가까운 순 정렬
 ↓
상위 문서 반환
```

`<=>` 거리값은 **작을수록 가까움**.

교안에서는 이를 다음처럼 유사도 형태로 사용:

```sql
1 - (embedding <=> 질문벡터)
```

## `LIMIT`만으로 부족한 이유

벡터 검색은 가까운 순으로 **순위**를 만들 뿐, 모든 결과가 관련 있다는 뜻은 아님.

```text
0.998
0.997
0.996
0.32  ← 관련성이 크게 떨어져도 LIMIT 자리를 채울 수 있음
```

따라서 개수뿐 아니라 **유사도 하한선**을 함께 사용할 수 있음.

```sql
SELECT content
FROM documents
WHERE 1 - (embedding <=> '[0.85, 0.15, 0.15]') >= 0.9;
```

RAG에서는 관련 없는 문서가 근거로 들어가는 것을 막는 데 중요.

# 15. 조건 + 벡터 검색

일반 SQL 필터와 의미 검색을 함께 사용.

```sql
SELECT content, published_date
FROM documents
WHERE category = 'pet'
  AND published_date >= '2024-01-01'
ORDER BY embedding <=> '[0.85, 0.15, 0.15]'
LIMIT 3;
```

흐름:

```text
WHERE
조건에 맞는 문서만 남김
        ↓
ORDER BY embedding <=> 질문벡터
의미상 가까운 순으로 정렬
        ↓
LIMIT
필요한 개수만 반환
```

즉:

> **조건 필터링 → 의미 거리 정렬 → 상위 N개**

### DB에서 먼저 거르기 vs 앱에서 나중에 거르기

**DB에서 먼저 필터링**

```text
조건 만족 문서 전체
      ↓
벡터 정렬
      ↓
TOP K
```

→ 조건을 만족하는 문서 중 가장 가까운 결과.

**벡터 검색 후 앱에서 필터링**

```text
전체 문서에서 TOP K
      ↓
앱에서 조건 확인
```

→ TOP K에 조건 만족 문서가 없으면 결과가 0건이 될 수 있음.

# SQL 핵심 치트시트

| 목적 | 핵심 문법 |
|---|---|
| 표 생성 | `CREATE TABLE` |
| 데이터 추가 | `INSERT INTO ... VALUES ...` |
| 열 선택 | `SELECT` |
| 행 필터 | `WHERE` |
| 정렬 | `ORDER BY` |
| 일부만 가져오기 | `LIMIT`, `OFFSET` |
| NULL 검사 | `IS NULL`, `IS NOT NULL` |
| 범위 | `BETWEEN` |
| 목록 | `IN` |
| 문자열 검색 | `LIKE` |
| 중복 제거 | `DISTINCT` |
| 집계 | `count`, `sum`, `avg`, `max`, `min` |
| 그룹화 | `GROUP BY` |
| 그룹 필터 | `HAVING` |
| 수정 | `UPDATE` |
| 삭제 | `DELETE` |
| 변경 확정·취소 | `COMMIT`, `ROLLBACK` |
| 표 연결 | `JOIN`, `LEFT JOIN` |
| 내부 쿼리 | 서브쿼리, `EXISTS` |
| 벡터 거리 정렬 | `ORDER BY embedding <=> 질문벡터` |

## 가장 중요한 구분

```text
SELECT     → 어떤 열을 볼지
WHERE      → 어떤 행을 남길지
GROUP BY   → 무엇을 기준으로 묶을지
HAVING     → 어떤 그룹을 남길지
ORDER BY   → 어떤 순서로 볼지
LIMIT      → 몇 개만 가져올지
JOIN       → 어떤 표와 연결할지
```
